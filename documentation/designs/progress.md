## 5. 工作方式

规划、派发、审查与合并的规则在仓库根目录的 `AGENTS.md`「Working Method」一节，那里是唯一的一份；本节只写审查标准各条在这里的含义。

每个 PR 按下面各条逐条看，任何一条不过就退回，不以「测试通过」代替审查（用户 2026-11-09：以资深架构师的要求审查架构与代码质量）。

- **清洁**：在拥有这个职责的那一层修根因，不在调用处打补丁；没有死代码、重复逻辑、兼容桥与只为一个用例加的特例；名字说明是什么，注释只写为什么。一个主构造函数加默认值，不留只为补默认值或保留旧签名的重载（D415）。
- **高内聚**：改动落在该职责所在的模块与类；一个类只因一种原因而变。
- **低耦合**：不新增跨模块依赖，不把内部类型漏到公开面；模块边界（[模块设计](06-modules.md) §3，`:architecture` 把守）不动；SPI、存储与线上格式的改动先有决定。
- **高性能**：决定、追加与订阅的热路径上不多一次往返、一次分配或一把锁，不阻塞线程；动热路径的改动带 Actions 上的 ABAB。
- **高扩展性**：经已有的端口扩展，不按后端或类型写分支；内存有界，按分区而不是全局加锁。
- **高可用**：取消、超时、重试与退避、幂等、崩溃后恢复这些失败路径都有定义并有测试；不静默丢弃，失败可见（台账、指标、日志）。
- **易用性**：公开 API 与运维动作的承诺简单、一致；报错说明该怎么办；行为变了，用户文档同一个 PR 改。
- **可维护性**：回归测试断言的是行为而不是实现；不靠时序碰运气；改动小到能一次读完，读不完就拆。
- **启动时的拒绝要跑整个构建的测试**：一条新的启动期拒绝会碰到每一个按自己选的名字或配置起宿主的测试，改动所在模块的 `check` 看不到别的模块；这类 PR 的说明要列出整个构建 `test` 的结果（#6688 第一次漏了 `:test-spring-boot`，协调者审查时也没有想到，[D470](decisions.md) ③）。每个 PR 的说明都要有补丁覆盖率一节，没有就不批准（#6688 第二次只败在门禁的补丁覆盖率上）。
- **改文档页的 PR 要构建文档站**：样例与布局的检查不构建站点；正文里代码块之外的 `<占位符>` 会被当作标签，构建失败（#6697 第一次败在这里）。说明的「跑了什么」里要有站点的构建。夜间运行执行的脚本，改动后先在分支上真跑一次再合并（#6698）。
- **给接口加默认方法，要查每一个靠委托实现它的测试替身**：新方法会绕过替身里对旧方法的挂起、失败或计数，测试仍然通过或变得不稳定而没有人改过它（#6711 给 `EventLog` 加 `heads` 之后，健康检查的一条测试只在几毫秒的窗口里通过，CI 上反复超时，#6719 修）。对外发布的模块（TCK 在内）加了公开成员，它的 ABI 清单要在同一个 PR 里更新并检查。提交前看 `git show --stat`，按路径暂存：仓库忽略的是目录 `node_modules/`，同名的符号链接不在其内（#6708）。机器、Docker 之类的标注读系统自己报告的，不凭印象写（[D474](decisions.md) ①、[D476](decisions.md) ④）。
- **类不过大**：超过约 600 行的类或文件（测试文件同样），改动不得让它再长：要加的逻辑属于哪个职责，就把那个职责抽成自己的类型，抽取小而机械的随同一个 PR，否则先出一个不改行为的 PR；新写的类型远低于这个数。600 行是提醒线而不是指标，判断仍看职责是否单一；声明式的文件（配置属性表、文案目录、TCK 规格）按内聚判断。现存的超线文件与例外见[审查台账](reviews.md)的 X-88。

## 6. 用户的长期要求

- 与用户用中文交流；代码、提交与 PR 用英文，提交与合并说明不带 Claude 署名。默认按推荐推进，不必询问；只有重大决策才给出推荐方案与用户讨论。
- 主会话是总架构师兼总协调：规划、派发、审查、合并，并编辑共享文档；实现交给子会话。**子会话一律用 Opus、Effort 为 xhigh，同时至多派五路**（2026-11-25：「子会话 Effort 使用 Extra」「子会话数最大 5」，[D482](decisions.md) ②；此前为按任务的难易选 Effort、至多两路，2026-11-21，当天最后的说法：「子会话派发：使用模型（Opus）基于难易度选择 Effort，平衡成本、效率与质量。最多派2路。」，[D447](decisions.md) ⑦；此前依次是「按任务的难易选模型」与「代码实现不要使用 Sonnet ，避免质量下降，除非简单任务」，第一轮里 Sonnet 的那一路漏掉了 JVM 反射语义上的细处）。成本靠 Effort 与并发来调，不靠换成更弱的模型。审查通过后由主会话开启自动合并；PR 默认开启 Auto-fix；子会话立不了的 issue 由主会话来立。
- 审查按资深架构师的标准（§5），并避免单个类过大。
- **在审的 PR 不积压**（2026-11-11）：未合并的 PR 多了，冲突的风险就大。每个会话同时至多三个，合并受阻时也不放宽：不开新的，不在未合并的工作上叠提交，先清存量。
- **临时故障造成的 CI 失败或不运行可以越过**（2026-11-11，两次）：前提是故障已确认、本机验证通过。故障的两种样子：检查失败而日志显示为基础设施故障、没有任何测试运行过；或运行一直排队、一个作业都没生成，同时 GitHub 有故障通报或全仓库没有运行完成。新的运行能正常开始时故障即已结束，新推送的提交走正常路径，只有卡在故障里的那个提交适用。本机验证指 CI 没能运行的全部内容，在该提交与 `main` 的合并结果上跑过：先用 `ci-scope.mjs` 算出 CI 会跑哪些作业，再跑这些作业的步骤。由主会话在已批准的那个提交上合并，并在 PR 上记下故障及其证据、所依据的本机验证与这条要求。这是「不绕过 PR 安全门禁」之下仅有的例外。第一次用于 #6079：它的三个运行创建于 GitHub 的 Webhooks 与 Actions 故障之间，排队一百多分钟没有作业。
- **GA 前格式保持 1，不考虑兼容性**（2026-11-10，D414）：GA 前改动存储或线上的形态就地改，不升格式号，不为旧形态写拒绝、转换或兼容代码，不提供升级路径。
- **设计记录保持精简**（2026-11-10）：进度、路线图与审查台账只留仍有用的内容，过期的删去，git 保留历史。
- **一个构造函数加默认值**（2026-11-10，D415）：删去不必要的构造函数重载。
- 发版：打标签与对外发布须用户确认，alpha、beta、rc 与 GA 的时机由用户决定（D202）。每个 `10.0.0-beta.N` 何时发由协调者定，并执行完整 CI、标签与发布，事后汇报（2026-11-17：「授权你发布所有 beta 版本。beta 版本用于下游升级试用，获得反馈后调整。beta 版不作兼容性承诺。」），不含改工作流与仓库设置，发布任务不自行重跑；rc 与 GA 每次另问。
- **beta.4 是性能专项，rc 之前的三件事排在它之后**（2026-11-12，[D425](decisions.md)）：把各负载做到存储自己的上限，不以持久性、顺序、等待的含义、拒绝或运维直接读存储的能力交换。
- **凡运行都以 JDK 25 为准**（2026-11-12，[D424](decisions.md)）：测试、服务、基准、演练与诊断都在 JDK 25 上跑，编译仍是 21；每个结果写明 JDK，别的 JDK 上的发现先在 25 上重现才算数。
- 新增第三方依赖，改发布自动化、安全设置、CI 工作流或 Dependabot、Renovate 的配置须先问用户；不绕过 PR 安全门禁。Renovate 对工作流里已固定版本的补丁或小版本升级，协调者对今天的主干核对后直接合并（2026-11-17：「默认按你推荐，重大决策再问我。」，协调者的理解）；改变工作流做什么的改动仍先问。
- **本机 Apple M5 Max 是默认的测量机器，随时可测**（2026-11-13：「允许，随时可测」，[D426](decisions.md)；此前是日常在 GitHub Actions 上测、本机要用户点头）：候选在本机成批筛选，一次只跑一批，一小时以上的运行先告知用户；Actions 是每个 PR 末尾的一次把关与资源紧的机器上的读数。里程碑的验证本机与 Actions 都跑（2026-11-10）。`bench.yml` 的触发在 beta.4 期间已授权协调者（2026-11-12，D425），2026-11-16 延续到 rc 之前的完整基准（L3、L4、A/A），其后的另问。不要 `./gradlew --stop`。
- **测量只在 M5 Max 上做；别的机器不测量**（2026-11-23：「本机不测量，留给 M5 MAX」，[D474](decisions.md)）：当天核实到协调会话与各子会话所在的机器是 Apple M4 Pro（14 核，24 GB），不是 M5 Max。在它上面只跑测试，不跑基准、不量时间与资源占用；需要测量的 PR 先靠测试与 Actions 上的对比过审，本机的数字等 M5 Max。派测量任务前先让会话读出机器自己报告的型号（`sysctl -n machdep.cpu.brand_string`），不照抄记录里的机器名。
- **机制要硬，策略要自由**（2026-11-21：「按你推荐」，[D447](decisions.md) ①）：框架自己的保证不让业务绕过，业务规则只给安全的默认值并留显式的出口；三个判断问题在 D447 ①，每个涉及约束的 PR 按它审。
- **默认按推荐推进，重大决策先记账、最后讨论**（2026-11-21：「默认按你推荐，重大决策先记账，最后跟我讨论，你继续推进目标。」）：协调者遇到取舍按推荐定并执行，不在回合末用问题把工作停住；重大的（公开 API 的形状、配置面、存储或线上格式、发版范围、对用户原先要求的例外或更正，界线是协调者的理解）记进 §2 的「待与用户讨论」，一个阶段结束时集中汇报。仍先问的：rc 与 GA 的发布，改工作流、发布自动化、安全设置或 Renovate 的配置，新增第三方依赖，发布作业失败后的重跑。
- **bug 清零才发版；beta 不用确认**（2026-11-21：「解决完所有issues bug 才能发版，beta 版 授权你发版，不用跟我确认」，[D447](decisions.md) ⑥）：带 bug 标签的 issue 全部关闭后才切版本；beta 由协调者直接发、事后汇报，rc 与 GA 仍每次另问。
- **下游使用者的反馈有价值的要吸收进 Wow 的特性**（2026-11-21：「另外下游使用者的issues中如果有价值的反馈应该吸收进 Wow 的特性中。」）：下游的 issue 不只是答复与登记。协调者的做法（协调者的理解）：每个下游 issue 判断它指出的是不是框架该有的能力；是的就排进 GA 前并派出，公开面的形状先出设计说明，按「机制要硬，策略要自由」审；不采纳的在 issue 里说明理由。只是用法问题的答复后关闭。
- **服务间调用默认受信**（2026-11-21：「服务间调用默认是授信的。」）：一个服务以自己的服务身份调用另一个服务，与进程内的受信调用同等对待；代终端调用方转发的不算，按那个调用方对待。涉及服务间的设计都按它审（协调者的理解：信任决定可不可以，是否要显式要求另论）。它依赖内部端口认出服务身份，而今天那是自报的、以网络策略为边界（D451 ③）。
- **用户点名「先设计跟我讨论」的事项只出设计说明**（2026-11-21，讨论取原值时）：用户点头前不派实现，对外只说方向与「设计待讨论」，不写成已决定。改动安全保证（掩码、授权、租户隔离）的事项，协调者都按这一条办（协调者的理解）。
- **等子会话时设兜底唤醒**（2026-11-21，用户同意多花的额度）：子会话的完成通知不一定能唤醒协调会话（当天一次空了约 4 小时 40 分）；有在等的子会话、CI 或发布时，设一个每小时一次的定时唤醒，无事可等时删掉。
- **定时的夜间运行没来时手动触发**（协调者的做法，2026-11-23）：`nightly.yml` 定时在 18:30 UTC，GitHub 通常晚到 23:30～01:10 才启动；过了这个窗口两小时仍没有、而主干当天动过，协调者手动触发它（它本来支持，不改工作流），并逐个看它派发的四个运行。
- **审过且检查全过的 PR，协调者可以直接合并**（2026-11-23：「放行你合并」）：PR 已是可合并状态时 `--auto` 会失败，这时用带 `--match-head-commit <审过的完整 SHA>` 的直接合并。一次一个 PR、写明审过的那个 SHA；不在循环里按当时读到的头提交成批开自动合并（权限检查拒绝过，协调者没有绕过）。
- **一方依赖的问题提到它的仓库**（2026-11-22：「cosec 升级过程中发现的问题，给 cosec 提issues，cosec 是一方依赖，由我们自己维护的。」）：在 Wow 的工作里发现 CoSec 的缺陷、文档缺口或缺的扩展点，直接在 `Ahoo-Wang/CoSec` 提 issue 并与 Wow 的 issue 互相引用；证据在子会话手里时由它写草稿、协调者核对后提交。只提 issue，改它的代码或发它的版本另问；CoSky 同样是一方库（用户 2026-11-23：「CoSky 是一方库，我们自己维护的。」）；CoCache、CosId 是否照此办理，遇到时先备草稿再确认（协调者的理解）。
- **按额度用量控制节奏，不过早撞上 5 小时的额度上限；不为成本降低质量**（2026-11-21：「基于额度用量，控制节奏，尽量避免过早撞5H」，随后：「不能为了成本而降低质量。」；当天五路同时起步，14 分钟用掉窗口的 14%）。节奏只靠并发与先后来调，不靠降低模型或 Effort：每一路的模型与 Effort 按任务的难度定，定了就不因用量而降（协调者当天曾把在跑的两路降为 medium，用户指出后恢复为 high）。协调者的做法（协调者的理解）：每次被唤醒先读用量；窗口里已用的比例不走在已过时间的比例前面（约每小时 20%），走在前面就不开新的，并停下优先级最低的一路；同时至多五路（用户 2026-11-25 定的上限，此前是两路）。审查的深度同样不因用量而减：读不完就少并行几路，不是少读几行。停下的一路留在它的会话里，不丢上下文，接上时发一条消息。
- **子会话的上限由用户定，现在是五路**（2026-11-25，见上；2026-11-21 为两路，2026-11-16 为五路，更早为三路与一路）：不自行放宽；没做完的写在 §2，不留在会话里；汇报从简，先测能定结论的几格。
- **构造函数的调优参数归入 Options，不引入 Builder**（2026-11-10，D416）：协作者留在构造函数里；装配类的协作者分组这次不做。
