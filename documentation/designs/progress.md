## 5. 工作方式

规划、派发、审查与合并的规则在仓库根目录的 `AGENTS.md`「Working Method」一节，那里是唯一的一份；本节只写审查标准各条在这里的含义。

每个 PR 按下面各条逐条看，任何一条不过就退回，不以「测试通过」代替审查（用户 2026-11-09：以资深架构师的要求审查架构与代码质量）。

- **清洁**：在拥有这个职责的那一层修根因，不在调用处打补丁；没有死代码、重复逻辑、兼容桥与只为一个用例加的特例；名字说明是什么，注释只写为什么。一个主构造函数加默认值，不留只为补默认值或保留旧签名的重载（D415）。
- **高内聚**：改动落在该职责所在的模块与类；一个类只因一种原因而变。
- **低耦合**：不新增跨模块依赖，不把内部类型漏到公开面；模块边界（[模块设计](06-modules.md) §3，`:architecture` 把守）不动；SPI、存储与线上格式的改动先有决定。
- **高性能**：决定、追加与订阅的热路径上不多一次往返、一次分配或一把锁，不阻塞线程；动热路径的改动带 Actions 上的 ABAB。
- **高扩展性**：经已有的端口扩展，不按后端或类型写分支；内存有界，按分区而不是全局加锁。
- **高可用**：取消、超时、重试与退避、幂等、崩溃后恢复这些失败路径都有定义并有测试；不静默丢弃，失败可见（台账、指标、日志）。
- **易用性**：公开 API 与运维动作的承诺简单、一致；报错说明该怎么办；行为变了，用户文档同一个 PR 改。
- **可维护性**：回归测试断言的是行为而不是实现；不靠时序碰运气；改动小到能一次读完，读不完就拆。
- **类不过大**：超过约 600 行的类或文件（测试文件同样），改动不得让它再长：要加的逻辑属于哪个职责，就把那个职责抽成自己的类型，抽取小而机械的随同一个 PR，否则先出一个不改行为的 PR；新写的类型远低于这个数。600 行是提醒线而不是指标，判断仍看职责是否单一；声明式的文件（配置属性表、文案目录、TCK 规格）按内聚判断。现存的超线文件与例外见[审查台账](reviews.md)的 X-88。

## 6. 用户的长期要求

- 与用户用中文交流；代码、提交与 PR 用英文，提交与合并说明不带 Claude 署名。默认按推荐推进，不必询问；只有重大决策才给出推荐方案与用户讨论。
- 主会话是总架构师兼总协调：规划、派发、审查、合并，并编辑共享文档；实现交给子会话（Opus），同时最多 5 个。审查通过后由主会话开启自动合并；PR 默认开启 Auto-fix；子会话立不了的 issue 由主会话来立。
- 审查按资深架构师的标准（§5），并避免单个类过大。
- **在审的 PR 不积压**（2026-11-11）：未合并的 PR 多了，冲突的风险就大。每个会话同时至多三个，合并受阻时也不放宽：不开新的，不在未合并的工作上叠提交，先清存量。
- **临时故障造成的 CI 失败或不运行可以越过**（2026-11-11，两次）：前提是故障已确认、本机验证通过。故障的两种样子：检查失败而日志显示为基础设施故障、没有任何测试运行过；或运行一直排队、一个作业都没生成，同时 GitHub 有故障通报或全仓库没有运行完成。新的运行能正常开始时故障即已结束，新推送的提交走正常路径，只有卡在故障里的那个提交适用。本机验证指 CI 没能运行的全部内容，在该提交与 `main` 的合并结果上跑过：先用 `ci-scope.mjs` 算出 CI 会跑哪些作业，再跑这些作业的步骤。由主会话在已批准的那个提交上合并，并在 PR 上记下故障及其证据、所依据的本机验证与这条要求。这是「不绕过 PR 安全门禁」之下仅有的例外。第一次用于 #6079：它的三个运行创建于 GitHub 的 Webhooks 与 Actions 故障之间，排队一百多分钟没有作业。
- **GA 前格式保持 1，不考虑兼容性**（2026-11-10，D414）：GA 前改动存储或线上的形态就地改，不升格式号，不为旧形态写拒绝、转换或兼容代码，不提供升级路径。
- **设计记录保持精简**（2026-11-10）：进度、路线图与审查台账只留仍有用的内容，过期的删去，git 保留历史。
- **一个构造函数加默认值**（2026-11-10，D415）：删去不必要的构造函数重载。
- 发版：打标签与对外发布须用户确认，alpha、beta、rc 与 GA 的时机由用户决定（D202）。
- 新增第三方依赖，改发布自动化、安全设置、CI 工作流或 Dependabot、Renovate 的配置须先问用户；不绕过 PR 安全门禁。
- 负载测试与基准在 GitHub Actions 上跑，日常不在本机测；本机 Apple M5 Max 的饱和快照是例外，用户要求时才跑（2026-11-10：rc 前的验证「本机也要跑」），由一个会话在协调者清出的窗口里跑。不要 `./gradlew --stop`。
- **构造函数的调优参数归入 Options，不引入 Builder**（2026-11-10，D416）：协作者留在构造函数里；装配类的协作者分组这次不做。
- **`wow-cocache` 不考虑迁移**（2026-11-10）：缓存可以重新回源加载，不为它的内容写迁移或升级步骤。
- **10.0.x 二进制兼容，10.x 源码兼容**（2026-11-11，D418）：GA 后公开的 Kotlin API 在次版本里不破坏调用方的源码，改名与删除等到主版本；所以公开面要在 GA 前定型。
- **视图引擎的设计由用户与 UI/UX 会话直接定**（2026-11-11）：协调者不参与设计讨论，只在交付时按代码质量审查并合并。
- **现有的 Builder 保留**（2026-11-11 按推荐）：`WowClient.builder()`、`CommandRequest.builder`（D337）；D416 只是不为构造函数的调优参数新引入 Builder。
- 打开的 PR 不超过约 15 个；保持仓库整洁：无孤儿文件、无死链、无名称中的版本特例；v9 真实项目的名称与内部细节不进入仓库。
