# Wow 设计文档

Wow 10 是 Wow 的一次整体重新设计：从第一性原理推出理想的目标架构，不受 9.x 兼容性的约束，历史只在迁移层一次性处理。本目录是它的全部设计记录。

开发线：默认分支 `main`；9.x 的维护线是 `v9`。设计基线：9.8.0（`v9` 上的 `b5813af56f`，2026-10-11 按 `b507c87f1e` 复核，其间 JVM 运行时无变化）。开发期 Wow 10 在长期分支 `v10` 上（2026-10-11 自 `07839c1c0f` 切出），2026-10-21 改名为 `main`；本目录 2026-10-22 由 `documentation/designs/v10/` 移到这里（D267 ㉓）。

## 维护约定

- **00 只写高层信息**：结论与理由，不写接口签名、表结构与算法细节；细节放进 01～07。00 与专题文档冲突时，以专题文档为准，并在同一个 PR 里修正 00。
- **每个决定只有一个家**：`decisions.md`。专题文档引用决定编号（如 D6），不复述推荐理由以外的讨论；决定拍板后，更新台账的状态与日期，再更新受影响的专题文档。
- **假设先于实现**：标为「待证据」的决定，在对应 spike 有结论之前，不开始依赖它的工作包。
- **状态**：每篇文档头部写日期、基线与状态（草案、已采纳、实施中、已实施、已取代）。里程碑完成时，更新路线图与相关文档的状态。
- 进度、路线图与审查台账只留仍有用的内容：一项做完即删去，git 保留历史；不在这些文件里追加逐日的合并流水。
- 用户可见的契约在实现落地时搬到文档站（`documentation/docs/{en,zh}/`）；本目录只解释为什么。
