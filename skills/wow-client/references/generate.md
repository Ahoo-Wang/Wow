# Generate the clients from the Manifest

A Wow V10 service publishes its contract as a Manifest: its bounded context, aggregates, commands, events, state, error codes and subscriptions (`GET /wow/manifest`, or the `manifest/baseline.json` the service commits). `@ahoo-wang/wow-generator` turns it into typed clients on `@ahoo-wang/wow-client`. Generated code is the contract on the TypeScript side: a changed command shows as a type error, not as a 400 in production.

## Run it

```bash
pnpm add @ahoo-wang/fetcher @ahoo-wang/fetcher-eventstream @ahoo-wang/wow-client
pnpm add -D @ahoo-wang/wow-generator typescript
pnpm exec wow-generator generate --input ./manifest.json --output ./src/generated --ts-config-file-path ./tsconfig.json
```

- `--input` takes a file or an http(s) URL (`-H 'Authorization: Bearer …'` for a protected one, with the token from the environment); prefer the Manifest the service commits, so a build does not depend on a running service.
- Several services: one output directory per service, or one run per Manifest into subdirectories (the eShop's web app runs `scripts/generate.mjs` over the five services' Manifests).
- Exit codes: `0` generated; `2` input or usage; `3` configuration; `4` the document cannot be generated, or `--strict` and a warning; `5` output (a path escapes, the manifest file is newer); `130` interrupted. Report the code, not "failed".

## What it writes

Per bounded context: `types.ts` (command, event and state types from the Manifest's schemas), `contract.ts` (`<Context>Contract`: the context's `NAME`, its context-level `Errors` and each aggregate's constant, whose `Errors` hold its domain error codes; the `<Context>ErrorCode` union, `<Context>Subscription` and the `<context>Wait` hops) and `client.ts` (`<Context>Client`: `.gateway`, a `CommandGateway`, and per aggregate `.<aggregate>.commands`, `.snapshots`, `.events` and `.state`). Per aggregate, in `<context>/<aggregate>/`:

- `aggregate.ts`: `<Aggregate>Aggregate` (context, name, path, ownership, `textNumbers`), `<Aggregate>StateField` (the `state.*` paths a query names) and the `<Aggregate>Event` union, named as the server sends them (`<context>.<aggregate>.<Event>`).
- `commandClient.ts`: `<Aggregate>CommandClient`, one method per command (kebab route, camelCase method) and a `…Stream` twin per command, plus the lifecycle commands the aggregate lists.
- `queryClient.ts`: `<Aggregate>SnapshotQueryClient`, `<Aggregate>EventQueryClient`, `<Aggregate>StateClient`.

Every file starts with `// Code generated by wow-generator. DO NOT EDIT.` and imports with `.js` suffixes, so it compiles under `NodeNext` and `bundler`.

## Exact numbers come from the Manifest

A field of a Kotlin `Long`, `BigInteger` or `BigDecimal` carries the schema format `int64`, `bigint` or `decimal` in the Manifest. The generator types it `string` and records its paths in `<Aggregate>Aggregate.textNumbers` (`state`, `events` by name, `commands` by name); the clients hand them to wow-client, which parses those numbers as their exact text and writes command fields back as unquoted JSON numbers. A field whose format changes moves between `string` and `number` in the types: the type check finds every use.

## Keep it current

- Commit the output with `.wow-generator.json` (the files it wrote; a later run removes what it no longer generates).
- In CI, regenerate from the committed Manifest with `--strict` and fail on any difference (`git diff --exit-code src/generated`). The service's own CI fails on a Manifest break against its baseline; the client's CI catches the rest.
- Never edit generated code: change the service (and its Manifest) or the generator's input, and regenerate.

## Not a Wow service: OpenAPI

For any OpenAPI 3 document (a third-party API, a service's own non-Wow routes) the same CLI generates models per component schema and a Fetcher decorator client per tag; that output needs `@ahoo-wang/fetcher-decorator` and `"experimentalDecorators": true`, and `wow-generator.config.json`'s `apiClients` (`ignorePathParameters`, `methodNames`) shapes it. A Wow service is generated from its Manifest, never from its OpenAPI document.
