## 1. 产品定义、目标、价值与特性

### 1.1 第一性原理：让已有数据服务于不同任务

业务用户需要的不是一组未经组织的记录，而是能够回答当前问题的信息。同一份业务数据可以服务于不同任务：查找待处理明细、比较不同分组、观察趋势，以及把多个结果组织成日常概览。任务之间的差异，往往发生在数据范围、组织方式和呈现方式，而不是业务实体或业务流程本身。

以已声明相应查询能力的订单数据为例：“待出库订单”需要筛选和明细排序；“各仓待出库数量”需要按仓库分组及计数；“出库工作概览”需要组合这些视图。三者应尽可能复用定义、配置协议和执行行为，不为每一种观察方式复制一套页面流程。

由此确定三项基础需求：**把受支持的观察方式表达为配置；让有价值的配置能够保存与复用；让同一配置的每次浏览具有独立运行状态。** 配置能力以宿主声明为边界，不能创造尚不存在的数据、指标、查询能力或授权范围。

### 1.2 产品定义

> **View Engine 是一个面向业务应用的可配置数据视图引擎。它以结构化配置描述数据范围、组织方式和呈现方式，提供记录、分析与 Dashboard 能力，并通过统一的执行、状态和交互机制，支持视图的保存、复用、组合与独立嵌入。业务系统负责数据与领域规则，引擎负责让数据观察方式可靠运行。**

其中，“视图”是一种面向任务的数据观察方式，不等于某个 React 组件、数据库视图或一次查询结果；“引擎”赋予配置明确的校验、执行、状态转换和恢复语义，不是把 JSON 映射成 JSX 的模板层。

产品由三个相互协作的部分组成：**视图描述表达意图，运行时落实执行语义，交互与呈现让用户使用和调整视图。** 核心既能消费代码提供的配置，也能消费交互产生的配置；用户不必经过可视化设计器才能使用已有视图。

本项目以 Wow 查询语义作为具体执行契约，React 作为交互与默认 UI 的实现环境。产品定义面向业务任务，不因此扩展成协议无关的万能查询层；Base UI、表格库和图表库是实现手段，不是产品本身。配置模型、Host 接入和三类视图运行时是这一定位的源码基础。[S01] [S02] [S11] [S13]

**保存视图保存的是观察方式，不是冻结业务数据。** 再次打开可以使用同一配置重新查询，但结果可能随时间、数据变化和服务端授权范围而不同。保存／分享视图不能被宣传为跨用户相同结果、历史数据审计快照或跨数据源一致时点。

### 1.3 目标

**用户目标：围绕任务组织数据。** 用户能够在已有能力内调整范围、排序、字段、分组、指标和面板组合，更快找到并理解所需信息。默认入口提供可直接使用的初始视图或明确的空态，不强迫每个人从空白画布学习一个复杂设计器。

**研发目标：让支持范围内的观察变化不再要求重新开发页面。** 业务接入集中于定义、查询能力、数据源、持久化服务和必要扩展；筛选编辑、请求协调、结果呈现、保存恢复与嵌入隔离由同一套引擎行为复用。配置化减少重复研发，不免除新业务指标和后端能力的开发。

**演进目标：复杂场景增加后仍然易用、可组合、可维护。** 默认界面覆盖普通需求，公开行为和任务部件支持不同布局。新增支持范围内的视图应主要改变配置或接入，不在通用组件中增加业务类型分支，也不复制一套控制器绕过原有契约。

### 1.4 价值

| 对象     | 价值目标                                             | 不能混淆的边界                                     |
| -------- | ---------------------------------------------------- | -------------------------------------------------- |
| 业务用户 | 减少重复设置，更直接地找到、比较和理解数据           | 可配置本身不是收益；任务应更容易完成               |
| 开发者   | 复用状态与流程行为，不只复用表格外观                 | 业务规则、数据访问和新增查询能力仍由业务侧提供     |
| 产品团队 | 把一部分列、筛选、指标选择和面板排布需求变为配置任务 | 不承诺任意需求都能免开发、免发版                   |
| 组织     | 沉淀个人与共享观察方式，降低重复解释口径的成本       | 共享配置不自动构成统一指标治理，也不授予数据访问权 |

价值判断以真实任务为单位：用户是否减少重复操作，开发者是否减少重复行为代码，配置能否被再次使用，结果来源能否被正确理解。组件数、配置项数、Hook 数和目录层数都不是产品价值指标；没有对照测量时不宣称具体效率提升比例。

### 1.5 产品能力结构

| 层级           | 能力                           | 面向的任务                                               | 关键边界                                               |
| -------------- | ------------------------------ | -------------------------------------------------------- | ------------------------------------------------------ |
| 共享表达能力   | **Filter：结构化筛选**         | 表达数据范围，保留可编辑条件和原始输入                   | 不是第四类视图，也不是服务端数据权限                   |
| 视图类型       | **Record：记录视图**           | 浏览、筛选、排序、分页、选择及汇总明细，以表格或卡片呈现 | 不在本轮扩展为单元格编辑 DataGrid                      |
| 视图类型       | **Analysis：分析视图**         | 使用受支持的分组与指标比较数据、观察分布和趋势           | 不自行发明业务指标，不在展示层重新聚合                 |
| 视图类型       | **Dashboard：视图组合**        | 将记录、分析及既定内容面板组织为概览，协调全局条件       | 不是任意页面构建器，也不是跨源联结或统一查询           |
| 跨视图使用能力 | **保存、重新打开、另存与共享** | 沉淀和复用观察方式                                       | 保存配置不等于保存数据快照；持久化与许可通过 Host 接入 |
| 跨视图使用能力 | **独立嵌入**                   | 在首页、详情页或其他业务页面复用已保存视图               | 复用实例，不共享分页、选择、临时筛选和错误状态         |

Filter、视图类型、保存与嵌入不强行使用同一抽象。独立筛选器和合法配置执行可以不使用实例持久化；完整视图管理在需要时接入服务。不同使用深度共享同一套规则，不要求轻量消费者先搭建完整工作台。

### 1.6 关键架构特性

| 特性                 | 用户或接入方可依赖的性质                           | 对应实现约束                                           |
| -------------------- | -------------------------------------------------- | ------------------------------------------------------ |
| **配置驱动**         | 支持范围内的观察方式可描述、保存和重新使用         | 配置与组件实现解耦；不是任意可执行脚本                 |
| **受约束执行**       | 非法或不支持的查询有明确反馈，不被静默放行         | 定义声明能力，编译与结果校验落实边界，查询经 Host 执行 |
| **状态隔离**         | 一份实例可被多个位置独立使用，编辑与浏览不互相污染 | 实例、运行位置、输入缓冲和操作身份明确                 |
| **结果保真**         | 结果的条件、计划和时间可追溯，换图不改变数据含义   | 成功结果绑定来源；不以新草稿重解释旧结果               |
| **行为与外观分离**   | 换主题或任务布局不复制查询、保存和恢复逻辑         | 核心、React 行为、任务部件和默认 UI 单向依赖           |
| **默认可用且可组合** | 普通任务直接使用，复杂场景有清晰扩展入口           | 完整视图与独立部件消费同一行为，不维护两套流程         |

可靠恢复、明确的资源预算、键盘与焦点交互、可验证的性能和真实包产物，是这些特性的交付条件，不作为额外业务平台扩张。结果保真约束执行与呈现的一致性，不代替业务服务保证原始数据质量或指标定义正确。

### 1.7 产品边界与本轮范围

| 不承担的职责                       | 协作方式                                                   |
| ---------------------------------- | ---------------------------------------------------------- |
| 业务数据库、数据仓库和通用计算后端 | 引擎编译、协调并调用查询；数据与聚合能力由宿主服务提供     |
| 用户、角色、组织与授权策略管理     | Host 提供可选许可结果，可信业务服务执行最终授权            |
| 订单审核、出库或库存调整流程       | 引擎提供动作上下文和当前性保护，业务组件与服务执行领域操作 |
| 任意页面低代码与任意 Widget 平台   | 专注数据视图表达与组合，不描述所有页面、路由和流程         |
| 通用基础组件大全                   | 复用成熟交互基础，公开有数据视图任务价值的部件             |
| 无限能力的 BI 与指标治理平台       | 只执行已声明的分析能力，承载业务口径而不垄断其定义         |

本轮覆盖 Filter、Record、Analysis、Dashboard、共享工作台、嵌入、扩展、主题，以及归属 Fetcher、基于 Wow 实现的 ViewHost 服务与前端适配。服务管理可低频修改的视图定义、可保存的视图实例和用户偏好，三者各有聚合边界；交付包含前后端契约与独立产物验证。不新增跨页全选、单元格编辑 DataGrid、Dashboard 嵌套、新图表类型、权限管理子系统或自动化业务写入。默认交互可以为任务清晰度调整，但不增加并存的历史产品模式，不以架构调整为名启动另一个全面视觉改版。

**授权规则归业务系统，Host 接入层提供授权结果，视图管理命令推导并检查操作可用性，可信服务端负责最终授权。** 引擎不计算业务数据范围。不接许可服务也能使用筛选、编译、查询、表格、图表与独立浏览；相关数据和引用访问仍由业务服务独立检查。

### 1.8 决策原则与需求准入

决策优先级为：**结果正确与数据安全 → 模型与所有权清晰 → 任务易用与 API 一致 → 性能、扩展性与可维护性 → 实施成本。** 尚未正式发布，不承担历史 API、导出路径或配置格式兼容；直接调整目标设计，完成切片不保留别名、兼容包装或双格式读写。

对于一项新需求，先判断它改变什么：已有能力的范围与组织选择，以及需要保存的列配置、图表映射和 Dashboard 几何，进入视图实例；界面元素与工具栏、配置区的布局进入部件和皮肤；新增可复用查询能力需要明确协议、Host 支持与完整测试；领域授权和业务流程留在业务系统。不能通过增加任意脚本、业务类型开关或无限配置项把边界问题藏起来。

复用已有价值的编译、请求调度、结果投影、保存核对和布局算法，保护的是正确性性质，不是现有类和字段的形状。也不为技术新鲜感更换全部基础库，或仅因未来可能切换供应商就建设万能适配层。

无兼容负担仅适用于本项目尚未发布的接口与开发配置，不意味着可任意改变 Wow 查询协议、第三方库行为或生产业务服务。协议翻译保留在明确接入边界；现有基础库按仓库锁定版本使用，不能用另一版本的 API 印象指导改写。安全与并发正确性是硬约束；非必要的抽象、额外模式和新平台能力不因“架构优先”自动获得建设资格。

当新增任务反复侵入通用组件、相同行为被多处复制、一个状态出现多个写入权威，或扩展点开始相互破坏时，先用任务与反例测试固定预期，再主动重构对应职责。限制单次建设范围，不降低正确性和工程质量；抽象是否成立由真实消费者验证。

**总判断标准：更多受支持的数据任务，是否能够通过复用配置与行为完成，而不是通过复制页面代码完成。** 产品闭环、工程反例与价值验证共同决定是否交付，分别见第 15—17 节。

本轮的完成对象是这些能力的目标实现与公开消费路径，不是“增加一批 Hook”。视图定义、实例配置、数据请求和结果来源的约束不因换 UI 消失，现有正确机制也不因重构而全部重做。

当前跨层接线还须同时调整：`ViewLoader.load()` 把定义、完整实例列表和许可初始化放入同一个等待屏障，并为列表项建立会话；`ViewHost` 只有创建接口携带 requestId，偏好写入返回 void，删除回执包含默认实例；`viewServiceContract` 仍有旧格式投影分支。这些不是目标合同的实现，必须在加载切片、写入切片和真实包消费者中一起更改，不能仅加一层 HTTP 适配器假定差异已经消失。[S02] [S42] [S43]

最小建设单元是一个可完成的用户任务，不是一个横向框架。共用纯规则、运行时与任务部件即可；不增加通用状态机语言、无限插件总线或可跨业务任意写入的操作平台。三个服务聚合使用自己的事件与版本，单包多入口和单服务多聚合已足以表达当前边界。

## 2. 架构边界与公开入口

### 2.1 单向依赖

分层服务于任务，而不是技术分类本身：配置层表达观察意图，运行时负责可靠执行，React 层绑定交互，默认 UI 提供直接可用的任务入口。自定义组合替换呈现结构，不重新实现查询和保存策略。

```text
业务宿主与页面
    ├── 默认 UI：工作台、独立视图、嵌入、任务部件
    └── 自定义组合
                 ↓
       React 行为、无样式任务部件、DOM 绑定
                 ↓
       核心会话、命令、执行、保存与恢复
          ├── 模型、纯转换、编译、校验、投影
          └── ViewHost 契约
                         ↑ 实现
              业务服务 / Memory / IndexedDB
```

独立筛选器、值编辑器和单元格无需创建 ViewEngine。图中的层次表达依赖方向，不要求每个组件都穿过引擎，也不要求每个文件都拆成 Hook、Context、Adapter 三份。

按三种消费深度交付：独立编译／控件、核心运行时、自带默认 UI 的完整视图。纯配置执行允许由调用方直接提供已准入的 definition 与 config，不为没有持久化的查询伪造服务端 instanceId 或 revision。默认应用不必自行组装每个内部控制器；高级调用方也不必创建整个工作台才能获得单一能力。

| 边界           | 职责                                                                         | 不允许承担                                                         |
| -------------- | ---------------------------------------------------------------------------- | ------------------------------------------------------------------ |

| 核心运行时     | 会话权威状态、命令策略、资源所有权、查询、写入核对；视图管理命令消费宿主许可 | 授权策略计算、权限远程加载编排、默认样式、页面布局、供应商渲染类型 |

Host 是业务应用与引擎之间的适配接口，不等于服务端，也不天然可信。生产接入中的前端 Host 转发请求和授权结果；Memory／IndexedDB 提供对应环境的存储实现。宿主接入、授权执行与事务边界分别见第 13 节。

React 行为与任务部件可以依赖 React、React DOM、必要的 Base UI 原语及经核对的 Fetcher React 核心能力；不能抵达本包的默认控件、皮肤、图标、React Grid Layout、Recharts 或默认 Table 渲染模块。Base UI 是无样式交互依赖，不应被误归类为品牌皮肤。

Table、Grid、Chart 的供应商适配位于默认 UI 的明确模块中。核心和通用控制器不出现供应商类型；不建设可以任意替换所有库的万能适配框架。

单包入口隔离不承诺减少安装依赖。分别检查源码模块图、构建产物模块图、声明文件依赖、使用方打包结果和安装依赖。核心在 Node 环境可导入、核心声明不要求浏览器 DOM；React 入口的声明允许 DOM 类型。重型可选模块故障降级不等于“缺少必需 npm 包也能正常安装”。[S15] [S16]

React 客户端入口的客户端标记应在实际构建中保留；纯核心与 Host 契约不标记为客户端专用。

### 2.3 代码组织

按 Filter、Record、Analysis、Dashboard 聚合能力，内部按实际需要区分 `model`、`runtime`、`react`、`ui`。共享运行时只放生命周期、调度、发布、资源账本与写入协调；共享 React 模块只放已经证明相同的绑定规则。

跨类型实例联合由契约装配层定义；每个类型的基础模型不反向依赖整个联合入口。ViewEngine 是装配入口，可以显式装配 Record、Analysis、Dashboard 三类运行时，不需要开放任意 view-kind 插件协议。Filter 属于共享表达能力，不新增一个 filter 实例种类；保存和嵌入沿各类型的明确契约复用，而不是另建平行视图引擎。

Dashboard 通过窄化的会话、位置、引用加载与资源预算端口复用核心，不持有能够任意改写全引擎的接口。SessionStore 负责权威状态发布，不同时包办 Dashboard 查询编译、LRU 淘汰和引用加载。拆分职责时不拆成互相同步的多个权威 Store。[S03] [S04]

“一份权威状态”指每项事实只有一个写入权威，不要求所有功能使用一个无边界巨型对象。会话、结果与资源账本可由内部职责模块管理，但跨模块变更通过同一个明确提交边界发布。控制器读取已有 handle，调用领域命令；不能用多组 Effect 互相同步实例镜像。编辑代次和内部 lease 是失效保护手段，不建设对外通用事务插件框架。

### 2.4 项目归属、仓库与交付边界

**ViewHost 是 Fetcher View Engine 的配套服务，产品与代码归属 Fetcher；Wow 是它使用的通用框架依赖。** 视图定义、实例配置、个人偏好和前端接入契约随视图产品演进，不进入 Wow 的框架核心。框架层确需补齐的通用机制在 Wow 中独立实现；不能把含视图领域类型的规则上移到框架。

同仓用于原子更新协议与消费者，不强迫前后端使用同一语言、构建、版本或部署流水线。前端由 pnpm 构建并发布 npm 产物；后端由自身 Gradle Wrapper 构建，独立发布服务制品并部署。后端构建不以完整前端 UI 构建为前提，前端发布不要求安装 JDK 或启动 JVM 服务。端到端联调在单独验证任务中组合两种产物。

语义以明确规则和双端正反例夹具落实：TypeScript 编译器代码不能自动成为 JVM 校验器，JSON Schema 通过也不能证明字段能力、指标引用或 Dashboard 映射成立。每个可保存的扩展协议在服务注册同身份、同协议版本的校验语义；仅在应用装配处提供 UI renderer 不等于服务端已支持。默认协议给出 TS／Kotlin 对应验证器与相同输入的预期语义结果；不为此新增任意 JavaScript 服务端执行器。

CI 分为前端、JVM 服务和契约联调三条验证路径；Schema、HTTP 合同、回执或定义版本语义变化触发两端验证。纯 UI 变化不触发后端发版，纯后端内部变化不强制发布 npm；涉及合同变更时验证明确的一对客户端／服务产物并安排协同上线，不承诺任意旧新组合互通。无兼容负担允许同步调整目标协议，不意味着跨进程通信可以没有版本与部署核对。

引擎的根入口、`/react` 和 `/ui` 不静态依赖 `WowViewHost`；只有选择 `/hosts/wow` 的消费者接入该适配器。业务数据仍由调用方注入的 `resolveSource` 连接原业务客户端，路由跳转仍由 `openOriginal` 等前端回调负责。其他符合 `ViewHost` 契约的实现继续可用，不以启动默认后端作为使用引擎的必要条件。

## 3. 状态模型：定义、实例、运行会话与编辑缓冲

### 3.1 领域概念与独立身份

**视图定义说明“允许怎样观察这类数据”，视图实例说明“具体采用哪种观察方式”，运行会话说明“这次使用的状态”。** 全文的正式领域术语统一如下：

| 概念         | 类型与身份                                | 归属及寿命                                                       |
| ------------ | ----------------------------------------- | ---------------------------------------------------------------- |
| 视图定义     | `ViewDefinition`；引用身份 `definitionId` | 可低频修改的独立聚合，保存字段、数据源和能力描述，不拥有实例集合 |
| 视图实例     | `ViewInstance`；引用身份 `instanceId`     | 一份可保存的具体配置一个聚合；按 `kind` 区分三类视图             |
| 用户视图偏好 | `UserViewPreferences`                     | 一个租户、用户、定义一份聚合，只保存实例引用和个人使用偏好       |
| 运行会话     | `ViewSession`；身份 `runtimeId`           | 前端的受管理编辑或独立浏览，不成为第四类后端持久化聚合           |

类型自身的主键使用 `id`；引用另一个资源时使用 `definitionId` 或 `instanceId`。`ViewInstance.id` 与引用它的 `instanceId` 指向同一个保存身份，不再额外增加同义 ID。尚未保存的实例草稿没有服务端实例 ID 和 revision，使用其运行会话与创建请求身份管理；成功创建后再关联保存身份。

定义与实例是“能力约束—具体配置”的关系，不是类继承，也不是父聚合包含所有子聚合。Dashboard 面板在所属实例配置内有稳定 `panelId`，被引用视图仍是其他独立的 `ViewInstance`。

**`runtimeId` 标识一次运行会话，`instanceId` 标识已保存实例。不能通过两者是否相等、字符串前缀或是否具有保存许可来推断运行模式。**

所有会话显式声明用途：受管理编辑、独立浏览或 Dashboard 面板浏览。未保存实例的 `instanceId` 为缺省值；创建成功只关联服务端身份，不重新生成 runtimeId，不重建图表或面板运行位置。

一个已保存实例可以同时对应多个独立浏览位置。工作台选中项引用运行会话；用户的默认实例偏好引用已保存实例。这两种状态不能合并。

同一 Engine、同一实例的受管理编辑会话默认只有一份，多处工作台呈现共享该 handle；重复打开不创建互相覆盖的编辑副本。不同 Engine／页面进程的并发编辑由服务端 revision 解决。本轮不增加多人实时协同或分支编辑产品。独立浏览位置不受此唯一编辑规则限制。

共享实例复用查询与呈现描述，不共享数据授权、选择或输入缓冲。已经保存的定义版本与配置验证凭据只证明某次校验事实，不是允许继续执行已撤销能力的凭证。实例保存不包含成功结果行和活动请求；重开后的查询采用对应环境的当前数据，缓存也不能冒充实例内容。需要固定历史数据的审计或导出产品必须有独立契约，不从“视图已保存”推断支持。

| 状态                     | 唯一权威与寿命                     | 持久化规则                                                            |
| ------------------------ | ---------------------------------- | --------------------------------------------------------------------- |
| 已采用定义               | 对应解释环境的不可变快照           | 服务来源带 definitionId 和定义 revision；本地纯配置按局部输入身份管理 |
| 保存基线                 | 受管理会话；来自已核对回执         | 持有实例 revision 与服务端记录的定义校验版本；未保存实例没有伪造基线  |
| 工作配置                 | 受管理会话                         | 保存当前合法配置，而非最后查询的配置                                  |
| 浏览配置                 | 独立位置或 Dashboard 浏览运行时    | 不回写原实例，不获得保存能力                                          |
| 编辑初始值               | 创建或局部编辑事务的初始快照       | 用于本地取消，不冒充服务端基线                                        |
| 已应用查询               | 数据运行位置                       | 与保存无关，绑定执行口径                                              |
| 查询尝试                 | 数据运行位置                       | 包含请求身份、计划和意图；失败时保留必要来源                          |
| 成功结果                 | 数据运行位置及结果缓存             | 绑定实际查询、schema、结果时间与结果身份                              |
| 选择与分页游标           | 数据运行位置                       | 不存入实例；选择只属于当前结果                                        |
| 输入缓冲与有效性         | 编辑会话；按节点身份和编辑代次隔离 | 需要恢复的原始值必须有受控、可序列化表达                              |
| 面板开关、焦点、显示模式 | 视图交互对象                       | 不存实例；按明确的界面寿命保留                                        |
| 写入恢复上下文           | 引擎写入协调器                     | 在逻辑写入结果核对前不得静默淘汰                                      |

Record、Analysis、Dashboard 仍使用判别联合，不要求所有类型共享同一份最大化状态结构。相同字段形状不是相同业务语义的证据。

### 3.2 可派生状态

`dirty` 表示工作配置相对保存基线改变；`pending` 表示当前草稿尚未应用；`stale` 表示可见结果与当前执行意图不一致；`inputInvalid` 表示输入尚不具备合法语义；`reconciliationRequired` 表示写入结果尚未核对。它们可以缓存派生，但不能独立由多个组件写入。

未保存实例没有保存基线，使用明确的 `isNew` 表达“尚未创建”；相对本地初始值的修改另行派生，不能因 dirty 为 false 就禁止合法新实例首次保存。没有成功结果属于“未运行／无结果”，不是“结果过期”；成功结果为零行属于有效空结果，不是未查询。`pending` 比较工作查询意图与已采用意图，`stale` 比较可见结果与已采用意图，不用一个“配置变了”标志替代两者。

声明比较的语义范围：实例等价、可执行查询等价、解释环境等价、结果身份和几何等价分别计算。查询等价采用可证明安全的规范表示与结构比较，不实现任意逻辑表达式的等价证明；顺序具有含义的数组不排序。元数据变化可以不重查，但任何影响查询或结果解释的变化不能仅因行数相同而视为等价。

存在一份历史成功结果，不等于可以继续对它执行业务动作。业务读取授权、本地配置编辑模式、查询有效性、实例写入许可和业务写入授权分别表达。`readonly` 不作为统管所有情况的单一开关：不能覆盖原实例的用户，在产品允许的编辑模式下仍可修改本地草稿并另存；浏览 handle 不暴露结构编辑与实例写入命令，即使该用户在完整工作台拥有相关许可。

`presentation` 中的列配置、汇总指标、可视化映射，以及 Dashboard 保存的面板引用与几何排列，属于可复用的观察方式，不是纯品牌样式。改变汇总指标可能请求独立 aggregate；改变图表映射仅投影既有成功数据；调整面板几何不重新查询。颜色、圆角、控件密度、工具栏和配置区的界面排布由默认 UI 或自定义皮肤负责，不能把实例中的 Dashboard 几何也归为换皮时可任意覆写的样式。

### 3.3 输入保真与受控状态

受控与非受控只能有一个值来源。是否受控由值属性是否提供决定，回调只负责通知。仅传回调时内部状态照常推进；受控父级拒绝变更时，组件不得暗中保留另一份权威值。

关联身份内不允许在运行中切换受控模式；需要切换时显式重建该交互实例。每次逻辑交互最多发出一次值变化通知，重复渲染不重复通知。

合法但未执行的配置可以保存；非法原始输入不可保存或作为新查询执行，但必须保留以便修复。已采用计划仍合法且环境有效时，显式刷新按该计划执行，不采用非法草稿；自动刷新在输入无效期间暂停。内置编辑器在工作配置中表达需要跨卸载恢复的原始值。自定义编辑器需要同样提供受控值或明确的序列化缓冲；库不承诺恢复藏在第三方 React 闭包中的任意私有状态。

未提交缓冲缓存不得镜像整份实例，只保存配置无法直接表达的局部输入与有效性。缓存键至少区分环境、runtimeId、节点 ID、编辑代次；节点删除、操作符换型、显式还原后，旧回调不能重新上报有效性。缓存达到上限时拒绝新的占用或提示处理草稿，不静默丢弃未保存输入。[S06] [S07]

输入有效性以节点和缓冲代次登记，编辑器卸载只释放 DOM 与订阅，不把尚未解决的无效缓冲自动改成有效。需要 DOM 的焦点和当前弹层不进入核心；“有未解决缓冲、暂不能提交”属于与 DOM 无关的编辑事实。纯核心从合法配置执行时不需要伪造一个已挂载编辑器；只有实际存在的待提交缓冲才参与对应会话的新配置提交和保存准入，不阻断独立于该缓冲的合法已采用计划刷新。

## 4. 生命周期、宿主身份与副作用所有权

### 4.1 资源所有者

| 资源                   | 创建与释放者                            | 借用者的操作边界                               |
| ---------------------- | --------------------------------------- | ---------------------------------------------- |
| Engine                 | 应用生命周期或 `useViewEngine`          | 读取及受限命令调用；不随消费组件卸载而 dispose |
| 受管理会话             | Engine 的显式打开／导航操作             | 不由 selector 隐式创建                         |
| 独立浏览位置           | `useOwnedViewPosition` 或显式位置所有者 | 不释放调用方 Engine                            |
| Dashboard 运行时       | Engine 的显式打开／激活路径             | Dashboard UI 不在 render 中分配运行时          |
| 面板位置               | Dashboard 面板运行时                    | 面板组件只借用；换皮不重建位置                 |
| 局部交互与编辑器 lease | 对应控制器的已提交生命周期              | 取消监听不清空实例                             |
| 自动刷新任务           | 对应运行位置的单一刷新所有者            | 多个观察组件不分别创建计时器                   |

读取操作只返回现有快照或明确的未打开状态。资源分配、订阅、网络启动、挂载计数变化和预算占用发生于显式操作或提交后的 Effect；不得隐藏在 render、selector、getSnapshot 或 useMemo 中。只创建不逃逸的纯对象不在此禁令内。[R02]

StrictMode 的建立—清理—再建立必须安全；旧订阅和旧请求失效，不能重复写入。保存、删除、另存等业务写入只由显式命令触发，不放在挂载 Effect 中。[R03]

### 4.2 环境与宿主更新

Engine 的服务命名空间、访问主体／租户和主 definitionId 在建立时固定。其内部可有多个按 definitionId 索引的解释上下文，以支持 Dashboard 引用其他定义；每个上下文维护已采用定义与解释代次。服务／访问环境、实例保存 revision、定义 revision、查询解释代次、编辑代次与写入操作身份分别管理，不用单一 version 同时取消全部事情。Props 普通引用变化不能静默替换这些语义。

定义和实例的服务 revision 为不透明值：前端只做同资源的相等性检查和服务明确提供的版本屏障核对，不按字符串大小或未经合同允许的数值转换比较先后。权限及定义通知必须指明资源与宿主已接受的结果；请求代次只能保护本地请求顺序，不能证明远端所有写入的全局时间顺序。

| 变化                               | 处理规则                                                                            |
| ---------------------------------- | ----------------------------------------------------------------------------------- |
| 同服务、同主体的凭证刷新           | 由稳定 Host 内部提供当前凭证；不销毁草稿，不取消已派发写入的核对                    |
| 同范围 UI 回调更新                 | 更新显示与通知绑定；不改变查询解释或正在执行的保存请求                              |
| 视图管理许可变化                   | Host 发布已校验的新许可；引擎只更新相关操作可用性并在派发前重新检查，不重建查询环境 |
| 权威实例／数据读取拒绝或范围撤销   | 按 Host 标明的资源归属使对应结果、引用与操作失效，不从保存许可变化推断读权限变化    |
| 编译器、字段语义、数据源语义变化   | 新解释代次或显式重载；定义变更按第 4.4 节保留草稿并重验，不用新规则重解释旧结果     |
| 更换服务、租户、用户或可信访问范围 | 结束旧环境，建立新 Engine；结果、缓存、恢复上下文不能跨范围混用                     |

同一环境不支持原地替换为另一个后端再接纳旧回包。每个已派发操作捕获原服务与身份，重试仍回到原服务。普通对象引用变化不等于身份变化；更换服务实现不能伪装为显示回调更新。回调／凭证／许可通过各自受限通道更新；同服务内定义演进只通过第 4.4 节的显式解释上下文更新，不能依靠替换整个 Host 或重跑初始化实现。

### 4.3 导航不是写入取消

切换页面可以让 UI 反馈失效，但不能据此宣称已发送的保存没有提交。存活 Engine 内，写入仍由写入协调器接收和核对；旧反馈不得关闭新实例的对话框或改变新导航。

真正关闭／释放持有未保存输入或未核对写入的所有者时，工作台提供离开提示；同一 Engine 内切换且保留原会话时，不误报数据即将丢失。引擎内恢复不等于刷新浏览器或关闭进程后的恢复：本轮不新增跨进程恢复日志系统。宿主需要跨刷新恢复时，必须另行提供同范围的安全恢复存储；未提供时不作该承诺。强制关闭不能被标记为确定失败，也不得在下次进入时盲目以新 requestId 重建同一对象。[S05]

### 4.4 定义更新与运行环境演进

`ViewDefinition` 有独立身份和修改版本。服务返回的定义必须携带 `id`、`revision` 与完整合法内容；定义修订不改变引用它的 `instanceId`。纯核心由调用方直接提供定义时可以使用局部不可变输入身份，不为本地查询伪造服务端 revision。

运行会话捕获已采用定义快照；查询计划及成功结果记录相应定义身份和版本。实例的 `validatedDefinitionRevision` 表示最近一次保存配置通过校验的定义版本，不是永久固定运行旧定义的许可。新打开或显式重载使用 Host 当前提供的有效定义；已经打开的会话不因对象引用变化而自动丢失草稿。

| 已核实的定义变化                                 | 运行处理                                                                                     |
| ------------------------------------------------ | -------------------------------------------------------------------------------------------- |
| 标题、字段标签或纯说明变化                       | 更新相关显示元信息；旧结果的来源仍指向执行时版本，不重新查询或重置分页                       |
| 新增不影响已有配置的字段或能力                   | 更新可选能力并重验相关配置；不把新增字段自动塞进已保存列或查询，不无故重查                   |
| 删除已引用字段、修改类型、收紧操作或改变单位语义 | 将受影响工作配置定位为待修复；已知失效的计划不再接纳执行，不静默删除条件或转换值             |
| 改变 sourceId、行键、时区或其他执行解释          | 进入显式定义重载／确认，形成新的解释代次；旧在途回包不能进入新环境，失效分页、选择和相关计划 |
| 明确的读取范围撤销                               | 按资源归属立即阻断和清理，不等待用户确认，不以保留旧定义继续访问                             |

同服务、同主体、同 definitionId 的定义重载分为“取得候选—核对来源与顺序—计算影响—采用”四步。候选加载或校验失败，不清空已采用定义、实例、输入与成功结果；若已知旧计划因撤回能力而失效，即使重载失败也继续阻止其新执行，显示待重验，不借恢复旧界面绕过失效事实。

采用时保持实例身份和可保留的 runtimeId，保留工作配置、原始输入、实例保存基线和未核对写入；按新规则派生问题并失效相关计划、游标、选择和旧编辑回调。纯标签变化不提高数据执行代次；执行语义改变的旧查询回包不能发布到新代次。已经派发的实例写入仍按原写入身份、原正文与原校验依据核对，不能因解释代次变化丢掉成功回执。无法对应的节点保留原值并定位问题，不以重建 Engine 清空草稿。切换服务、用户或主 definitionId 则按第 4.2 节结束环境。

定义对象不包含前端闭包或 renderer 实现。返回受信任 sourceId 和组件协议引用后，只能解析到应用预先注册的能力；新定义不能注入 URL、可执行代码或任意服务地址。新增能力只改变可选项，不能自动打开隐藏列、增加指标或修改已保存实例。

对旧成功结果只允许继续使用其原计划、resultSchema、单位与时间来源；不得以新定义重解释旧行。仅定义结构变化、且结果仍可读取时，可以带明确历史标记保留旧结果并关闭不再有效的动作；授权撤销另按第 13.3 节处理。标题等非执行变化无需制造新的数据请求。

一次定义变更可能只影响部分 Dashboard 面板。依各面板引用定义及实际使用字段重验，保留其他面板的有效位置、结果和配置；不能把所有面板一起标成新定义下的成功结果。活动实例版本固定与定义有效性检查是两件事，见第 10.1 节。

定义更新与在途实例保存并发时，保存回执仍按原提交和实际校验版本核对；不能因定义已更新就把已提交写入视为失败或换 requestId 再创建。保留新草稿，并在下一次保存／执行前完成必要重验。服务端跨聚合时序的确切含义见第 13.6 节。

定义变化通过加载、显式重载或 Host 已有通知发现，不新增默认轮询、审批发布或批量实例迁移。没有变化通知时不承诺立即感知后端更新；业务查询服务仍执行当前的协议校验与访问检查。定义 revision 不是后端数据/schema 部署版本：业务服务不支持按旧语义执行时，应拒绝对应旧计划，不能把结果质量责任交给一份历史定义。需要跨部署精确结果解释的接入必须由业务源提供其语义身份；服务端能否做到该点是接入验收，不从 view-engine 的元数据版本推断。

Memory／IndexedDB 遵循选用的定义输入合同；本轮的定义持久化写模型落在 Wow 服务，不要求每个轻量 Host 实现定义编辑。

## 5. 命令、查询与写入协议

### 5.1 接纳与完成分离

可能拒绝、排队、取消或被替代的数据执行命令采用显式接纳结果。纯 getter、编译函数和同步编辑动作不套用异步命令协议；Host 的原始 Promise 在边界统一转换，不把其网络异常契约强制传播到 UI。以下为类型规格，不是已实现 API：

```ts
type ReadAdmission<T> =
  | { accepted: false; issue: OperationIssue }
  | {
      accepted: true;
      operationId: string;
      completion: Promise<ReadOutcome<T>>;
    };

type ReadOutcome<T> =
  | { status: 'succeeded'; value: T }
  | { status: 'failed'; issue: OperationIssue }
  | { status: 'cancelled' | 'superseded' };
```

OperationIssue 的目标字段为 `code`、`scope`（运行时／节点／面板归属）、`messageKey`、`params` 与 `recovery`（不可重试／重试原读取／重新运行／核对写入）。它使用明确的错误码、归属、文案键及安全参数；不以中文错误字符串作为程序分支。预期的拒绝、失败、取消和替代通过协议返回；编程错误可以抛出，UI 的最后防线负责捕获并报告。适配层统一归一化 Host 异常，不能让同一种预期失败有时 resolve、有时 reject。

视图管理操作可用性区分 `UNSUPPORTED`（缺少对应服务）、`BROWSE_ONLY`（当前消费模式不提供此动作）、`AUTHORIZATION_UNAVAILABLE`（许可未知或未接入）、`FORBIDDEN`（宿主明确不允许）、`INVALID_CONFIG`、`CONFLICT`、`BUSY` 与 `RECONCILIATION_REQUIRED`。这些是拒绝原因，不是新增权限策略语言。配置无效或正在保存不得统一提示为未授权；最终服务端拒绝也不得伪装成客户端配置错误。服务端发现保存所依据定义已变化时返回 `DEFINITION_CHANGED`，与实例 `REVISION_CONFLICT` 分开；前者要求重验能力，后者要求核对实例编辑，不提供含糊的统一“覆盖即可”恢复。

`accepted: false` 不改变已应用口径、不取消仍有效的旧请求，也不关闭配置区。排序、翻页等“修改并查询”的复合命令在接纳前只准备候选，未接纳不提交该复合命令的状态变化；独立的草稿编辑不受此规则阻止。`accepted: true` 只表示请求获得执行资格，不表示数据已经成功。配置区是否关闭根据接纳结果和仍有效的交互会话决定；Promise 结束本身不是成功信号。

拒绝可以发布独立的操作问题用于提示，但不能把有效旧结果改成“本次查询失败”，也不改变原选择、分页或应用口径。`accepted` 的对象是本层命令：单次查询表示已获得本地调度资格，Dashboard 表示编排任务已被接纳，不保证所有子查询都有空闲配额，详见第 10.3 节。

等价配置的复用是一条显式成功路径：只有同环境、同查询、仍可访问的成功结果可用，且没有需要恢复的失败／未完成执行时，才可推进等价显示信息而不发请求。界面提示“条件未变，继续使用当前结果”，不显示“已更新数据”。无结果、最后尝试失败或结果过期时，相同配置仍需执行／重试；`refresh` 明确要求重新读取。重复点击已在途的同一意图返回可解释的 BUSY／已执行中结果，不重新开一条查询。

### 5.2 查询快照与意图

每次查询捕获不可变的配置、已应用筛选、分页或游标、作用域、解释环境、请求身份和必要的时间语义。服务定义来源记录 definitionId 与执行时定义 revision，纯本地定义记录局部解释身份。成功结果携带同一来源，不从最新工作草稿或最新定义回填来源字段。

`apply` 执行当前合法草稿并推进应用口径；`refresh` 执行已应用口径，不夹带未应用草稿；`retry` 重试最近失败的已接纳尝试。失败尝试因环境、引用或新的已应用意图而失效时显示“运行当前配置”，而不是继续称为重试。仅存在新的未应用草稿，不会自动使仍有效的旧尝试失去重试资格。

Record 排序与页大小动作使用已应用筛选并重置分页；未应用的筛选草稿继续保留。Analysis 有未运行查询草稿时，不允许结果表排序顺便执行整份新草稿；显式运行后才开放对应结果排序。游标仅沿有效链向后读取，刷新从起点开始，失败重试使用失败游标；重复游标被拒绝。[S08] [S09]

Record 的排序与页大小采用“只提交明确修改的字段”，不能从闭包中的整份旧配置覆盖较新的筛选草稿；复合命令提交前核对候选依据版本。Analysis 的显式刷新允许继续读取已采用的合法计划，即使工作草稿尚未运行；自动刷新仍因编辑状态暂停。刷新有效性依据已采用计划及其环境，而非最新草稿的输入是否完整。

已采用 B 的查询失败或取消后，即使保留 A 的成功结果，也不能把已采用意图回退成 A。A 保持历史来源和受限动作；刷新重新读取 B，重试仅对仍有效的失败尝试开放。暂存结果、取消原因、最近失败尝试和当前活动请求分别表达。

相对时间必须区分配置描述与执行时点。纯编译不读取未注入的当前时间；若 Wow 协议由服务端解释相对条件，则结果标明其协议口径，不虚构所有数据源使用同一时钟。需要跨源统一时间锚点时，只在 Host 明确支持该契约时使用；不能仅把多个请求同时发出就宣称快照一致。

等价条件复用必须同时考虑求值依赖。“最近七天”在两个执行时点拥有相同表达式，但不必有相同边界；显式 apply、refresh 或 retry 对依赖当前时间的条件重新执行，除非源明确支持并固定了可复用求值锚点。只编辑标签仍不发请求，但不能把下一次明确查询也短路成结果复用。`receivedAt` 仅表示本地接收时间，不冒充服务端求值时刻或数据库快照时刻；重试同一描述也不承诺得到原始数据快照。

默认扩展协议声明是否有时间或外部动态求值依赖，未知依赖保守视为不可跨次复用；不得由 UI 猜测扩展函数内部是否读取时钟。一次重试属于原失败意图，但其新的请求身份、时间与结果来源仍单独记录。

### 5.3 调度、取消与重入

同一 Engine 中 Record、Analysis、所有范围汇总及面板数据查询共享逻辑并发与排队预算；不为每个面板再建立独立的数据并发池。元数据加载使用单独但同样有界的池。[S03] [S10]

调度器只处理接纳、排队、截止时间、替代和释放；每个能力负责查询语义。相同 key 的替代策略与队列满时的拒绝策略分别定义，不能把“排队”解释成无限保留同一位置的陈旧意图。

只有新请求完成接纳后才能替代旧请求。旧请求完成或 finally 不能释放新请求的配额。旧取消回调引发同步观察者启动新命令时，原路径继续前必须重新核对操作身份。

一次逻辑请求的配额从接纳／启动到终态由同一 token 持有。排队项的等待截止与执行项的执行截止分别记录，不因续排无限延长寿命。取消、超时和失败在宿主不合作时也能结束本地操作；订阅者、日志及适配回调不能持有或释放另一请求的配额。

超时和 AbortSignal 约束的是本地逻辑操作；Host 不响应取消时，远端可能继续运行。库保证迟到结果不能提交，不承诺强制终止远端工作或严格限制其物理并发。同步扩展编译器也不能靠 Promise 超时抢占 CPU。

### 5.4 写入与核对

写入分别表达“是否已提交”“是否拿到精确回执”“查询读路径是否可见”。可验证回执证明该操作已提交后，列表延迟或查询超时不能把它降回 unknown。请求发出后超时、断线或本地取消仅说明观察未完成；没有提交证明时保留 unknown，不自动转成确定未提交。读取命令的 cancelled 不作为写入结局。

精确回执核对通过即推进对应保存基线；`visibility=pending` 单独显示“已保存，列表同步中”。保存按钮不因此再次创建或覆盖；采用回执直接更新本地已知实例摘要，后续读屏障只负责确认可见，不再次推进基线。能够证明已提交但拿不到可验证完整回执时，保留 knownCommit 与原请求，显示“已提交，回执待核对”，不谎称从未提交，也不把未知正文作为保存基线。

保存提交配置 B 时记录提交快照、保存基线 revision、操作身份及导航身份。期间可以继续编辑到 C。B 回执通过身份、种类、内容与 revision 协议核对后推进保存基线；C 仍作为未保存工作配置保留。回执不更改已经发生的新导航。

三种写入必须分别核对：

| 写入               | 回执归属                                             | 期间的新编辑                                   |
| ------------------ | ---------------------------------------------------- | ---------------------------------------------- |
| 未保存实例首次创建 | 在原 runtimeId 关联新 instanceId；基线推进为提交值 B | C 留在同一会话，必要时继续标为未保存修改       |
| 覆盖已保存实例     | 原实例身份不变，推进其基线和 revision                | 保留当前工作值 C，不因 B 回执覆盖              |
| 从已保存实例另存   | 产生新实例；新实例的保存基线是 B，原实例基线不变     | C 留在源会话，不自动搬到新实例，也不清掉源草稿 |

默认另存成功后留在当前视图，提示新实例名称并提供“打开”。用户显式打开时才建立／选择目标实例会话及按其激活策略查询；另存自身不隐式查询。首次创建当前草稿不是另存跳转，仍保持原运行位置。关闭源视图不得替代丢弃新编辑的明确决定。[S05]

业务数据读取错误或图表当前不可表达，不自动成为配置不合法的原因。保存仍取决于独立的持久化服务及其访问状态；业务查询服务离线不应阻塞可用的保存服务，保存服务本身不可达则按写入错误处理，不承诺离线写入。保存校验取当前实例及声明能力，而不是要求已有成功数据；不为了保存发起业务数据查询。Dashboard 已知绑定无效必须修复；仅目标元数据暂不可取得时，保留明确的待核验提示，按结构及现有声明保存，实际引用读取与执行继续严格准入，不把未核验标成已验证。

本轮保留原样内容保存契约：Host 可生成 ID、revision 和权威元数据，不静默改写用户配置。确需服务端规范化的接入不伪装成此契约，应显式返回规范化差异并设计冲突处理；本轮不新增该分支。

创建重试复用同一 requestId、原提交正文与原访问范围。不能凭列表中某个相似对象推断它就是创建结果。同一个 requestId 携带不同正文必须拒绝。保存和删除采用版本前提。删除回执只确认目标实例的删除与版本，不携带被误称为同一事务结果的用户默认视图；用户偏好独立读取，失效默认引用与当前页面的选中回退分别处理，见第 13.6 节。[S05] [S28] [S29]

视图管理命令在派发前按同一规则重新核对宿主许可、服务能力、会话模式与状态；默认 UI 和自定义 UI 均不能跳过这一检查。许可读取只消费 Host 已取得的结果，不在命令内启动角色判断或权限请求。查询命令不以视图实例的保存／共享许可作为准入条件。

写入协调器在调用 Host 前完成恢复元数据预算预留。无法保留恢复上下文时不派发写入；结果未知后锁定不安全的后续写入，但不删除新草稿。冲突确认绑定被审阅的本地、基线和远端身份；任一变化均要求重新确认。许可在请求派发后撤销，不证明该请求未提交，不丢弃其回执或未知结果恢复信息；后续重试重新检查当前许可，由服务端判断该次重放是否允许。

写入互斥与 unknown 门禁以环境、目标实例或同一创建事务为范围，不因一个实例待核对而锁住全 Engine 的无关查询与无关实例写入。同一目标的 save、rename、delete、覆盖冲突等操作共享协调；改变另存目标不得绕过源创建事务的未核对结果。门禁范围随服务契约明确，不建设通用跨实例事务管理器。

纯读取远端状态用于核对时检查读取可用性，不错误地要求具备覆盖保存许可；重放 create 是可能写入的动作，仍需当前对应许可。原未知请求的重放被拒绝，不能证明此前尝试未提交。读到相等配置最多证明当前远端状态一致，不自动证明本次写入是唯一原因；仅根据明确回执或协议允许的状态核对更新 UI，不宣称事件级审计或网络 exactly-once。

精确回执和当前资源状态不是同一数据流：回执 N 只结清它对应的写入，已经观察到的 N+1、删除或读取撤销仍作为当前状态保留。迟到回执不能把最新列表、查询缓存或有效偏好回退成 N。单实例可编辑基线按对应提交与冲突合同更新，当前远端已前进时继续保留冲突事实。核对已删除实例的原操作可以返回获准读取的历史事实，但不能据此重新使该实例可浏览。

### 5.5 Host 端口与端到端读写合同

Host 是可选能力的组合，不是一个全功能后台必须实现的接口。有限的 `ViewHost.operation` 端口统一提供定义、实例和个人偏好操作的核对，不接受任意业务命令；它不使普通引擎获得定义维护或领域写入权限。只用本地配置执行时，definition/config 可以由调用方直接给定；需要相应持久化动作时，才要求配套写入、版本与核对合同。统一更新核心类型、本地 Host、WowViewHost、服务门面和消费者，不用适配器内部的隐藏重试弥补缺失的请求身份。[S02] [S43]

| 端口                                 | 目标输入／输出                                                                           | 生命周期边界                                                                    |
| ------------------------------------ | ---------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| `definition.load`                    | id、可选读取屏障、取消信号 → 当前定义及来源／revision                                    | 独立加载；引擎不获得定义管理命令                                                |
| `instance.list`                      | definitionId、query、cursor、limit、可选读取屏障、取消信号 → `Page<ViewInstanceSummary>` | 返回一页摘要和 nextCursor，不包含全部会话或默认偏好；读取屏障用于结清目录可见性 |
| `instance.load`                      | instanceId、可选读取屏障、取消信号 → 完整保存实例                                        | 可独立点查；摘要不是完整实例，不据其构造查询会话                                |
| `instance.create/save/rename/delete` | 操作特定载荷、写入上下文、所需期望版本 → `WriteObservation<T>`                           | 创建／保存携带设计依据 definitionRevision；改名／删除不重写配置                 |
| `preference.load`                    | definitionId、可选读取屏障、取消信号 → 存在状态、revision、保存偏好与有效解析            | 与实例列表分离；从不存在不能伪造 revision=0                                     |
| `preference.saveOrder/saveDefault`   | 有界字段意图、存在／版本前提、写入上下文 → `WriteObservation<PreferenceState>`           | 修改顺序不覆盖默认值；共用该用户定义范围的写入协调                              |
| `operation.reconcile`                | 有资源归属的原操作引用、取消信号 → 精确回执或仍待核对                                    | 只读，不自动重放；有 unknown 写入可能的 Host 必须给出可行核对路径               |
| `permission`                         | 同步结果及可选变化通知                                                                   | 不发网络、不成为初始化等待屏障                                                  |
| `resolveSource`                      | 注册 sourceId → 业务查询源                                                               | 不走视图管理持久化服务，不由配置提供任意 URL                                    |

`Page<T>` 只有本页 `items`、`nextCursor` 和明确可选的授权后总数；总数不可精确计算时省略，不能报告未过滤数量。列表上下文和错误不覆盖正在使用的运行会话。完整加载、部分加载、空页和到达上限是不同状态。

写入上下文必须含一个逻辑意图稳定的 `requestId` 和可选的单次观察 `signal`。操作引用同时声明资源类型、目标身份或创建定位信息，并绑定拥有它的 Host 服务／访问环境。实例覆盖与定义更新各自携带该资源的期望 revision；创建偏好使用明确 `absent` 前提，已存在偏好使用 `matches(revision)`，服务端用 Wow 的创建／版本合同执行，而非把 absence 当任意版本覆盖。一个逻辑写入的重试不生成新 requestId，真正新意图才生成。

`WriteObservation<T>` 采用下列互斥结局；这里是目标类型规格，不是当前 Promise 接口已经支持的行为：

| 结局                        | 必需内容                                                                       | 引擎行为                                                      |
| --------------------------- | ------------------------------------------------------------------------------ | ------------------------------------------------------------- |
| `committed`                 | 原操作身份、对应资源身份、提交 revision、精确且已准入的回执值；独立 visibility | 推进该操作的基线；visibility=pending 只等待读路径，不再次写入 |
| `committed_pending_receipt` | 可验证的提交身份／版本证明、原请求和回执问题；不提供猜测的实例值               | 保留提交证明，等待回执；不按未提交重试，不更新未知正文        |
| `unknown`                   | 原操作引用、原载荷及本次观察问题                                               | 继续核对或经显式动作重放同一意图；不清空草稿                  |
| `rejected`                  | 该逻辑意图确定未提交的证据与有归属的问题                                       | 保留草稿，显示可修复原因；允许更改后作为新意图提交            |

`committed.visibility` 为 visible 或 pending；pending 必须提供同服务、同主体范围的 `readFence`。它是服务返回的不可解析令牌，不是可任意跟随的 URL。前端不比较 opaque revision 的大小，由服务在读取屏障处比较实际版本并返回是否满足。到达有界等待期限只结束等待，不能回退提交证明。

一次重放的拒绝不等于原逻辑操作的 rejected：协调器中已有 unknown 时保留该状态和最新尝试问题，直到得到原提交回执或协议能证明原操作不可能再提交。本轮不新增可撤回已上总线命令的分布式取消协议。服务端已确定提交、但当前主体不再允许读取回执正文时，只返回允许披露的结局或访问拒绝，前端不得用本地旧数据补造正文。

同步 Memory 实现可立即返回 committed/visible；IndexedDB 在事务完成后返回。两者仍处理同键不同载荷、版本冲突和对应回执，不能用永久进程内 Map 冒充需要跨进程保证的服务；其实际持久范围在各自合同中明确。核心与默认 UI 不识别 HTTP 状态或 Wow 阶段名，映射由 Host 适配层唯一负责。

## 6. 原子发布、稳定读取与 React 并发

### 6.1 单次发布边界

同步状态提交依次完成：准备候选及相关索引、纯推导与校验、预留所需预算、在无外部回调区间内提交权威状态与内部所有权、通知订阅者。提交失败必须回滚本次预留，不留下半次 Map、运行位置或预算变化。这里的原子性指本地观察者不可见半状态，不承诺回滚已发出的远端请求。

异步查询的预算不可在“发布 loading”时提前释放，而应持有到对应逻辑终态。对被替代请求的 abort、资源 dispose 与通知视为可能重入的副作用：先提交新所有权，再按旧 token 精确清理；副作用返回后重新核对代次。写入在实际调用 Host 的最后边界重查许可与身份，不能只在较早的 prepare 阶段检查后允许同步观察者改变前提。

观察者只在状态提交完成后调用。观察者异常隔离并记录安全诊断，不能回滚已经完成的命令，也不能阻断其他观察者。通知导致的新命令属于新的提交；禁止在纯 updater 或编译器回调中重入变更命令。

Dashboard 的一轮“采用口径”可以原子更新本地决策，但不把多个网络响应当作一个数据库事务。

### 6.2 读取契约

所有公开 handle 提供稳定 subscribe 与 getSnapshot。相同状态重复读取返回相同对象；未改变的子快照维持引用。派生对象按明确输入缓存，不能只在 selector 外层套 useMemo 后继续返回每次新建的 getSnapshot。[R01]

UI 的状态快照中不混入含方法的运行位置对象；位置 handle 单独传递。状态可检查、可比较，操作对象有自己的寿命。选择器只读、不分配资源，不访问 DOM、不发请求。

快照不包含可供外部调用的私有操作对象；并非所有内部资源都要求序列化。AbortController、Promise 和 DOM ref 留在资源所有者中，状态只暴露可解释的身份和阶段。没有观察者不代表资源必须释放，已经释放的资源也不能靠重新订阅复活；活动资源与订阅数量不是同一权威。

失效 handle 返回明确的 closed／unavailable 状态，不吞掉真正的类型错误、存储损坏或程序异常。读取单个位置时使用该位置绑定的 definition，而不是工作台当前选中定义。

先用稳定的子快照降低不必要更新。根布局组件不能订阅全部面板结果后再把所有子组件重新渲染；面板数据、布局、操作可用性和整体摘要分别读取。需要摘要变化的根部件更新是合理成本，不能把所有根更新都判作失败。

Context 传递稳定的 handle／依赖，不携带每次重建的全会话巨型对象。控制器的读、编辑与 DOM 绑定职责可以组合，但不可借“全能 controller”让所有消费者订阅全部状态。先利用结构共享与选择性快照验证收益，只有通知本身成为可测瓶颈时再拆通知通道。编辑器重验、旧回执和结果渲染不能通过多个 Effect 互相修正才能成立。

编译与结果缓存按环境、定义身份、编译器集合、配置语义、编辑有效性和结果身份失效；实例保存许可变化本身不触发查询重编译或清空结果。操作可用性投影另依赖宿主许可、服务能力和会话状态，变化须被相关 selector 观察，不能只监听数据 session 引用。授权相关的数据缓存失效依据 Host 报告的权威读取拒绝或访问范围撤销；查询意图、结果身份、解释环境变化及正常缓存淘汰仍按各自规则处理。

### 6.3 渲染与服务端边界

并发 render 中不修改已提交回调使用的 ref 或公共 handle；事件读取已提交快照，执行前再核对操作身份。被放弃的渲染不能污染当前界面命令。[R02]

本轮默认支持客户端启动：服务端输出确定的加载壳，客户端 hydration 首次输出与之匹配，提交后创建 Engine。读取 Hook 的服务端快照采用稳定初态；不把活的客户端 getSnapshot 随手当作服务端快照。预载结果的完整 SSR/hydration 不在本轮范围，不宣称已经支持。服务端不得建立跨请求共享的用户 Engine。[R01] [R03]

## 7. Filter：配置协议、编辑行为与渲染装配

**任务目标**：让用户表达要看的数据范围，并保留可继续编辑的观察意图。它向 Record、Analysis、Dashboard 及独立消费者提供同一表达能力，不管理业务授权范围，也不以必须打开完整工作台作为使用前提。

### 7.1 三种能力分别表达

Filter 的协议描述只包含编译、清空、合法输入与字段／操作符能力。编辑描述包含模式支持、默认值、输入解码与有效性。renderer 只负责 React 呈现。默认视觉注册表只从 `/ui` 装配，通用编辑器解析不能静态导入全部日期、选择和远程控件。[S06] [S07]

扩展作者可以在应用装配处用同一个协议对象声明编辑器；Node 使用者只导入协议对象，React 使用者再绑定 renderer。绑定复用同一标识和协议描述，不复制编译规则，也不需要手工维护三份同步表。不能为了“一次注册”，反而要求核心从含 JSX 的模块导入整份扩展。

编译描述在 Engine 生命周期内固定。仅替换能解释同一输入协议的 renderer 不重建查询环境，但必须重新建立该编辑器的局部 lease，保留已外置原始值并重新确认输入有效性；协议语义变化需要新环境和配置校验。缺少 renderer 时显示可修复问题，不伪造默认值；只读／纯核心查询不因没有 UI renderer 而失去已有合法编译能力。

只换 className、主题变量或同一 renderer 的样式 Props，不是替换编辑器实现，不重建 lease。默认 UI 丢失某 renderer 时保留配置摘要和诊断，不能静默替换协议、清除值或把未参与当前编辑的合法实例永久锁死。新增／替换编辑器实现的有效性重新登记只作用于该节点和编辑代次。

### 7.2 编译准入

配置树保存节点身份、未设置控件、显示属性和原始输入；编译表达式仅表示可执行条件。完全未设置可不产生谓词，部分填写和非法输入必须产生问题并阻止整次执行，不能删除坏分支后扩大结果集。

简单模式与高级模式共享同一配置模型。模式切换有结构前提，不能为进入简单模式静默丢掉重复字段、逻辑分组或元素作用域。清空值、删除节点、撤销输入是不同动作。

自定义编译输出必须重新核对字段绑定、操作符、嵌套作用域和资源预算。编译器不能借一个字段控件越权改写整个查询。显示标签变化不被误判成查询变化；不同类型的值，例如数字 `1` 与字符串 `"1"`，不合并。[S06]

### 7.3 查询提交

独立筛选器的受控值以调用方已接受的值为准，提交捕获该值和编辑代次；不能在调用 onChange 后假设父级已经同步接受输入。引擎绑定的筛选器直接使用对应会话的工作草稿，不再内部复制一份。

提交前核对结构、编译结果和输入缓冲有效性。被拒绝的提交不推进 applied；已接纳查询可推进 applied，但查询失败不会被显示为数据成功。支持复用相同表达式时推进编辑显示属性基线，不因此发出无意义请求。

### 7.4 候选与日期

远程候选的 search 和已选项 resolve 独立管理请求、错误和重试。搜索词或 source 语义改变取消旧查询；旧回包不得混入新候选。IME 组合期间不发送中间词查询，组合结束只提交最终文本。候选游标去重，重复游标拒绝；标签回填失败不删除已选 ID。[S17]

已选 ID、保存时的显示标签和当前源可读标签分开：普通解析失败可以保留用户原值并提示；Host 明确报告该候选已不可访问时隐藏其受限标签与明细，不据旧标签宣称可访问。保留修复所需的 ID 不等于向用户暴露服务拒绝披露的内容。缺失项与无权限项的可显示文案由有归属的源结果决定，搜索失败不得自动清空选择。

日期类型、datetime 类型、日期范围、时区和重复小时偏移分别处理。工作草稿允许未完成文本；禁止用 Number、Date 的隐式容错替代输入校验。环境需要时区时在定义解析阶段确定，不在每次 render 隐式读取不同系统默认值。[S06] [S30]

### 7.5 公共行为与任务部件

公开 `useFilterController`，提供显式命名的只读状态、节点动作、模式动作、清空／撤销／提交及问题定位。默认 FilterPanel 和自定义组合共同使用该契约。无样式任务部件覆盖根区域、节点、添加入口和提交入口；只公开有组合价值的部件，不公开每一层 div。

键盘 Enter 提交必须排除组合输入、已处理事件和内部弹层交互。焦点、错误关联与 disabled 属性交由任务部件统一维护；用户可换元素或样式，但不能绕过对应核心命令的再次检查。

## 8. Record：查询结果、分页、汇总与业务动作

**任务目标**：帮助用户找到并理解具体记录，完成明细浏览、比较、当前页选择和范围明确的汇总。表格与卡片是不同表达，不是两套查询流程；业务动作入口服务于选定上下文，不把订单或库存流程并入引擎。

### 8.1 结果与配置分别读取

`useRecordController` 绑定一个明确的 runtimeId，输出结果、查询状态、分页政策、当前页选择和受保护的动作。RecordContent 的默认 UI 只负责组合工具栏、结果、汇总和分页。

成功结果的查询配置与当前展示配置分别保留。列宽、标题、卡片布局可以对当前结果重新呈现；不能把新筛选或新排序标记成旧行的真实来源。主表加载错误、汇总错误、动作错误和输入问题有各自归属，不串成一个覆盖一切的 error 字符串。[S08] [S18]

### 8.2 选择和延迟业务操作

选择仅包含当前成功结果的类型化记录 ID。新查询或换页按策略清理选择；后台刷新期间用户开始选择时取消该后台刷新，防止操作目标在确认过程中被替换。

行操作绑定结果身份，批量操作额外绑定选择身份；两者都绑定访问范围和应用口径。打开对话框时保存的是动作上下文，不是永久有效授权。真正业务请求前必须再次核对最新状态；结果、选择或范围已经改变则拒绝并提示重新选择。

当前性 guard 只证明本地上下文没有变化，不能证明后台记录自读取以来未被他人修改。业务写入还需由相应业务服务核对资源版本与业务不变量；引擎不因为拿到当前行就承诺库存调整或审核一定成功。不要把数据请求成功视为业务动作自动完成。

UI guard 只核对动作上下文的当前性，不是服务端授权。行操作和批量操作的业务许可由宿主业务组件消费，审核订单、调整库存等请求由对应业务服务最终授权；这些许可不加入视图实例的保存／删除许可表。组件库只暴露受限 refresh、选择清理和当前性检查，不接管业务写入或根据角色判断业务权限。

### 8.3 Table 与 Card

TanStack 负责表格内部计算，默认 Table 适配器承担其类型与事件转换。通用控制器输出列语义和几何数据，不输出 `fve:*` 类名。列宽、固定偏移和必要滚动定位属于功能几何，不因无样式化删除。

保留服务端排序、类型化行键、列宽在手势结束提交、窄容器固定列降级以及剩余空间处理。选择列宽与固定偏移由同一几何参数计算，不能默认 UI 使用一个尺寸而 headless 模型硬编码另一个尺寸。

Card 使用同一个结果与动作契约，不经完整 Table 页面裁剪得到；Table 与 Card 不强行共享不同的 DOM 键盘模式。本轮不把普通数据表包装成未完整实现键盘协议的 ARIA Grid。

### 8.4 汇总来源

本页汇总绑定当前可见成功行；所有范围汇总绑定明确的已应用筛选及指标集合。修改汇总指标可以更新聚合请求，不重查主表；未应用筛选草稿和行选择不改变汇总范围。空集、null 与零分别处理。[S09]

应用新范围后，旧行若暂时保留必须标注为历史结果；不能把旧本页汇总和新范围汇总无标注地放成同一口径。每个汇总快照包含范围身份和结果时间，状态失配时显示等待／历史标记或占位，不显示虚假的一致总计。

主表失败不吞掉独立汇总错误，汇总失败不清掉可用记录。汇总重试只重试对应范围的聚合，不重新执行整张页面的所有请求。

## 9. Analysis：查询编译、展示投影与编辑生命周期

**任务目标**：把宿主支持的分组与指标组织成能够比较、解释的数据结果，并提供适当的表格或图表。指标的业务含义、字段能力和计算来源由业务定义提供；引擎承担受约束编译、执行与展示，不建设通用数据仓库或任意计算后端。

### 9.1 纯编译阶段

编译器按结构与预算、根过滤、Elements 范围、维度、基础指标、派生指标、Having、有效排序与输出 schema 分段组织。段间使用显式上下文，不在 UI 中重复推导能力，也不为文件拆分引入通用 AST 插件框架。

维度、指标、别名和字段类型分别验证。自定义贡献限于声明角色的一项输出，再由核心重建和复验。元素路径相对对应层级解释，派生指标按允许的依赖顺序引用；数组顺序有语义时不得排序以求比较方便。[S11]

单位、数值格式、日期分桶与时区进入计划的结果解释。展示投影不偷偷改变查询计划；纯编译也不发起数据请求。

### 9.2 查询与保存能力独立

`useAnalysisController` 读取绑定会话并复用显式命令；编辑配置不自动运行，合法但未运行的配置允许保存。区分结构有效、查询有效、输入有效、展示有效、可执行与可保存。

查询语义合法而展示映射失效时，允许运行并用数据表检查结果，但阻止把已知失效的展示配置作为合法实例保存。未知协议或非法 JSON 属于准入失败，不能借“只看表格”绕过。

这里的“展示映射失效”分两种：保存校验使用当前工作查询编译得到的 `draftSchema`；显示旧结果使用成功结果的 `resultSchema`。新草稿的图表映射对 draftSchema 合法、但对旧 resultSchema 不适配时，允许保存新实例并提示先运行，当前结果降级到原始数据表。不能用旧结果 schema 拒绝一个合法未执行的新设计。[S32]

数据相关的图表限制也不属于实例结构错误：本轮查询出现负值、空值、超过可视化分组数或系列数时，只限制当前图形呈现；不会反向证明已保存实例非法。保存是否允许由配置及声明能力决定，渲染是否可用由对应成功数据决定。

查询区关闭依据本次“运行并查看”操作的接纳与仍有效的界面事务；拒绝执行、旧 Promise 完成或用户已切换实例，不关闭新配置区。查询接纳后进入等待／执行反馈，而不是直接显示成功。显式刷新只使用已应用计划，即使存在新草稿也不夹带它；自动刷新在编辑期间暂停，显式“运行当前配置”才采用新草稿。

### 9.3 编辑转换与引用修复

添加、删除、重排、操作切换和可选字段计算进入纯规则。删除一个指标后，依赖它的公式或展示映射保留为可修复问题，不静默删除用户设计。冗余的结果排序引用是否清理由显式动作规则决定，并通过该动作的测试说明，不在一般 normalize 过程中隐式变更。

原始数字／公式输入与错误必须在会话切换后恢复。输入缓冲及有效性由编辑会话中的节点注册集中拥有，Root 负责绑定，不在每个 useAnalysisController 中新建一份。不同配置部件可以同时编辑不同节点；同一节点的多个可写呈现共享一份受控值或显式拒绝冲突写入，只读观察者不争用编辑所有权。卸载一个观察面板不清除另一编辑面板的状态。

未激活的大型编辑器允许卸载，但前提是可恢复缓冲已外置。隐藏图表、隐藏编辑器缓存和成功结果缓存分别受管理，不靠保留所有访问过的 React 子树无限维持草稿。

### 9.4 展示投影与降级

投影输入固定为成功 plan、schema、rows 与当前展示配置。禁止对重复分组擅自聚合、把 null 补成零、平均多个平均值，或把不可相加指标解释成占比／堆叠。指标单位、系列数量和分组规模必须满足可视化能力。[S12]

图表无法表达某结果是呈现问题，不是数据请求失败。始终保留与成功 schema 对应的数据表和来源说明；失效的展示别名不能让原始表格列一起消失。

图表模块异步加载失败只影响图形区域。ErrorBoundary 重置键使用结果和展示语义身份，普通查询进度或无关面板更新不反复重挂图表。不同图表外观共享投影，不复制聚合逻辑。

## 10. Dashboard：多位置协调、引用与布局编辑

**任务目标**：将多种已定义的观察方式组织为可复用概览，明确每个面板看什么、全局条件如何作用。组合协调不等于合并数据源；面板保留独立查询与结果来源，不新增跨源联结、统一授权或原子数据快照承诺。

### 10.1 运行时职责

Dashboard 运行时管理实例／浏览配置、全局条件、应用事务、面板编排和预算。Panel 运行时管理一个面板引用的身份、Host 访问结果、数据位置、加载和阻断，不计算用户对引用的授权。它们不是 React Effect 拼出的第二套请求系统。[S13] [S14]

默认面板复用 Record／Analysis 的结果内容与受限浏览命令，不嵌套完整工作台后添加大量隐藏选项。Markdown、链接和图片沿用既定内容类型，不分配无意义的数据位置。

面板内容读取所属位置的 definition、resultSchema 与结果状态，不从工作台当前主定义补齐字段或能力。面板级变更以 panelId、引用代次、定义解释代次和运行位置共同核对；仅 panelId 相等不能让删除后重新添加的另一引用接收旧轮结果。

引用在加载时核对 instanceId、definitionId、kind 和环境。工作台中原视图的未保存配置不成为引用基线。已采用引用在当前活动浏览中固定，普通 refresh 只查询数据；观察到服务端实例更新时提示“引用有更新”，由用户显式 reloadReference 采用新保存配置，不能因原视图改名或保存而自动清掉面板临时状态。

固定引用不等于固定过期解释环境：恢复或重载取得 definition 后，按第 4.4 节比较 revision 与实际使用的能力。只有 revision 改变而相关执行语义不变时，更新必要显示与校验信息，不重建数据位置；已知执行语义失效时，先禁止旧计划的新执行，再显式采用新解释代次或进入待修复状态。不能把旧 instance 配置与新字段、单位、作用域规则悄悄拼成“同一版本”。仅许可刷新或无关文案变化不重建查询环境。恢复访问仍需经过 Host 的权威读取，不能凭保留元数据恢复访问。[S14]

能读取 Dashboard 实例，不代表能读取所有引用视图或业务数据；每项访问由对应业务服务校验，Dashboard 不实现权限继承或合并算法。同一 Dashboard 中两次引用相同 instanceId 仍以 panelId 和独立 runtimeId 区分，不共享分页、临时筛选或错误状态。

### 10.2 全局条件与浏览配置

Dashboard 实例编辑模式与临时浏览模式分别管理。临时浏览只能修改声明允许的筛选值，不修改绑定结构、面板组成或共享实例。实例编辑模式可以产生本地结构和布局草稿，但覆盖、另存为个人实例、另存为共享实例分别检查对应宿主许可。不能覆盖原实例不等于不能编辑本地草稿；能够改变筛选值也不代表获准扩大服务端允许的数据范围。

每个全局过滤器对每个相关数据面板必须有明确绑定或明确排除。字段同名和类型相同不足以证明业务语义兼容。字段映射要求确认语义、作用域和时区；转换器输出重新按目标能力验证。映射缺失、转换器失败和字段不兼容均阻断对应面板，不退回 match-all。[S19]

结构无效或全局原始输入无效时，整次 apply 在接纳前拒绝。全局配置可编译、但某个目标绑定或引用失败时，可以采用这一轮配置并返回逐面板状态：合法面板执行，失败面板 blocked。二者不能混成“所有失败都继续”或“任何失败都回滚所有数据”。

### 10.3 应用事务与并发

一次 apply 捕获完整的过滤配置、参与面板引用身份、查询语义版本及操作代次。可以提前加载引用元数据，但加载期间不把新草稿合入已接纳操作。

Dashboard apply 是一个编排操作，不假定能同步编译所有尚未加载的引用。执行阶段固定为：接纳本轮意图 → 准备引用元数据 → 计算逐面板决策 → 原子采用本地口径 → 逐面板调度 → 汇总终态。接纳前检查全局结构、原始输入与编排预算；未接纳不影响旧轮。接纳后发生引用加载失败属于本轮结果，不伪装成“从未接纳”。

本地采用前检查本轮及各引用代次，失败不发布半份 applied。旧元数据或同步重入造成代次变化时重新判断，所有 committing／batching 标志在 finally 中按本轮身份释放。各面板数据请求独立向共享调度器申请，不为整个 Dashboard 一次性占用超过池容量的配额，也不因 parent accepted 就假称全部子请求已接纳。

终态报告包含 roundId、overall（succeeded／partial／unavailable／no-data）和每个参与面板的 succeeded／reused／blocked／failed／cancelled／superseded 状态及问题归属。全部数据面板可用才是 overall=succeeded；部分可用为 partial；全部不可用为 unavailable，并给出失败／阻断原因；本轮被替代不发布完成提示。内容面板不计入数据成功分母，零数据面板为 no-data，显示“无数据查询”。采用逐项汇总，不能由第一条 Promise 拒绝决定其他面板的结果。[S13]

若复用第 5.1 节 ReadOutcome 包装，外层 succeeded 仅表示编排已完成并产出了报告，UI 必须读取 report.overall，不能据此外层字段宣称所有数据成功。reused 保留原结果时间，显示条件已采用／结果复用，不显示“全部数据已刷新”。本轮在口径采用前取消不改变旧 applied；采用后取消保留已采用口径，终止仍属于本轮的子请求并保留相应历史结果标记，不自动回滚成上一轮意图。

数据查询池／队列满导致的子请求未启动，记录为该面板的调度问题，已采用口径仍保留；其旧结果保持历史标记，不算作新一轮成功。全局状态、面板状态与查询调度分别清晰，不把 Promise.all 的短路错误直接展示为整张 Dashboard 均未执行。

| 并发变化                               | 必须行为                                                         |
| -------------------------------------- | ---------------------------------------------------------------- |
| Q1 加载期间用户仅编辑 Q2 草稿          | Q1 可按捕获配置执行；Q2 继续显示待应用                           |
| Q1 后接纳 Q2 apply                     | Q1 不再提交 applied 或覆盖 Q2 的面板决策                         |
| 面板删除或更换引用                     | 旧引用位置立即失效；旧计划不得提交到同 ID 的新引用               |
| 仅改变面板几何                         | 不改变查询语义版本，不取消已接纳查询                             |
| 新增数据面板                           | 先加载元数据并显示待应用，不擅自执行未确认绑定                   |
| 暂停、销毁或 Host 明确撤销相关读取范围 | 取消或阻断对应工作；finally 仍释放临时标志和预算                 |
| 仅撤销实例保存许可                     | 更新写入操作可用性，不取消仍合法的面板查询，不清除结果或布局草稿 |

首次激活已保存 Dashboard 自动准备并执行其已保存合法口径，无法执行的面板显示明确原因。编辑期新增面板及条件采用显式 apply。重复 apply 仅在同解释环境、同引用版本、同有效查询且已有可访问成功结果时复用；只有 position 存在但无结果、最后执行失败或旧结果不匹配时，仍须执行或报告相应失败。强制重新读取使用 refresh。

本地 applied 只表示采用了查询口径，不表示所有数据源同一时刻成功。每个面板的 loading、blocked、failed 和成功结果来源独立呈现。普通查询失败可保留仍可访问的旧结果；绑定不安全、引用替换或读权限拒绝时，不显示可能越过新边界的数据。

### 10.4 面板快照与通知

Dashboard 根布局读取面板列表、几何、编辑状态与独立摘要；每个数据面板读取自己的稳定快照。Panel 快照按引用元数据与绑定数据会话缓存，而不是每次 getSnapshot 新建对象。[S14] [R01]

查询进度不重新编译全局筛选。全局条件、目标定义、转换器语义或编辑有效性改变才使相应编译缓存失效。引用标题变更可以更新标题组件，但不无理由重建数据位置。

面板局部错误只重置其错误边界；布局模块错误降级为有语义阅读顺序的静态容器，仍能读取数据并保存已确认的实例。

### 10.5 布局协议和适配器

持久化几何使用供应商无关的 panelId 与 x/y/w/h。校验和几何快照工具不导入 React Grid Layout；移动、碰撞、压缩、鼠标和触控预览属于 RGL 适配。键盘与指针调整使用同一规则，不实现两个冲突的布局算法。[S20]

几何常量、约束和控件偏移来自同一配置。窄屏使用视觉阅读顺序降级，不把临时响应式坐标写回桌面配置；几何排序的并列情况使用稳定顺序，保持 DOM 阅读和焦点顺序可预测。

所有 DOM 监听和坐标测量使用实际容器的 ownerDocument／defaultView，不混用全局 document；iframe 中的 Escape、失焦、点击和拖动清理只作用于对应 DOM 文档。排序键采用 y、x 与稳定的面板顺序作为 tie-breaker，焦点跟随同一 panelId，不因视觉移动重挂正文。

拖动必须有不需要持续按住指针的等价入口。默认在面板“位置与尺寸”菜单中提供可点击的移动步进和尺寸输入，支持键盘和触控；只支持方向键不满足单指针非拖动操作。窄屏继续提供此入口，并注明调整的是保存的桌面几何；不能留下只显示说明而实际不可操作的按钮，也不增加另一套布局算法。[R05]

拖动每一帧仅更新局部预览，结束时同步校验并提交一次几何事务。提交函数明确返回 accepted／rejected 或抛出由适配器处理的错误；外层错误展示不得吞掉提交失败后又返回“成功”。只有提交成功才推进撤销栈和播报，失败恢复权威几何。

### 10.6 布局编辑会话

布局编辑会话由 runtimeId、编辑代次、实例基线身份和面板集合代次绑定。一个 Dashboard 同时只有一个布局写入者；其他视图只观察，不各自维护可写历史。事务身份、活动手势和写入门禁在该运行时的编辑协调器登记；React Hook 只绑定这一份事务，不另存一份权威状态。核心 save 命令同样检查门禁，不能仅依赖默认按钮被禁用。

历史只保存几何，最多保留 50 次完成的几何操作。开始编辑记录初始几何；完成只结束编辑，不隐式保存；取消只恢复仍存在且身份匹配的面板几何，不恢复内容、引用或已删除面板。

面板新增、删除或替换时，结束并重新建立布局历史基点，保留已经提交的几何，不把上一组面板的历史应用到新组成。普通数据刷新不影响历史。

保存与布局交互遵循以下规则：正在拖动时不能保存；手势结束后可以保存当前实例。对应写入尚未确定或精确回执未核对时，禁止几何移动、布局撤销／重做／取消及会改动同一面板组成的操作；其他可保留的本地输入按各自合同编辑。精确回执核对成功即推进基线、结束当前布局编辑并清空其历史，不等待列表可见。确定未提交失败恢复原编辑会话；unknown 或已提交待回执时保留工作几何，不自动回滚。其他实例、面板数据读取和无关功能不受该布局门禁阻断。

这里结束历史的“保存成功”仅指当前实例覆盖或当前新实例首次创建推进自身基线；另存为新实例不推进源基线，不清空源布局历史。布局写入冻结限于对应实例的几何事务，不冻结无关面板数据读取或其他实例。历史预留同时计量 initial、past、future，淘汰最早可舍弃撤销项可保住 initial；不能为维持 50 步把本地取消基点偷偷丢弃。

布局模块失效、宿主撤回本地布局编辑模式、相关实例读取失效、显式实例还原或远端版本被采用时，结束失效会话并取消活动手势，不对已经更新的实例执行补偿性写回。仅保存许可变化不结束仍获准的本地编辑会话，也不清除布局历史；没有对应写入许可时只阻止该保存或另存动作。保存已派发时仍按写入核对规则处理，而不以随后许可变化回滚工作几何。正常几何变更保留数据位置和面板正文实例；布局库自身失败造成的 UI 重挂不应清除运行时结果。

## 11. 共享工作台、独立嵌入与 API 组合

**跨视图任务**：让观察方式能够保存、重新打开、另存、共享，并用于不同页面。工作台提供直接可用的完整体验，嵌入复用保存基线，独立部件按需使用；它们是消费路径，不是需要重复开发的另一组视图类型。

### 11.1 职责明确的消费路径

核心公开类型化会话 handle 和命令接口，不要求使用者从 ViewEngine 方法的 ReturnType 推导长期公共契约。内部类型推导不受限制，但公共 API 不暴露 SessionStore、任意 patch 或供应商对象。

React 入口提供以下职责明确的能力：

| 能力                                          | 责任                                                                   |
| --------------------------------------------- | ---------------------------------------------------------------------- |
| `useViewEngine`                               | 建立固定环境 Engine，提供明确的 loading／ready／failed 状态并负责释放  |
| `useViewSession`、`useViewCapabilities`       | 读取绑定会话及操作可用性；不分配运行时、不请求权限、不自行解释授权策略 |
| `useOwnedViewPosition`                        | 为一个保存基线建立独立浏览位置；只释放自身位置                         |
| `useFilterController`                         | 筛选编辑与显式提交                                                     |
| `useRecordController`                         | 结果、分页、选择与动作有效性                                           |
| `useAnalysisController`                       | 分析编辑、查询接纳和结果呈现协作                                       |
| `useDashboardController`、`useDashboardPanel` | Dashboard 元状态和稳定面板读取                                         |
| `useDashboardLayoutEditor`                    | 单一布局写入者、同步几何提交与有界历史                                 |

这些职责不由一个包办所有 view kind 的大 Hook 代替。默认 ViewPage、RecordView、AnalysisView、DashboardView、EmbeddedView 消费同一组行为接口；API 名称按本节实现，不额外增加同义 alias。

### 11.2 嵌入契约

嵌入从明确的已保存实例快照建立独立浏览位置，不借用工作台的编辑会话。保存快照可以由调用方或 Host 加载提供；“已保存”要求真实 instanceId／revision 与结构准入，不要求先加载同定义所有视图列表、选择实例或渲染工作台。首次激活由位置所有者执行；同一实例的多个嵌入拥有不同 runtimeId、临时筛选、排序、分页、错误与结果。

独立嵌入与 Dashboard 面板采用相同的活动引用策略：当前浏览固定已采用的实例版本；Host 或当前工作台已观察到新版本时提示可更新，不为发现更新额外开启轮询。用户显式“重新加载视图配置”后采用新版本并重新建立浏览状态；有临时修改时先提示这些修改将被重置。普通“刷新数据”继续当前有效口径，界面换皮、父组件重复渲染、源实例改名或保存均不自动清掉临时状态。[S21]

实例标识或可信环境显式切换时结束原位置；读取撤销立即失效，不等待用户确认。执行相关定义变化按第 10.1 节处理，不继续使用不匹配解释环境。位置所有者卸载会释放自身位置；只卸载／替换借用它的 UI 不释放运行时。不能一边声称组件拥有位置，一边承诺该组件卸载后仍无限保留位置。

浏览操作只修改协议允许的临时参数：Record 的筛选、排序、分页，Analysis 的结果浏览和合法筛选等；不暴露实例结构编辑、保存或删除。Dashboard 临时值不改变绑定关系。需要完整配置编辑时通过宿主导航打开工作台，不把浏览模式偷偷升级为编辑模式。

### 11.3 工作台与实例管理

默认工作台先提供宿主声明的可用初始视图、可解释的空态和必要操作；新建或高级配置是按需进入的任务，不要求用户先理解底层协议。工作台只协调导航、实例管理、配置区与当前视图；不在 shell 重新计算查询策略或授权规则。加载定义、加载实例、选择实例、默认偏好、排序、保存冲突和未知结果核对分别有状态。默认按钮、菜单、快捷键和自定义工具栏共用 `useViewCapabilities` 的操作可用性，不分别判断用户角色。

没有仍有效的许可结果时，仅有关的管理操作显示暂不可用；不将它并入定义／结果的整体加载门禁。后台刷新本身不自动撤销 Host 仍明确认定有效的许可，许可失效或明确撤销时才更新对应操作。默认查询与展示可以继续按数据服务的访问结果工作。保存按钮在未保存实例上对应创建，在已保存实例上对应覆盖，分别读取创建范围许可和当前实例保存许可，不把一个 `save` 布尔值同时当作两种授权。

首次创建绑定当前运行身份；另存成功默认停留源视图并提供“打开新视图”，采用第 5.4 节的源／目标语义。用户在请求期间已经离开源视图时，不弹回、不替换新页面局部状态。删除当前实例后的选中回退与服务端默认偏好分别处理，不能用同一个“第一个实例”值同时覆盖二者。

相邻包、示例、Storybook 和文档全部通过目标入口接入。默认 UI 同样不得访问私有 Store；公开行为 API 的可用性用另一个真实组合验证，而不是通过测试专用捷径成立。

### 11.4 自动刷新

已有自动刷新保持默认关闭，只对本轮明确支持的视图开放。倒计时属于局部 UI，不更新实例，也不驱动编译。数据读取与相关汇总完成后再开始下一个周期，不叠加请求。

暂停条件包括浏览器页面处于后台、正在编辑或使用浮层、未应用配置、输入无效、已选择记录、写入／核对、查询错误以及不安全的游标状态。核心维护数据与操作政策，React 提供可见性、焦点和局部交互 lease。将计时器从默认按钮中抽出，但不让一个全局 document 查询把无关组件永久当成当前视图正在编辑。

一个位置最多一个自动刷新所有者。重复渲染、多个观察者、主题变化不新建计时器；切换对应视图后恢复关闭。独立嵌入和 Dashboard 不因复用控件就自动获得新增的周期刷新能力。[S22]

### 11.5 默认任务信息架构

默认 UI 必须让用户能回答三个问题：“正在编辑什么”“当前结果使用什么”“改动是否保存”。内部 runtimeId、epoch 和 lease 不出现在常规业务界面。

领域代码统一使用 ViewDefinition／ViewInstance／ViewSession；面向业务用户的常规名称仍使用“视图”“保存配置”“定义已更新”，不把聚合根、实例 ID 或回执阶段当作用户必须学习的术语。需要定位问题时再在可展开详情中提供安全的资源与操作身份。

| 区域       | 主要内容                                          | 操作层级                                                           |
| ---------- | ------------------------------------------------- | ------------------------------------------------------------------ |
| 视图管理区 | 名称、个人／共享／系统标识、未保存状态、视图导航  | 保存配置为实例动作；另存、改名、删除与管理放入明确菜单             |
| 查询区     | 条件草稿、条件摘要、查询／运行入口                | 提交当前草稿为主动作；刷新已有口径是独立次动作                     |
| 结果区     | 明细、分析或面板，成功来源与更新时间              | 分页、排序、选择只影响明确范围；失败与历史结果标记在此呈现         |
| 展示区     | 列与卡片配置、汇总选择、图表映射或 Dashboard 布局 | 纯展示不重查主数据；汇总指标按协议独立聚合；布局完成不等于保存实例 |

默认保存入口显示“保存配置”，必要处短说明“不执行查询”。Record 使用“查询”，Analysis 使用“运行分析”，Dashboard 使用“应用条件”；刷新标明“刷新数据／刷新全部数据”。全局视图管理区与当前查询区职责不同，可以各有主动作，但同一任务不能同时存在两个行为不同、标签相同的提交按钮。

Analysis 保留查询配置 Sheet、中央结果和按需展示配置：查询 Sheet 打开时运行主入口位于 Sheet，背景控件不参与交互；关闭时使用工作区主入口。展示区在宽容器以侧栏展开，窄容器改为单个配置面板／Sheet，不把查询与展示叠成两层互相抢焦点的模态窗口。容器宽度决定排列，不按设备或窗口名称猜测。

关闭查询配置只关闭表面并保留草稿；Escape 不等于撤销编辑。“查看结果”显示既有结果，不暗中运行。“运行并查看”只在本次命令接纳后关闭并把焦点移至结果标题或等待状态。“撤销查询编辑”明确恢复最近采用配置；“还原已保存配置”明确作用于实例且不自动运行；两者不能共用含糊的“重置”。恢复后结果是否过期按其真实来源重新派生，不能自动谎称已同步。

### 11.6 可解释状态与恢复路径

| 状态                       | 呈现                                                   | 默认下一步                                                               |
| -------------------------- | ------------------------------------------------------ | ------------------------------------------------------------------------ |
| 还没有可用视图             | 明确是空列表，不是查询零行                             | 选择 Host 提供的起始视图；有支持且有许可时创建 Dashboard／从起始配置另存 |
| 配置尚未完整               | 保留输入，字段级错误与可定位摘要                       | 补全条件／指标；不以清空输入消除错误                                     |
| 已编辑、尚未应用           | “条件尚未应用”；已有结果保持原口径                     | 查询／运行当前配置；可以独立保存合法配置                                 |
| 等待／执行中               | “等待查询／正在查询”，结果区域 aria-busy，保留稳定尺寸 | 等待或通过规定动作替代，不重复派发同一意图                               |
| 成功零行                   | “当前条件没有结果”，展示已应用摘要                     | 调整条件；不是重新加载整个 Engine                                        |
| 有历史结果且新请求失败     | 就近显示错误与“上次成功结果”，时间和口径对应           | 重试失败尝试；草稿变化时另有运行当前配置入口                             |
| 图表无法表达               | 明确图形问题，数据表仍可读                             | 调整展示映射或查看数据表，不提示重新查询就一定能修复                     |
| 保存结果未知               | 持续显示“保存结果待核对”，不发成功 Toast               | 核对原操作；不要以新 requestId 另建一次                                  |
| 已提交但回执不可用         | “已提交，回执待核对”，保留原操作与草稿                 | 取得该次精确回执；不重放成新业务意图                                     |
| 已保存但目录读路径延迟     | “已保存，列表同步中”，当前基线已推进                   | 有界刷新目录／查询可见性；不重新执行保存                                 |
| 写入冲突                   | 显示本地与远端差异概要及版本变化                       | 保留本地、采用远端或按当前许可另存／确认覆盖；默认不覆盖                 |
| 定义更新影响当前配置       | 指出被删除或变更的字段、操作或解释规则；保留其他配置   | 明确重载定义并修复，不以删除失效条件执行更宽查询                         |
| 定义仅增加能力或修改纯说明 | 更新可选项或说明，不冒充查询刷新                       | 继续使用现有有效视图，不弹阻塞式重建提示                                 |
| 访问被拒绝                 | 隐去对应不可访问数据，保留非敏感错误说明               | 通过 Host 重新验证或返回可访问任务，不无限重试                           |

初始引导不新增万能创建向导：Record／Analysis 从宿主声明的有效起始配置编辑并另存，Dashboard 使用其明确创建能力。业务指标、字段选择与默认名称由定义／示例提供，不在通用引擎内硬编码订单、仓库等实体。

同一个错误只在它的权威归属区域显示主要信息；全局摘要负责定位，不在 Toast、页面、面板重复播报相同错误。禁用按钮旁提供可访问的不可用原因，不能只靠不可聚焦按钮的 Tooltip。未实现的服务可以隐藏入口，暂时无效／缺许可的相关任务使用一致的隐藏或禁用政策，不在同一页面随机变化。

在同一 Engine 内切换保留中的会话不弹“离开将丢失”警告；只在真正释放有未保存输入／未知写入的所有者时询问。浏览器 beforeunload 只能作为尽力提示，不承诺能拦截全部关闭动作；本轮没有跨刷新恢复存储时明确这一限制。

### 11.7 交互验收条件

键盘可完成导航、筛选、配置提交、结果查看和布局调整；IME Enter 不误提交；所有关键操作具有可访问名称。模态窗口有明确关闭入口，焦点留在活动窗口内，关闭后返回仍存在且可见的触发区域；嵌套选择器优先消费 Escape，不同时关闭上层工作区。[R06]

非拖动入口覆盖实际提供的全部拖动任务，不只 Dashboard：列宽有数值／步进入口，列顺序、视图顺序和分析项重排有可点击的移动入口；与拖动共用相同命令、约束和撤销范围。键盘等价与单指针非拖动等价分别检查，不以支持方向键替代鼠标／触控的非拖动路径。[R05]

窄容器与 200% 缩放下，实例操作、主要提交、错误原因和恢复入口不被裁切；必要的数据表水平滚动限制在结果区，不让整个工作台横向溢出。图表及 Dashboard 不依赖悬停才能读取关键值，触控用户能访问与键盘等价的动作。默认主题保留清晰焦点、可读对比和适当目标尺寸；本方案不把使用 Base UI 或通过自动化扫描当成无障碍认证。

默认界面的固定状态集包含首次加载、无视图、未查询、编辑未应用、查询零行、历史结果、局部失败、许可未知、冲突、保存待核对和模块加载失败。实施需为这些状态补齐 Storybook 与真实浏览器验证，视觉检查和行为测试分别记录。

### 11.8 目录、点查、偏好与启动路径

实例目录、完整实例、运行会话和用户偏好分别读取。目录页只保存有界摘要缓存，不为每一项分配会话、编译器或结果预算；用户打开某实例时才加载其完整配置并建立／复用对应受管理会话。引擎已就绪与目录全部加载完成不是一回事。当前实现的完整列表／许可等待屏障在此被明确的端口与状态替代。[S42]

| 使用路径                              | 必需加载                                     | 不作为前置条件                     |
| ------------------------------------- | -------------------------------------------- | ---------------------------------- |
| 直接提供 definition/config 的核心执行 | 本地准入及业务数据源                         | 实例列表、偏好、许可网络、默认服务 |
| URL／调用方指定 instanceId            | 点查该实例及其定义，必要的实际访问检查       | 同定义全部实例列表、默认偏好成功   |
| 默认工作台未指定实例                  | 第一页目录与个人偏好各自加载，按默认策略选择 | 全目录抓完、无关视图配置有效       |
| Dashboard／独立嵌入                   | 指定实例及其引用依赖                         | 工作台当前选中项、完整导航目录     |

显式 instanceId 优先于个人默认。没有显式选择时，已返回且有效的默认 ID 可以直接点查，不因它不在第一页就认为失效。偏好读取慢或失败时显示独立状态和重试；用户已手动选择后，晚到默认值不能抢走导航。目录失败不清除已打开且仍可访问的视图；单个完整配置结构损坏或语义失效只阻断它自身，不让整组目录不可用。

分页使用不可解释 cursor，绑定查询条件、当前访问范围和影响排序的偏好版本；过期返回 CURSOR_EXPIRED，重开目录页但保留已打开会话及输入。不穷举所有分页后伪装成一次 list，不把“这一页为空”“已到上限”当作整个定义没有实例。授权过滤在存储／服务范围内落实，既不泄露未授权总数，也不以一页内隐藏数据伪造完整结果。

个人排序与分页须有一致合同。服务对显式 order 中当前可见 ID 按其顺序组织摘要，未列入的可见实例按稳定的服务排序键追加；默认采用受控创建顺序加 id 消歧，不由前端分页后局部排序冒充全局排序。order 有界，服务可先处理这个有界集合再进行余项分页；不因此加载全部实例配置。并发新增／删除不承诺数据库快照级遍历；页结果按 ID 去重，并在 cursor 失效时允许重新加载。

`SetViewOrder`／`preference.saveOrder` 接收 `scopeInstanceIds` 和 `orderedInstanceIds`，必须是相同、无重复的集合。它只重排这些 ID 在现有显式顺序中的槽位，遗漏的原 ID 与默认项不变；scope 中尚未进入显式顺序的可见 ID 先按 scope 顺序追加再重排。示例：原顺序 [A,B,C,D]，scope=[A,C]，ordered=[C,A]，结果为 [C,B,A,D]。完整重排只有在 UI 明确选择完整集合时才发生，当前筛选页不能被当作全量覆盖。

界面明确表述“调整所选视图的相对顺序”；同组已加载项通过拖动或非拖动“上移／下移”提交同一动作。偏好版本冲突保留本次重排意图并提示重新加载偏好后再确认，不暗中以最新 revision 重试。默认项不要求存在于显式 order 中。GET 不产生清理写入；删除、访问撤销与分页未加载分别处理，不能据未出现在当前页移除偏好。

## 12. 扩展、DOM 语义与主题

### 12.1 扩展边界

优先用配置表达已有能力，用任务部件改变交互结构，用明确的领域扩展接入新业务表现。扩展只有在代表可复用职责且能接受契约验证时才进入公共面；不能为了免改业务代码把任意流程塞进配置，也不要求新业务对象靠修改通用引擎来接入。

| 扩展                  | 允许                                               | 禁止                                                   |
| --------------------- | -------------------------------------------------- | ------------------------------------------------------ |
| Filter 协议与编辑器   | 合法谓词贡献、值清空、编辑能力                     | 改绑字段、忽略非法分支                                 |
| Analysis 协议与编辑器 | 明确角色的维度／指标贡献                           | 任意替换整个聚合查询                                   |
| 单元格与业务操作      | 只读数据、明确动作上下文；宿主业务组件接入自身许可 | 修改输入快照、任意写 Store、借视图保存许可授权业务写入 |
| OptionSource          | 搜索、回填、取消、缺失项报告                       | 静默改变选中身份                                       |
| Dashboard transform   | 显式语义转换                                       | 未验证输出直接执行                                     |
| Layout／Chart 适配    | 几何交互与显示                                     | 保存实例、发起领域业务写入                             |

扩展是受信任的同进程代码。输出校验可以保护数据协议，不能沙箱化恶意 JavaScript，不能保证阻止扩展读取页面信息或无限循环。需要运行不可信代码的产品必须使用独立隔离机制，不由本轮注册表承担。

注册标识是配置协议身份，不是 CSS 名称。未发布阶段允许重设标识，但协议、renderer 和所有开发配置须同次更新；未知标识保留可修复错误，不按名称相近自动替换。

### 12.2 部件渲染契约

样式定制使用语义化 Tokens、任务部件的 className/style 与稳定状态属性；结构定制使用无样式部件或控制器。不要用不断增长的 renderToolbarStart／End／Before／After 参数代替组合，也不要把全部 div 都公开。

`render` 定制时保留 ref、disabled、ARIA 关联和事件组合。使用者事件可以按明确约定阻止该 UI 的默认动作，但对应命令仍检查会话状态、动作当前性，以及实例管理动作所需的宿主许可；不能依赖事件合并保证数据安全，也不在事件层运行另一套授权策略。自定义组件需要把约定的 DOM 属性与 ref 转发到真正交互元素。[R04]

焦点目标通过 ref 和任务部件注册关联，aria-label 只表达可访问名称，不作内部查询协议。面板、工具栏、弹层关闭后的焦点恢复依据仍连接且可见的目标；目标已消失时回退到对应任务区域，不聚焦已释放实例。

### 12.3 样式与 Portal

默认样式复用已有命名空间和 Tokens，不因为架构调整更换 Tailwind。几何定位、hidden、滚动边界和焦点可见性属于功能约束，应与纯品牌皮肤区别描述。

Portal 的行为归交互层，主题与字体传递归默认 UI 的 ThemeScope 桥接。ThemeScope 支持局部明暗主题、密度和字体，不依靠 document 根上的单一全局主题。自定义皮肤负责自己的主题传递，但可复用行为层的目标容器与焦点能力。[S23]

动态主题变化只重新计算对应视觉值，不重建 Engine、丢失编辑或重新查询。倒计时不逐秒触发读屏播报；错误、查询状态和布局播报各自限于有意义的状态变化。

默认 UI 提供一个有默认中文文案的受控消息解析入口，按 OperationIssue 的 messageKey／安全参数呈现；业务定义的字段名和用户标题不自动翻译。更换 UI locale 不改变数值原始值、日期语义或查询时区，不创建新查询；locale 与定义的 timeZone 分别配置。缺少文案键使用明确的安全回退，不显示堆栈或未清洗服务端错误。此入口是文本接入契约，不新增翻译管理平台。

## 13. 格式准入、宿主授权接入与服务事务

### 13.1 当前格式

保存的 `ViewInstance` 使用统一封套：`id`、`definitionId`、实例 `revision`、`formatVersion`、`kind`、元数据、相应 `config` 和服务端校验凭据。`validatedDefinitionRevision` 随实例状态持久化，并由创建／配置保存的精确回执返回；改名不更新此校验依据。`ViewDefinition` 采用自己的 id、revision、格式标识与能力描述，不套实例 kind 联合；偏好也有独立存在状态和 revision。各 revision 互不代用，formatVersion 只识别结构。当前开发接口只支持目标输入格式，不保留旧格式投影分支。[S43]

校验凭据区分本实例结构／本定义语义已验证与外部依赖待验证：Dashboard 的可暂存外部依赖必须列出 panelId、已知引用身份及 pending／verified 状态；根 validatedDefinitionRevision 不能被解释为所有目标源和绑定永久有效。存在明确非法绑定时拒绝配置保存；目标元数据暂不可取得而允许保存时，服务回执仍声明未完成的依赖验证，执行时逐面板严格准入。客户端不能提交一个布尔值自证完成。

格式封套作用于完整 ViewInstance。嵌入其中的 Filter 是共享配置，不为每个节点重复包一层实例封套，也不引入第四种 filter 视图。纯运行配置无需服务端身份；已保存实例必须具有服务端确认的身份与 revision。跨类型模型使用判别联合，不能把 config 放成无约束 Record<string, unknown> 后再到每个 UI 中自行分支。

区分三个校验层次：结构是否可安全读取、语义是否可执行、当前能力是否允许操作。合法结构中失效字段或未知扩展可以进入修复界面，但不能直接执行或保存为合法配置。新格式覆盖 Filter、Analysis、Record 和 Dashboard 的相应规则；不是只给 Dashboard 单独加一个版本号。

开发夹具与初始化示例同步更新；本地数据重建通过显式重置或新的受控存储空间完成。不自动覆盖未知格式、损坏数据或未经授权删除本地用户内容。

当前输入格式与 Wow 事件历史是两种协议。未发布开发环境可以显式重建测试事件库；一旦某部署开始保留正式事件，之后的代码必须能重放该部署承诺保留的事件类型与版本，或有明确验证的数据演进路径。不能以“不兼容旧 HTTP 输入”为由删掉仍有权威事件依赖的溯源处理。这里不要求当前开发期维护已废弃实例格式，也不提前建设通用迁移平台。

### 13.2 有界入站与快照防护

从网络文本开始由 Host 限制响应大小；解码后的对象再由核心检查结构。采用有界、迭代式的深度／节点检查，拒绝循环、非法原型、访问器、稀疏数组、非有限数值和不允许的字段路径，再进入复杂编译或大对象复制。不能先递归遍历整个恶意对象，再检查总预算。[S24]

外部对象不能因为 Object.isFrozen 为真就被视为已经深度验证。内部验证后的不可变快照可用结构共享与快速路径，外部入站数据要经过完整信任边界。内容相等、查询等价和资源身份相同分别处理，不用同一个 JSON.stringify 或 hash 代替全部判断。

JSON 规则针对数据，不承诺对同进程恶意 Proxy 的陷阱访问做到无副作用。结果行仍受记录和分析各自约束，不能仅因为能 structuredClone 就认为可以安全保存为 JSON。

### 13.3 可选的宿主许可与操作可用性

**业务系统制定授权规则，Host 提供决策结果，视图管理层消费许可，可信服务端对实际请求最终授权。** Host 可以运行在前端；接口名不代表其具有可信服务端的安全边界。引擎不接收或解释角色、组织、权限树、行级范围策略或权限表达式。[S02]

#### 责任分工

| 责任                                                 | 所属位置                                     | 对引擎的输出或作用                     |
| ---------------------------------------------------- | -------------------------------------------- | -------------------------------------- |
| 用户、角色、组织及资源授权规则                       | 业务授权系统                                 | 针对目标资源与动作的许可结果           |
| 获取、刷新、缓存许可并处理返回顺序                   | Host 接入层或业务应用已有的权限设施          | 同步可读结果及可选变化通知             |
| 服务是否存在、模式是否支持、配置与会话状态是否可执行 | 视图引擎的对应命令与纯派生规则               | 操作可用性和准确的不可用原因           |
| 按钮、菜单和快捷键的呈现                             | 默认 UI 或自定义组合                         | 消费同一操作可用性，不重复业务授权规则 |
| 最终资源访问检查及写入事务                           | 可信视图配置服务、业务查询服务、业务写入服务 | 成功回执或具有准确资源归属的拒绝       |

#### 最小接入契约

`ViewHost.permission` 为可选接入端口，限于视图实例和个人偏好管理，不扩展为独立权限系统。采用同步的 `getInstance`、`getDefinition` 结果读取，以及可选的 `subscribe` 变化通知：实例级结果包含 `save`、`rename`、`delete`、`saveAsPersonal`、`saveAsShared`；定义级结果包含 `createPersonal`、`createShared`、`reorder`、`setDefault`。创建许可区分个人与共享目标，排序及默认视图许可只作用于当前用户偏好，不因此允许修改共享实例。结果未就绪或许可项缺省表示未知，明确的 `false` 表示不允许，二者都不放行该管理操作，但提示原因不同。

`getDefinition` 在此只表达“该定义范围内创建实例、调整个人顺序和默认项”的许可，不代表修改 `ViewDefinition` 聚合的管理权。定义创建／更新由服务的受控管理门面独立授权；普通实例编辑器、嵌入和引擎加载不获得这些命令，也不为定义维护扩张一套前端角色系统。

许可结果不进入可保存的实例，不由 UI 根据可修改的角色名、owner 或 scope 字段自行计算。Host 可以把同一业务服务返回的许可缓存后暴露给引擎，也可以在本地单用户应用中显式提供固定许可；不要求建设权限后台。授权细节、网络接口、凭证处理和远程刷新由 Host 或应用所有者管理，Engine 不调用许可 `load`／`refresh`，不等待它们才完成纯查询环境初始化，也不新增权限轮询、角色模型或专用权限 Store。

只用筛选、编译、查询、展示、布局计算或独立浏览时，可以完全省略这个端口。查询服务、引用加载及候选服务仍独立执行其资源访问检查；省略的是前端管理许可接入，不是绕过业务授权。操作许可缺失、尚未就绪或读取失败时，相关实例管理动作不放行；不把存在 `instance.save` 方法视为已经获准保存，也不阻塞无关查询。只读／浏览 handle 的方法集合仍由消费模式约束，不因宿主返回了保存许可就自动增加实例写入命令。

宿主负责把不同后端授权方式转换为这个有限结果集。返回顺序由 Host 依据其权威版本或明确的请求／订阅代次处理，保证先前启动、晚到的旧响应不会覆盖已接受的新决定；没有权威版本时不假定请求序号能证明服务端策略时序，也不承诺立即感知所有变化。Engine 只消费已接受的结果，并丢弃已解绑 Host 或旧环境的通知，不在内部复制权限请求和排序逻辑。

#### 操作可用性

实例写入是否可执行，取决于**对应宿主许可、服务能力、当前消费模式、配置有效性以及会话操作状态**。这些判断共享一份规则，UI 读取派生结果，命令派发前再次读取当前输入；未授权、服务缺失、浏览模式、配置无效、冲突、正在提交和待核对具有不同原因码，见第 5.1 节。

本地草稿编辑与持久化授权分开。不能覆盖共享实例的用户，在产品允许的编辑模式下仍可调整本地配置；另存为个人或共享实例分别需要对应许可。产品关闭编辑模式时不暴露结构编辑命令，但不能把这解释成用户的服务端保存许可被撤销。新建实例的首次保存使用创建范围许可；覆盖已有实例使用该实例的保存许可；变更目标范围不能复用另一动作的许可。

服务端必须根据请求的真实身份和目标资源再次判断，不能采信客户端的 `save: true` 或前置检查结果。客户端的检查用于一致的交互和减少无效调用，不提供绕过服务端的授权凭证。

#### 不同授权结果的失效边界

| 授权结果或变化                                       | 引擎／宿主的处理                                                                             |
| ---------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| 仅撤销保存、删除或共享许可                           | 更新相应管理操作可用性；保留仍可读结果及本地草稿，不推断业务读权限也被撤销                   |
| 许可未知、读取失败或刷新中                           | 依当前有效快照与 Host 的明确失效状态处理；未知或失效的管理许可不放行，普通查询不等待权限加载 |
| 实例读取被可信服务端拒绝                             | 阻断对应实例与引用的呈现及有关操作；不继续凭本地元数据声明可访问                             |
| 业务数据读取被明确拒绝，或 Host 明确通知读取范围撤销 | 清除对应范围的可见结果及派生数据，失效相关选择与查询代次；迟到的旧成功结果不能恢复它们       |
| 临时网络或查询失败                                   | 可以保留尚未被权威撤销的成功结果并标记失败；不自动升级为权限撤销                             |
| 业务写入被拒绝                                       | 由相应业务组件／服务处理，不据此撤销视图实例保存许可或清空无关数据                           |
| 写入派发后许可撤销                                   | 继续核对已派发请求；不宣称未提交、不删除恢复上下文；后续写入或重放重新校验                   |

读取拒绝必须关联已知请求资源、实例、数据源或运行位置，不能只凭一个没有操作归属的 `FORBIDDEN` 清空整个 Engine。同一资源的多个位置如何失效，按 Host 明确报告的撤销范围处理；引擎不根据仓库名称或角色推测范围。没有实时撤销通道时，库只能在得到权威拒绝或明确失效通知后处理，不宣称即时感知后端所有政策变化。成功结果发布仍检查运行环境、操作代次与已知读取失效状态，但不为每个回包新增一次权限请求。

### 13.4 Host 实现与可信服务边界

生产服务使用 Kotlin、Wow、Spring Boot 与响应式 WebFlux；前端 `WowViewHost` 是该服务的协议适配器，不是服务端本身。服务作为业务模块接入应用的认证与授权设施，可独立部署，也可由既有 Wow 应用装配，不要求为视图存储另建平台。领域模型与执行约束见第 13.6 节。

前端业务 Host 负责把请求送到相应服务，并传回许可结果、权威回执或结构化错误，不在本包内实现生产角色管理与授权决策。视图配置服务分别授权定义维护、实例管理和个人偏好；业务查询服务独立限制可访问的数据范围和字段；订单、库存等业务写入由相应业务服务独立授权。视图配置公开可见不代表其数据或引用公开可读。

Memory、IndexedDB 和真实业务服务共享存储与操作协议，但不共享安全边界或并发假设。Memory 的同步 Map 临界段不插入 await；IndexedDB 的读取、当前注入策略检查、revision 检查、修改与回执在同一原生事务内提交，以事务 oncomplete 而非单个 put 成功作为完成。[S25] [S31]

创建实例的权威事件同时携带足够的幂等核对信息；不能先提交实例，再在另一非原子存储中补写唯一回执。生产服务中的许可检查、个人／公共可见性、系统实例保护、默认偏好和排序规则，在可信执行边界依据真实用户及资源判定，不采信请求正文提供的 owner、scopeKey 或许可值。Memory／IndexedDB 为本地应用与测试提供相应策略实现，规则不塞进核心 Engine。浏览器本地策略与 IndexedDB 事务可以保护应用内一致性，不能防止控制该客户端的用户修改本地数据，也不能代替生产业务服务的授权。

客户端超时无法撤销已经提交的事务。未知结果保留核对路径；损坏存储明确报错，不自动用初始化数据替换。开发 HTTP 实验不因目录重构升级为生产服务承诺。

### 13.5 内容安全

Markdown 不启用未审计的原始 HTML 执行路径；配置链接和图片使用各自的协议白名单。外链打开行为、图片失败和无效 URL 明确降级。图片地址合法不代表资源可信或具有访问授权。[S26]

诊断默认记录操作种类、阶段、耗时、资源规模和安全错误码，不记录行数据、过滤值、Token、完整身份信息或未经清洗的服务器异常。可选诊断回调抛错不影响命令结果。

### 13.6 基于 Wow 的 Fetcher ViewHost 服务

#### 服务职责与部署边界

服务归属 Fetcher，落在 `services/view-host`；使用 Kotlin、Wow 和 Spring Boot／WebFlux 实现，独立构建与部署，具体仓库边界见第 2.4 节。服务管理**可低频修改的视图定义、可保存的视图实例和个人使用偏好**，不拥有查询得到的订单、库存或指标数据。Wow 提供 CQRS、事件溯源、快照与查询机制；不把整个 StatefulViewHost 的 Map 翻译成一个租户级大聚合。[W01] [W02]

| 能力                            | 实现位置                          | 边界                                                                       |
| ------------------------------- | --------------------------------- | -------------------------------------------------------------------------- |
| 定义创建与低频整体更新          | `ViewDefinition` 聚合             | 独立维护字段、数据源与能力约束，不携带所有实例，不以修改频率替代一致性判断 |
| 定义读取                        | `ViewDefinitionProvider` 应用端口 | 默认读取定义聚合快照；引擎不依赖定义写接口                                 |
| 实例创建、覆盖、改名、删除      | `ViewInstance` 聚合               | 三种视图共用实例生命周期；配置按 kind 分别校验                             |
| 个人排序与默认实例              | `UserViewPreferences` 聚合        | 每个租户、用户、定义独立；不修改共享实例                                   |
| 实例列表、点查与 Dashboard 候选 | 受约束的查询应用服务              | 只返回当前主体可见资源，不公开未授权的通用快照查询                         |
| 管理许可                        | `ViewAuthorization` 应用端口      | 适配业务已有授权，定义维护与实例保存分别授权                               |
| 数据查询                        | 原业务查询服务                    | 前端 resolveSource 绑定业务客户端，不由此服务充当通用数据库代理            |
| 打开原视图                      | 前端导航回调                      | 不成为服务端命令或聚合事件                                                 |

采用 `view-host` 限界上下文。Gradle 的 `api` 模块定义命令、事件和门面 DTO，`domain` 定义聚合与不变量并依赖 api，`server` 装配认证、WebFlux 门面、查询与异常映射；不允许 domain 反向依赖 server 或前端包。独立服务的领域模型采用普通 Wow 依赖，不复制框架源码、不把视图类型放进 Wow 核心。不默认新增 Kafka、Saga 或专用投影；实际多节点部署单独验证所选消息基础设施。

#### 三类聚合与领域身份

| 聚合根                | 实例粒度             | 聚合内的一致性                                                   | 聚合外的引用                              |
| --------------------- | -------------------- | ---------------------------------------------------------------- | ----------------------------------------- |
| `ViewDefinition`      | 一份定义             | 字段、行键、数据源与声明能力共同合法，更新具有独立期望版本       | 被实例以 definitionId 引用                |
| `ViewInstance`        | 一份具体视图         | kind、配置、归属和生命周期合法；Dashboard 本地面板及绑定一起校验 | definitionId，以及面板所引用的 instanceId |
| `UserViewPreferences` | 一个租户、用户、定义 | 有界且不重复的顺序和默认偏好，字段命令不互相覆盖                 | 只保存 instanceId，不复制实例配置         |

`ViewSession`、运行位置、分页、选择、输入缓冲和查询结果不成为服务端聚合。定义修改不更新实例聚合版本，实例保存不更新定义版本，个人排列也不修改共享实例。聚合边界表示独立事件流和版本，不要求这三类聚合分别部署成三个服务。

各聚合采用命令根组合状态对象，例如 ViewDefinition／ViewDefinitionState、ViewInstance／ViewInstanceState、UserViewPreferences／UserViewPreferencesState。命令侧读取当前状态、保护不变量、返回事实事件；状态只在 onSourcing 中修改。回放不重新查权限、不调用网络、不读取当前时间或随机数。命令类与状态类是同一聚合的职责拆分，不是两份互相同步的权威状态。[W02]

凡进入持久写入合同并被接纳的新逻辑命令，均产生可核对的事件；相同目标值可以产生“已接受该配置／偏好”的幂等业务事实，即使字段内容不变，版本仍按协议推进。UI 可在派发前跳过没有变化的操作，但不能把产生新快照作为普通无事件或 Void 命令的唯一完成条件。相同 requestId 重放直接核对原事实，不再追加；已删除实例收到另一个删除意图则明确拒绝，不能伪造一次新删除回执。[W03]

**ViewDefinition：一份定义一个聚合。** 状态表达名称、sourceId、字段、时区、允许操作、Record／Analysis／Dashboard 能力和必要的受控元信息。定义来自业务声明并通过服务维护；写入不能凭空增加查询服务不支持的能力。创建和更新均检查字段身份唯一、类型与操作符匹配、行键约束、分析字段引用、数据源及能力组合，并受配置规模与结构预算约束。

| 命令                   | 领域事实                | 关键约束                                                                       |
| ---------------------- | ----------------------- | ------------------------------------------------------------------------------ |
| `CreateViewDefinition` | `ViewDefinitionCreated` | 服务端核对身份、定义维护授权、完整定义与后端声明能力；稳定创建意图对应唯一目标 |
| `UpdateViewDefinition` | `ViewDefinitionUpdated` | 携带定义期望 revision，一次提交完整候选；全部校验通过才更新，不发布中间半状态  |

低频更新采用整体提交，不为每个字段属性设计一套命令，不默认加入审批、多版本发布、协作编辑或定义删除／级联清理。定义变更不批量改写所有实例；引用配置不再有效时进入可修复状态。`ViewDefinitionProvider` 保留为读取端口，其默认实现读取聚合快照，而不是与聚合并存的第二份可写定义仓库。代码生成的初始定义通过显式初始化或更新命令进入服务，启动不能用旧配置悄悄覆盖已经维护的定义。

定义 ID 不是 sourceId：同一业务源可以有多份定义，不暗中增加“每源仅一个定义”的全局唯一约束。受控初始化清单持有稳定资源身份及请求身份，不能每次部署生成新定义后让旧实例悬空；人可读别名只有在产品显式要求唯一时才设计独立约束。配置与能力变化不由事件回放根据当前源重新计算。

**ViewInstance：一份可保存的具体视图一个聚合。** 状态记录 definitionId、kind、格式版本、服务端确定的创建者／所有者、个人或共享范围、标题、配置、最近配置校验所用的定义 revision 和删除状态。配置采用 RecordConfiguration、AnalysisConfiguration、DashboardConfiguration 等判别结构或对应受验证 JSON 载荷，共用生命周期不等于配置使用无约束 Map。

| 命令                 | 领域事实                         | 关键约束                                                                       |
| -------------------- | -------------------------------- | ------------------------------------------------------------------------------ |
| `CreateViewInstance` | `ViewInstanceCreated`            | 身份与范围由服务确认，配置通过指定定义版本校验；requestId 与创建目标绑定       |
| `SaveViewInstance`   | `ViewInstanceConfigurationSaved` | 指定实例期望版本，保持定义、kind、所有者和范围不变，原样保存配置并记录校验版本 |
| `RenameViewInstance` | `ViewInstanceRenamed`            | 非空且有界标题、实例期望版本；不重写配置，也不宣称旧配置已经在新定义下通过校验 |
| `DeleteViewInstance` | `ViewInstanceDeleted`            | 授权和实例期望版本成立；提交墓碑，不擦除权威事件历史                           |

另存是读取源实例并校验目标范围后的新建意图，不在源聚合上产生保存事件。原创建者、租户、所有者、kind、definitionId 和系统模板身份不能通过普通 save 改写；系统视图发布走受控管理路径，不暴露成普通用户创建范围。后端不采信正文中的 owner 或许可值。

Dashboard 的 panelId 标识聚合内面板实体，布局是其配置值，筛选绑定与面板关系在同一 Dashboard 实例提交中校验；面板不是独立聚合。面板引用的 Record／Analysis 仍是其他 ViewInstance，移动面板不修改引用实例，移除面板不删除引用实例。目标实例后续删除或访问拒绝只使引用不可用，不级联删除整个 Dashboard。

**UserViewPreferences：每个租户、用户、定义一份偏好聚合。** 使用 `SetViewOrder` 与 `SetDefaultView`，独立版本及幂等身份；只保存实例 ID，不复制定义、配置或运行状态。SetViewOrder 使用第 11.8 节的显式作用集合重排；SetDefaultView 只更新默认字段，允许 null。首次写入使用 absent 前提，竞争失败后重新读取并经用户确认再发新意图，不自动合并成无前提覆盖。偏好大小有界，不将一个租户全部用户偏好或一个用户所有定义塞入同一聚合。[W03]

框架完整聚合身份包含上下文、聚合名称、tenantId 和 id；同一个 NamedAggregate 下的 id 必须跨租户唯一。三类资源各自使用服务器分配或经可信命名空间规范化的 ID，保存完整身份用于路由与存储，不假设 tenantId 自动建立第二套 ID 命名空间。[W02]

#### 定义版本、实例版本与校验

| 字段                          | 语义                                                                             |
| ----------------------------- | -------------------------------------------------------------------------------- |
| 定义 `revision`               | ViewDefinition 已提交聚合版本的不透明表示，用于定义写入并发控制                  |
| 实例 `revision`               | ViewInstance 已提交聚合版本的不透明表示，用于实例写入并发控制                    |
| 偏好 `revision`               | UserViewPreferences 自己的并发版本                                               |
| `formatVersion`               | 对应资源序列化结构版本，不表示内容的新旧                                         |
| `validatedDefinitionRevision` | 由服务端记录，表示当前已保存实例配置通过哪一份定义校验；不授予旧能力或数据访问权 |

新创建／配置保存意图携带设计依据 `definitionRevision`。服务先认证、确定资源归属并检查原请求记录，再对尚未提交的新意图取得定义的权威状态进行版本与语义校验；不可直接把可能落后的快照列表当作“最新定义”。校验开始时版本已不同则返回 DEFINITION_CHANGED，保留配置，要求采用当前定义重验。纯标签变化可以无阻塞地采用后重验，但仍作为新的已确认提交依据，不能用同一幂等键暗中换正文。改名、删除与偏好动作不要求把失效的旧配置重新保存为合法。

DefinitionProvider 的读取职责与业务能力注册职责分开：它返回保存的能力描述；验证器再与服务明确注册的协议／源能力匹配。不默认遍历全部业务后端探测能力，也不因定义 JSON 写了支持就调用实际未部署的方法。

定义更新、实例覆盖、改名、删除和偏好修改在命令信封中携带各自期望 aggregateVersion，不能只在 HTTP 层先 GET 后比较。解析对外 revision 时核对资源类型与身份；定义 revision 不能拿来更新实例。版本冲突返回明确问题，不自动取最新版再覆盖。[W03] [W04]

服务端必须执行结构、kind、规模、字段能力、扩展身份及引用结构校验。结构 Schema 的权威位置与生成流程见第 2.4 节；依赖能力的语义通过 `ViewDefinitionValidator` 和 `ViewConfigurationValidator` 处理。二者获得明确的定义快照与受控能力注册，不使用空实现或前端的 valid=true 作为证明。验证规则不塞进 onSourcing，重放只应用已提交事件。

定义和实例属于两个独立聚合。实例校验采用定义 N 之后、实例事件追加之前，定义仍可能变成 N+1；本服务接受并记录“该提交按 N 校验”的事实，不声称跨聚合原子外键或绝对最新版本校验。新打开、定义更新已被观察后的新执行、以及后续保存按第 4.4 节重新准入；旧提交的回执不能被改写成按 N+1 校验，也不能因此倒退实例版本或抹掉用户草稿。

未知写入的核对优先确认原 requestId 是否已提交；已经提交且当前允许读取回执时，返回原内容、实例版本和原 validatedDefinitionRevision，不在新定义下重新验证并推翻历史提交。尚未证实提交的重放保留原正文和定义依据；若当前定义不再接受它，可拒绝此次重放并保留原未知操作的核对信息，不能由一次拒绝推断原尝试未发生。

后端可用 JSON 树承载配置，但按资源类型与版本准入；不归一化掉原始输入、未知可修复结构或顺序有语义的数组。合法结构中已失效配置可以读取修复，新的配置保存仍要求合法；Dashboard 部分外部元数据暂不可取得时遵循明确的待核验与执行阻断合同，不伪造验证成功。业务结果不进入定义或实例事件；配置本身可能包含敏感过滤值，遵循访问与保留政策。

#### 读取模型与写入可见性

三类聚合优先使用 Wow 的实时快照作为当前状态读模型，设置快照策略为 `all`，并选择支持实际查询需求的快照后端。首个生产实现采用 Wow 的 Mongo EventStore／SnapshotStore；快照集合按实际生成结构建立租户、定义、可见性／所有者、删除状态、排序键所需索引。不要为与聚合状态相同的列表再维护一套投影集合。专用投影仅在读模型存在实质差异且有测量依据时增加。[W05] [W06]

单定义、单实例和单用户偏好的权威恢复使用 `StateAggregateRepository`，不由应用手工拼接快照与事件。列表与候选使用受限快照查询，在存储查询中落实租户、个人／共享可见性和删除过滤，再执行必要的资源授权；分页和总数都在相同可见范围内计算，不能先对全量数据分页后只在前端隐藏不可见行。超出存储可表达的授权策略由应用在正确的后端范围内处理，不返回未过滤的总数或候选名称。

| Wow 观察阶段               | 本服务可据此做什么                 | 不能作的推断                                     |
| -------------------------- | ---------------------------------- | ------------------------------------------------ |
| `SENT`                     | 表达命令已被总线接受               | 不能返回“实例已保存”                             |
| `PROCESSED`                | 开始核对命令处理与权威事件结果     | 不能认定快照查询和任意投影已经可见               |
| `SNAPSHOT`，且策略为 `all` | 核对当前聚合快照已完成保存         | 不证明查询副本、客户端缓存、其他聚合或投影已完成 |
| 指定 `PROJECTED` 函数      | 仅在使用该专用读模型时确认相应分支 | 不证明其他分支或所有外部系统一致                 |

写门面默认尝试等待 SNAPSHOT，并在总观察预算内核对权威提交及实际读路径；该等待是降低常见写后读取延迟的策略，不是定义“是否已经写入”的唯一条件。精确回执已证实提交时返回 committed，实际读路径未达到所需版本则 visibility=pending；不能仅因快照分支失败返回 unknown。只有无法证实提交时才进入未知操作核对。[W05] [W07]

读取屏障由服务核对内部聚合版本、资源身份与访问范围；不透明令牌只用于该资源的允许读取，不向客户端暴露任意历史查询能力。读路径返回更高版本、已删除或当前访问拒绝，也可能说明历史提交已完成但资源后来变化；它们不会改写该次精确回执的内容，当前状态与历史操作结清分别处理。

**写入回执必须来自该请求对应的权威事件／版本，不能取最新快照冒充。** 请求 Q1 保存版本 N，Q2 已推进到 N+1 时，Q1 仍返回自身提交的内容和 N；前端据此保留保存期间产生的新草稿。读屏障可以确认当前可见版本不小于 N，但响应正文必须仍属于 Q1。事件、原请求摘要及必要的历史版本提供核对依据，最新快照不替代写入回执。

定义读取可按可信服务／租户、definitionId 与 revision 缓存不可变快照，查询最新版本时采用明确的刷新或失效规则。低频修改不是永久缓存的理由；定义写入回执确认后更新该定义的读取缓存，不批量推进实例版本。普通展示消费者只需要读取端口；`ViewDefinitionProvider` 不在读取过程中生成更新命令。

#### 幂等、重复提交与结果核对

所有写入携带逻辑意图稳定的客户端 requestId。服务规范化可信租户、主体、资源类型与客户端键，产生框架 requestId；完整目标聚合进一步限定去重范围。共享实例上的两个用户碰巧提交相同客户端键，不能认领彼此的操作；同一用户在同目标上用相同键换动作或正文仍须拒绝，所以动作与正文进入摘要，不用改变去重命名空间来绕过检查。[W04]

定义／实例创建另外绑定稳定目标 ID。分配规则包含可信命名空间和创建身份，不包含可变正文；同意图改正文不能因此生成另一目标。规则在重试窗口、凭证刷新和服务重启后稳定；若使用密钥化方案则须保留能定位原操作的密钥版本，不能轮换后失去目标。偏好目标由可信租户、用户、definitionId 稳定确定，不随 requestId 生成一份新偏好。另存是新的意图和新的目标实例，但不改变源实例。

每次已接受的业务事件保留操作类型、可信主体关联、原提交摘要、所用定义／协议依据及恢复本次回执所需的数据；框架事件流保存规范化 requestId。摘要覆盖资源、动作、目标、源引用、期望版本、definitionRevision 及原配置等业务输入，排除 Token、单次尝试时间和当前最新定义。重放先按原摘要核对，不用今天的外部状态重算原请求含义。

摘要采用 UTF-8 的 RFC 8785 JCS 规范表示后计算 SHA-256，并以双端金样验证所选实现；该选择只定义本服务的规范比较，不要求配置原文格式化成 JCS。对象键顺序不影响摘要，数组顺序、字符串内容和字符串／数字类型有意义。JSON 数值 1 与 1.0 表示同一数值，不承诺保留词法写法；需要精确小数或超出安全整数范围的业务值必须由对应协议使用字符串，不能由后端把 Long 舍入后仍称原样保存。[R07]

HTTP 解码前拒绝重复属性名、非法 Unicode 和非有限数值；不能让解析器先丢掉重复键再校验。字符串不自动 trim 或 Unicode 规范化；标题的输入约束与配置摘要分开。JCS 库通过跨语言测试，不手写简单排序后 JSON.stringify 冒充完整规范。原样保存指已准入 JSON 的语义内容一致，不保证原 HTTP 空白、键顺序或数值词法完全保留。

Wow requestId 去重发生在单个聚合内，不能替代创建目标绑定或“同键不同正文”检查。必须由 EventStore 的原子追加保证重复 requestId、初始聚合身份和事件版本冲突的最终裁决；预检、内存 Map 或先查后写都不是持久约束。[W04] [W08]

操作核对入口先认证并检查原操作／目标的访问权，再定位对应权威事件、比对原摘要并构造该次回执。新的定义或当前实例状态不能反向否定已提交的历史事实；服务端拒绝披露的历史字段不因调用方持有旧 requestId 而可读。

固定基线 EventStore 的 existsRequestId 只返回布尔值，并提供按聚合版本范围读取和 single；不存在可直接套用的“按 requestId 返回完整回执”接口。[W08] 每个服务写命令固定产生一条版本化事件流：已知期望版本 N 时先核对 N+1 流，创建先核对初始版本；必须同时匹配规范化 requestId、主体和摘要，不能只因该版本存在就认领。无法直接定位时使用有界历史读取或可重建索引；未找到或预算耗尽返回仍未核对，不证明请求不会晚到提交。索引只优化定位，不能与权威事件做不受保护的独立双写。

超时、断线或下游失败不自动映射为“未提交”。`PROCESSED` 失败也可能发生在事件已追加之后，必须按权威历史核对。重复请求存在只证明需要核对，不直接把 `DuplicateRequestId` 转成任意成功。核对请求尚未观察到事件时，不保证命令不会随后提交；只能按相同业务身份安全重试或继续核对，不能换键创建。[W04]

业务结果采用第 5.5 节 WriteObservation，不把“已提交但读路径未可见”编码成未知写入。精确回执可用时 HTTP 200／创建 201 返回 committed，并附 visibility 与必要的 readFence；已证实提交但暂不能提供完整回执，或还不知道提交与否时，202 返回对应待核对结构。确定的新意图拒绝使用 4xx 和结构化问题；网络 500、框架阶段名或一次重放的 4xx 不能独自推翻先前未知状态。

HTTP 适配器先验证响应结构、请求及资源归属再转换结局，不能只按 2xx 当成功。核对只 GET 原操作；只有调用方显式重放才能再次发送同一写入。自动网络重试若启用，必须保持原键、原目标和原正文，且与框架内重试共享有限预算，避免两层无界叠加。

#### 删除与个人偏好的跨聚合边界

删除只对 ViewInstance 聚合提交墓碑和删除回执，不与 UserViewPreferences 伪装成一个原子事务，不在删除路径遍历所有用户并发起大量偏好写入，也不为此强制加入 Saga。

偏好读取分别返回存储值与当前有效解析：显式 order 与可访问、未删除实例做交集，未排序的可见实例按第 11.8 节追加；默认引用失效时 effectiveDefault=null，但网络暂时不可核验不是默认已被证明失效。默认为 null 不暗中写公共视图。页面选中回退不反写偏好，GET 不隐式清理。

已保存偏好中失效 ID 可以保留为当前用户自己的 opaque 引用，不返回对应的受限标题或存在性细节。设置偏好只校验本次明确作用的 ID；缺席于某一分页不是删除证据。部分页重排不删除未提交 ID，不改默认项；确需清理时由后续明确写入处理。

设置偏好时校验目标在当前允许的定义与可见范围内，但校验后实例仍可能并发删除或失去访问权；通过上述读取解析保证不会据失效引用恢复访问，不声称拥有跨聚合外键事务。后续显式偏好写入可以清理失效 ID。删除的 UI 语义是移出可用视图，不承诺擦除所有事件历史；合规硬删除与存储保留由服务部署政策处理。

#### HTTP 门面与前端适配

ViewHost 是应用端口，不要求后端 API 与每个前端方法同名。生产服务使用固定的、受认证的业务门面，内部调用 CommandGateway 与查询服务；没有与门面等价的认证、授权及身份规范化链时，不公开生成的内部聚合命令路由或全局通用命令入口。

| 目标 HTTP API                                                                  | 用途                       | 约束                                                                                          |
| ------------------------------------------------------------------------------ | -------------------------- | --------------------------------------------------------------------------------------------- |
| `POST /view-host/definitions`                                                  | 创建视图定义               | 定义维护专属授权；稳定 requestId，完整定义校验和服务端身份确认                                |
| `GET /view-host/definitions/{definitionId}`                                    | 读取当前定义快照           | 返回定义 revision 与能力描述；能力描述不是数据授权凭据                                        |
| `PUT /view-host/definitions/{definitionId}`                                    | 低频整体更新定义           | requestId、定义期望 revision 必需；同一提交校验完整候选，不批量改实例                         |
| `GET /view-host/definitions/{definitionId}/operations/{requestId}`             | 核对定义操作               | 只返回当前允许读取的原操作回执，不用最新快照冒充                                              |
| `GET /view-host/definitions/{definitionId}/instances`                          | 返回一页可见实例摘要       | query／cursor／limit 有界，排序与偏好版本一致；不附全部配置或初始化所有会话                   |

| `GET /view-host/operations/creations/{requestId}`                              | 尚未收到 ID 时核对创建     | 必须指定 definition 或 instance 资源类型；按可信租户、主体及稳定分配规则定位                  |
| `GET /view-host/definitions/{definitionId}/preferences`                        | 读取个人偏好及有效解析     | 可信主体定位；默认引用可以失效，不产生隐式清理写入                                            |

| `PUT /view-host/definitions/{definitionId}/preferences/default`                | 修改个人默认实例           | 独立存在／revision 前提及 requestId，只改默认值；null 明确可表达                              |

| `GET /view-host/candidates`                                                    | Dashboard 可见引用候选     | 仅 Record／Analysis；搜索与分页保留授权范围                                                   |

接口表是目标业务合同，不是现有 Wow 自动路由。路径中的 definitionId／instanceId 对应资源自己的 id；请求中的期望 revision 经门面转换到对应 Wow 聚合版本。创建核对入口使用必需的 `resourceType=definition` 或 `resourceType=instance` 参数，不允许仅凭客户端 requestId 在不同资源和租户间搜索。资源类型缺失、不匹配或回执不可访问均返回明确拒绝。

读接口可接收该资源的 opaque readFence，并以有界等待返回屏障满足、仍等待或有归属的拒绝。fence 由认证门面验证，不能指向不同租户、资源或外部主机。创建、保存、改名、删除、定义维护和偏好写入全部遵循同一 observation 结构，具体 value 仍按动作和资源判别，删除回执不伪装成未删除的 ViewInstance。

前端 WowViewHost 位于 `packages/view-engine/src/hosts/wow`，通过 `/hosts/wow` 使用。它依赖生成的类型化 HTTP 客户端，将资源、分页和 observation 转为第 5.5 节的引擎契约；不把分页接口耗尽成旧完整列表，也不把 202 或未经校验的 CommandResult 当保存实例。核对和读可见性等待有总期限与取消边界，跨同意图重试保持请求身份。

加载页不会删除已经点查／编辑的实例；精确写回执也不会直接覆盖已知更新的目录缓存。许可由应用取得并同步暴露，普通引擎不调用许可 load／refresh；resolveSource、openOriginal 由宿主注入，不从服务端配置构造任意网络地址。

定义维护命令属于受控管理门面，不自动加入普通引擎 handle 或实例工具栏。维护方可以使用同一 HTTP 合同生成的管理客户端；引擎仅需 `ViewHost.definition.load` 和应用提供的明确重载／变化信号。读取服务不可用和缺少定义修改权是不同问题，后者不阻塞合法视图浏览。

CommandResult、内部快照封套和事件载荷不直接充当前端 ViewInstance；定义 DTO、实例 DTO、偏好 DTO 和操作回执各有资源类型。共享契约与实际客户端转换用同一组跨语言夹具验证；服务构建不导入 React 或 npm 源文件，客户端发布包不包含 JVM 可执行文件、数据库凭证或服务配置。全部目标路由只有一套合同，不保留历史同义路径或转发别名。

#### 身份、授权与反应式执行

身份只从已验证的认证上下文获取；HTTP 正文、任意 tenant／owner 请求头或 UI 的布尔许可不可信。应用层调用当前授权策略，聚合处理时基于当前实例状态核对所有者、范围、系统保护与对应许可。内存／本地开发策略不能作为生产默认放行策略，缺少认证或授权接线时应拒绝启动生产配置或拒绝操作。

第三方授权系统与 EventStore 不天然共享事务，不能宣称权限撤销和事件追加在不同系统中强原子。授权以既定执行检查点及策略合同为准；确需更强撤销保证时由业务安全体系提供共同事务或受验证的授权代次，不在视图服务中虚构保证。

CommandGateway、StateAggregateRepository 与查询接口保留 Reactor Publisher 的完整链路，不在 WebFlux event loop 中 block，也不在领域处理器中自行 subscribe。连接超时只结束观察，不当作分布式回滚。事件存储、快照、框架等待与服务端认证均采用实际后端集成测试，不用控制器 mock 代替。[W02] [W05] [W07]

## 14. 资源预算与性能契约

### 14.1 预算覆盖范围

预算必须覆盖普通工作台、独立嵌入、Dashboard 面板和未激活但仍保留的会话，不能只约束一个 Dashboard。每个结果同时计入其局部所有者预算和 Engine 全局预算。

| 预算                          |                  初始目标值 | 覆盖对象                                 |
| ----------------------------- | --------------------------: | ---------------------------------------- |
| 数据查询逻辑并发／等待        |                       4／48 | Record、Analysis、汇总和全部数据位置共享 |
| 元数据加载并发／等待          |                       4／24 | Engine 内的引用与候选元数据加载          |
| 活动及保留的数据位置          |                          64 | 所有嵌入和面板执行位置合计               |
| 单实例配置                    |                     256 KiB | 可保存配置及必要元数据                   |
| 单 Dashboard 全部面板／过滤器 |                      12／32 | 面板数量包含数据与内容面板               |
| 单 Dashboard 保留结果         |           12,000 行、16 MiB | 面板结果合计                             |
| Engine 保留结果               |                      64 MiB | 全部位置的结果与汇总                     |
| Engine 定义与引用元数据       |                     128 MiB | 含暂停后的恢复引用                       |
| 无活动消费者的结果缓存        |   最多 5 份，且服从字节上限 | 可淘汰的历史成功数据                     |
| 未保存工作实例                |                32 份、8 MiB | 已打开的编辑会话，不含只读列表摘要       |
| 编辑缓冲与布局历史            | 4 MiB；布局每会话最多 50 步 | 不可从实例重建的局部数据                 |
| 未核对写入                    |                16 项、8 MiB | 原提交配置与最小恢复上下文               |

独立 Filter 控件没有 Engine 时，搜索和回填分别最多一个逻辑在途请求；接入 Engine 时使用注入的调度与资源上下文，不因是候选请求而绕开总量控制。

这些数值是明确的初始准入策略，不是已经实测的吞吐量或延迟保证。已有数值与新增全局上限统一由 RuntimeLimits 管理，禁止散落在组件中。调用方可在校验后的配置中调整，测试覆盖收紧和放宽边界；不支持负数、非整数、无限值或定时器溢出。[S27]

表内已实现值与目标全局值不能混写为当前支持规模：例如全局位置数、全局结果字节、编辑缓冲和恢复总量是需补齐的目标策略。准入配置可调整，但不能超过 Wow 协议或结构校验的不可放宽上限。优先复用现有调度器与计数机制，以模块内额度检查实现必要覆盖，不为此引入新的全局资源管理框架。

字节采用定义清楚的可序列化载荷计量，不能把它宣称为精确 JavaScript 堆内存。引用共享可以减少物理占用，账本可以保守计量，但不能漏记多个位置的独立结果。超大响应的网络和解码峰值仍需要 Host 配合限制。

### 14.2 预留、提交与释放

候选配置、位置创建、结果替换和恢复上下文分别先预留、后提交。新结果替换旧结果按最终占用核算；被拒绝时旧结果及预算不变。关闭、删除、引用替换、超时与取消的所有路径必须释放本次所有权，晚到 finally 不能释放新资源。

快照通知频率、当前页面是否可见与资源拥有者寿命分开。多个观察者共享同一位置不重复计量；多个独立位置的数据结果不能因 instanceId 相同漏计。任何新增预算都要覆盖拒绝、释放、并发替换与取消路径，不仅增加一个配置字段。字节计量在内容变化时缓存，不因滚动、倒计时或权限按钮变化重新序列化全部结果。

只淘汰可以重建的闲置结果和派生缓存；不自动淘汰未保存实例、非法输入缓冲或未核对写入。没有可安全淘汰内容时拒绝新操作并说明需处理的资源。不能用取消用户保护来通过压力测试。

### 14.3 性能验证

性能服务于找到信息、调整观察方式和再次使用视图的任务。除内部计算指标外，测量用户从提交意图到看到可解释结果的等待及操作反馈；测量中区分引擎开销、宿主网络和后端计算，不用一项总耗时概括全部成本。

性能先优化无关订阅、编译与投影，再优化算法。不得靠去掉输入校验、取消快照保护、合并身份或清空草稿降低耗时。

分别测量编译与校验次数、React render／commit、请求数量、冷启动加载、主线程时间、保留载荷和实际包体。计时基准固定环境、预热策略与采样方式；绝对性能门槛来自可重复基线，不凭空承诺任意数据规模。

以下结构断言无需速度猜测：主题或倒计时变化新增查询数为零；布局变更新增查询数为零；面板 A 数据更新不增加面板 B 的查询编译次数，且 B 的快照引用不变；普通行选择不重编译整张 Dashboard；未变化计划不会因错误提示闪烁重复投影。

## 15. 目标模块落点与实施顺序

实施优先级由用户任务、可复用行为和风险决定，不由目录迁移难易决定。先明确观察方式的配置与执行边界，再建立最小公共基础，用完整任务验证 Filter 和三类视图；每个切片同时交付正确性、默认体验与公开消费能力，不先建设无法服务真实任务的大框架。

B 阶段只公开已满足边界的基础读取与生命周期 API，不先导出仍有视觉依赖的 Filter／Table Hook。目标 `/ui` 可以先承载尚未完成内部行为提取的既有组件，只要它不反向污染 `/react`；领域 controller 在对应完整切片成熟后加入 `/react`。这不是兼容层，而是按目标职责先归位再提取，同一时刻只保留一份实现。对外入口切换与全部仓库消费者更新须在一个可构建提交内完成。

D 的三条能力线在共享契约稳定后可以独立推进；Dashboard 不等待另外两者全部结束，但其结果内容和全局筛选必须使用已明确的共享契约。每个完成切片同时更新调用方、测试、文档并删除被替代实现，不把临时包装交给下一阶段。

每个切片先补当前反例，再修改实现与目标测试，最后删除失去职责的旧代码。最先落地的是受控状态、布局提交失败和双 schema 等范围明确的正确性约束，以及引擎读取／创建分离；不以一轮巨大 Store 改写作为所有 UI 进展的前提。UI 布局变化需满足第 11 节任务契约，不通过改测试文案隐藏丢失的任务。默认命令只改一处策略，默认 UI、独立嵌入和自定义组合应共同验证。

写入协调、全局预算和公开入口分别有明确所有者与退出条件；若现有类已能满足目标，仅移动／收窄职责即可，不要求所有模块改为新框架。最终清理涵盖 exports、导入、注册、CSS、类型、fixture、文档和脚本，但保留有效回归与源码许可证。

Fetcher 的 `services/view-host` 在共享合同明确后独立推进，并从第一个写入切片与前端联调：先完成“定义创建／读取 → 记录实例创建／保存 → 精确回执 → 重新打开”一条真实 Mongo 链路，再加入实例改名／删除、偏好与分页、定义竞争和 Dashboard 外部依赖。每条已暴露的写路径同时具备认证授权、版本、请求身份和失败核对，不先交付无安全边界的 CRUD 再承诺最后补齐。AggregateSpec、WebTestClient 与实际存储测试随切片建立，不能把正确性全部推迟到 E／F。

双端配置验证先覆盖全部内置协议和正反例，再为实际使用的自定义协议成对注册；不以实现任意扩展解释器作为服务首条链路前提。定义读取使用聚合仓库／快照的明确合同，服务只依赖 Wow 通用产物。第 13.6 节的是全部交付要求，不要求一开始把全部支持设施先建完才看到可运行的用户任务。

### 15.3 代表性产品闭环

采用固定、能力明确的业务夹具完成纵向验证。订单夹具声明状态、创建时间、仓库等任务所需字段，以及分组计数能力；夹具只是验证输入，不把这些字段或状态写入通用引擎规则。

**闭环一：明细观察与复用。** 用户从默认订单视图筛选待出库记录，调整列和排序，保存为获准的个人视图。重开时恢复配置，不恢复旧选择或页码；当业务服务数据已经变化时，执行得到新数据并显示正确来源。

**闭环二：分析与概览。** 从宿主声明的有效分析起始配置编辑并另存为按仓库计数的视图，将它与已保存记录视图组合为 Dashboard，明确设置全局筛选绑定。再次打开恢复面板与布局；各面板使用自己的查询、访问结果和失败反馈，不把所有结果标作同一时点快照。无需为此扩展通用全类型创建向导。

**闭环三：不同消费者与业务对象。** 将已保存视图嵌入另一个页面，再用公开行为接口实现结构不同的自定义组合；两者不共享临时浏览状态，也不复制查询或保存策略。用另一份能力明确的库存定义与 Host 接入复验；差异只在定义、配置、宿主与受限扩展，不要求在核心中增加“订单／库存”分支。

**闭环四：定义演进与独立交付。** 通过受控管理 API 创建订单定义，再建立多份实例与个人偏好。分别测试纯标签更新、新能力增加和已使用字段移除；实例版本不被批量推进，旧结果不改换来源，用户可在保留草稿的前提下修复并重新保存。定义更新与实例保存并发时核对实际 validatedDefinitionRevision。分别构建 npm 产物与 JVM 服务，再从共享合同运行端到端验证，不以同仓作为隐式依赖。

**闭环五：故障下的可解释完成。** 在同一真实产物中注入“事件已提交而快照延迟”“目录加载失败但实例直达可用”“定义更新期间保存回执晚到”和“仅加载一页的个人重排”。用户必须能区分已保存、回执待核对与目录同步，草稿及未加载偏好不丢失；恢复动作不新增重复实例，也不自动查询更宽数据。

首次接入不要求每项能力全部启用。独立 Filter、纯核心查询、默认完整视图和嵌入分别有最小消费者；只使用查询时不要求持久化、管理许可或默认 JVM 服务。产品闭环与第 16 节工程反例一起验证，不用只演示成功路径的页面代替运行时测试。

## 16. 对抗性验收场景

下表规定必须验证的目标行为。状态、命令与类型断言通过自动化验证；视觉可达性、屏幕阅读器和真实用户理解需相应浏览器或人工检查，不宣称全部可由单元测试证明。实现时使用可控 Promise、固定时钟、故障注入、引用身份断言和真实公开入口，不通过超长 sleep 掩盖竞争。每项场景对应至少一个目标测试／检查，尚未执行不得标为通过。

### 16.1 身份、写入与生命周期

| B07  | 修改筛选草稿后点击刷新或旧尝试重试             | 刷新已应用口径；重试仍有效的失败尝试；不偷偷执行新草稿                     |
| B08  | 新查询失败，旧结果仍在                         | 行、计划、时间和历史标记匹配；不把旧行标作新结果                           |
| B09  | 仅改列宽、布局或显示模式                       | 新增主查询为零，结果位置身份不变                                           |
| B10  | 更改汇总指标，或主表与汇总先后返回             | 只增加需要的 aggregate；不同来源口径不被无标注混排                         |
| B11  | 打开批量操作后结果或选择改变                   | 最终业务请求前 guard 拒绝陈旧动作；不仅检查按钮状态                        |
| B12  | Analysis 展示映射失效或图表模块抛错            | 数据表使用成功 schema 仍可读；不重算聚合、不填零                           |
| B13  | 新 schema 对应合法新展示，但旧结果不含该别名   | 可保存新设计；旧数据表仍按 resultSchema 读取，不用旧 schema 阻止保存       |
| B14  | 最新草稿非法，但已应用计划仍合法且用户显式刷新 | 只执行已应用计划，草稿不被清掉；自动刷新继续暂停                           |
| B15  | B 请求取消／失败，仍保留 A 结果                | applied 不回退；A 标为历史，刷新 B；不能把 queryStatus=success 当作 B 成功 |
| B16  | 同配置再次应用但只有位置没有成功结果           | 重新执行或返回明确的失败／等待状态，不以 position 存在当成结果可复用       |
| B17  | 同配置仅元信息变化且已有有效成功结果           | 可无请求地确认等价意图，提示结果被复用而非已刷新；强制刷新仍发请求         |
| B18  | 原始输入无效时关闭／卸载编辑器，再触发保存     | 无效事实与原值仍保留，不因 onUnmount 清空有效性而放行                      |
| B19  | 当前图表数据有负值／过多系列，但配置结构合法   | 图形局部降级；配置保存不被结果数据特征错误阻断                             |
| B20  | 尚无数据源成功响应，但合法实例需要保存         | 保存不要求业务查询成功、不隐式查询；明确结构／元数据未核验信息             |

### 16.7 Wow 服务、回执与读写一致性

| 编号 | 场景                                          | 必须断言                                                                                  |
| ---- | --------------------------------------------- | ----------------------------------------------------------------------------------------- |
| W01  | 以同一身份、同一 requestId 并发创建           | 创建目标稳定；EventStore 只接纳一次初始事实；成功或待核对响应指向同一实例                 |

| W06  | Q1 保存版本 N，Q2 已提交 N+1 后 Q1 返回       | Q1 返回自身版本及正文；不将最新快照拼成 Q1 回执                                           |

| W08  | 不同租户／主体使用相同客户端 requestId        | 目标命名空间与读取权限隔离，不覆盖、认领或泄露其他作用域                                  |
| W09  | 创建重试丢失最初 HTTP 响应                    | 可从原 requestId 定位创建目标和回执，不换随机 ID 重新创建                                 |
| W10  | 删除实例同时另一用户修改默认偏好              | 无跨聚合事务承诺；有效偏好不指向已拒绝／删除资源；删除不遍历所有用户                      |
| W11  | 偏好读取发现失效默认和排序 ID                 | 返回有效解析；GET 不产生写入，不把 UI 选中回退保存为个人偏好                              |
| W12  | 不可见实例出现在列表候选与总数                | 存储查询／服务输出按真实可见范围限制，不能只在前端过滤                                    |
| W13  | 直接调用聚合生成路由并伪造 owner／tenant      | 未接入相同可信边界的内部路由不对外开放；服务端不采信载荷身份                              |
| W14  | 仅提供前端校验通过标志或 Schema 结构合法      | 服务端仍执行配置语义和能力校验，缺少验证器不进入生产接线                                  |
| W15  | 快照乱序到达或节点重启后恢复                  | 快照版本不倒退；缺失检查点由框架仓库恢复，查询与回执来源不混淆                            |
| W16  | 精确回执已验证但读路径未可见                  | committed/visibility=pending 推进该操作基线；只确认读取屏障，不再次保存，也不退为 unknown |
| W17  | 核对索引不存在或历史读取达到预算              | 不将缺索引／预算耗尽当作原请求未提交，明确待核对并限制资源                                |
| W18  | 同时修改用户顺序与默认值                      | 独立字段命令及存在／版本前提；冲突不自动覆盖，重排不改变默认项                            |
| W19  | 另存共享视图后撤销源实例写许可                | 源只读许可与目标创建许可分别检查；源基线不因另存推进                                      |
| W20  | 生产使用实际 Mongo EventStore／SnapshotStore  | 运行版本、幂等、重放、删除、可见性和恢复合同；内存测试不代替持久化证据                    |

| G02  | 两个请求用同一定义 revision 更新完整定义           | 最多一个提交，另一请求返回定义版本冲突；不自动读新版本重写                                   |
| G03  | 候选定义包含重复字段、悬空分析引用或非法能力       | 整次拒绝，没有字段先改、能力后改的半状态；原快照及版本不变                                   |
| G04  | 保存实例时客户端 definitionRevision 已过期         | 返回 DEFINITION_CHANGED，保留实例草稿；不混成实例覆盖冲突，不偷偷替换依据保存                |
| G05  | 实例按定义 N 校验后，定义 N+1 在实例提交前完成     | 允许按已声明合同记录 N；回执不改写成 N+1；新打开／后续执行发现新定义时重验，不宣称跨聚合原子 |
| G06  | 定义已更新，原未知实例创建随后查到成功回执         | 核对原实例、正文和原校验版本，不因新定义重新拒绝历史事实；不再生成第二个实例                 |
| G07  | 定义只更新标题、纯标签或增加未使用能力             | 无额外数据查询、分页重置或实例版本修改；有效配置保留，结果来源仍对应原执行                   |
| G08  | 移除已用于筛选的字段或收紧操作                     | 定位问题并阻止失效计划；不忽略条件扩大查询，不自动删除用户输入                               |
| G09  | 数据源／行键／时区语义变化后旧回包到达             | 旧解释代次不能发布到新环境；原结果按原 schema 标记，相关草稿保留并重验                       |
| G10  | Dashboard 多面板中只有一个定义被变更               | 只重验受影响引用，其他有效位置与结果不重建；绑定不安全的面板不执行宽松查询                   |
| G11  | 修改定义、实例或个人偏好之一                       | 不推进另外两类聚合的版本；不同用户／定义偏好不进入同一大聚合                                 |
| G12  | 移动或移除 Dashboard 面板后修改被引用实例          | 面板配置属于 Dashboard 实例，被引用实例独立；不因移除面板删除引用目标                        |
| G13  | 持有实例创建／另存许可，直接调用定义维护 API       | 定义管理单独授权，普通 getDefinition 许可不授权修改定义；未许可请求无持久变更                |
| G14  | 同一核心包分别使用 Memory、WowViewHost 和自有 Host | 默认服务与适配器不是核心必需依赖；纯查询不要求启动 JVM 或接许可服务                          |
| G15  | 单独构建前端与单独构建 JVM 服务                    | 前端不要求 JDK／后端启动；后端不要求完整 UI 构建；联调任务显式组合两边产物                   |
| G16  | 只改内部 UI／后端实现，或改变共享 HTTP／Schema     | 前两者不强制另一端发版；合同变更触发两端验证，生成客户端与实际服务一致                       |
| G17  | TypeScript、Kotlin、HTTP 和夹具同时读取资源身份    | definitionId、instanceId、runtimeId 各指唯一概念；revision 按资源核对，没有旧同义类型或路由  |
| G18  | 服务启动配置比已保存定义更旧，或定义通知乱序       | 不以初始化覆盖已维护定义；Host 不回退已接受快照，Engine 不由旧通知复活失效计划               |

### 16.9 端到端协议与隐含前提

| 编号 | 场景                                                | 必须断言                                                                  |
| ---- | --------------------------------------------------- | ------------------------------------------------------------------------- |
| H01  | 保存、改名、删除、偏好及定义写入分别超时后重试      | 所有端口保持原 requestId／目标／正文；适配器不生成另一业务意图            |
| H02  | 提交已证明但回执无法取得或准入失败                  | 保留 knownCommit 并核对回执；不把未经验证正文当基线，不倒退成确定未提交   |
| H03  | 回执 N 晚于已观察的 N+1／删除状态                   | 原操作结清，但目录与当前状态不回退、不复活已删除或不可访问资源            |
| H04  | opaque revision 的词法顺序与实际提交顺序不同        | 客户端不自行比较大小；服务读屏障按正确资源及内部版本确认                  |
| H05  | 两个主体在同一共享实例使用相同客户端请求键          | 规范化框架键分离；当前主体不能认领或读取另一个主体的原操作                |
| H06  | 同一主体、目标、请求键换动作或正文                  | 摘要不匹配拒绝；不因 action 被放进独立键空间而绕过去重                    |
| H07  | 新意图设置与当前值相同的偏好／配置                  | 派发前明确跳过，或服务接纳并产生可核对事实；不等待永远不会产生的快照      |
| H08  | 原未知写入重放遇到定义变化或许可拒绝                | 此尝试问题单独记录；不宣称更早的尝试没有提交，继续允许合规核对            |
| H09  | 只加载 [A,C] 却调整完整顺序 [A,B,C,D]               | scope=[A,C]、ordered=[C,A] 得到 [C,B,A,D]；未作用 ID 和默认值不丢失       |
| H10  | 偏好不存在时顺序与默认两个请求同时创建              | absent 前提让创建唯一；冲突明确，不以任意版本覆盖另一字段                 |
| H11  | 默认实例不在目录第一页，或偏好晚于手动选择返回      | 有效默认可点查；用户主动选择优先，不被晚到默认抢走                        |
| H12  | 目录或许可失败，但指定实例和定义可读取              | 直达／嵌入仍完成任务；目录错误不清空存活会话，不等待全量目录              |
| H13  | 分页期间查询或偏好顺序改变                          | 旧 cursor 明确失效，重载摘要而不丢编辑；空页／上限不冒充全目录为空        |
| H14  | 定义重载失败，或重载期间原保存成功                  | 失败不抹掉草稿；已知失效计划仍阻止新执行；原写回执按原身份核对            |
| H15  | 相同“最近七天”配置在不同时间显式运行                | 未固定求值锚点时执行新请求；标签编辑不请求；不把接收时间写成源求值时刻    |
| H16  | Dashboard 面板同 ID 替换引用后旧轮完成              | 核对引用／解释／位置代次；旧成功不能给新引用计数或显示                    |
| H17  | TS、Kotlin 校验同一自定义协议但服务端未注册         | 保存明确拒绝或指出不支持；不把有 renderer 或结构合法当作完整语义支持      |
| H18  | 两端 JSON 含重排键、1/1.0、字符串 1、重复键与大整数 | 规范比较金样一致；数值和字符串不混淆，重复键与精度损失入站即拒绝          |
| H19  | Dashboard 外部元数据暂缺但按合同保存                | 回执携带未完成依赖验证；执行仍逐面板准入，不用根定义版本冒充全部有效      |
| H20  | 标签解析先成功后源明确撤销候选读取                  | 不用旧受限标签恢复可访问内容；必要修复 ID 与可显示文本分别处理            |
| H21  | 显示语言／数字显示地区变更                          | 原值、查询时间语义、Engine 与请求不变；文案回退安全，业务名称不被擅自翻译 |
| H22  | 非拖动方式调整列宽、列序、分析项和视图顺序          | 点击／触控入口可达，复用同一命令及范围，不仅测试 Dashboard 方向键         |
| H23  | 已保留正式事件后输入格式改版                        | 所支持历史事件仍可确定性重放；删除旧 HTTP 格式不误删事件处理              |
| H24  | 读屏障或操作定位引用被替换为别的主体／资源／URL     | 服务校验范围，适配器不任意跳转，不泄露精确回执或越范围读取                |

## 17. 验证链路与完成条件

### 17.1 测试层次

产品测试覆盖第 15.3 节的真实任务闭环、第 16.5 节的复用边界与第 16.6 节的交互场景。核心测试覆盖纯转换、计划和结果保真；运行时测试覆盖异步时序、观察者重入、操作可用性和资源账本；React 测试覆盖受控矩阵、StrictMode、实例替换和布局事务。Host 合同测试覆盖许可缺省、已接受结果的顺序、结构化访问拒绝和可信服务端最终检查；不在引擎测试中实现角色系统。源码模式与 React Compiler 模式都执行目标接口测试。

编译期反例验证不同 view kind 的命令不能交叉调用，浏览位置没有实例写入能力，未接许可端口也可以构造查询消费者，快照深层不可写，扩展角色与输出受约束，受控／非受控 Props 不能同时提供冲突值。类型测试是产品契约，不测试内部类型工具必须以某种写法实现。

架构检查同时检查运行时导入与声明文件，不只用文本匹配找 CSS。构建后检查核心和 `/react` 的全部可达模块、供应商静态旁路、CSS 作用域、客户端标记和 package exports。

默认 UI 与第二种组合从真实打包归档安装、解析和执行，不使用源码 alias 或工作区私有 import 绕过导出约束。Grid／Chart 的懒加载失败用真实构建 chunk 的网络失败注入验证，不仅 mock 一个 React 组件抛错。[S15] [S16]

每个入口至少有独立消费探针：核心 Node、React headless、默认 UI、Memory、IndexedDB、可选 `/hosts/wow`。单包安装仍可能安装 UI 依赖；D09 检验的是核心的运行／声明依赖不加载它们，不把“只导入核心”写成“完全没有安装 UI 依赖”。测试核心声明时关闭 skipLibCheck，并核对没有借上层 React 类型意外引入 DOM。

回归测试先固定语义再改实现；确需改变 UX 或 API 的旧测试随目标更新，例如新增非拖动尺寸入口后不能继续要求页面绝无 spinbutton。保护数据位置稳定与不重复查询的断言必须保留，不能把结构变化作为删除全部回归的理由。[S40]

浏览器验证覆盖宽窄容器、明暗主题、键盘、IME、真实拖动、Portal、错误降级和反复挂载释放。不同浏览器的已知第三方问题必须有精确说明与行为验证，不能扩大整个类别的忽略规则。

Fetcher ViewHost 服务对 ViewDefinition、ViewInstance、UserViewPreferences 分别使用框架 AggregateSpec 验证命令、事件与状态演进；对实际 EventStore／SnapshotStore 执行持久约束与恢复测试；用 WebTestClient 和真实认证上下文验证门面，不只 mock CommandGateway。Mongo 集成验证使用隔离测试实例，核对实际索引、快照策略和所选一致性配置。前端契约验证覆盖写结果映射、202／unknown 核对、版本冲突、许可缺省与删除后偏好解析。定义版本变更、跨聚合校验竞争和第 16.8 节项目边界同时验收。前端验收命令不能作为 JVM 服务已通过测试的证据，JVM 测试也不代替前端状态和交互验证。

第 16.9 节同时在协议模型、Host 合同和前端消费路径验证。模型探针只能证明其表达的规则，不当作源码实现、真实网络、React 焦点或 Mongo 原子性通过；跨语言 JCS、Schema 和语义夹具分别执行。总场景数不作为质量分数，实施测试必须可追溯到对应不变量及实际产物。

### 17.2 执行入口

在仓库工作区依赖就绪后，沿用并更新现有验证链路：

```bash
pnpm --filter @ahoo-wang/fetcher-view-engine... build
pnpm --filter @ahoo-wang/fetcher-view-engine test
pnpm --filter @ahoo-wang/fetcher-view-engine lint:check
node packages/view-engine/scripts/verify-package.mjs
pnpm verify:view-engine
```

服务目标验证入口与前端独立：

```bash
cd services/view-host
./gradlew :api:check :domain:check :server:check
```

这是服务模块建成后必须提供的目标入口，不是声称当前仓库已存在的可执行任务。`:server:check` 应接入隔离 Mongo 的持久化及 HTTP 合同测试，测试环境缺失必须明确失败或报告未验证，不以全量跳过当作通过。前端 `verify:view-engine` 不启动后端作为每次 npm 发布的隐式前提；独立的契约联调任务启动选定的 JVM 与前端产物，执行共享夹具和完整闭环。

目标 exports、实际测试配置和浏览器前提在同一切片更新。浏览器安装、工作区构建等前置条件由项目现有流程满足；不能用此命令清单代替真实运行输出，也不能把环境未就绪当成测试通过。

每次切片验收记录代码提交、执行命令、退出码、失败清单和测试／浏览器环境。第 16 节场景由实施测试建立对应关系；这里只保存有效契约，不保留方案变更日志。最终全套验证必须在同一目标产物上完成，不能把不同提交的绿色结果拼成一次全量通过。仓库不可运行时可以做源码或最小探针验证，但必须准确标明范围，不把简化模型等同于真实 React、RGL 或宿主事务。

### 17.3 交付约束

源码、公开导出、配置读取器、依赖、脚本、Storybook、示例与文档同步收敛。无消费者的文件、弃用别名、兼容开关、双实现、临时 shim、过期 fixture 和复制的行为删除；需要保留的行为测试适配到目标 API。

文档只描述目标架构与使用方式，不包含修订日志、历史方案对照、已否决选项或临时审查注释。源码也不保留为废弃结构辩护的说明。正常版本控制、有效测试、来源依据与写入恢复数据不是废弃设计，不通过删除它们制造表面上的清理完成。第三方许可与版权声明按实际分发内容维护，不作为残留注释删除。

每个能力切片提供可复现的构建和测试结果。不得通过降低覆盖率门槛、删除关键反例、扩大排除范围或让公开消费者依赖私有模块来通过验收。

重构完成必须同时满足产品和工程条件：受支持的观察方式可以配置、执行、保存、再次使用并独立嵌入；默认 UI 与自定义组合消费同一行为；Filter、Record、Analysis、Dashboard 的配置、结果、所有权和失败语义准确；更换布局、皮肤或业务定义无需复制命令策略；不接许可服务也可查询与展示，管理动作只消费宿主授权结果并与可信服务端分工；身份、预算和恢复路径在反例中仍成立；公开产物不包含已被替代的实现。目录或接口整理完成、内部测试通过，都不能替代用户任务闭环。同时，三类后端聚合与定义更新规则成立，正式领域命名一致；前端、后端和共享合同归属 Fetcher，Wow 仅作为框架依赖。写入结局、精确回执、读可见性、分页目录和局部重排在真实消费者中一致；两种产物独立构建、发布和部署，联调验证明确版本组合。

### 17.4 产品价值验证

产品价值与技术正确性分别验证，不能从单元测试通过推导“用户效率已经提高”。以下指标用于固定任务与真实消费者的对照；在有实际测量前只作为验证方法，不设未经证实的提升比例。

| 维度             | 验证方法                                                                                         | 结果解释                                                       |
| ---------------- | ------------------------------------------------------------------------------------------------ | -------------------------------------------------------------- |
| 找到并理解信息   | 固定目标记录或指标，观察从打开视图到正确识别信息的完成率、步骤和耗时；同时询问当前条件与结果来源 | 操作变少但误读结果增多，不算有效改善                           |
| 减少重复配置     | 完成一次保存、离开、重开和再次使用，记录需要重设的内容；检查临时状态是否不当进入实例             | 应复用观察方式，不要求重填有效配置，也不承诺复现原数据         |
| 减少重复开发     | 在同一公开包基础上接入第二个业务定义和第二种页面结构，检查变更文件、重复策略、私有依赖及接入步骤 | 合理的 Host 与领域扩展是接入成本，不把它们伪装成引擎已自动提供 |
| 支持团队复用     | 在不同用户环境使用同一共享视图，核对配置语义及各自数据范围                                       | 共享有效观察方式，不共享许可、临时状态或数据缓存               |
| 控制持续维护成本 | 修改一项通用交互或修复一个时序问题，运行默认界面、独立嵌入和自定义组合测试                       | 一次行为修复应惠及对应消费者，而不是分别修补多份实现           |

首次交付至少提供代表性闭环的可重复证据、第二消费者的真实接入，以及明确的当前能力范围。对外产品说明采用本方案第 1 节定义，区分目标能力、已实现接口和已执行验证；不以依赖库名称、配置项数量或“企业级”标签代替可检查的承诺。
