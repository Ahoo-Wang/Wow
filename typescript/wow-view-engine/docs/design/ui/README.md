## 措辞与 MessagesProvider

- 措辞在 `ui/`：`model` 只带 `code` 与 `params`，`ui/messages.ts` 给出英文句子。`ViewSurface` 与四个入口（`DataWorkbench`、`DashboardWorkbench`、`EmbeddedView`、`EmbeddedDashboard`）的 `messages` 属性按 key 覆盖，这也是本地化的入口；每层 `MessagesProvider` 合并在上一层之上，应用在外层设一次即可。
- 目录按前缀分文件放在 `ui/messages/`（`save`、`header`、`record`、`filter`、`config`、`scope`、`view`、`manage`、`analysis`、`dashboard`、`status`、`definition`），每个文件 `as const satisfies Record<string, string>`，`messages/en.ts` 铺成英文目录。组件只 import `ui/messages.ts`，它导出 `ViewMessages`、`defaultMessages`、三个格式化函数与前缀回退。
- **key 是类型**：`MessageKey = keyof typeof en`，`MessageFormatters.label(key, params?, fallback?)` 只收它，删键或拼错是编译错误；全包没有 `MessageKey` 断言。运行时拼出的 key 走闭合联合（`ViewKind`、`ViewAudience`、`RecordLayout`、`DateShape`）。界面上能选的闭合枚举整套命名——`label.operator.*` 覆盖 `FilterOperator` 全部成员（`operatorKey()` 只拼一次），`label.chart.type.*`、`label.group.type.*`、`label.metric.function.*`、`label.relative.unit.*`、`label.relative.preset.*` 同理——只命名一半的集合没法翻译。派生拼写只兜底宿主给出的未知成员，`test/messages.test.tsx` 逐个核对。
- **一个面叫它打开的东西什么，由那个面定**（[D26](../decisions.md#d26-阶段-34-联合审查的十一条拍板2026-09-24) Q34，`ui/kinds.ts` 的 `SurfaceKind`／`kindWord`）：新建、保存与它的「更多操作」、共享确认、另存、删除、离开确认、写入冲突、视图管理器（连同拖动说明）、侧栏（标题、三个分组、收起／展开）、切换器、打开中与打不开时的那一句、整板要先修正、自动刷新的说明、一块渲染失败时的提示，这几处外壳的话说「视图」；仪表盘工作台与嵌入的板子把 `SurfaceKind` 设成 `dashboard`，同一处就读它自己的那几条（`label.dashboard.new`、`label.dashboard.shared-heading`、`label.dashboard.delete-consequence`……），删除确认还写清在仪表盘里新建的分析随之删除。**引擎报来的话也一样**（`kindIssue`／`useKindIssue`）：同一个报错代码各种视图共用（写入、列表、打开是一套协议），所以由面来挑词——代码先按 `formatMessage` 的回退找到它读的那一条（`view.save.failed.unavailable` 读 `view.save.failed`），那一条在仪表盘上有自己的句子就换成它（「仪表盘保存失败。」「这个仪表盘已不存在。」「你不能写这个仪表盘。」，`label.dashboard.*`），不提视图的句子（「无法连接服务端。」）原样。读它的是报「这个打开着的东西」的几处：状态行、写入被拒的那一行（标题栏与管理器的行）、打不开、侧栏列表读不出、另存与第一次保存的对话框、嵌入的框（`EmbedFrame` 按它唯一的种类设 `SurfaceKind`）与嵌入板的报错条；面板上的视图、选视图的列表、在仪表盘里新建的分析与「另存为视图」「复制为共享视图并替换」照旧说视图。只有指「这个打开着的东西」的外壳读它——板子里的面板显示的仍是视图，选视图、「另存为视图」照旧说视图，用的是各自的 key。宿主覆盖 `label.dashboard.*` 即可改仪表盘的说法。（见 test/kindWords.test.ts「what a board calls itself (D26 Q34)」——扫两份目录：板子能被报的每一个代码（`view.*`、`config.*`、`runtime.kind.*`，连同每个 `*.failed` 拼上每个存储错误码）在仪表盘上说出来都不带「视图」／view，板子自己的每一句都点名仪表盘——test/dashboardWorkbench.test.tsx「names the board in its chrome: the list, its fold, the switcher, the save menu (Q34)」——它还扫一遍屏上所有 `aria-label`，不许有「视图」——「says what the engine reports about the board as a board’s (Q34)」、test/embeddedDashboard.test.tsx「says a board it cannot open is a dashboard, in the host’s language (Q34)」、test/dashboardExtensions.test.tsx「says a refused save of it as a view’s: a view is what it makes」、「moves on to the view that is still there once the open one is deleted」、test/dashboardBuilding.test.tsx「asks before 保存 writes over a shared board, naming it」）
- **一词一义**（R5 X-08、X-09）：「撤销」只指退回一步（编辑条的 `useBoardHistory`、⌘Z）；丢掉还没应用的条件是「放弃筛选修改」；清掉一个值是「清除」（交叉筛选「再点一次清除」）；自动接线提示上拿掉自动接上的那几块是「只接刚选的面板」。仪表盘上一律说「仪表盘」，不说「板」；内容面板的种类是「标题」「文字」「图片」「链接」（「分节」「笔记」不再出现，取目录里用得最多的那个词）；链接面板里一条链接显示的字叫「链接文字」，与「文字」面板分开。
- **屏幕上的名字用字段标题，不用 id**：`ConditionPill` 的四个无障碍名（`condition-of`、`operator-of`、`value-of`、`remove-of`）都拿 `field.label`（取不到才退回 `leaf.field`）。（见 test/filterPanel.test.tsx「names every control on a row after the field, not its id」）
- **vendored 组件写死的文案在调用处合缝**：`spinner.tsx` 写死 `aria-label="Loading"`，所以渲染 `<Spinner>` 的三处（`RefreshControl`、`SaveActions`、`SaveAsDialog`）传入 `label.status.loading`；`DashboardWorkbench` 只把 `busy` 交给 `RefreshControl`。（见 test/refreshControl.test.tsx 与 test/saveActions.test.tsx「announces the write in the host catalogue, not in English」）
- 宿主的覆盖是 `Readonly<Record<string, string>>`，本包从不读它不认识的 key。第二份目录 `zhCN`（`ui/messages/zh-CN.ts`，`satisfies Record<MessageKey, string>`）与 `en` 一同从 `/ui` 导出，可整份交出或 `messages={{ ...zhCN, 'label.x': '…' }}`；它是没有组件 import 的叶子模块，不进只引组件的打包。Storybook 的 view-engine 故事默认跑 zh-CN（`stories/view-engine/fixtures.ts` 的 `HOST_LANGUAGE`），因为夹具数据是中文；`RecordWorkbench` 的 `English`（「英文目录」）是英文目录的回归。
- 工作台在面之外的提示用 `useViewMessages(messages)` 读同一份合并结果。缺失的 key 沿点号回退到最长的已知前缀（如 `view.open.failed.not_found`），再退回 key 本身，永远不渲染空白。测试扫描源码里所有 `issue(...)` 的 code，缺一条就失败；并断言 `Object.keys(zhCN)` 与 `Object.keys(en)` 相同、每个 `{param}` 两边都在。（见 test/messages.test.tsx「the message catalogue」「the Chinese catalogue」「components write no copy of their own」）

## 两级 severity 与 StatusStrip

- 两级 severity 都是**单行状态条**（`StatusStrip`）而不是整块 Alert：结果区始终留着上一次成功的结果，不阻塞的提示不该把它顶下屏幕。tone 有 warning／error／info，error 以 `role="alert"` 播报，其余 `role="status"`。
- **一行高是布局的决定，不是不用组件的理由**（D16 裁定 7）：状态条是 shadcn `Alert` 的紧凑变体——`ui/alerts.tsx` 的 `LineAlert` 用一层 cva 把块状网格改成一行会换行的 flex、`AlertAction` 放回行尾（vendored 不手改，D16 裁定 8）。句子是 `AlertTitle`，没有 description。tone 同时决定颜色（`border-destructive`／`border-warning`／`border-border`）、图标（`TONE_ICON`，全包一套）与播报方式。`frame` 两种：`box` 是带边横幅；`bare` 无边无底色、13px（`TEXT_UI`），用于对话框里的行与一排控件中的槽位。
- **每一处 callout 都走这一份配方**：状态行（`StatusStrip` 与 `WarningStrip`／`ErrorStrip`／`QueryStrip`）、写入结局（`OutcomeActions`）、导出超上限（`export-over-limit`）、条件超预算（`filter-too-large`，tone `info`——这一屏改不对，Clear 才是出路）、`RenderBoundary` 的 compact 面（`bare` + `inline-flex w-auto`）。第二份配方就是两条 callout 对 warning 长什么样各执一词。重试按钮用 `outline`，本就跟着周围的 tone 走。
- 多于一条时只显示概述与「{count} more」（`label.status.more`），展开后改说收起（`label.status.less`）。
- `error` 阻塞。条件级的 error 就地标在 pill 上并禁用 Apply，所以工作台的 error 条只报条件以外的那些，即编辑器控制器交出的 `filter.unmarked`（`filter/marks.ts` 的 `unmarkedErrors`：code 以 `filter.` 开头且路径解析到一条被渲染的条件才归编辑器；畸形子节点与分组本身没有 pill，照样报在状态条里，否则它们禁用 Apply 却无处可看）。标题 `label.view.needs-fixing`／`label.dashboard.needs-fixing`。
- `EmbeddedView` 没有编辑器，全部报出并取代结果；查询失败例外：上一次结果还在时失败条与结果并排（`label.query.stale`）。`warning` 不阻塞但要被看见：用主题的 `warning` token（`text-warning`／`border-warning`，宿主以 `--fve-warning`／`--fve-dark-warning` 定制）；一条时那句话就是标题，多条时标题是 `label.view.warnings-count`。
- **宿主的收窄被拒，说的是收窄而不是视图**：`EmbeddedView` 的 `scopeFilter`（`EmbeddedDashboard` 锁定或隐藏的筛选值同理，见 [embed.md](embed.md)）不被定义接受时，是一条 destructive `Alert`（标题 `label.scope.refused`，正文列出理由），而不是 `label.view.needs-fixing`——宿主改不了别人存的视图。首次打开被拒与后来被拒同理（[decisions.md](../decisions.md) D17-5）：收窄不生效，视图照原样跑，结果留在屏幕上、告警压在上面。（见 test/embeddedView.test.tsx 与回归 story「ScopeRefused」「ScopeRefusedOnOpen」）
- 同 code 同 params 的 warning 只说一句（`dedupeIssues`）。查询失败是一条 error 状态条：标题是失败那句，右端 Retry；上一次结果还在时同一行接着说「· 显示的是上一次成功的结果」（`label.query.stale`）——读者最需要的一句不折叠。失败从不清空结果。（见 test/statusStrip.test.tsx「StatusStrip」「dedupeIssues」「WarningStrip」「ErrorStrip」「QueryStrip」）
- **结果自己的 warning 与配置的 warning 并排，note 在其下**（`NoteStrip`，info 语气；仪表盘面板头是一枚灰色 info 图标，不染面板边）：汇总行退回本页口径（`runtime.summary.page-only`）、还有没列出的组（`analysis.result.more-groups`／`analysis.result.at-limit`）这类发现随结果走（`ProjectedView.issues`，见 [../runtime.md#规则](../runtime.md#规则)）——`state.issues` 每次 `edit` 都重算，放进去就会在下一次按键时消失，而数字还在屏幕上。`RecordWorkbench` 与 `AnalysisWorkbench` 把两者拼给 `WorkbenchShell` 的 `warnings`，`EmbeddedView` 并进自己那条。

`FilterPanel` 的条件 pill 见 [FilterPanel 的布局](#filterpanel-的布局)。

## 值按字段显示

- 规则在 `ui/display.ts` 的 `displayValue`（已应用条的措辞在 `ui/summary.ts`）：Wow 把时间存为毫秒时间戳、枚举存为代码，原样打印没法读。声明了 `options` 的字段按选项标签显示（数组逐项，未知的码原样）。
- `cell ?? kind` 为 `datetime` 时经 `Intl.DateTimeFormat`（`dateStyle`／`timeStyle: 'medium'`），为 `date` 时只显示日期；`datetime` 上不带时刻的挂钟字符串（`2026-01-31`）只显示到日——它指一整天（[kernels.md](../kernels.md#日期条件一个字符串算哪一刻)），印 `00:00:00` 是陈述一个没人选过的时刻。不带偏移的字符串（`LocalDate`／`LocalDateTime`）是挂钟时间，原样显示不换算时区；日历上不存在的挂钟时间（`2025-02-29`、`24:00`）原样显示，不交给 `Date` 顺延。
- DATE_HISTOGRAM 的键显示为桶起始的年、季度（`2026 Q3`）、月、日或时刻，按公历命名（Wow 按公历切桶）。HISTOGRAM 的键读成它起头的那一段（`bandText`，见 [analysis.md#数字按它自己的列读](analysis.md#数字按它自己的列读)）。
- 分析的表格、坐标轴、提示、热力图与指标卡共用 `valueText`（图表侧经 `useValueLabel`），指标的格式来自 `metricFormat`（[kernels.md#指标的数怎么读](../kernels.md#指标的数怎么读metricformat)）；宿主给了 `renderCell` 就由宿主决定。
- 语言取 `ViewSurface` 的 `locale`（缺省为运行环境），时区取 `timeZone`；工作台透传同名属性，并把时区交给引擎的 `environment.timeZone`——相对日期按它解析、未声明时区的 DATE_HISTOGRAM 按它切桶、界面按它显示，一行按什么时钟被筛选，就按什么时钟显示。分组自己声明了时区的按那个时区读。
- 表格、卡片与图表的类目共用这套规则：`RecordColumnView` 带 `options`，`RecordCardField` 带 `kind`、`cell`、`options` 与 `numberFormat`，`AnalysisColumnView` 见 [kernels.md#compileanalysis-与-projectanalysis](../kernels.md#compileanalysis-与-projectanalysis)，`AnalysisChart` 经 `AnalysisView.schema` 拿到它们。`spec.colors` 的键仍是原值。`numberFormat` 构造不出来时先放弃语言、再放弃格式，不让整张表抛错。（见 test/display.test.ts「displayValue」）
- **界面印出的每个数字走 `formatNumber(value, format, locale)`**：语言先取 `numberFormat.locale`，再取界面的 `locale`，不按机器的语言；没有 `numberFormat` 也按界面语言分组（`534,897`）。坐标轴（`charts/axis.ts` 的 `formatValue`）与句子参数（`formatMessage` 交给 `formatNumber`，语言由 `MessagesProvider` 带着）读同一个格式器。是名字不是数量的数（年份、工号）由定义写 `numberFormat: { useGrouping: false }`，句子里以字符串传入。（见 test/display.test.ts「formatNumber」、test/messages.test.tsx、test/recordPagination.test.tsx「RecordPagination groups its numbers」）

## 控制器输出合同

- 控制器输出只读状态与动作函数，不输出 JSX、类名与供应商类型。受控值合同统一：是否受控由值属性决定，回调只通知，一次逻辑交互最多一次通知。命令一律以状态兑现而不是抛出：`useSaveCommands` 的每个动作都 resolve，结局落在 `state.error` 与 `state.write`，因此点击处理器不需要 try/catch。加载态由"手上的答案属于哪一次请求"推出而不是在 effect 里同步 setState，这也是 React Compiler 规则要求的形状。
- 排序与列的改动立即 `edit` 后 `apply`：表格渲染的列与行来自上一次成功结果，由内核按执行时的配置投影，因此不重跑就看不到改动；筛选则等提交。

## shadcn 与两个样式边界

- `ui/` 用 shadcn + Base UI。注册表组件原样落在 `ui/components/`（与 `ui/lib` 一起排除在覆盖率、Prettier、ESLint 与 Codacy 之外），由 `shadcn add --diff` 升级，因此不启用 Tailwind 前缀——前缀会让每个文件都要手改、从此跟不上上游。本包测的是其上的组合。
- 隔离由**两个样式边界**承担。Tailwind 的 preflight 与工具类是全局的，所以 `scripts/scope-utilities.mjs`（`postcss-prefix-selector`）在构建时给每条规则加上 `:where(.fve-root, .fve-root *, .fve-tokens, .fve-tokens *)`：`:where` 不改特异性；用「边界或边界内」，因为弹层自己带着根类。`:root`／`:host` 的主题变量改写为 `.fve-root, .fve-tokens`，免得与宿主的 Tailwind 互相覆盖；只有 `@property` 天然全局，它注册的只是 `--tw-*`。
- **两个边界里只有一个是 surface**（D17-10）。`.fve-root` 是 `ViewSurface` 渲染的面：token、utility、base 规则，加上它自己的底（`--background`／`--foreground`）与 `data-theme` 钉住的模式。`.fve-tokens` 是宿主给**自己的 chrome** 戴的类：同一份 token、utility 与 preflight（戴上它的区域也被重置，这是代价），但不涂底、不认 `data-theme`、不是面——要底色自己写 `bg-background text-foreground`，明暗跟祖先上的 `.dark`。两个类不戴在同一元素上；`RecordTable` 这类视图组件只在面里渲染。
- `verify-package` 守住构建产物：边界之外没有规则、没有 `:root`，且**每一处作用域都同时点到两个边界**，少一个就是一整个边界悄悄不画。Storybook 对主题文件走同一个插件。`cn` 取自同名包。主题以独立入口 `/styles.css` 交付。
- **vendored 组件的颜色与边框只在包装里扩展，不在调用处**（D16-8）：在组件旁放一层持有自己 cva 的薄包装，调用处传 variant 或状态而不是一串颜色。颜色一共**四个家**，越界就是缺陷：
  - `ui/variants.tsx`——vendored 组件差的那层颜色与边：`ToneBadge`（见 [record.md](record.md#徽章的颜色由定义说了算但只能从主题里挑)）、`WrappingBadge`、`DestructiveAction`（见[保存与视图管理](#保存与视图管理)）、`SectionDivider`、`PillInput`／`PillChips`／`PillSelectTrigger`（pill 里不画边的控件，`chrome="box"` 要回边）、`TableDataRow`（行的静息／悬停／选中，见 [record.md](record.md#表格-chrome层次与冻结列)）、`SidebarItem`；以及结果区那圈边的槽位配方 `resultFrameChrome` 与 `resultSlots()`（见[工作台骨架](#工作台骨架)）。不写版式；
  - `ui/alerts.tsx`——callout（`LineAlert`），另带语气图标与播报 `role`；
  - `ui/RowItem.tsx`——列表行：`data-dragging` 的底色、`data-broken` 的灰字与 `density` 变体；
  - `ui/record/sticky.ts` 与 `ui/record/columns.ts`——表格自己的 chrome，没有上游组件可包：两端同一个灰的带子（`BAND`、`BAND_ROW`）、冻结格子的 `bg-inherit` 与层级、冻结列那道边（`EDGE`），表头格子的 `HEAD_CELL`／`HEAD_HOVER`（悬停反着往行的底色抬一档，因为注册表 `accent` 与 `muted` 同值）。

  版式留在调用处的 `className`；「这块面上无条件如此」的规则在 `styles.css`。不从父元素往下够 `[data-slot=…]`：上游改个 slot 名就无声失效。（见 test/variants.test.tsx，这些类名字符串的唯一断言处）

- **一列行只有一个配方**（[decisions.md#D16](../decisions.md#d16-站在-shadcnbase-ui-肩膀上审计后的八条裁定) 裁定三）：视图管理行、列设置行、排序条目、卡片正文、链接面板都是注册表的 `Item`（`ItemMedia` 领头、`ItemContent` 居中含 `ItemTitle`／`ItemDescription`、`ItemActions` 收尾，折行用 `ItemFooter` 或 `basis-full`）。`ui/RowItem.tsx` 只加状态色与 `density`（弹层与对话框里用 `dense`）；状态标记留在调用处，测试按 `data-slot` 与 `data-dragging` 认行。**能拖的几列只有一份把手** `ui/DragHandle.tsx`：同一枚 `GripVerticalIcon`、同一组方向键（↑／↓ 各移一位）、拖动途中静音（`IconButton` 的 `silent`）。**算不算一次放下**是 `ui/dragDrop.ts` 的 `dropped()`，各处在它之上问自己的那一句（`sort/drag.ts`、`manage/drag.ts`、`ColumnSettings`、`analysis/drag.ts` 的 `seriesDrop`）。**拖拽库的插件也只设一次**（Q-11，`ui/dragPlugins.ts`）：六个可排序列表（列设置、排序、视图管理、系列、标签栏、筛选条）的 `DragDropProvider` 都是 `announcedPlugins(…)`——库的默认插件，其中 `Accessibility` 换成按这个列表的措辞配好的那一份（`dragAnnounce.ts` 的 `dragAccessibility`）；每一行的 `useSortable` 都是 `withoutOptimisticSorting`——去掉乐观排序，它在指针移动时就改 DOM，放下时读到的下标就旧了。（见 test/dragHandle.test.tsx、test/renameInput.test.tsx「the drag plugins」）
- **就地改名只有一个框**（Q-10，`ui/RenameInput.tsx`）：面板标题、标签页的名字、视图管理器的一行共用它，规则一套——出现即获得焦点并全选，打字即替换；Enter 保留、Esc 放回原名，两个键都停在框里（`stopPropagation`，框可能在对话框或弹层里，同一个键不该再关掉它们）；离开（点别处、Tab 走）也保留——移到框里自己的 ✓／✕ 不算离开；名字先 trim，与原名相同就不算改名、什么也不写。各处只说自己不同的那一点：空名能不能要（`required`：标签页与视图不要——Enter 不动、离开放回原名；面板要——空标题即回到按视图起名），此刻能不能收（`held`：管理器有写入在途时 Enter 与 ✓ 等着、离开也不关），Enter／Esc 之后键盘回哪里（`returnTo`：面板回它的「⋯」；标签栏自己把键盘还给那一页的按钮），框里要不要 ✓／✕（`answers`：管理器的一行要，因为改名时那一行别的按钮都退场了）。它在挂上的那一刻就拿到键盘，与打开它的菜单项同一次提交：菜单随后收起时键盘已不在菜单里，焦点管理就不把它拿回触发钮（对话框不同，它晚一拍才拿键盘，所以要 U-01 的 `DialogMenuItem`）——标签栏的普通菜单项与面板菜单都成立（浏览器里「TabsBuilt」用键盘走一遍）。（见 test/renameInput.test.tsx「RenameInput, one in-place rename」）
- **一个控件加一句话就是一个 `Field`**（shadcn forms 规矩）：标签 `FieldLabel`（屏幕上的词就是无障碍名，不再挂 `aria-label`），成组的勾选框与单选 `FieldSet` + `FieldLegend`，说明 `FieldDescription`，拒绝 `FieldError`。无效态两处都写：`data-invalid` 在 `Field` 上，`aria-invalid` 在控件上。一个词命名多个控件时（`ColumnRow` 的列名）各控件自带 `aria-label`、共用一条 `FieldDescription`。

## 主题、弹层与明暗

- 弹层经 Portal 渲染到根之外，所以本包组件一律从 `ui/popups.tsx` 引入各 `*Content`：它给弹层加上 `fve-root` 类与所在面的主题（钉住的值或解析出的跟随结果），并把 `z-index: var(--fve-popup-z-index, 50)` 写在 **positioner** 上（D11：positioner 自成 stacking context，内容里的 `z-50` 出不去）。六个弹层照 registry 的结构自己组装 Portal／positioner／popup；`test/popups.test.tsx` 与 vendored 那份逐字比对类名与结构，有意的不同只有两处且按名归一化：破坏性对话框的遮罩与边（`forceRender`、`ALERT_DIALOG_BACKDROP_DIM`、`ALERT_DIALOG_RAISED`），与 Popover 的两个滚动类（`PopupKind.adds`）。`RecordWorkbench.test.stories.tsx` 的 `PopupsOverRaisedHostLayer` 在真浏览器里验层级；`architecture.test.ts` 守住引入规则。
- 明暗只有一套判定：`dark:` 变体与 token 用同一组选择器——`.fve-root[data-theme='dark']`、`.dark .fve-root:not([data-theme='light'])`，外加 `.dark .fve-tokens` 下不归某块面管的后代。宿主用祖先上的 `.dark` 让视图跟随，`ViewSurface` 的 `theme` 用 `data-theme` 钉住；`verify-package` 断言两处集合一致。
- **`theme="system"` 跟随系统**（阶段 5，Q43）：面用 `useSyncExternalStore` 活读 `prefers-color-scheme`，把答案写成与钉住时同一个 `data-theme`。方案原想在样式表里多一组 `@media (prefers-color-scheme: dark)` 包裹的根，那要把暗色 token 块与 `dark:` 变体各抄一份、`verify-package` 再多守一对；写成属性后样式表一个字不动，弹层、图表与观察者看到的就是普通的钉住，首帧在渲染时读出、没有闪烁。代价：它只在 React 渲染出的面上成立，`fve-tokens` 没有它（它本来就不钉明暗）；平台答不出（没有 `matchMedia`、服务端渲染）时按亮色。宿主的 `.dark` 管不到它：读者要的就是系统。（见 test/styleBoundary.test.tsx「a surface that follows the system」，test/chartTheme.test.tsx「redraws when the system it follows turns dark (5B)」）
- **预设是另一个入口里的一组值**（阶段 5，5B）：`/themes.css` 里每套预设是一个 `:where([data-fve-preset='<名>'])` 块，只给 `styles.css` 已经读的 `--fve-*`／`--fve-dark-*` 赋值，不画东西、不分明暗——明暗仍由上面那组选择器决定，预设只供两半的值。三条规矩由 `verify-package` 在构建产物上断言：块只能是这个形状、只能赋 `--fve-` 变量、不能有 at-rule；每套赋的变量集合相同，等于两个 token 块读的全部 `--fve-*` 减去图表八色（Q47，系列跨预设保持身份）、`pin-shadow`（由明暗定）与 `text-ui`（宿主的排版），所以一套套在另一套里时整套换掉；`neutral` 就是样式表自己的值，全部写 `initial`（变量回到未设，token 落回 `styles.css` 旁边写着的内置值），内置值仍只有一处。`:where` 不占特异性：宿主在同一元素（它的 `:root`）上自己写的 `--fve-*` 总赢过它选的预设，而预设总赢过只是从祖先继承来的值。宿主挂在 `<html>` 上，所有面与 portal 到 `<body>` 的弹层都继承。**挂在子树上也送得到弹层**：面从自身往上找最近的 `data-fve-preset`（或用 `preset` 属性钉住，工作台、`EmbeddedView`／`EmbeddedDashboard` 都透传），经 `useSurfacePreset()` 交给 `ui/popups.tsx`，弹层与遮罩照抄这个属性，做法与 `data-theme` 一样——方案里记的「子树上的预设管不到弹层」因此不再是限制；宿主只换了元素上的 `style` 变量、不设属性的，仍只有 `<html>` 上的能到弹层。5B 用一套只在测试与 story 里的预设验机制。（见 test/styleBoundary.test.tsx「a preset reaches the surface and its popups」，test/chartTheme.test.tsx「redraws when the preset pinned on its surface changes (5B)」，浏览器故事「数据视图/主题/回归」的 `PresetPinnedReachesPopups`、`PresetOnPartOfThePage`、`NeutralUnchanged`）
- **内置三套预设**（阶段 5，5C；D30 Q42、Q47）：`neutral`（默认，全部 `initial`）、`blue`（neutral 的灰配 shadcn `blue` 主题的主色）、`slate`（灰阶逐档换成 Tailwind slate，主色取补偿控制台的 blue-600）。与 neutral 相同的值一律写 `initial`，neutral 的值只在 `styles.css` 一处。取舍三条：两套的暗色 `primary` 取 blue-400 而不是 shadcn 的 blue-800——`primary` 也写字（单元格链接、默认视图的星标）、也是表示状态的填充（勾上的复选框、侧栏里打开的那一项的竖条），blue-800 在暗色卡片上约 2:1；`input`／`ring` 不改成品牌色，仍是调到 ≥3:1 的那档灰（`slate` 只把灰换成同亮度的冷灰），这是 shadcn 主题本身也不动的两个；状态色与图表八色三套共用。每套 × 每种明暗的每一对（正文在页、卡片、弹层、表头带、悬停行上；各 `-foreground` 在自己的填充上；`primary` 作字与作填充；侧栏；状态色作字与作徽章——10% 同色淡底叠在四种行底上；控件边与焦点在各种底上，暗色另加 `bg-input/30` 的底）都由单测按两份样式表解析出的值量：字 ≥4.5:1、控件边与焦点 ≥3:1。（见 test/presetContrast.test.ts、test/paletteInk.test.ts「every palette slot has an ink that reads on it」，故事「数据视图/主题/预设」）
- **暗色状态色是安静的**（阶段 5，Q44，结清 D18 第 12 条）：暗色 success／warning／destructive 原是 Tailwind 400 档，chroma 0.19～0.21，软徽章在深底上发艳。三者保留色相、chroma 降到 0.15；success、warning 保留原亮度，destructive 从 0.704 提到 0.76，于是 danger 徽章在选中行上直接用自己的 token 就有 5.48:1（neutral 暗色；各套中最紧的是 slate 暗色的 5.37:1），`variants.tsx` 里只为暗色写的 `color-mix` 补丁删掉。亮色状态色不变。（见 test/presetContrast.test.ts「the dark status colours are desaturated (Q44)」，浏览器故事 `ToneBadgeInkInDarkTheme`）
- **面不嵌套**：CSS 没有「最近祖先」选择器，内层根的 token 是自己的，`dark:` 认的却是外层根，钉成相反模式就是浅色 token 配深色 utility。`test/styleBoundary.test.tsx` 钉住：嵌套时 `useSurfaceTheme()` 说 light、utility 却是 dark；`fve-tokens` 里钉成 light 的面从 token 到 utility 都是 light。
- **宿主拿本包原语画自己的 chrome，戴 `fve-tokens`**（D17-10）：读祖先上的 `.dark`；不读自己身上的 `data-theme`／`.dark`；不涂底、不发 `MessagesProvider`／`TooltipProvider`、不当弹层的根；其下的面自己判断明暗，所以暗色宿主里钉成亮色的视图是对的。样板是 `stories/view-engine/EmbeddedView.stories.tsx` 的假宿主页。嵌入视图放在卡片上时，宿主在那张卡片上把 `--fve-background`／`--fve-dark-background` 设为卡片色（暗色下 `--card` 比 `--background` 亮一档）；不设成 `transparent`——行、冻结列、悬停色与危险按钮的字都用 `--background` 画。（见回归 story「OnTheCardInTheDark」）
- **动效让给 `prefers-reduced-motion: reduce`**：`styles.css` 里一条媒体查询、两个边界都点到，把时长削到 `0.01ms !important`（削到零会让靠退场动画卸载的 Base UI 弹层卸不掉）。`[data-slot='spinner']` 与 `[data-slot='skeleton']` 排除在外：停掉它们是把「进行中」画成「卡住了」。`RecordWorkbench.test.stories.tsx` 的 `ReducedMotionIsHonoured` 量规则本身。**图表也让**：`ui/charts/motion.ts` 的 `useChartMotion` 活读这个偏好给每张图的 `animation`（ECharts 的 option，D21），平台答不出就照常动；单测按「少动」跑（`test/setup.ts`）。（见 test/chartMotion.test.tsx「useChartMotion」）
- 每个 token 读 `--fve-<token>`（暗色 `--fve-dark-<token>`）并以内置值兜底，宿主在 `:root` 上赋值即可，portal 弹层同样继承；`--fve-popup-z-index` 抬所有弹层。根默认涂 `--background`，宿主要透出底色就把 `--fve-background` 设为 `transparent`。（见 test/popups.test.tsx「popups carry the theme out of the root」「a dialog themes its backdrop as well as its surface」）
- **图表跟着 token 重读，不只跟着明暗**（阶段 5，5A）：图表库拿的是读回来的具体 `rgb()`（D21），级联送不到它，所以要有人告诉它重读。`ViewSurface` 的观察者盯着根与每一层祖先上的 `class`、`data-theme`、`data-fve-preset` 与 `style`，每次变动在根上读一遍图表读的那些 token（`charts/theme.ts` 的 `CHART_TOKENS`，加上两种底色 `--background`、`--card`），读数变了才经 `useSurfaceTokens()` 往下送；`EChart` 以明暗和这份读数为依赖重读、就地重画，不重挂载。从前只依赖明暗：宿主换一套 `--fve-*`、明暗不变，其余界面换了，图停在旧色上。只换样式表、不动任何属性的切换观察不到，README 写明「换主题请改属性」。`readChartTheme` 读不到样式表时（jsdom）用的兜底色 `CHART_FALLBACK` 是亮色 token 的第二份拼写，由测试逐值对齐 `styles.css`（它第一色位曾漂在调色前的那一档上）。（见 test/chartTheme.test.tsx「redraws when the host swaps its tokens and the mode stays」「falls back to the stylesheet’s own light tokens」，浏览器故事「分析视图/图型/回归」的 `ChartFollowsHostTokens`）
- **一个没人读的 token 是一份没人守的合同**：两个 token 块里声明的每一个都要有读者（一处 `var()`、或注册成颜色后的一个 utility），`--info` 因此删掉（阶段 5 Q45）——info 语气的 callout 用页面自己的安静灰 `text-muted-foreground` 与 `border` 边，黄与红留给真有问题的时候。能从别的 token 推导的就推导：`--quiet-foreground` 是 `--foreground` 的七成（`color-mix`），`--destructive-foreground` 是 `--background`，宿主只改前景或底色它们也跟着走；宿主仍能单独覆盖。（见 test/styleBoundary.test.tsx「the tokens the theme declares」，浏览器故事「数据视图/主题/回归」的 `QuietInkFollowsForeground`）
- **`--ring` 与 `--input` 是独立的值，不指向品牌 token**：shadcn 品牌主题的惯用写法 `--ring: var(--primary)`、`--input: var(--border)` 会把 1.4.11 要的 3:1 交给一个品牌色和一档分隔线灰。本包两态都给它们自己的灰（测试钉住它们不引用 `--primary`／`--border`／`--accent`／`--secondary`／`--muted`），宿主改 `--fve-primary`／`--fve-border` 动不到焦点与控件边；宿主自己覆盖 `--fve-ring`／`--fve-input` 就欠自己的主题同一条线，README 的 token 表下写明。（见 test/styleBoundary.test.tsx「keeps the focus ring and the control edge off the brand tokens」）
- **Popover 有滚动口**：比 registry 多 `max-h-(--available-height)` 与 `overflow-y-auto`——本包在 Popover 里开与字段一样长的列表，portal 出去的弹层不跟页面滚。
- **控件的边画 `--input` 而不是 `--border`**（`Checkbox`／`RadioGroupItem`、`Input`、`Select` 触发器，以及 `outline` 档徽章）：「边就是控件」按 WCAG 1.4.11 要 3:1，两个主题都钉在 ≥3:1（浏览器故事 `ControlBordersInLightTheme`／`ControlBordersInDarkTheme`、`OutlineBadgeEdgesInLightTheme`／`InDarkTheme`）；宿主覆盖 `--fve-input` 时同样欠这一条。徽章那条在 `styles.css`（面上无条件），问 `group/badge` 加 `data-variant` 而不问 `data-slot`——调用处的同名 prop 会顶掉 `data-slot`。
- **焦点只有一种画法**：vendored `Button` 的 1px `border-ring` 加 3px `ring-ring/50`。表头排序与已应用条的 ✕ 都是 `Button variant="ghost"`（✕ 是 `size="icon-xs"`，点击目标 24px），不另抄配方。`--ring` 两主题 ≥3:1（`FocusIndicatorsInLightTheme`／`InDarkTheme`）；暗色 `--border` 让行线 ≥1.5:1（`DarkHairlines`）。一块能滚、因此是 Tab 站的区域若与裁掉溢出的容器一样宽（仪表盘面板的正文），同一套画在边里（`variants.tsx` 的 `FOCUS_INSET`）：画在外面会被裁得只剩一条灰线（[dashboard.md](dashboard.md) 面板 chrome）。**记录行与卡片也是这一套**（阶段 5，5A）：行（`FOCUS_ROW`，画在每一格上）是一条全强度 1px `--ring` 内边加里侧的半强度光晕，卡片（`FOCUS_CARD`）是收进卡片边里的 1px `outline-ring` 加外侧的 3px 光晕。从前两处只画半强度光晕，浏览器里量到亮色 1.74:1（行）／1.77:1（卡片）、暗色 2.38:1／2.15:1；现在亮色 3.49:1／3.64:1、暗色 5.73:1／5.76:1。（见浏览器故事「数据视图/主题/回归」的 `FocusMarksInLightTheme`／`FocusMarksInDarkTheme`）
- **会开对话框的菜单项把键盘交出去**（`ui/HandOffMenu.tsx`）：菜单收起时把键盘还给触发钮，而它收起晚于对话框打开，键盘就被拿回模态对话框后面。一个菜单里有项会开对话框（或一出现就要键盘的东西）时，它是 `HandOffMenu`＋`HandOffMenuContent`，那几项是 `DialogMenuItem`：选了它，菜单收起时不动键盘；其余项与 Esc 照旧还给触发钮。对话框关上时还给哪颗，仍由它自己的 `finalFocus` 说。今天用在仪表盘的添加菜单与面板菜单（[dashboard.md](dashboard.md) 的「添加」）。
- **按下去把自己拿走的控件，键盘落到下一个说得通的地方**，不掉到 `body`：列表里用 `useListFocus`，仪表盘的撤销用 `land`，筛选条用 `ui/dashboard/landing.ts` 的 `useLanding`（按下时说落在哪，拿走它的那次渲染之后再落；只在键盘真的掉了时才挪）。各处落在哪见 [dashboard.md](dashboard.md#筛选d22-fg批-c)。

## 字段目录与选择器分组

- 列出字段的三个选择器（添加条件、列选择、分析的分组与指标）都经 `fieldGroups(fields, definition.fieldGroups, key)` 分组：未被任何分组列出的字段在前、无标题，其后按目录顺序列出各分组并带标题，组内按该分组自己的 `fields` 顺序；
- **列设置有两条自己的读法**（[record.md](record.md#列设置的目录分组与搜索)）：目录只嵌在中间区里，组内的行按表格画的顺序排——这份列表本身就是列序；
- 没有字段的分组不显示。目录声明在 `DataViewDefinition.fieldGroups`（`{ id, label, fields }[]`），字段本身不记录归属，组序与组内序不被字段顺序绑住（字段顺序决定默认列序）；列了未声明的字段或把一个字段列进两个组都在定义准入时报错。Dashboard 的全局字段与元素字段不分组。

## 版式：三块、一套间距、一种选项控件

五条规则，后来的改动按它们判。落到代码上是 `ui/layout.ts` 一处（`SPACE`、`TRAY`、`TEXT_UI`）。

- **主列是三块，不是一摞行**。视图头是 banner：一条 `border-b`，不做卡片，以 `-mx-4 px-4` 通到工作区边，与侧栏头下那条线（`view-list-header`）接成一条。条件区是托盘（`TRAY`：`rounded-lg bg-muted/40 p-3`，不加边——pill 才带边）；结果块是一条贴边的带（2026-09-23 起：顶上一条 `border-t`，左右与底以 `-mx-4 -mb-4` 穿过工作列的内边距、就是工作区自己的边，无内边距）。块只在有内容时才存在，空卡片是空头承诺。仪表盘以 `resultFramed={false}` 退出。
- **间距是有级差的尺子**：块与块 16px（`SPACE.BLOCKS`）、行与行 12px（`SPACE.ROWS`）、控件组之间 8px（`SPACE.GROUPS`）、组内 4px（`SPACE.WITHIN`）。主列的块间距归外壳（`WorkbenchShell` 发给 `<main>`），工作台不往 `className` 塞自己的 `gap-*`——`cn` 让调用处赢。vendored 组件不在尺子上的间距在调用处合缝。分析托盘同尺：槽与槽 `SPACE.ROWS`、两列之间 `SPACE.BLOCKS`、卡片之间 `SPACE.GROUPS`。（见 test/recordWorkbench.test.tsx 与 test/analysisTray.test.tsx「steps the tray’s rows by the ruler」，故事 `BlockSpacing`、`EditorRowSpacing` 量像素）
- **字号只有三档**：13（`TEXT_UI`）、14（`text-sm`）、16（`text-base`，定义名）。12 与 12.8 不成级差，12.8 又不落像素栅格，所以并成 13px：`styles.css` 的 `--text-ui`（`var(--fve-text-ui, 0.8125rem)`）；vendored `sm` 控件的 `text-[0.8rem]` 与 `Badge` 的 `text-xs` 由一条作用域规则钉到它上面。真正低一级的 12 只留给图表里面的标签、vendored 菜单的分组标题与快捷键、`AND`／`OR` 代码字样。（见 stories/view-engine/RecordWorkbench.test.stories.tsx 的 `TypeScaleIsThreeRungs`）
- **一屏只有一个 primary，它是跑查询的那一个**（D17-3）：编辑带底部的 Apply。两颗调同一个 `runtime.apply()` 的按钮回答不了「哪一颗跑查询」，所以分析托盘也只有一颗应用。宿主的全局动作不用 primary（见[动作槽位](#动作槽位)）。（见 test/analysisTray.test.tsx「carries one primary button on the screen, and it is Apply」）
- **互斥选项是一个控件，不是一排按钮**：≤3 个短选项用分段控件；一句话或多于三个用 `Select`；同一职责的几个动作用 `ButtonGroup`；主动作带变体用拆分按钮（`SaveActions`）。分段控件是 `ToggleGroup spacing={0}`（registry 自带的合缝规则，传 prop 不算改 vendored）；`sm` 组的外角由 `styles.css` 按 `[data-size='sm'][data-spacing='0']` 钉回 8px。（见 test/resultToolbar.test.tsx「ResultToolbar grouping and weight」）
- **registry 没有的组件，往下一层拿 Base UI 原语**，形制照 `ui/popups.tsx`：只加 `data-slot` 的薄包装。目前只有 `ui/toolbar.tsx` 包 `Toolbar`，结果工具栏借它拿到 `role="toolbar"`、`aria-orientation` 与漫游焦点（[record.md](record.md#resulttoolbar-的三组)）；`ToolbarItem` 在工具栏里是 `Toolbar.Button`，不在时原样渲染。解决不了问题的不换（`Toolbar.Group` 之于 `ButtonGroup`）。

## 工作台骨架

- 骨架自上而下（[decisions.md#D12](../decisions.md#d12-一屏七块每块只回答一个问题)）：**标题栏 → 状态行 → 筛选托盘 → 结果条件带 → 结果块（工具栏 → 结果 → 汇总 → 分页）**，每块答一个问题，一个问题只在一处答。`ViewHeader` 一行说清这是哪个视图：种类图标、视图名、受众（`data-slot="view-audience"`，窄于 `@md` 时只留给读屏）、存没存过的标记（`label.header.new-view`／`label.header.unsaved`），保存紧跟名字；写入结局（`WriteOutcome`）落在标题栏下一行。**状态行**（`data-slot="status-line"`，`empty:hidden`）只装 `ErrorStrip`（`filter.unmarked`）与 `WarningStrip`；只有一条 error 时直接说那句，行尾可带出路（`ErrorStrip` 的 `action`，Record 给「打开列设置」）。查询失败是结果块的状态（`QueryStrip` 在 `strips` 槽，见 [record.md#结果块有结果才有工具栏是第一行](record.md)）。`EditorBand` 是编辑器的折叠带：已保存的视图打开时折起（结果才是要看的），没存过的展开；状态属于这一次打开，以 `runtime.id` 重置，不入库。（见 test/editorBand.test.tsx「EditorBand」与 test/viewHeader.test.tsx「ViewHeader」）Analysis 的编辑器也在这条带里（[analysis.md#托盘范围--维度--指标--结果一个应用](analysis.md#托盘范围--维度--指标--结果一个应用)）；Dashboard 只接标题栏、状态行与结果条件带。
- **搜索常驻在已应用条的末端**（`ui/workbench/SearchBox.tsx`，`useSearchBox`）：定义有 `search` 字段时，「正在显示 …」一行的右端是一个搜索框——搜索本身就是那些条件之一，这一行有整行宽度（放在标题栏会把标题栏挤成两行）；窄到放不下时整体换到下一行。框以搜索字段的显示名命名；输入只改草稿，**Enter 才应用**（输入法组字时的 Enter 不算，`isPlainEnter`），✕ 拿掉搜索并重新查询；`type="text"` 加 `role="searchbox"`（WebKit 会在 search 输入框里再画一个 ✕）。出不出现由定义决定，宿主可用 `features.search: false` 关掉，关掉后搜索仍是编辑器里能加的条件。记录与分析视图都有。（见 test/searchBox.test.tsx「the search box」）
- **下钻出的视图多一行「来自」**（`ui/workbench/OriginBar.tsx`，`data-slot="origin-bar"`，`role="region"`）：「返回 {来源}」、「来自 {来源}」与下钻加上的条件（同 `summaryText`）。它是工作台的事实（`workbench.held.origin`），返回走 `workbench.back()`。
- **左侧栏的第二个占用者：`panel` 槽**（`data-slot="view-panel"`）：给了就画它而不是视图列表。目前只有分析的可视化面板（[analysis.md#可视化结果工具栏呼出左侧栏先选图型](analysis.md)）——配图时不需要导航，结果区一格不动。槽按 React 读孩子的规矩读，`false` 就是「现在不要」。（见 test/chartPicker.test.tsx「the visualization panel」）
- 骨架由 `WorkbenchShell` 画，几个工作台共用；外壳自己画刷新拆分按钮、查询失败条（仪表盘传 `strips={null}`）与 warning 条（视图 issues 加 `resultIssues`）。一种视图只交独有的槽位（`ui/workbench/parts.ts` 的 `WorkbenchParts`）：侧栏（`ViewList`，`manager` 只在 `manager.can.anything` 时交出）、`LeaveDialog` 与主列。主列：打不开时是「无法打开」；没有视图可开时是同一形制的「还没有视图」（`ui/workbench/NoViews.tsx`，带「新建视图」，失败时换成失败那句，无创建权限时只有标题）；否则 `ViewHeader` → 状态行 → `editor` → `AppliedBar` → 结果块（`toolbar` → `strips` → `result`）。块画在 `ui/workbench/`：`Sidebar.tsx`（`SidebarColumn`、`FoldedSidebar`）、`TitleBar.tsx`、`StatusLine.tsx`、`ConditionBlock.tsx`、`ResultBlock.tsx` 的 `ShellResult`。
- 结果块只在有结果、有在途请求、或 `strips` 真会画东西时才存在（`resultBlockShown`）。**正在打开**（`opened.loading`）时主列是 `ui/workbench/OpeningSkeleton.tsx`：形状与打开后一致的标题栏与结果块骨架；整块 `aria-busy="true"`，里面一句 sr-only 的 `role="status"`（`label.workbench.opening`），其余 `aria-hidden`——`aria-busy` 不挂在活区上，否则那句永远播不出。
- props 是 `{ workbench, kind, title, theme?, messages?, locale?, timeZone, actions?, freshness?, editor, editorLabel?, editorModes?, editorOpen?, defaultEditorOpen?, onEditorOpenChange?, editorPending?, toolbar?, strips?, result, errorAction?, defaultSidebarOpen?, onSidebarOpenChange?, expandable?, hasResult?, resultPending?, warnings?, onRenderFailure?, className? }`；`hasResult`、`resultPending`、`warnings` 留给 Dashboard 覆盖。其余读自 `WorkbenchController`（[react.md#useworkbench](../react.md#useworkbench)），只有三样由外壳持有：**侧栏收起、编辑带展开、视图铺满**——只属于此刻这一屏，不入库。铺满决定侧栏折不折，所以前两者合在 `ui/workbench/useWorkbenchFolds.ts`；编辑带在 `ui/workbench/useEditorFold.ts`。
- **结果区是一条贴边的带，只在顶上画一条线**（D12 Ⅳ–Ⅶ，2026-09-23 用户按推荐改定，推翻 2026-09-21 的「一圈边」）：`ResultBlock` 是 `border-t -mx-4 -mb-4 overflow-hidden`——左右与底穿过工作列 16px 内边距，贴着工作区自己的边（与标题栏那条 `-mx-4` 的线同一种做法）。那圈边当初是为了在结果区可能停在半屏时把工具栏、行与分页圈成一件事；工作台填满容器、结果块到底以后（[record.md](record.md) 的「工作台永远填满它的容器」），它的左右下三条边只是在重画工作区自己的边，框里套框，还白占 32px 宽、16px 高。顶上那条线仍在说一件事：条件到这里为止、结果从这里开始。无内边距；留白按槽位给，与工作列的 16px 对齐——`[data-slot=result-toolbar]` 第一行（`border-b px-4 py-2`），末行（`[data-slot=record-pagination]`）`border-t bg-muted/40 px-4 py-2`，状态条 `mx-4 my-3`，空态 `my-6`，卡片 `p-4`，表格通到边、不画自己的外框。配方按作者分家：外壳填的 `toolbar`／`strips` 在 `resultFrameChrome`；某一种视图的家具由那种视图交进来（`resultSlots('caption','empty','cards')` → `WorkbenchShell.resultSlots`，见 [record.md#结果块](record.md#结果块有结果才有工具栏是第一行)），共用的外壳不长 `if`。（见 test/workbenchShell.test.tsx「the result block」，故事 `BlockSpacing`／`QueryFailed`）
- **「无法打开」与空结果同一副形制**：`Empty` + 图标 + 标题（`label.view.unopenable`）+ `Issue` 作描述 + 「回到默认视图」（`label.view.open-default`，`workbench.choose(list.defaultInstanceId)`，只在默认视图是另一个时才画）——通常只是某个视图不在了，不是应用坏了。保留 `role="alert"`。外壳也给这一屏 `@container/header`，定义名照常显示。切换器此时的标签与可及名都是「选择视图」（`label.workbench.choose-view`）。（见 test/recordWorkbench.test.tsx「offers the default view as the way out of one that cannot open」、test/sidebarCollapse.test.tsx「collapsing with nothing to switch to」，故事 `CannotOpen`）
- **两级标题**：定义名是 `h1`——侧栏标题（`view-list-title`），收起时是标题栏 `leading` 里的 `definition-title`（后跟灰色 `/`，与切换器连成「订单 / 待出库订单」）；视图名是 `h2`（`headingLevel` 可定级）。收起只挪 `h1` 不降级：`definition-title` 16/600，切换器的视图名 14/500（`text-sm` 写在调用处，`cn` 合并掉 vendored 的 `text-[0.8rem]`）。（见 stories/view-engine/TitleBar.test.stories.tsx 的 `CollapsedPathIsTwoLevels`）`main` 以视图名的 id `aria-labelledby`，只在标题在屏幕上时才指。（见 test/accessibility.test.tsx「the open view names the region it is drawn in」）
- **标题栏两组，之间不串**。左组 `data-slot="view-identity"`：`leading`、种类图标、视图名、受众、未保存标记与 `SaveActions`——保存改的就是这个名字底下的配置。视图名 `w-0 max-w-max min-w-[6em] grow`，受众与保存紧贴名字。右组 `data-slot="view-controls"`：先是框架功能（编辑带开关、刷新 `freshness`、铺满），一根竖线之后是宿主的全局动作——永远排最后，用 `outline` 而非 primary（[动作槽位](#动作槽位)）。那根线分两种作者，是这块面上唯一非看见不可的分隔线，所以是 `SectionDivider`（注册表 `Separator` 的 `--border`、20px、`self-center`）：它靠高过组内间距被读出来，不靠更黑；不用间距代替，因为这一行只有 8px 一档，16px 的空档读起来像换行。（见 stories/view-engine/TitleBar.test.stories.tsx 的 `TitleBarDividerInLightTheme`／`InDarkTheme`）功能一律是带边的图标按钮，只有同时报告状态的才带文字（编辑带的当前模式、刷新的当前间隔）。
  - **还原在「已修改」标记上**（`UnsavedMark`，`data-slot="view-unsaved"`）：那个词加一颗 ↺（「还原」，写入在途或结局未结清时禁用）；从没存过的视图只有「尚未保存」。按下先问一句——运行时只能放回已保存那份，「撤销」许诺不出来——与切视图同一形状（`AlertDialog`、`DestructiveAction`、`label.revert.*`）；答完焦点落在视图名上（`finalFocus`）。保存菜单因此只剩「另存为」。（见 test/viewHeader.test.tsx「ViewHeader, taking the edits back」）**只改了展示时分开说**（[D23](../decisions.md#d23-搁置待议的六条拍板2026-09-23) Q15）：草稿与保存的只在展示成员（布局、图，`presentationMembers`）上不同时，那个词是「只改了展示」（`label.header.unsaved-look`，`data-look-only`），↺ 不问、一步放回保存的样子——丢的是一种看法，不是一个问题；放回也不发查询，展示的修改从没进过 `applied`。判定是 runtime 的 `presentationOnlyEdits`。（见 test/analysisUi.test.tsx「says only the look changed, and takes it back in one press」、test/presentationOnlyEdits.test.ts）
- **标题栏窄下来时只有名字让步，让步有下限**。「一组一根弹簧」：每组按内容定尺寸，恰好一个成员会缩——`view-identity` 里的视图名（`w-0 min-w-[6em] grow`），收起侧栏后是 `view-collapsed` 里的 `ViewSwitcher`（`w-0 min-w-[calc(6em+3.25rem)] max-w-fit grow`）。`view-header` 带 `flex-wrap`，放不下时右组整组换行；`view-controls` 带 `ml-auto`。
  - `min-w-0` 只给真有弹簧的组，否则组报低了，`flex-wrap` 永远不触发，两组叠在一起。`truncate` 做不到：不折的一行仍按整串文字要宽度；`w-0` 让组把名字算作零，`grow` 再把余量给它。
  - 下限 6em 同时是那一组向上报的数，所以识别组要不到 6em 时右组换行。下限写在「按整串文字向上要」的元素上：`view-title` 自己；切换器则是按钮（名字在带 `white-space: nowrap` 的 `span` 里），6em 加图标、gap、chevron 与内边距（`3.25rem`）。
  - 被截断的名字带全名：`h2` 外面一个 `Tooltip`，触发器就是 `h2` 本身。（见 test/viewHeader.test.tsx「carries the whole name it may have to truncate」）
  - 缩无可缩时先按**栏宽**退化（`view-header-band` 是 `@container/header`）：窄于 `@md` 时受众只留图标、`SaveActions` 的词进 `sr-only`，窄于 `@2xl` 时定义标题不画。还放不下就老实溢出，不互相盖住（回归 story「标题栏/回归」逐档量 `getBoundingClientRect()` 与 `elementFromPoint()`，只能在浏览器里跑）。
- **只有图标的按钮把名字挂在 hover 上**（D12）：`aria-label` 与 tooltip 是同一个字符串。配对只在 `ui/IconButton.tsx`：`IconButton` 管常见形状，触发器已是按钮时用 `IconTooltip` 原样收下（`DropdownMenuTrigger`、`ToggleGroupItem`、chip 的 `<button>`）。状态变，名字跟着变（「铺满屏幕」／「退出铺满」）。拖动途中把手静音用 `Tooltip` 的 `disabled` 而不是受控 `open`。标签在上、菜单在下（故事 `AMenuIsNotCoveredByItsOwnTooltip`）。外层触发器的 `data-slot` 盖掉里层的，所以带 tooltip 的菜单触发器按 `aria-haspopup` 找。`test/iconTooltips.test.tsx` 要求三个工作台及其弹层里凡没有文字的 button 都带 tooltip 印记。

- **哪些控件存在，宿主说了算**（D18 Ⅺ）：`features`（`ui/features.ts` 的 `WorkbenchFeatures`：`export`／`layouts`／`columns`／`sort`／`visualization`／`manage`／`search`，缺省全开）；关掉的一项**不存在**而不是置灰（D4）。`manage` 三个工作台都认（`WorkbenchShell.manage`），前四项在 `ResultToolbar.features`（列设置关掉时卡片设置也关），`visualization` 在 `AnalysisParts.features`（按钮与面板一起不存在）。能不能做是 store 的 `ViewPermissions`，另一个问题。记录视图另有 `emptyAction`：不传是工作台的答案（有条件就清空、没有就展开编辑带），传函数是宿主的，传 `null` 没有按钮。（见 test/features.test.tsx）
- **视图能铺满屏幕**：`ViewExpandToggle`（`data-slot="view-expand"`，`aria-expanded`，`label.workbench.expand-view`／`collapse-view`——不叫「全屏」）在标题栏右组。状态归 `WorkbenchShell`，不入库；工作台透传 `expandable`（默认 true）。规则：
  - **就地展开，不是 portal**：`useViewExpansion(target, toggleRef, enabled)`（`ui/ViewExpansion.tsx`）只在 `closest('.fve-root')` 上写 `data-view-expanded`——重新挂载会丢草稿、选择、滚动与 IME，还会离开宿主的 `.dark` 祖先。`ViewSurface` 合并调用方的 `ref`，并透传 callback ref 的清理函数。
  - **不用 top layer**（`requestFullscreen()`、`popover="manual"`）：portal 到 `document.body` 的弹层会落到它后面。面取 `z-index: 0`，自成 stacking context 但不高出一级——盖住宿主普通内容，宿主刻意抬起的东西仍在上面；弹层自带层级（D11）。
  - **`position: fixed` 不等于视口**：带 `transform`、`filter`、`contain`、`container-type` 等的祖先会成为 containing block。所以**量**：面上去后读 `getBoundingClientRect()`，差值写回 `--fve-expanded-x/y/w/h`（兜底即 `inset: 0`），`resize` 时重算；祖先缩放时再量一次，用「要的与到手的之比」除掉 scale（故事 `FillTheScreenInScaledHost`）。祖先裁剪、祖先的 stacking context 高过弹层、祖先旋转或斜切这三种治不了，宿主应把工作台放到那个容器外。
  - **不是模态**：没有 `aria-modal`、不困焦点、不设 inert——内容还是宿主 DOM 里的那些，声称模态是我们无权做的承诺。`test/accessibility.test.tsx` 在两种状态下都跑 axe。只借一样：背景不滚。锁写在 `document.scrollingElement` 上，按 important 写，两个轴（`overflow-x`／`overflow-y`）分开存、分开还；按 `document` 计数，几个面同时铺满时最后一个收起的才还；卸载走同一条清理路径。
  - **Esc 收起，但前面有东西时轮不到它**：对话框、菜单、列表框、原生 `<dialog open>`、焦点停在 `data-popup-open` 触发器上的、`defaultPrevented` 的、以及输入法组字中（`event.isComposing` 或 `keyCode === 229`）都先于它。判定用事件自己那个文档的 `Element`（iframe 里的 `instanceof` 才对）。几个面同时铺开时按文档顺序判谁在前。收起后焦点交给仍在前面的那个面身上的控件（开关不在面里时是它的出口），都收完才回到自己的按钮；按钮带 `aria-keyshortcuts`（只在铺着时）。
  - **控件没了，铺满就结束**：`enabled` 转 false 时在渲染里清掉状态（不进 effect，免得先画出一个没有出口的面）；`enabled` 为 false 时 `toggle` 不做事。工作台传 `expandable && (open || opened.loading)`：切换视图的加载中不结束（铺满是工作区的姿态，Q7），切到的视图打不开才结束。
  - **目标晚到或中途没了都算数**：`target` 是 `RefObject`，React 填、清都不出声，所以铺着时用 `MutationObserver` 盯 document，解析出的节点变了才重跑。
  - **高度给结果**：铺满时成为定高弹性列——根 `overflow: hidden`，侧栏与主列 `min-height: 0` + `overflow-y: auto`，结果块与 `RecordTable` 的滚动容器 `flex: 1 1 auto; min-height: 0`（后者 `max-height: none`），只作用于自己在滚的那一个（`data-scrolls`；`scrolls={false}` 的不吃）。编辑带与条件块封顶 `max-height: 50%` 并自己滚——这一条不论铺不铺满都生效（2026-09-23 审查，托盘曾把图表挤到约 230px，见 [analysis.md](analysis.md#托盘范围--维度--指标--结果一个应用)）。表格的粘性两种状态都成立（见 [record.md#表格-chrome层次与冻结列](record.md#表格-chrome层次与冻结列)，故事 `FillTheScreen`／`FillTheScreenInTransformedHost`）。嵌入视图没有 `main`，`:not(:has(> main))` 的根拿 `overflow-y: auto`。
  - **嵌入不长自己的开关**（`EmbeddedView`、`EmbeddedDashboard`）：它是结果本身，不为一个按钮造一行 chrome；宿主拿 `ref` 与从 `/ui` 导出的 `useViewExpansion` 放在自己的 chrome 里。开关不在面里时，面自己露出一个出口 `data-slot="view-exit"`（`label.workbench.collapse-view`，平时 `hidden`；点击由持有铺满的面接），占根的 flex 列一行（`order: -1`）并 `position: sticky; top: 0`——触屏上没有 Esc，出口不能被盖住或滚走。（见 test/viewExpansion.test.tsx 与回归 story「FillTheScreen」「FillTheScreenInTransformedHost」）
- 留给扩展的缝：`ViewHeader.leading`／`ViewHeader.trailing`、`data-slot="view-sidebar"`、`defaultSidebarOpen`／`expandable`。

## 刷新是一个拆分按钮

- **主键一次刷新，`▾` 选间隔**（`RefreshControl`，`ui/RefreshControl.tsx`，在标题栏的 `freshness` 槽，三种工作台一样）。主键是名为「刷新」的图标按钮，唯一的文字是离下一次自动刷新还有多久（D12）。两半答同一个问题——屏幕上这些数字怎么更新——所以是一个控件。
- **间隔就是 `ViewConfigBase.refresh.interval`**：选中即 `edit({ refresh: { interval } })` 加 `apply`（D3 的例外，计时器读 `applied`）。它像任何编辑一样让视图变脏，`Save` 才落库；配置里没有第二份间隔。
- **档位三档**（30 秒、1 分钟、5 分钟），只留整数且落在 `runtime.limits` 的 `[minRefreshInterval, maxRefreshInterval]` 里的（与 `validateRefresh` 同一判断）；不允许的**不存在**（D4）。选中的那个跑得起来就并进梯子，跑不起来不并——菜单给的是出路。`▾` 只在梯子空、没有在跑的间隔、`refresh` 也没被准入报错三者同时成立时不给：正在跑的间隔要有地方关，被拒的 `refresh` 要够得着修法 `{ interval: null }`——**报了错的那一项，一定够得着**。
- **凭据在走**：计时器武装着时按钮写剩下多久（`30s → 29s → …`），刷新时换成 spinner、写 `0s`（清掉字会让旁边的按钮挪位），落地后重数。数的是 runtime 的 `nextRefreshAt`（[runtime.md#自动刷新](../runtime.md#自动刷新)），界面不另起一只钟；`useRefreshCountdown` 只在有东西可数时才跳。单位词 `label.refresh.seconds/minutes/hours`，向下取整到填得满的最大单位，不用 `mm:ss`。runtime 因编辑器有焦点、页面不可见、草稿被拒而停表时，退回那一档本身（`30s`），不冻在一个倒数上。
- **宽度不抖**：凭据是一格 grid，读数之上叠着该档每个单位带最宽的读数（`invisible`），右对齐；单位词是目录的，`min-w-[Nch]` 预测不了宽度。
- **倒计时不念**：整格 `aria-hidden`，主键的 `aria-describedby` 指向只在有间隔时写出的 `sr-only` 句子 `label.refresh.on`，说节奏不说倒数。它是关于视图的事实，不是三态凭据之外的第四个点。
- **凭据读 `applied`，菜单勾 draft**：凭据只跟计时器真正读的那份（同 `AppliedBar` 读 `result.own` 的理由）；菜单勾的是 `Save` 会写下的数。两者只在草稿被拒时分开。
- **停表时机由 runtime 说了算**（[runtime.md#自动刷新](../runtime.md#自动刷新)）。查询在途时只禁用主键；仪表盘的 `state.query` 永远 `idle`，所以读 `dashboard.resolving || dashboard.loading`（与 `DashboardViewRuntime` 的计时器问同一件事）。`▾` 照常可选。（见 test/refreshControl.test.tsx 与 stories/view-engine 的 `AutoRefresh`）

## 三态各有一处凭据

- 三处，不是四处：刷新的 cadence 说「这个视图在自己刷新」（见[刷新是一个拆分按钮](#刷新是一个拆分按钮)），不参与下面这三处说的「屏幕上的东西走到哪一步了」。
- **草稿未应用**是 pill 与应用按钮上的点（`data-pending`），折起时是 `label.editor.pending` 计数。**基准是整份配置**（D17-6，`runtime/pending.ts` 的 `comparePending`：条件按节点比、其余成员各算一项；在 runtime 层因为 `dequal` 与 `revert` 在那里）：只 `edit` 不 `apply` 的控件与 apply 被拒的控件都算「没应用」。`useFilterEditor.pending`／`pendingCount` 读整份配置，pill 的 `isPending(path)` 只比那一节点，「放弃筛选修改」只在条件不同（`conditionsPending`）时出现。超预算的树算一项。**不进查询的成员不算**（筛选的简单／高级、记录视图的表格／卡片——切换即完成；分析的布局当场应用 `setLayout`，因为图表只为跑过的布局整形）：它们由模型声明（`*_PRESENTATION_MEMBERS`，经 `presentationMembers(kind)` 合并），`comparePending` 只读这份清单。
- **已应用**是结果块顶部的 `AppliedBar`，读 `state.result.own.filter` 而不是 `applied`——查询答复之前 `applied` 已走在前面。**还没有任何结果时**（第一次的答案在路上，或第一次就失败了），它读 `state.applied.filter`：屏幕上没有行可以被它说错，而等第一批行落地才冒出来的条件带会把整个结果块往下推（2026-09-23 审查 P1）。何时算「问过了」由 `hasAsked` 一处说（`runtime/viewRuntimeTypes.ts`：有结果、在途、或失败；被拒而没跑的配置不算）。Dashboard 没有自己的结果，读 `state.applied.filter`，是否有结果可描述看面板。
- **未保存**是标题旁的标记，Save 只在 `dirty && can.save && !pending` 时可按。
- AppliedBar 保留树的逻辑：根下每个直接子节点一个 badge，分组合成一个。文字由 `ui/summary.ts` 的 `summaryText` 拼（不用内核的英文兜底 `FilterSummaryItem.text`）：字段名来自定义，操作符走 `label.operator.<OP>`——只有一个值的条件例外，`EQ`／一个候选的 `IN` 说「是」、`NE`／一个候选的 `NOT_IN` 说「不是」（`label.relation.is`／`is-not`；从前同一条上「状态 属于 待出库」与「仓库 等于 华东」读成两种关系，2026-09-23 审查 P2-2），值按[值按字段显示](#值按字段显示)的规则（`cell`、`kind`、`numberFormat` 跟着摘要项走）。相对值区间用 `label.relative.window.<direction>`、边界用 `label.relative.instant.<direction>`，命名时段用 `label.relative.preset.*`；分隔符 `label.filter.join`。
- 分组以操作符词起头（`label.filter.all-of`／`any-of`／`none-of`），嵌套加括号；只有一条时 `all-of`／`any-of` 省略，`none-of` 是否定、总要说。谓词条件（`ELEMENT_MATCH`）同样读出它的条件，空谓词说 `label.filter.any-entry`。值读不出只说字段名（`blank`），字段消失的连操作符一起说。✕ 的可访问名用同一段文字。
- 每个 badge 的 ✕ 把对应条件的值设回未填写并重新应用（`clearValue(path)` + `submit()`），字段行留在编辑器里。
- 没有条件而问过了时显示 `label.applied.all`，什么都还没问时整条不渲染（`AppliedBar` 的 `asked`，外壳传 `hasAsked(state)`，`EmbeddedView` 同）。宿主的作用域条件（`scoped`，`variant="outline"` + `data-scoped`，`label.applied.scoped`）自成一组、不带 ✕——读者拿不掉，也不在 draft 的路径上。**仪表盘不画这一条**（[D27](../decisions.md#d27-仪表盘不画正在显示条2026-09-24)）：它的筛选改了就跑、没有草稿与已应用两态，筛选条就是它的「正在显示」；板子的固定范围在筛选条那一行只读地写作「固定范围」（[dashboard.md](dashboard.md)「筛选」）。再往后是**没人写下却在生效的口径**（`implied`，`data-implied`，读屏附 `label.applied.implied`）：定义声明了 `deletion` 一维而无人作答时，条上说「仅未删除」（D17-2），改口径要把字段加进条件。`EmbeddedView` 整条只读（`readOnly`）。（见 test/appliedBar.test.tsx「AppliedBar」）

## 保存与视图管理

- `SaveActions` 是拆分按钮组：能存就是 Save，否则是 Save as；**从没存过的视图**（`commands.state.isNew`）按 Save 打开 `SaveAsDialog` 的 `intent: 'first'`（「保存视图」，预填名字）——第一次保存就是创建。`pending` 时显示 `label.save.saving`，落地后 2.5s 内显示 `label.save.saved` 并播报一次。
- **就地保存一个共享视图先问一句**（2026-09-23 审查 P1：「保存共享视图一键覆盖所有人的版本」）：`commands.state.audience === 'shared'`（`useSaveCommands` 按 `audienceOf(scope)` 给出）时，主按钮的 Save 打开 `AlertDialog`（`data-slot="shared-save-confirm"`，标题 `label.save.shared-heading`「更新所有人看到的视图？」，描述 `label.save.shared-description`「这会更新所有人看到的「{title}」。」，确认 `label.save.shared-confirm`「更新给所有人」，取消什么也不写）。**不是破坏性的语气**（不用 `DestructiveAction`）：没有丢掉作者不想改的东西，只是受它影响的人不在场，所以要说出来。个人视图照旧一按就存；第一次保存与另存为本来就走对话框，不再加问。（见 test/saveActions.test.tsx「asks before saving over a shared view, naming it」）
- 写入在途或结局 `unknown`／`conflict` 未结清时，还原与菜单一并禁用：否则被保存掉的配置会成为新基线上的脏草稿，或被随后的 Retry／「保留我的」撤回。`hasErrors` 只在主按钮是就地 Save 时禁用它——Save as 去另一个受众，准入由对话框自己判，锁住它等于锁死只读视图的唯一出口。
- 改名、删除、排序、设默认改的是列表，在侧栏的管理器（`ViewManager` + `useViewManager`）里；按钮按许可存在或不存在，系统视图没有改名与删除。未打开实例的写入结局显示在它那一行。删除确认把后果拼出来：基础句，shared 加一句，删的是当前打开且 dirty 的再加一句。
- 键盘与焦点（见 [management.md#列表偏好与默认视图](../management.md#列表偏好与默认视图)）：改名框是共用的 `RenameInput`（见上文「就地改名只有一个框」）：Enter 提交、Escape 取消并 `stopPropagation`，离开也提交，原样的标题不写；`DeleteDialog` 收 `finalFocus`，管理器传自己的标题；`SaveActions` 与 `WriteOutcome` 给 `onCreated`（只在另存创建了视图时），`WorkbenchShell` 据此把焦点送到新视图的标题。这组回调是 `ui/WriteOutcome.tsx` 的 `ViewWriteCallbacks`，只声明一次：`WriteOutcome` 全收，`ViewHeader` 转手，`SaveActions` 用 `Pick` 只取 `onSaved` / `onCreated`。
- 删除遇到冲突时「保留我的」用 `write.remote` 刷新后的摘要再确认一次（见 [management.md#冲突与未知结果](../management.md#冲突与未知结果)）。
- **顺序是拖出来的**：行首一枚手柄（`label.manage.drag`），只在所在受众组内生效；键盘在同一枚手柄上（方向键移一位，空格拿起／放下，Esc 取消），落库之后播报一次。落下提交整个定义的完整顺序（`moveTo(id, index)`，`index` 按本组计数），失败不回滚而在那一行报出。
- 行尾的处置是一个**每种动作一格的网格**（`ItemActions` 里的 `ButtonGroup` 带 `grid grid-cols-3`：设为默认／改名／删除），同一个动作在每一行落在同一横坐标，缺席的不画成置灰。**就地改名走 `InputGroup`**：✓ 与 ✕ 在框里（`InputGroupInput` + `InputGroupAddon align="inline-end"` + `InputGroupButton`，`label.manage.rename-confirm`／`rename-cancel`），改名时 `ItemActions` 不画；输入框按所改的视图命名（`label.manage.rename-of`）。默认视图的星星实心并带 `aria-pressed`。对话框打开时焦点给标题（`initialFocus`）。`rejected` 那一行带 `label.rejected.dismiss`，恢复按钮在 `manager.pending` 非空时禁用。管理入口按 `manager.can.anything` 给。（见 test/saveActions.test.tsx「SaveActions, the split button group」「WriteOutcome」与 test/viewManagerUi.test.tsx「ViewManager rows」「the manage button on the view list」）

落到文件上：「结局→一句话加一排按钮」只有 `ui/OutcomeActions.tsx`，视图（`ui/WriteOutcome.tsx`，`box`）与管理器的行（`ui/ViewManagerRow.tsx`，`bare`）共用（见[两级 severity 与 StatusStrip](#两级-severity-与-statusstrip)）。冲突与拒绝是 error，可能已落库的未知是 warning。**冲突的三条出路一律 `outline`，按代价从小到大排**：使用最新版本 · 另存为我的副本 · 覆盖为我的版本（管理器的行没有「另存」）——哪条损失最小取决于两份配置，屏幕替不了谁作主。（见 test/saveActions.test.tsx「offers the three ways out of a conflict, safest first and none of them emphasised」）`WriteOutcome` 另有复制出口与落地通知，`ui/ConflictConfirm.tsx` 是双栏确认，`ui/DeleteDialog.tsx` 兼做冲突后的二次确认。这三处问的都是「会丢东西」，所以是 `AlertDialog`（`role="alertdialog"`，主题副本在 `ui/popups.tsx` 的 `AlertDialogContent`）：点旁边关不掉、没有角上的 ✕。

破坏性确认的问法、答法与层次是一套：

- **问句点名**：`label.delete.confirm` 带 `{title}`——对话框正好盖住它说的那一行。
- **执行那一颗是实底的 destructive**：`ui/variants.tsx` 的 `DestructiveAction`（`DeleteDialog`、`LeaveDialog`、`ConflictConfirm` 共用）。注册表的淡彩 destructive 在 14px 上不到 WCAG 1.4.3 的 4.5:1（同[徽章那一条](record.md#徽章的颜色由定义说了算但只能从主题里挑)）；底色写两遍（`bg-destructive dark:bg-destructive`）。
- **上面那一层要看得出在上面**：Base UI 默认不画嵌套弹层的遮罩，删除确认又从管理器里抬起，所以 `AlertDialogContent` 给遮罩 `forceRender` 并加深到 `ALERT_DIALOG_BACKDROP_DIM`（只有破坏性对话框用）；暗色下两张卡片同色，卡片边加到 `ALERT_DIALOG_RAISED`（`ring-foreground/40`）。（见 test/viewManagerUi.test.tsx「names the view it is about in the question」「confirms with a solid destructive button」、test/popups.test.tsx「dims what is behind it harder than a plain dialog」，故事「DeleteActionContrastInLightTheme／InDarkTheme」）

## 离开保护

切到另一个视图会释放 runtime，而未保存的草稿只活在 runtime 里：`useLeaveGuard`（`/react`，见 [react.md#useworkbench](../react.md#useworkbench)）在 `dirty` 或写入结局为 `unknown` 时先问一句，没东西可失去时一句不问——每次都拦的守卫，人会学会不读就点掉。`/ui` 只有 `LeaveDialog({ leave, messages? })` 照 `leave.asking` 画，两个按钮接 `confirm` 与 `cancel`；它是 `AlertDialog`（「留下」要按出来），渲染在 `ViewSurface` 之外，所以单独递 `messages`。

关标签、后退、点走外链不经过 `request`，所以同一判据还挂一道 `beforeunload`（D18 Ⅸ，`react/workbench/leaveGuard.ts`）：脏或未知时挂上，干净时与卸载时摘下。处理器只做 `preventDefault()` 与 `returnValue`，不带措辞（浏览器不显示）。`EmbeddedView` 没有草稿，不挂；宿主可传 `guardUnload: false`（`useWorkbench` 的选项）——那句提示属于整份文档，由宿主拍板。（见 test/workbench.test.tsx「useLeaveGuard」「beforeunload」）

## 动作槽位

- 三层业务动作走 render 槽位（`RecordActionSlots`）：`global` 在标题栏，`bulk` 在有选择时的结果工具栏，`row` 在表格最后一列（sticky）与卡片页脚，统一裹在 `RowActions` 里且只裹一层：包装由表格与卡片加，工作台只绑定（`bindRow`）。**槽位里的按钮不用 primary**（同屏唯一的 primary 是 Apply，见[版式](#版式三块一套间距一种选项控件)），用 `outline`／`secondary`；样板是 `RecordWorkbench.stories.tsx` 的 `WithActions`。动作是代码，由宿主交出，不按字符串注册也不进配置：存下来的是看法，能对记录做什么属于挂载它的应用。（见 test/rowActions.test.tsx「RowActions」）
- **批量命令有标准状态条**（`ui/BulkStatus.tsx` 的 `BulkStatus`）：宿主把 `useBulkCommand` 交给 `record.bulk`，工作台画在工具栏与行之间，进度、结局、原因、语气与出口都不用宿主写（[react.md#usebulkcommand](../react.md#usebulkcommand)）。它是 `LineAlert` 用在宿主的命令上。跑时 `info`（进度加「停止」）；落定后全做完 `info`、部分 `warning`、全失败 `error`，没有 success 档；落定句说出最常见两种原因各几条、其余几种与「未完成的仍选中」。它属于结果区而不属于 bulk 槽位：结局比选择活得久。（见 test/bulkCommand.test.tsx「BulkStatus」）

## 渲染边界

- **宿主交进来的 React 各有一道边界**：没有边界时，一个抛错的行动作会把标题栏、编辑带和未保存的草稿一起卸掉。`WorkbenchShell` 给全局动作槽、编辑带与结果块各一道 `RenderBoundary`（`ui/RenderBoundary.tsx`，`react-error-boundary`），`DashboardPanel` 给每个面板的正文一道，`EmbeddedView` 给自己的正文一道。落到边界的那一块换成可复原的错误态（`label.render.failed`、错误原话、「重试」，`role="alert"`）；全局动作槽的那道是单行的（`compact`，`bare` frame）。
- **错误不被吞掉**：每次都以 `RenderFailure { boundary, panelId?, error, componentStack? }` 交给宿主的 `onRenderFailure`（三个工作台、`DashboardGrid`、`EmbeddedView` 与 `EmbeddedDashboard` 都收）。重试只是再画一次。
- **失败属于那一次打开**：边界以 `runtime.id`（面板以子 runtime 的 id）为 reset key。（见 test/renderBoundary.test.tsx「RenderBoundary」「the workbench boundaries」「the dashboard panel boundaries」；故事「Record 工作台/回归」的 `RenderFailure`）

## FilterPanel 的布局

- 分组是带边框的块，头部是**操作符选择器**与删除，主体是一条条件带：等宽栅格（轨道 `minmax(min(20rem,100%),1fr)`——不夹到带宽，20rem 会让 pill 冲出窄带），持双输入的条件（区间、日期）放得下时占两格。操作符读作一句话（「满足全部条件」／「满足任一条件」／「全部条件均不满足」）；三个操作符在任何位置都受理，不以禁用出现（`model/filter.ts` 的 `FILTER_GROUP_OPERATORS`，选择器、加分组菜单与准入共用）。
- **值控件只要 pill 剩下的宽度**：`w-full min-w-0`，选中的值由 registry 的 `line-clamp-1` 夹断——自带下限的值控件会长出 pill 的边。（见 test/filterValueEditor.test.tsx「lets the value select shrink to whatever room the pill has」）pill 是 `flex-wrap`，值那一格带下限（单输入 6rem、双输入 9rem，`data-wide`），放不下时整格掉到下一行，✕ 跟着走。（见 stories/view-engine/FilterPanel.test.stories.tsx `TheValueStaysInsideItsPill`）
- **区间两端之间一个 `~`**（`label.filter.range-join`，`aria-hidden`；两端名为 `label.filter.range-from`／`range-to`，都 `flex-1`）：区间是一个答案。已应用条用同一个目录项（`ui/summary.ts` 的 `range`）。日期区间本来就是一个触发器里的一句话。
- pill 是内联的（字段 · 操作符 · 值 · 删除），未填写时虚线边框；error 标 `data-invalid`（destructive 色），只有 warning 标 `data-warning`（条件照常执行）。**error 还要落到控件上**：`aria-invalid` 按 code 分派——`filter.operator.*` 给操作符选择器，`filter.value.*` 给值编辑器（`FilterValueEditor` 的 `invalid` 传到每个录入或选取值的控件），`filter.field.*` 两个都标。`label.operator.*` 每一项都是人话（`is`／`at least`，不是 `eq`／`gte`），派生拼法只兜底宿主自定义 kind。（见 test/messages.test.tsx「says every comparison operator in words rather than in the enum」）
- **取反是 pill 上的开关**（D18-7）：`data-slot="filter-negate"`、`aria-pressed`、名为「{field} 条件取反」，按下后操作符前多一个「不」（`label.filter.negated`），树里这条包进只有一个子节点的 `nor` 分组（`isNegation`，`negateAt`），不给每种 kind 补否定操作符；`isSimpleTree` 认这种分组。**这层包装只有内核知道**（A3）：UI 只问 `conditionOf`／`conditions`（给出 `{ leaf, index, path, negated }`），✕ 一律 `remove(path)`，由 `removeConditionAt` 连 `nor` 一起删。高级模式照树画成分组块，pill 上不再给开关；已应用条把单叶 `nor` 说成「排除 …」（`label.filter.not-of`）。（见 test/filterPanel.test.tsx「negates a condition from its pill and says so in the sentence」）
- `ELEMENT_MATCH` 条件和分组一样渲染为块。简单模式只显示根分组的条件带，高级模式显示根分组的块。
- **模式切换放在外面有地方的地方**（`modes={false}` 交出去）：Record 与 Dashboard 挂在标题栏折叠带的下拉里（[工作台骨架](#工作台骨架)）；Analysis 的编辑器是面板加分析编辑器，一个「筛选」折叠带折不住两块，所以留在面板顶部（分段控件，见[版式](#版式三块一套间距一种选项控件)）——够不着的模式是丢掉的能力。两处读**生效的**模式；简单模式画不出这棵树时那一项禁用，原因（`config.filterMode.not-simple`）经 `aria-describedby` 挂在项上（分段控件的那句写在 `ToggleGroup` 外）。
- **底行是出入口**（D12 Ⅱ：Add 靠左，Clear／Apply 靠右）：简单模式是**添加筛选 · 放弃筛选修改 · 清空条件 · 查询**；高级模式只剩出口——每个块自带「在这个分组里添加 · 添加分组」，**一个分组一套入口**。（见 test/filterPanel.test.tsx「gives the root group one way in, not two」「keeps the single way in where the panel is the only way in」）超预算的树只有「清空条件」。Apply 是同屏唯一的 primary，面板里的输入不会自己重跑查询。
- **条件区封顶 40vh**：条件树在 `max-h-[40vh] overflow-y-auto` 的滚动口里（`data-slot="filter-tree"`），底行在外、总看得见——托盘是改条件的，结果是看的。不默认折起内层分组：那会藏起正在生效的条件。空的简单模式不画滚动口。
- **添加筛选是一张勾选表**：浮层标题「选择筛选字段」、右上「完成」、搜索框，字段按 `fieldGroups` 分组，宽处两列（弹层自己的容器查询）。勾上加一条（`addLeaf`），取消拿掉（`remove`）——「一个分组一个字段一条条件」让映射唯一。浮层一直开着，`完成` 或 Escape 关，焦点回到触发按钮：建筛选本来就要挑好几个字段。
- **嵌套分组另起一个控件**：「在这个分组里添加」旁的 chevron，菜单 `AND 满足全部条件`／`OR 满足任一条件`／`NOR 全部条件均不满足`。
- **Enter 即提交**（`aria-keyshortcuts="Enter"`），四种情况不算：IME 组字中、按着修饰键（这两种是 `ui/filter/enter.ts` 的 `isPlainEnter`，值编辑器也问它）、落在面板控件的弹层里（与 `leavesEditor` 同一个 `[data-popup-open]` 标记）、目标本身吃 Enter（按钮、链接、textarea）。`blocked > 0` 时拒绝。
- **未填写的值显示「未设置」**（`label.filter.not-set`），每种输入都用这一句（占位属于 `SelectValue`）；日期例外说 `label.date.pick`。**空值不读时钟**：新加的日期条件两端是占位、叶子保持空白（「最近 7 天」「今天」这类默认值本身是完整答案）。没有「清除值」控件，✕ 删整条。
- **带时刻的字段（`withTime`）在日历下给时刻输入**（D17-1）：同一弹层一次提交，区间两端各一个（`label.date.time-from`／`time-to`），单边一个（`label.date.time`）；原生 `type="time"`，`step="1"`，秒可选。存不带偏移的挂钟串（`2026-01-31T15:30:00`），时区由内核解析。空着的框不是零点：存的是日子本身，按区间读，提示 `label.date.time-hint`；没选日子时框禁用。读回时给了时刻读到秒，没给只读到日。
- **日历说面的语言**（`ui/filter/inputs/calendar.tsx` 的 `SurfaceCalendar`）：`react-day-picker` 要 date-fns `Locale` 对象，而 `locale` 是 BCP-47 标签，所以逐项给 `formatters` 与 `labels`，都走 `Intl.DateTimeFormat`（与 `ui/display.ts` 同路）；日期格是裸数字；一周起始取 `Intl.Locale#getWeekInfo`（取余换算，缺失时用库默认）；四句导航名走目录（`label.date.calendar-previous`／`-next`／`-today`／`-selected`）。不支持 `captionLayout="dropdown"`。（见 test/filterValueEditor.test.tsx「draws the calendar in the surface language, its chrome included」「SurfaceCalendar」、故事 `TheCalendarSpeaksTheSurfaceLanguage`）弹层 `w-auto min-w-[17rem]`，时刻控件是名字在上、框在下；弹层带 `aria-label`（popover 是 `role="dialog"`）。
- 条件上的 error 数（`filter.blocked`）大于零时 Apply 禁用，左侧 `label.filter.blocked` 说还有几条；草稿与已应用不一致时按钮带点。`submit={false}` 时底行不渲染（Dashboard 的全局条件带）。已应用摘要在 `AppliedBar`：根是 OR／NOR 时折成一个 badge；作用域条件另起只读一组。（见 test/filterPanel.test.tsx「FilterPanel tree editing」）

落到文件上：`ui/FilterPanel.tsx` 只留根（焦点边界、Enter 提交、超预算提示、底行）；`ui/filter/` 下是 `GroupBlock.tsx`（含条件带）、`ConditionPill.tsx`（含元素匹配块与 `PendingDot`）、`AddEntry.tsx`、`FieldChecklist.tsx`、`FilterModes.tsx`、`groupOperators.ts` 与 `FilterActions.tsx`。

- **`FieldChecklist.tsx`**：触发器 `aria-haspopup="dialog"`，弹层是 Base UI `Popover`，里面是搜索框（`InputGroup`）、`FieldSet`／`FieldLegend` 分组、每个字段一枚 `Checkbox` 配 `FieldLabel`，一格一个 Tab 站；列数由容器查询 `@md/checklist` 定；勾选不关弹层、不清搜索词。不用 `Combobox multiple`（[decisions.md#D16](../decisions.md#d16-站在-shadcnbase-ui-肩膀上审计后的八条裁定)，用户裁定）：未勾选项没有标记、像单选菜单，单列也看不全字段。
- **`ui/FilterValueEditor.tsx`** 只是按 `EditorDescriptor.input` 分派的 switch，**全包唯一知道这个封闭联合的地方**（成员在 `filter/fieldKind.ts` 的 `EDITOR_INPUTS`，准入据此拒绝未知 `input`；`default:` 画 `inputs/unsupported.tsx` 的只读原值加原因），也是 [extension.md](../extension.md) 所说将来按 kind 注册渲染器的缝。每种输入一个文件在 `ui/filter/inputs/`（`text`／`number`／`select`／`remote`／`date`／`daterange`／`relative`，公共部分 `shared.tsx`，日历包装 `calendar.tsx`）。
- **`multiple` 是一份值列表**：每个值一枚带删除按钮的 chip，末尾一个录入框（「输入后按 Enter」，数值带 `inputMode="decimal"`）。Enter 与**离开录入框**都把内容收进列表（去按「查询」会先 blur，刚打的数不能被吞）；空值、半个数字、重复值不进；带修饰键的 Enter 不算（`isPlainEnter`）。列表被外面整份换掉时（撤销、重载、换视图），录入框里没收进去的东西跟着清空，否则撤销等于没撤——判据是「是不是同一份列表」，不在 effect 里同步（见[控制器输出合同](#控制器输出合同)）。数值 `IN`／`NOT_IN` 收任意多个值，占两格。（见 test/filterValueEditor.test.tsx「takes as many values into a number list as are entered」「forgets what was being typed once the list is replaced from outside」「leaves a modified Enter to whatever else wants it」、test/filterPanel.test.tsx「builds a numeric IN of as many values as are entered」「discards a number that was being typed along with the edits」）
- **`reference` 的值是搜出来的**（`inputs/remote.tsx`）：`optionsFor` 给了整份列表就本地过滤；否则用 runtime 的 `optionSource(remote)`（`ViewRuntime` 从 `resolveOptions` 拿来，经 `FilterTreeController.optionSource` 交到 pill）这个 `OptionSource`，控件是 `Combobox multiple` 的 chip 盒（`PillChips`）：打开才发第一次请求、停手 250ms 再发（`inputs/candidates.ts`），每次带 `AbortSignal`、新词中止旧请求；尾部三态（搜索中、没有匹配、失败加「重试」且保留已列出的），还有下一页时给「更多」；两样都没有就退回打字。值保持来时的形状：`{ items: [{ id, label }] }`（label 随 id 保存）或纯 id 列表。（见 test/filterValueEditor.test.tsx「searches a source once typing pauses, and writes what was picked in the value's own shape」）

**文本字段的值可以从数据里挑**：允许按值分组、又没有 `options`／`remote` 的文本字段，其 `EQ`／`NE`／`IN`／`NOT_IN` 条件由 `ConditionPill` 从 `FilterTreeController.valueCandidates(path)` 取源、交给 `FilterValueEditor` 的 `candidates`，输入换成 `inputs/suggested.tsx`（Base UI `Combobox`）。**列表是帮手不是栅栏**：列的是最常见的值、不一定全，所以打的字始终是值。单值时框里就是值本身，打开时列出全部、只有之后打的字才缩小列表；多值时是 chip 盒，打的字作为「添加 …」排最后，离开录入框也收进去（同 `ValueChips`）。每个值旁是记录数（`formatNumber`），可达名称说全（「QuotationSaga（615,004 条记录）」）。底部四态：读取中（`Spinner`）、没有匹配、「字段的值读取失败：{源的原因}」加「重试」、答案不全时「只列出了最常见的值，输入以缩小范围」。框在 pill 里不画边（`PillComboboxInput`，D12），也不画下拉箭头（多一个没名字的 Tab 站）。（见 test/suggestedValue.test.tsx「a text value offered from the data」「lists the values with how many records hold each, and writes the one picked」「keeps what is typed as the value, whether or not the list holds it」「adds several values, one of them typed」「says why the values could not be read in the source's words, and asks again」）
