栅格、面板 chrome 与面板级告警。三种视图共用的骨架、状态条与 `FilterPanel` 见 [README.md](README.md)；面板与子 runtime 的关系见 [runtime.md#dashboard](../runtime.md#dashboard)。

## DashboardGrid 与几何写回

- `DashboardGrid` 画的是配置中的 `layout` 原样，库自己不紧凑；**24 列**（D22 E），存的是旧的 12 列的板子由运行时读成 24 列、每个面板落在原来的像素上（[model.md#dashboard-配置](../model.md#dashboard-配置)）；
- 只有用户动手才把几何写回（`dashboard.place(panelId, layout)`，只应用这一处摆放，见 [runtime.md#dashboard](../runtime.md#dashboard)）——一次拖拽或缩放结束，或者一条键盘命令（见下一节），库自身在挂载或属性变化时算出的布局不写回，因此打开已保存的 Dashboard 不会变脏。（见 test/dashboardUi.test.tsx「DashboardGrid」「with a stored layout the grid would have compacted」）
- **碰撞只有一套规则，是内核的**（`placePanel`，`src/dashboard/layout.ts`）：被摆的面板占它要的格子，被它盖住的面板让开——正好落在下一块上时两块对调（被压的那块上到它原来的位置，与 react-grid-layout 纵向紧凑对拖着的那块一样），否则往下推，推下去的再压到谁就接着推；**然后整个标签页上浮压紧**（批 A 走查，照 Metabase）：拖走的面板原位由下面的补上，放到空处的面板浮到有东西托住为止，动手之后不留洞。只有动手才压紧——打开保存的仪表盘什么也不动，旧板子里本来的洞第一次动手时一并收掉。（见 test/dashboardLayout.test.ts「placePanel」）库自己的碰撞处理不用——不紧凑时它让缩放的面板直接叠在邻居上、拖过去的面板要么叠上要么和邻居对调行，和键盘走的内核规则是两个答案（R6、R9）。所以 `useGridPlacement`（`ui/gridPlacement.ts`）告诉库「可以叠」（它就什么都不处理），再把内核当作库的 compactor 交进去：手势进行中每一步都按「手势开始时的布局」重新摆一次正在拖的那块，拖下时的预览因此正是松手后应用的布局，被推开的面板在拖走之后也会回来；松手只把这一块交给 `place`，其余由运行时按同一规则推。手势以外（挂载、每次新布局）它什么也不改，屏幕上是准入过的布局原样。（见 test/dashboardPlacement.test.tsx「placing a panel」；浏览器里 stories/view-engine/Dashboard.test.stories.tsx「KeyboardStepPushes」）
- 栅格要的是像素宽度，而容器只有上了屏才知道自己多宽。量它的是 `react-grid-layout` 自己的 `useContainerWidth`，不是这里另写一个 `ResizeObserver`：同一个观察者、同一套取宽规则，没有 `ResizeObserver` 的环境照样能画，连续几次缩放合并到同一帧。容器报 0（被隐藏时就是这样）时这个 hook 照实上报，栅格不收，面板保持上一次能画的宽度（从没画过就是库的起始 1280px）。**第一次绘制之前就量好**（`useGridWidth`，[D31](../decisions.md#d31-仪表盘的固定宽度全宽2026-09-24) 顺带）：这个 hook 从 1280px 起、在被动 effect 里才量，栅格于是先拿到一份 1280px、24 栏的布局——手机上也是——库在挂载前按百分比画它；提交所在的任务跑得久（大板子、慢手机）时浏览器可能先画出这一帧，再落成一列。现在在 layout effect 里量（React 在绘制前应用它的更新），量到之前不画面板，没有一份布局以它没有的宽度交给库；服务端不跑 effect，面板不出现，客户端第一次渲染与之一致。板子的宽度切换时也在 layout effect 里重新量。（见 test/dashboardUi.test.tsx「follows the container width once it can be measured」、test/dashboardWidth.test.tsx「the first frame」）
- **宽度**（[D31](../decisions.md#d31-仪表盘的固定宽度全宽2026-09-24)）：固定宽度的板子整块——筛选条、编辑条、标签栏与面板，它们都在栅格的根里——`max-width` 为 `FIXED_BOARD_WIDTH`（1200px，`ui/layout.ts`，为什么是这个数见 D31）、`mx-auto` 居中；全宽的不设上限。根上 `data-width` 说是哪一种（测试读它，不读类名）。工作台与嵌入画的是同一个 `DashboardGrid`，所以一致。窄于 `md` 时固定宽度不起作用——容器本来就比它窄，照常一列。（见 test/dashboardWidth.test.tsx「a board drawn at its width」；浏览器里 stories/view-engine/DashboardWidth.test.stories.tsx 的 1920px 与 375px）

- **面板按阅读顺序画**：先按行、行内从左到右（内核的 `readingOrder`，`src/dashboard/layout.ts`；面板叫「面板 3」时数的也是这个顺序），与配置里的数组顺序无关，所以 Tab 走的是眼睛走的路；
- **窄于 `md`（768px）时一列**（D22 J）：栅格的列数被库自己的断点读法（`getBreakpointFromWidth`，量的是栅格拿到的宽度，不是给面板写媒体查询）换成 2（`STACKED_COLUMNS`），面板由内核的 `stackedLayout` 按上面的阅读顺序叠成一列、各保留保存时的高度——**阅读顺序里挨着的两张指标卡并排、各占半宽**，行高取高的那张；后面没有指标卡跟着的那张独占一行。理由：指标卡是一个数和几个字，手机上按桌面行高一张一行，运营日报八张卡要滚过两千多像素的空白（补偿控制台首页十一张，批 6 的记录）；390px 下并排后这八张从 8 行变 4 行，整块栅格从约 4010px 缩到 2930px。半宽的卡按卡自己的宽度（容器查询 `@container/metric`，窄于 16rem）把数字降一档，变化徽标放不下时折行，不越过卡的边。这一列是**推导出来的读法**，不写回：抓手、菜单、缩放角都不出现，指针拖拽与缩放关掉，交给 `place` 的手势回调也不接、键盘命令也不落——窄屏里摆出来的位置没有一个能对应回宽布局。它的**顺序**却能：搭的时候每块面板有一枚调顺序的抓手，由 runtime 写回宽布局（见下文「搭板子」的「窄屏」）。容器被隐藏时量到 0 不是手机，断点停在上一次画得出的宽度。原来 414px 下分析面板被挤到 130px 上下，柱标签叠在一起、被截断。（见 test/dashboardLayout.test.ts「puts two cards next to each other in reading order side by side」，test/dashboardUi.test.tsx「in a column narrower than md」；浏览器里 stories/view-engine/Home.test.stories.tsx「OnAPhone」量了并排与卡内不溢出；浏览器里无横向滚动、每个面板满宽、标签都在图里，见 stories/view-engine/Dashboard.test.stories.tsx「OnAPhone」）
- **空仪表盘只许诺做得到的事**（U1，D22 A）：说「这个仪表盘还没有面板」，再用一句说仪表盘是什么（把已保存的记录视图和分析视图并排放在一起看）。**能搭这块板的人**在 `EmptyHeader` 之下的 `EmptyContent` 里拿到同样的第一步——「添加视图…」、「新建分析…」（只在有人提供那个对话框时，见下文「扩展」）、「添加标题」——按下去同时进入编辑；**不能搭的人**什么按钮也没有，一个按不动的入口就是那扇不存在的门。（见 test/dashboardUi.test.tsx「says what an empty dashboard is, and promises nothing」、test/dashboardBuilding.test.tsx「offers an empty board its first steps, and a reader who cannot build it nothing」）
- 面板里的 Record 视图以 `selectable={false}` 渲染 `RecordTable`：Dashboard 是读数的地方，没有工具栏也没有行动作，没有任何东西读选择，勾选框因此只是一列点不出结果的控件。

## 摆放面板：键盘与指针写同一个 layout

`react-grid-layout` 2.2 没有键盘传感器——拖拽是 `react-draggable` 的、缩放角是 `react-resizable` 的，两者都只听鼠标与触摸。所以键盘等价物不是一个开关，而是本包自己的一组命令（D17 第 7 条：仪表盘编排按可达性缺陷处理）。它们都落在 `dashboard.place()` 上，和一次手势产生的东西完全相同——一块面板的新 `layout`，一步一格，因为拖拽本来也是吸附到列与行的；一步踩到邻居上，邻居照内核的规则往下让开，和指针拖过去一样。

- **搭的时候看得见格子，格子是近似正方形的实心方块**（用户 2026-09-24 走查：「仪表盘编辑模式下，显示网格线」，再看截图：「网格线优化：参考 metabase，用正方形方块」；[D34](../decisions.md#d34-搭板子时的格子是实心方块行高仍是-80px2026-09-24)）：只在搭的状态、宽栅格里画（`arranging`：窄于 `md` 的一列读法里没有可落的格子，不画；一块面板都没有的标签页是 `Empty`，不画）；读的时候干净。工作台与嵌入画的是同一个 `DashboardGrid`，所以一致。**行高仍是 80px，面板几何不变**；每行切成最接近正方形的块数（`ui/dashboard/gridBlocks.ts` 的 `blockHeight`：n 块、块与块之间一道 10px 的缝，块高 (80 − 10·(n−1))/n，取与栏宽最接近的 n），块宽就是栏宽：全宽 1920px 一块 70×80，1200px 的固定宽度两块 40×35，776px 三块 22×20。行的上下边永远是块边，所以面板的四条边永远落在块的边上；竖向一步（拖、缩放、方向键）仍是一行。块是**软的实心、3px 小圆角**，`--border` 调到 45%（`color-mix`；不新造颜色，亮色约是 `--muted` 那一层浅灰，暗色约是卡片色，预设各取自己的）。画法是 Metabase 的「一整行一张 SVG、纵向重复」：`gridBlocks` 把一行 24 栏、每栏 n 块的 `<rect rx>` 写成 SVG，放进元素上的 CSS 变量（`--grid-blocks`、`--grid-blocks-size`、`--grid-blocks-top`），每栏的左边与宽是**库自己的算法**（`react-grid-layout/core` 的 `calcGridItemPosition`，边距与内边距取 `defaultGridConfig`——板子两样都没设：缝 10px、内边距 10px；24 栏），按 `drawnWidth` 算，与面板同一次取整；`styles.css` 的 `dashboard-grid-blocks` 把它当 `mask-image`、从内边距起纵向重复，颜色写在样式表里——SVG 在 data URI 里读不到 CSS 变量，所以它只管形状。它是栅格所在的 `dashboard-tab-panel` 里的**一个**图层（不是一格一个节点；不做成那一层的背景，因为遮罩会把面板一起裁掉）：`aria-hidden`、`pointer-events: none`、`z-index: -1` 垫在面板下（那一层 `relative isolate`）。（见 test/dashboardWidth.test.tsx「the grid blocks while a board is built (D34)」；浏览器里 stories/view-engine/DashboardWidth.test.stories.tsx「GridBlocksWhileBuilding」量面板高度与改前一样（350／350／170px）、块数是最接近正方形的那个、面板的四条边落在块的边上，固定 1200px 与全宽各量一遍）
- **一颗把手，指针拖、键盘摆**（V-02）：面板标题行开头的把手（`DashboardArrange.tsx` 的 `PanelHandle`，`panel-grip`，名字「移动或调整「北区订单」大小」）。指针拖它就是库的拖动；键盘按 Enter 或空格（一次没有指针的点击，读屏的「按下」也是它）**进入摆放**：把手成按下的样子（`aria-pressed`），板子的播报区说「正在摆放……：方向键移动，Shift＋方向键调整大小，Enter 完成，Esc 放回原处」；方向键一步移一格，Shift＋方向键一步改一格大小，每一步说落在哪；再按 Enter／空格或离开把手就留在那里；**Esc 把这次摆放的每一步都撤回**（每一步是撤销历史里的一步，Esc 按步数撤回），面板回到按下 Enter 之前的位置。没进摆放时方向键什么也不做，读屏在标题行上用方向键走不会误挪面板；指针点一下不拖也不进摆放。键的说明是把手的描述（`label.panel.handle-hint`）与 `aria-keyshortcuts`。原来是并排两颗——「移动」抓手与「摆放」菜单（八条命令写成字）——读者分不清该按哪颗，合成这一颗后菜单删掉了。东南角（`panel-resize`）照旧：指针缩放，聚焦时也答方向键调大小；
- **一步是什么**：`arrangePanel`（在内核里，`src/dashboard/layout.ts`，把手与角都调它，看的是整块板子）。左右与大小一步一格；上下是压紧的板子上的一步——往下挪一行会被上浮送回原处，所以「下移」是让它落到别处的最小一步，也就是越过下面那块、两块对调，「上移」同理（批 A 走查）。边界就是内核的边界（`x`、`y` 非负，`w`、`h` 至少一格，`x + w` 不越界），所以没有哪一步能产出 `validateDashboard` 会拒的 layout；一步什么也不会改变——一列最下面那块往下、第一列往左——面板不动，播报区说「「北区订单」不能再往这边动了」（`label.panel.arrange-stuck`），这一下不算撤销历史里的一步。落位播报说的是压紧之后它停在哪。（见 test/dashboardLayout.test.ts「arranging by keyboard」、test/dashboardPlacement.test.tsx「trades places with the panel above on a keyboard step up」、test/dashboardUi.test.tsx「arranges a panel from its one handle: Enter, the arrows, Shift and the arrows, then Enter or Escape (V-02)」）
- **每个手柄以自己的面板命名**：「移动或调整「北区订单」大小」「调整「北区订单」的大小」，哪些键能用由 `aria-keyshortcuts` 说，而不写进名字。原来缩放角全板同名（「用方向键调整这个面板的大小」），读屏走一遍板子分不出自己在哪个面板上（U8）。`resizeConfig` 是整张栅格级的属性，库只把 axis 交给这个工厂——但它返回的元素被 `react-resizable` 追加进**栅格项本身**的子节点里，所以栅格项是我们的 `PanelGridItem`，它向子树提供「这是哪个面板、叫什么」，角从 context 读名字与 id；不在栅格项里时它只说「调整这个面板的大小」、什么键也不答；
- **面板叫什么**（`panelName`）：自己的标题；没有标题的视图面板用它显示的视图的标题；标题卡片用它的字；内容面板用种类（标题／文字／图片／链接）；剩下的（视图打不开、又没有标题）按它在板上的位置叫「面板 3」。**从不用 `panel.id`**——那是配置里的键，不是看板子的人起的名字。**板子起的名字不重名**（`panelNames`，批 A 走查）：两块没标题的文字面板原来都叫同一个名字，抓手、发现、落位播报按名字指向的是两块；现在按阅读顺序编号「文字」「文字 2」，并绕开作者起的标题（作者自己起了两个同名的，那是作者的）。标题、抓手、角、菜单、正文滚动区、落位播报都用这同一个名字；（见 test/dashboardUi.test.tsx「names an untitled panel by what it shows, never by its id」「numbers the names it makes up, in reading order, around the titles given」「names each corner after its own panel」）
- **标题卡片**（`heading`）：它的字就是面板的标题元素（`panelName`），卡片上**只有这个标题**、字号大一档（`text-base`）、没有正文——没有一块可滚动、可聚焦却空着的区域；新加的标题卡片叫「新标题」，加上就地改名。标题层级与其它面板同级（工作台里 `h3`）：标题卡片是读者扫板子时的路标，把它升一级会让它下面的面板在大纲里变成它的子节，而栅格上的「下面」并不是从属。（见 test/dashboardBuilding.test.tsx「adds a heading and names it in place」）
- **落位要说出来**：指针能看见面板在自己手下动，键盘只有一个不在屏幕上的 layout，所以每一步都说这个面板现在在第几列第几行、多宽多高（`label.panel.placed`），说在板子的那一个播报区里（见下文「一块板一个声音」）。宽高各是一个带量词的整句（`label.panel.columns`、`label.panel.rows`，英文单数各有 `-one`，按 `count` 选，见 [README](README.md)），英文不再出「1 columns」；
- **聚焦时角必须看得见**：上游只在指针悬停在面板上时才画那个 20px 的角（`opacity: 0` → `:hover` 时 `1`），键盘到得了却看不见就等于没到。`styles.css` 里补了 `:focus-visible` 的一条。

### 一块板一个声音

- **一个面只有一个播报区**（Q-03／U-08）：栅格、标签栏、筛选条、搭板子的对话框（添加、复制、移除、另存、新建分析……）说的每一句都进板子的那一个 `aria-live="polite"` 区域（`data-slot="dashboard-announcement"`）。它由画这块板的那一层建（`DashboardWorkbench`、`EmbeddedDashboard`，或宿主用 `DashboardGrid` 自拼的那一层——`DashboardBoard` 是包内部件，不从 `/ui` 导出），经 `Announcer.tsx` 的 `SurfaceAnnouncer` 交给里面的每一个部件；部件用 `useSurfaceAnnouncer`：在一块板里就借板子的声音，单独被宿主画出来（一张单独的 `DashboardGrid`、一条单独的标签栏）才有自己的一个区域。原来一块板上五个播报区，两句同时来时读屏念串了，也说不出是哪一句答的这个键。**同一句再说一遍照样念**：每一句是区域里一个按次数取 key 的新节点，读屏念的是新加的内容——交叉筛选连按两次同一种结果也听得到第二次。（见 test/dashboardFilterBar.test.tsx「says everything in one region, and has no toasts to show while read」）
- **提示（toast）只在搭板子时挂**：提示只有自动接线会发（下文「筛选」），所以 `ToastViewport` 只在编辑中存在，读板子的人（只读嵌入在内）的地标列表里不再多一个英文的「Notifications」；它以目录里的词命名（`label.filters.toasts`「接线提示」）。它是注册表 `toast` 自己的区域，与板子的声音分开：提示带「撤销」按钮，要看得见、按得到，不只是念一句。`@dnd-kit` 的 `Accessibility` 插件在 `<body>` 上另挂一个区域，说它自己驱动的拿起与放下（筛选与标签页的排序）——那是拖拽库的，不在板子里。

（见 test/dashboardUi.test.tsx「placed by keyboard」；浏览器里的那两件 jsdom 做不到的事——移动真的到了屏幕上、聚焦时角真的可见——在 stories/view-engine/Dashboard.test.stories.tsx「KeyboardLayout」）

## 刷新是整块板子的

- 仪表盘的刷新同样是标题栏里的那个拆分按钮，但它编辑的是**仪表盘自己的** `refresh.interval`：`DashboardRuntime` 为整块板子持有唯一一个计时器，被引用实例自身的 `refresh` 在其中被忽略，以免两层计时器（[runtime.md#dashboard](../runtime.md#dashboard)）。读板子时选的间隔是这位读者这次打开的，不进草稿，板子不因此「已修改」；搭板子时选的才是板子自己的，随保存写出（D26 Q35）；搭板子期间整板不自动刷新，保存或取消后恢复（Q39）。所以菜单顶上多一句 `label.refresh.panels` 说清这一层关系——控件若什么都不说，看上去就像在给每个面板各设一个间隔。那句话用读者的词：「仪表盘上的所有面板按这里的间隔一起刷新；面板所显示的视图自己保存的刷新间隔在这里不生效」，不说「计时器」「被引用视图」（U9）；
- 主键那一半在引用还在解析时禁用（`dashboard.resolving`，此时没有哪个面板能被刷新），**在任一面板的查询还在途时也禁用**（`dashboard.loading`）：仪表盘自己不跑查询，`state.query` 永远是 `idle`，问它「有没有东西在跑」永远答没有，于是一屏正在加载的面板会被一次点击整片顶掉，而按钮上连个转圈都没有。`useDashboard` 因此自己订阅各个子 runtime——子 runtime 的查询变化不会通知仪表盘的订阅者（那是有意的，否则每个面板每次请求都要让整张栅格重渲染），所以要知道这件事的人得自己去问。（见 test/refreshControl.test.tsx「the dashboard title bar, saying whose timer it is」）

## 面板失败：保留上次的结果，可以重试

- **刷新失败不丢上一次的结果**（R5）：子 runtime 的 `result` 只随成功推进，面板照样画它，上面一条 `QueryStrip`（`stale`）说「〈原因〉 · 显示的是上一次成功的结果」——与两个工作台、`EmbeddedView` 同一句话、同一个部件。从前面板见到 error 就把整块正文换成「查询失败」，断一次网读者正在看的数就没了，而工作台与嵌入视图都留着。只有**背后什么都没有**的失败（第一次就失败）才占正文（`panel-failed`，`Empty` 的形状）。
- **单个面板可以重试**（U4／G5）：两处失败都带「重试」——正文里的 `panel-failed` 在 `EmptyContent` 里放一个按钮，stale 那条线在行尾放 `QueryStrip` 自己的按钮——都调 `dashboard.refreshPanel(panel.id)`，只重跑这一块；从前唯一的出路是标题栏的整板刷新，为一块面板把其余全部重跑一遍。`DashboardPanel` 单独使用、没人给 `onRetry` 时不出按钮。
- 文案复用 `label.query.failed`／`label.query.stale`／`label.query.retry`，没有新词。（见 test/dashboardPlacement.test.tsx「a panel whose query failed」；浏览器里 stories/view-engine/Dashboard.test.stories.tsx「RefreshFailedKeepsData」）

## 面板 chrome 与 warning 标记

- **栅格上方说什么只有一份读法**（R3b：Q-01／A-07）：`useDashboard().issues`（runtime 的 `boardFindings`）——仪表盘自己的发现，加 draft 里面板级、却还没有哪块面板带着的（固定范围改了、尚未 Apply 时映射到会告警的面板字段，这时 `state.panels` 仍是上一次 applied 的，不说就会被保存原样存下）。别的面板级发现归面板自己的框。工作台与嵌入都读它、按 severity 分：工作台把 warning 交给状态行（error 仍是状态行自己的那一条），嵌入分成红条与黄条；两处原来各算一份（工作台逐条比对面板带着的，嵌入干脆扔掉所有 `['panels', i, …]`），嵌入于是看不到 draft 里那条 warning。（见 test/dashboardWorkbench.test.tsx「says a draft panel warning no panel carries yet, until apply hands it over」）
- **状态条上的面板级发现要说是哪个面板**：内核的句子说「这个面板……」，在面板自己的框里是清楚的，挪到栅格上方的状态条里就什么也没指。工作台（经 `WorkbenchShell` 的 `nameIssue`）与嵌入的两条都先过同一个 `boardFindingNamer`（`ui/dashboard/findings.ts`）：路径是 `['panels', i, …]` 的发现改说成「「北区订单」：……」（`label.panel.finding`），名字取自 draft 里的那个面板（发现就是对 draft 下的），筛选按条上的名字说（下文 X-03）；
- **面板标题是标题元素**：工作台里是 `h3`，在视图自己的 `h2`（`ViewHeader`）之下，按标题跳读能一个个面板走到；原来是一个带样式的 `div`。嵌入的板子没有画自己的标题时，面板标题默认 `h2`（在宿主页面的 `h1` 之下），画了标题（`withTitle`）就在它下一级；宿主用 `EmbeddedDashboard` 的 `headingLevel`（正式开关，`DashboardGrid` 同名属性）按自己的大纲改——只有宿主知道自己的大纲；`withPanelTitles` 关掉时标题只给读屏（见 [embed.md](embed.md#开关)）。（见 test/embeddedDashboard.test.tsx「puts the titles where the host outline wants them: the board’s, and its panels one under」「keeps a panel’s title for a screen reader alone when the host turns titles off」）
- **嵌入的仪表盘同样画整张栅格**（R3）：一个面板的 error 只停那一个面板（runtime 照跑其余的），嵌入原来把它当成整块仪表盘的，用一条红条顶掉了整张栅格。现在面板带着的 error 与 warning 都归面板自己说，栅格上方说的是上一条那一份；只有仪表盘自己的 error（含落在 `['panels']` 本身、不属于任何一个面板的「面板太多」，runtime 的 `blocksBoard`）才不画栅格。（见 test/embeddedDashboard.test.tsx「draws the grid around a panel that is out」；浏览器里 stories/view-engine/EmbeddedDashboard.test.stories.tsx「DashboardWithAPanelOut」）
- **出不来的面板说为什么、找谁**（U5）：正文是一个 `Empty`，标题是原因，描述是出路，同一个词不说两遍（原来是「这个面板不可用」下面再一句「……不可用」，而且不说为什么）。原因按内核的 issue code 映射成读者的话（`PanelUnavailable.tsx` 的 `OUTAGES`）——视图被删或你没有权限（`dashboard.panel.unavailable`，存储分不出是哪一种，面板也就不猜）、没能打开、指向的不是记录或分析视图、视图并不对这块板的所有读者开放、仪表盘的筛选接不上这个面板（`dashboard.binding.*`）、视图保存的设置已经用不了（子视图自己的内核发现）；仪表盘自己关于一个面板的其余规则（位置、文字长度、链接协议）本来就是读者的话，照说。**从不出现** instanceId、scope 代码、字段名或存储抛出的 `error.message`——那几条内核句子也一并改掉了占位符。出路按读者分：**读板子的人**被告诉该找谁——「请视图的所有者共享给你／打开它修正」「请这个仪表盘的维护者替换或移除这个面板」，没有一颗按下去什么也做不了的按钮；**正在搭板子的人**就是那句话要找的人，于是那句换成「换成另一个视图，或把它从仪表盘移除」，下面是真按钮：数据面板「替换视图…」、内容面板「改内容…」，都有「从仪表盘移除」（与面板菜单一样立即移除，「撤销」找回）。（见 test/dashboardUi.test.tsx「says why a panel is out, in words its reader uses」、test/dashboardBuilding.test.tsx「offers the way out as buttons rather than a person to ask」、stories/view-engine/Dashboard.test.stories.tsx「PanelUnavailable」）
- 面板正文自己会滚动（面板高度由布局定、读的时候至多长到八行，见下文「表格面板按行长高」，内容不一定装得下），所以它带 `tabIndex={0}` 与 `role="group"`、以面板标题为名：能滚动而键盘到不了的区域是一条实打实的缺陷。记录面板本来靠行里的控件凑巧满足了这一条，图表面板则一个可聚焦元素都没有——图表是一张 `role="img"`，里面没有任何能拿焦点的东西，见 [analysis.md#图表怎么被读出来](analysis.md#图表怎么被读出来)；
- **表格贴到面板两边，别的都留在面板的边距里**（用户 2026-09-25 问运营日报「付款超过 48 小时仍未发货」「左侧的留白需要吗？」，按第一原理定，与工作台「图留边、表贴边」同一条规矩）：面板正文左右留 `--panel-padding`（8／12／16px，随密度），就是标题的缩进，图表、指标卡、笔记、提示都站在里面。表格原来也站在里面，第一格再加自己的内边距，于是勾选框比标题靠右 8px，表头的灰带、行线和横向滚动条两边都差一截不到卡片边，滚走的列从冻结主键左边那条缝里露出来。现在正文画的是记录表或分析表格（`record-table`／`analysis-table`）时，正文让出左右内边距：表格连同表头灰带、行线、滚动条通到卡片内边缘，冻结列就顶着卡片边；第一列的左内边距与最后一列（填充列不算）的右内边距换成 `--panel-padding`，所以勾选框或第一列的字正对标题，最后一列右边留同样的空。与表格并排在正文里的东西——过期提示、宿主的批量命令、选择条——照旧留边，正文下面的「共 N 条记录」「第 1 / 1 页」也是（`panel-paging` 自己带边距），都对齐标题。空结果、失败、骨架不是表格，照旧在边距里。规则在 `styles.css`「In a dashboard panel too, a table runs to the card's edges」，只按槽位写，不改组件；工作台那一半是它上面的「A drawing keeps the column's gutter」。（浏览器里 stories/view-engine/OpsDailyEdges.test.stories.tsx「TableRunsToThePanelEdges」在三档密度下量：表格左右等于正文内边缘、首格内容与标题左缘差不超过 1px、滚到最右时末列右内边距等于边距、冻结列仍在卡片边，图表与指标卡两边的边距不变；Fulfilment.test.stories.tsx「AnalysisTableRunsToThePanelEdges」量分析表格）
- **正文的焦点框画在边里**（U-03，`variants.tsx` 的 `FOCUS_INSET`）：正文与裁掉溢出的卡片一样宽，画在外面的 ring 两边被裁掉，只剩一条 1.77:1 的灰线。现在是每个控件都戴的那一套（1px `--ring` 边加半透明的 3px 光晕）往里画。**带 warning 的面板警示色画在卡片的 ring 上**（U-04，`PanelCard`）：注册表的 `Card` 用 ring 画边、没有 border，原来要的 `border-warning` 画的是一条 0px 宽的边——状态在元素上，屏幕上什么都没有。（浏览器里 stories/view-engine/Dashboard.test.stories.tsx「PanelChromeInLightTheme」「PanelChromeInDarkTheme」量了两者的对比度）
- **记录面板只有一页时只留「全部」一行汇总**（[D26](../decisions.md#d26-阶段-34-联合审查的十一条拍板2026-09-24) Q40）：与工作台同一个 `useSummaries`，面板里的行就是同条件下的全部时，「本页」只是换个名字重复「全部」，不画；多页时两行照旧。规矩见 [record.md](record.md#两行汇总本页与全部)。（见 test/recordSummaries.test.tsx「draws the one row in a dashboard panel as in the workbench」、test/dashboardUi.test.tsx「keeps the summary scope readable without the selection column」）
- **第一次的答案在路上时说出来**（U-13）：记录面板与分析面板还没有第一份结果时画骨架，正文同时 `aria-busy="true"`、带一句只给读屏的「加载中」（`panel-loading`）。**不是播报区**：一块板一打开就是十几块面板同时加载，十几声「加载中」正是板子只留一个声音要避免的噪音；读者 Tab 到正文时听到它。（见 test/dashboardUi.test.tsx「shows a skeleton until a panel has data」）
- **标题行放不下时徽章让到下一行**（U-10）：面板的名字是读者认面板的唯一依据，「不受……影响」「点击筛选……」「此处改为……」这几枚是附加说明；原来徽章不收缩、标题先被挤没。现在徽章在标题下自成一行。（浏览器里 stories/view-engine/Dashboard.test.stories.tsx「TitleOverItsBadges」在手机宽度上量了标题）
- Apply 之后由面板承载，条里不再重复。面板级的由面板自己呈现：不可用的面板在正文里说明理由（首个 error，或独自到来的那条 warning），随之而来的其余 warning 仍在头部标记里，能运行却带 warning 的面板（子 runtime 对自身配置的 warning，以及它上一次**结果**自身的 warning——汇总退回本页、分析填满上限——都已重定址到面板，见 [runtime.md#dashboard](../runtime.md#dashboard)）照常显示视图，头部加 `panel-warning` 标记并以 `data-warning` 标出边框。（见 test/dashboardWorkbench.test.tsx「DashboardWorkbench」、test/dashboardContent.test.tsx）
- **面板上的图表提示说列标题**：头部标记里的发现先过 `analysisIssueNamer`（`ui/analysis/issueNames.ts`，工作台与嵌入视图用的同一个），维度与指标按列标题说、不说别名；`chart.as-table` 说出图型与原因（「柱状图画不了这个结果（最多两个维度），先以表格显示」）。这一条原来根本到不了面板：子 runtime 只有 warning 被重定址到面板，这条是 note，一张退回表格的图在仪表盘里一声不吭——现在子 runtime 对自身配置的 note 同样交给面板（`panelIssues`，见 [runtime.md#dashboard](../runtime.md#dashboard)）。（见 test/dashboardBuilding.test.tsx「says why a chart shows as its table, in the words of the picker」）
- 这个标记是 `IconTooltip`（`ui/IconButton.tsx`）而不是一个挂着 `title` 的 `span`：`title` 只有鼠标悬停才出得来，键盘与触屏都够不着，于是 warning 说了什么就只有拿鼠标的人读得到。走同一条通路之后，同一份 `messages.issues(warnings)` 既是控件名也是气泡文案，聚焦与轻点都能打开。颜色（`text-warning`）落在图标上而不是按钮上——那是标记本身的含义，按钮保留 ghost 变体自己的悬停与聚焦配色。（见 test/iconTooltips.test.tsx）
- **有话要补的徽章同一条路**（U-11，`IconButton.tsx` 的 `BadgeTooltip`）：「点击筛选「仓库」」（按下去会怎样）、「此处改为饼图」（为什么和视图不一样）、接线条上的「手动」（不是按同名自动接的）原来各挂一个 `title`。现在徽章渲染成一颗按钮（`Badge render={<button>}`），套注册表的 `Tooltip`：悬停、聚焦、轻点都打开；徽章上的字仍是它的名字，补的那句同时是它的可及描述（`aria-describedby`），读屏两句都念。（见 test/dashboardPressUi.test.tsx「says so on the panel, sets the bar from it and marks the group; a second press clears」、test/dashboardExtensions.test.tsx）

## 内容面板：排版与占位

- **文字面板里的标题排在面板标题之下**（U-12）：作者写的 `#` 原来画成 `h1`，按标题跳读时它跳到视图名（`h2`）上面，读起来像一个新页面。现在 `MarkdownPanel` 把 `#` 画成面板标题的下一级、`##` 再下一级，封顶 `h6`（`headingLevel`：工作台里面板标题是 `h3`，文字面板的 `#` 就是 `h4`；嵌入里跟着宿主给的级别走，`DashboardPanel` 经 `ContentPanel` 交下来）。字号按作者写的深度（`data-depth`）画，不按大纲给的级别：`#` 在哪一级都是文字面板里最大的那一档。（见 test/dashboardContent.test.tsx「puts a note’s headings under the panel’s title, never past h6」、test/embeddedDashboard.test.tsx「puts the titles where the host outline wants them: the board’s, and its panels one under」）
- **markdown 面板不引 `@tailwindcss/typography`，而是把那几条覆盖写成一个具名常量**（`MARKDOWN_PROSE`）。优先复用第三方是这一包的默认，这里是反过来的那一种，理由写在调用处：`prose` 是一栏文章——`max-width: 65ch`、围绕 16–20px 正文的字号阶梯，即便 `prose-sm` 的 `h1` 也有 30px 上下，比面板自己的标题还大，而面板多宽是用户拖出来的；它的颜色是一套写死的 gray，要让它认 `--foreground`／`--muted-foreground`／`--primary` 就得在 `styles.css` 里重定义十六个 `--tw-prose-*`，比它要替掉的那四条规则还多，而且颜色从此有两个决定的地方；它大部分规则是给这个面板画不出来的元素准备的（原始 HTML 是关的）。原来写在类名里的 `prose-sm` **一直是死的**——插件从未安装，编译出的样式表里一条 `prose` 规则也没有；
- **图片加载失败的占位就是 `Empty`**（`EmptyMedia variant="icon"` + `EmptyDescription`），与 `DashboardGrid` 里「面板不可用」「查询失败」同一个形状，不再是一个自己居中的 `div`。不放标题：作者写的 `alt` 是仅有的那句话，上面再加一句「图片加载失败」等于把同一件事说两遍；`alt` 缺席时才用 `label.image.failed` 当那句描述。（见 test/dashboardContent.test.tsx）
- **带链接的图片要有名字**：链接的名字是它里面的文字，没有 `alt` 的图片什么也不给，于是读屏只念一个「链接」。没有 `alt` 时用面板标题、再没有就用「打开链接的页面」（`label.image.link`），写在链接里的一个 `sr-only` 里；
- **在新标签页打开要先说**：面板上的每一个链接（文字面板里的、链接面板的、图片的）都 `target="_blank"`，看不见标签栏的人会发现原来的页面突然到了另一页后面、后退也没用。所以每个链接的名字末尾带一句「（在新标签页中打开）」（`label.link.new-tab`，`sr-only`）：只说不画——链接面板已经画了外链箭头，文字面板与图片没地方再放一个图标。（见 test/dashboardContent.test.tsx「says every link opens a tab of its own」）

## 搭板子（D22 A～E，批 B2、B3）

**读与搭分开**（D22 A）：读板子时什么都不动——没有抓手、缩放角、摆放菜单，指针拖不动，键盘命令不落；标题栏行尾一颗「编辑」进入搭的状态，面板上的这些才出现。「编辑」**只给能保存这块板的人**（`SaveCommands.can.save`：系统仪表盘只读、没有保存权限的读者都没有），系统仪表盘因此只有「另存为」（D4）。编辑状态属于这一次打开，记在 runtime 上（`DashboardRuntime.setBuilding`、`state.building`，D26 Q39：两种界面读同一份，整板的计时器据此停表）：换一个视图就回到读。它**不是** runtime 的 `setEditing`——那个是编辑器拿着焦点、暂停自动刷新的意思，条件面板一失焦就会把它关掉。（见 test/dashboardBuilding.test.tsx「offers 编辑 to whoever may save it, and nothing moves until it is pressed」「offers a system dashboard 另存为 and no 编辑」「offers no 编辑 to a reader who may not save the board」；浏览器里 stories/view-engine/DashboardBuilding.test.stories.tsx「NoGripsUntilBuilding」「SystemDashboardHasNoEdit」）

- **标题栏：一个状态一颗 primary，站在同一处**（[D32](../decisions.md#d32-仪表盘读的时候编辑是主按钮在行尾2026-09-24)，用户 2026-09-24 走查：「编辑作为主按钮，放到最右侧」）。**读**：「编辑」是 `default` 变体（`data-emphasis="primary"`），在整行最后——框架功能（刷新、铺满）与宿主的全局动作之后（`ViewHeader` 的 `build` 画在 `view-controls` 的末尾）。嵌入不搭板子（[D36](../decisions.md#d36-嵌入一律不写档位是-staticinteractive2026-09-24)），没有「编辑」。读一块板时没有要手动跑的查询（筛选改了就跑，D27），接下来要做的就是搭它，所以它是这一屏唯一的 primary。名字旁的保存组**读的时候只给「另存为」**（`SaveActions` 的 `copyWhenClean`，`ViewHeader` 在有「编辑」时打开它）：板子的改动只在搭的时候发生、由编辑条的「保存」存下，读的时候就地保存永远按不下——一颗常灰的「保存」加一个 ▾ 只为收着另存为，是两颗假控件；另存为本身仍要（复制一块板，系统板与不能保存的读者也靠它）。读的时候真有未保存的改动（runtime 允许别处写草稿）时，拆分的「保存 ▾」照旧回来，仍是 `outline`。从编辑条保存回来，那一颗先说「已保存」、禁用一小会，再变回「另存为」，读屏照旧听到保存成功。**搭**：「编辑」离开，编辑条的「保存」是唯一的 primary，在编辑条最后（「取消」`ghost` 在它前面），与读的时候「编辑」同在行尾。键盘顺序因此是：名字 → 另存为 → 刷新、铺满 →（宿主动作）→ 编辑。（见 test/dashboardBuilding.test.tsx「has one primary a state, last on its line: 编辑 read, 保存 built」「offers the save in place again while something read is unsaved」；浏览器里 stories/view-engine/DashboardBuilding.test.stories.tsx「EditIsThePrimaryAtTheEnd」）

- **编辑条**（`ui/dashboard/EditBar.tsx`）在栅格上方、全局筛选之下：「正在编辑」与一句说明（面板随改随跑；按「保存」才存下这些改动）、「＋ 添加 ▾」、「取消」、「保存」。它是一个以「正在编辑」为名的 `region`。**编辑中提交与回退只有一处**（用户 2026-09-23 定：一件事一种做法）：标题栏上的保存按钮与「已修改 ↺」都收起来——「保存」就是那次保存、「取消」就是那次还原，旁边再有一颗保存或一个 ↺ 就是同一条命令换个名字，只会让人猜哪颗才算。离开编辑（「保存」或「取消」）之后标题栏照旧：有未保存的修改（例如正在拼的全局条件）就有「已修改 ↺」。开关是 `WorkbenchShell`／`ViewHeader` 的 `commitElsewhere`。（见 test/dashboardBuilding.test.tsx「leaves 「已修改 ↺」 to the edit bar while the board is built」；浏览器里「BuildFromEmpty」「CancelReverts」）「添加筛选」在「添加」旁边（批 C2，见下文「筛选」）；「撤销」「重做」在它们前面（下一条）。**「仪表盘宽度」**在「添加筛选」之后（`ui/dashboard/BoardWidth.tsx`，[D31](../decisions.md#d31-仪表盘的固定宽度全宽2026-09-24)）：一组 `ToggleGroup`，固定宽度（`FoldHorizontalIcon`）与全宽（`UnfoldHorizontalIcon`）两个图标，以字命名、有气泡，当前那个按下——与结果工具栏的布局切换同一做法；按下当前那个不改（板子总有一个宽度）。每按一下是撤销历史里的一步（`setWidth`）。窄于 `md` 时不出现：一列的读法里没有宽度可看。（见 test/dashboardWidth.test.tsx「switches from the edit bar」；浏览器里「SwitchWhileBuilding」）
- **撤销与重做**（`ui/dashboard/history.ts` 的 `useBoardHistory`，runtime 见 [runtime.md#dashboard](../runtime.md#dashboard)）：编辑条上一组两颗图标按钮（`ButtonGroup`，`Undo2Icon`／`Redo2Icon`），窄屏也在（那里的每一下同样是一步）。**每一步是一条搭板子的命令**——加、删、摆、调顺序、改名、展示、内容、点击、标签页、筛选、接线、时间粒度、宽度；同一件东西上连着的同一种改名或设定（逐字打的名字、试过的几种图型）是一步。按钮的名字与气泡**说出这一步**：「撤销移除「北区订单」」「重做对筛选「仓库」的修改」，没有可撤销的是「撤销」且禁用——被移除的面板也叫得出名字，因为搭板子期间见过的名字都记着。按下之后板子的播报区说「已撤销移除「北区订单」」。**键盘**：焦点在板上（编辑条、筛选条、标签栏、面板都算）时 ⌘Z／Ctrl+Z 撤销、⇧⌘Z／Ctrl+Shift+Z／Ctrl+Y 重做，写在按钮的 `aria-keyshortcuts` 上；**在输入框、文本域、下拉与组合框里不接**——那里的 ⌘Z 是它自己的；板子开出的对话框与弹层也不接（它们不在板子的 DOM 里，哪怕 React 的事件冒泡到了）。焦点规则照 `listFocus.ts`：按到最后一步、这颗按钮禁用了，键盘换到另一颗；用键撤销时焦点所在的控件跟着没了（撤销一次添加），落到「撤销」、「重做」或编辑条上。**「取消」、「保存」、换一块板都让历史重来**：取消与保存之后没有什么可撤销的，下次按「编辑」从空的历史开始（[D25](../decisions.md#d25-阶段-3-收尾的四条细化2026-09-24) Q26）。（见 test/dashboardBuilding.test.tsx「removes a panel at once, says so, and puts the keyboard on 撤销, which brings it back」「takes steps back and forth by ⌘Z and Ctrl+Shift+Z on the board, never inside a field」「offers no step to undo outside building, and forgets them on 取消」；浏览器里 stories/view-engine/DashboardBuilding.test.stories.tsx「RemoveThenUndo」）
- **编辑条在搭的时候一直看得见**（R3b，照 Metabase 的编辑条固定在顶上）：加一块面板会把它滚进视野，编辑条从前随板子顶部一起滚出去，要滚回来才结束得了。它现在吸在滚动这块板的那个框的顶上（`sticky top-0`，`data-sticky`）——工作台里是主区，工作台放在宿主页面里时也可能是宿主的页面或宿主自己的滚动框——压在滑到它下面的面板之上。底色因此是那条浅灰带不透明的一版（`bg-row-hover`，静止时看上去一样），上方还带一截 1rem 的底色：工作台滚动的主区有内边距，粘住的边停在内边距上，不遮住的话面板会从那一截里露出来；静止时这一截就是它与筛选条之间的空隙，本来就是底色。这截底色是板子站着的那层地（`bg-canvas`，`.fve-root[data-kind='dashboard']` 画的那一色），不是 `background`：分开两者的主题（如 porcelain 的灰地白卡）下，原来它在标题栏与编辑条之间画出一条白带，读作多出来的一个空行（用户 2026-09-25 走查）。（浏览器里 stories/view-engine/DashboardBuilding.test.stories.tsx「EditBarSitsOnTheGround」：每个预设、亮暗两色，编辑条上方到标题栏之间没有与地色不同的底）筛选条、接线条、标签栏都在它的上下文里照常滚走，被它盖住的只是已经滚过去的部分。宿主要让它吸住，包着嵌入的框不能是一个不滚的滚动框（`overflow: hidden`／`auto` 却不滚）：粘住只认最近的滚动框，那样它就吸在一个永远不动的框上——要裁切就用 `overflow: clip`。（浏览器里 stories/view-engine/DashboardBuilding.test.stories.tsx「EditBarStaysInView」：工作台的框比板子矮，滚到最后一块面板，「取消」「保存」仍在框顶、在最上层）
- **「保存」就是那次保存**（[D26](../decisions.md#d26-阶段-34-联合审查的十一条拍板2026-09-24) Q37：取代交互稿的「完成」，一颗按钮说它做的事）：走 `SaveCommands.save` 同一条路，共享板先问一句、点名这块板（#1836 的 `SharedSaveConfirm`），个人板直接存；**从没保存过的板**弹首存对话框问名字与受众；没有改动就直接退出、什么也不写；写没落地（冲突、拒绝、结果未知）就留在编辑中，出了什么事照旧由标题下的 `WriteOutcome` 说。被整板 error 挡住的草稿「保存」禁用，原因在状态行里。（见 test/dashboardBuilding.test.tsx「saves on 保存 and reads the board again」「asks before 保存 writes over a shared board, naming it」「leaves at once on 保存 with nothing to save」）
- **「取消」是 `revert`**：有改动先问——与 ↺ 同一个问题、同一个对话框（`RevertDialog`）——再回到保存的样子并退出；没有改动直接退出。从没保存过的板没有可回的地方，所以没有「取消」。（见 test/dashboardBuilding.test.tsx「puts back the saved board on 取消, asking first」；浏览器里「CancelReverts」）
- **焦点**：按「编辑」时这颗按钮离开标题栏，焦点落到编辑条的「正在编辑」上（`tabIndex=-1`，只被送达、不是 Tab 站）；「保存」「取消」之后回到重新出现的「编辑」上（它在行尾，焦点回的仍是它本身）。都只在焦点真丢了（落到 `body`）时才做——从空板子的第一步进来，焦点已经在对话框或标题的输入框里。这一份外壳是工作台的（`ui/dashboard/buildShell.tsx` 的 `useBuildShell`）：「编辑」、焦点回到它、`onTabChange`／`onFiltersChange` 两个上报；离开守卫由 `useWorkbench` 守整份草稿。原来嵌入也共用它（A-14），[D36](../decisions.md#d36-嵌入一律不写档位是-staticinteractive2026-09-24) 起嵌入不搭板子。
- **编辑条与接线条的底色和边写在一处**（U-06，`variants.tsx` 的 `ModeBar`）：「正在编辑」与「正在给……接线」两条、每块面板底部的接线条，都是一条带边的浅灰带，原来在三处调用各写一遍颜色。
- **编辑中面板按草稿实时重跑，「保存」才写回**：每一次增删改都是 runtime 的一条 `DashboardEditing` 命令（`useDashboard().edit`），同时写进草稿与屏幕，正在编辑的全局筛选照样待应用（[runtime.md#dashboard](../runtime.md#dashboard)）。

### 添加（D22 A、B）

- **「＋ 添加 ▾」**（`ui/dashboard/AddMenu.tsx`，Base UI 菜单，两组）：数据——「已保存的视图…」「新建分析…」（后者只在 `onAddOwnedAnalysis` 在时——`DashboardWorkbench` 总是给，见「扩展」；嵌入或宿主自拼的板子没有它就没有这一项）；内容——「标题」「文字…」「图片…」「链接…」。带省略号的会先问一些东西；标题直接放上板，**就地改名**（焦点直接在名字框里，所以这一项让菜单不把焦点还给触发器）。
- **新面板放哪、多大**：当前标签页、从读者屏幕上能看到的第一行起的第一个空位（`fromRow`，按栅格顶边滚出视口多少行算），大小按种类（`defaultPanelSize`：指标卡 6、图 12、表格 24，按 24 列）。已保存的视图**先读进来再放**（`DashboardRuntime.preload`）——不读就不知道它是指标卡还是表格，从前一律按图的 12 列放；读进来的引用直接用于这个面板的子 runtime，不多读一次。（见 test/dashboardBuilding.test.tsx「adds a saved view from the picker, sized by what it shows」）视图还在读时按了「取消」，读完也不加：续体读的是那一刻的 `dashboard.edit`（不在搭就没有），runtime 在搭建之外也拒绝（Q-02）。（见 test/dashboardBuilding.test.tsx「adds nothing once 取消 ended the building while the view picked still loaded」）
- **选一个视图**（`ui/dashboard/ViewPicker.tsx`）：一个对话框，列出每个数据定义下的记录与分析视图（每次打开现读，刚在别处存的也在），**与视图切换器同一套分组**——系统视图、共享视图、我的视图——每行带种类图标、系统视图的锁、「种类 · 数据」一行说明；按名称搜索，按种类（全部／记录／分析，`ToggleGroup`）与数据定义（多于一个时，`Select`）收窄。**已经在板上的仍可再加**，行尾标「已在板上」（同一个视图两块面板、各看各的，是正常用法）；**共享板上的个人视图**当场标「只有你看得到」——允许放（D22 B，面板上随后是 `dashboard.panel.scope-too-narrow` 的 warning）。「替换视图…」用同一个对话框，标题换成「替换「X」显示的视图」。列表读失败的定义说一行 warning，其余照列。
- **内容的小表单**（`ui/dashboard/ContentEditor.tsx`）：文字（Markdown，默认一句提示语，`MAX_MARKDOWN_LENGTH`）、图片（地址必填、描述、点击时打开、显示方式「完整显示／铺满裁切」）、链接（一条一组：文字、地址、说明，可加可删，至多 `MAX_PANEL_LINKS`），每种都可选一个面板标题。内核会拒的东西——地址不是 http／https／mailto／相对路径、链接没有文字——**在字段上先说**（`data-invalid` + `aria-invalid` + `FieldError`，第一次提交之后才标），不写一块会被准入拒掉的面板。改的时候清空的可选项是删掉那个键，不留一个空字符串让内核拒。（见 test/dashboardBuilding.test.tsx「writes a note, a picture and links through their forms」）
- 加上、复制、移除都在板子的播报区说一句（「已添加「X」」「已复制「X」」「已移除「X」」）：指针看得见面板出现或消失，别人听不见。对话框关上时焦点回到打开它的那颗按钮——「＋ 添加」或面板的「⋯」——而不是跟着已关掉的菜单项落到 `body`（`FinalFocus`）。
- **会开对话框的菜单项把键盘交给对话框**（U-01，`ui/HandOffMenu.tsx`）：菜单收起时会把键盘还给它的触发钮，而它收起**晚于**对话框打开——收起动画还在走，焦点管理随后把键盘拿回板上的「添加」或「⋯」，落在模态对话框后面，打的字进了板子。所以会开对话框（或别的一出现就要键盘的东西，如就地改名的框）的菜单项是 `DialogMenuItem`，它所在的菜单是 `HandOffMenu`／`HandOffMenuContent`：选了这样一项，菜单收起时就把键盘留在它去的地方；别的项和 Esc 照旧把键盘还给触发钮。添加菜单的「已保存的视图…」「文字…」「图片…」「链接…」、面板菜单的「替换视图…」「改内容…」等都走它；对话框关上时把键盘还给哪颗仍由它自己的 `FinalFocus` 说。内容的小表单打开时键盘在第一个框里。（浏览器里 stories/view-engine/DashboardBuilding.test.stories.tsx「MenuItemsHandTheKeyboardToTheirDialog」：每一项用键盘选、菜单完全收起之后键盘仍在对话框里、打字进得了第一个框，Esc 回到触发钮）

### 面板菜单（D22 D）

每块面板标题行末尾一颗「⋯」（`ui/dashboard/PanelMenu.tsx`，名字「「X」的操作」），两组，**一项只在做得到时出现**（D4），一项都没有就不画这颗按钮：

- **看**（读与搭都有）：「在工作台中打开」——只在宿主给了路由钩子 `onNavigate(to)` 时（`DashboardWorkbench` 与 `EmbeddedDashboard` 同名属性，见下文「点击」），交出 `{ kind: 'view', definitionId, instanceId, scopeFilter, filter, from }`（`DashboardController.handOver`，D26 Q30），两部分都**已经映射成那个视图自己的字段名**：`scopeFilter` 是板子的固定范围与页面锁定、隐藏的筛选，到了工作台是作用域、没有 ✕；`filter` 是读者在板上设的值，到了工作台是视图**自己的**条件——视图开着就是「已修改」，每一条都能拿掉（✕ 整条拿掉，拿光了视图就是保存时的样子、不再「已修改」），「还原」一次拿掉。宿主把整个对象交给 `DataWorkbench` 的 `handOver`。板内分析没有已保存的视图，交出的是 `{ kind: 'unsaved', … }`：它自己的配置、读者的值并进它自己的条件，页面持有的同样是 `scopeFilter`。四个出口（这一项、追问、点击去另一个视图、板内分析）一种交法。`from` 是回板子的路：工作台据此在标题栏下画「返回〈仪表盘〉」，按下把 `{ kind: 'dashboard', …, filters, tab }` 交回宿主的路由——草稿仍是交来的样子就不问，读者在那之外改过才经离开守卫问，板子按离开时的筛选与标签页打开（D26 Q33）；宿主不必自己画返回键。（批 D「打开源视图」；见 test/dashboardPressUi.test.tsx「在工作台中打开 an analysis the board owns」、test/boardHandOver.test.tsx「leaving a board through the host’s route (D26 Q30)」「the way back to the board (D26 Q33)」；浏览器里 stories/view-engine/DashboardClicks.test.stories.tsx「OpenInWorkbenchKeepsBoardFilters」）「刷新这个面板」（`refreshPanel`）。「导出数据…」（见下一条）。
- **「导出数据…」**（记录面板与分析面板，D22 运维「单面板导出复用导出」，分析面板 D25 Q28）：打开的就是工作台的导出窗口（D14，`ExportDialog`）——它现在是受控的窗口（`open`／`onOpenChange`／`finalFocus`），工具栏上自带触发器的那一颗是 `ExportButton`；交付是同一个 `useExportOffer`（`ui/record/exportOffer.ts`），挂在面板的子 runtime 上（`ui/dashboard/PanelExport.tsx`）。所以文件里是面板画的那些列、每个值照格子的读法，条数、条件、列、文件名在按下之前摆明；条件里有板子的筛选到这块面板时映射成视图字段的样子（子 runtime 的作用域），文件的行就是面板显示的那些。**文件按面板的名字起**（`panelName`：读者看的就是它，作者给面板起的标题是板子上的叫法），`<面板名>-<yyyy-MM-dd>.csv`。面板的行没有勾选框，所以没有「选中」一项。**只在面板有行时出现**（P-17：没有结果的导出是一个空文件）。**分析面板**同一扇窗、同一个菜单项，交付换成分析工作台的 `useAnalysisExportOffer`（`ui/analysis/exportOffer.ts`）：文件是表格读法下的组——分组列在前、指标在后，「前 N 组」之内，合计行显示时在最后——不管面板此刻画的是表还是图（面板自己的看法换成饼图也一样），窗里按组说文件里有几行、没有「所有／选中」；有组才出现，见 [analysis.md](analysis.md#导出数据表格读法下的行d25-q28)。窗口第一次打开时才挂上（不导出的面板不跑导出的钩子）；关上时键盘回到这块面板的「⋯」。开关：`DashboardWorkbench` 的 `features.export`（与记录工作台同一个名字，缺省开），`DashboardGrid` 的 `panelExport`（缺省开，只读的板子缺省关），`EmbeddedDashboard` 的 `withExport`（缺省关，见 [embed.md](embed.md#开关)）。只读的板子开了导出，面板的「⋯」里就只有这一项。（见 test/dashboardPanelMenu.test.tsx「opens the export window over the panel’s rows, under the board’s filters, from the keyboard」「is on no panel where the host turned exports off」、「takes the groups as the table reads them, whichever the panel draws」；浏览器里 stories/view-engine/DashboardBuilding.test.stories.tsx「PanelExportWindow」）
- **改**（只在编辑中）：「改标题」（就地，Enter 或离开保留、Escape 放弃，空白回到按内容命名；标题卡片改的就是它的字）、「改这里的展示…」（分析面板，有 `onEditPresentation` 时）、「恢复为视图的样子」（面板有自己的展示覆盖、有 `onResetPresentation` 时）、「改内容…」（文字、图片、链接）、「替换视图…」、「复制」（原面板旁边第一个空位）、「移到标签页 ›」（板子有两个以上标签页时，子菜单列出其余的，没名字的按位置叫「标签页 2」）、「复制为共享视图并替换…」（见下文）、「另存为视图…」（板内分析，且有 `onSaveOwnedAsView` 时）、「点击时…」（分析面板，见下文「点击」）、「从仪表盘移除」（立即移除，可撤销）。
- **移除不问，可撤销**：按下就移除，板子的播报区说「已移除「北区订单」，按「撤销」可以找回」，键盘落到编辑条的「撤销」上（它的名字就是「撤销移除「北区订单」」）。原来先弹一个确认，因为 runtime 没有单步撤销、「取消」会连别的改动一起撤掉；有了撤销，问一句就只剩打断——移除的东西就在眼前、马上找得回。**删一个带面板的标签页照旧先问**（见下文「标签页」）：被删的面板多半不在屏幕上（删的常常是没在看的那一页），看不见的损失撤销救不了——没人会发现要撤销；「取消」编辑（整块板回到保存的样子）与共享板的「保存」也照旧先问：前者连撤销的历史一起丢掉，后者写到别人看得见的地方，都撤销不了。（见 test/dashboardBuilding.test.tsx「removes a panel at once, says so, and puts the keyboard on 撤销, which brings it back」；浏览器里「BuildFromEmpty」「RemoveThenUndo」）
- **「复制为共享视图并替换…」**（D22 B，用户拍板「共享板可引用个人视图并提醒、给复制为共享视图并替换」）：共享板上一块面板显示的是某人的个人视图——头部带着 `dashboard.panel.scope-too-narrow` 的那条 warning，别的读者在这块面板里什么也看不到——搭板子时它的「⋯」多这一项。**只在做得到时出现**（D4）：面板带那条 warning、显示的是这位读者打开着的已保存视图（别人的个人视图他本来就打不开）、他有在这份数据下建共享视图的权限（`engine.permissions(definitionId).createShared`；与「编辑」只给能保存的人同理，按不下去的入口不画）；读板子时、个人板上、已经共享的视图上都没有。按下去先问（`SaveAsDialog` 的 `share`，经扩展 `copyAsShared` 打开）：一句说清会发生什么——「〈视图〉」是个人视图、其他读者看不到；会复制成「〈数据〉」的一个共享视图**并立即保存**、面板改为显示副本、样子与筛选都和现在一样；个人视图不变；按「保存」保存仪表盘——下面只有标题一栏，**不问受众**（共享就是这一步的意思）；**标题从视图自己的名字开始**，不加「副本」：副本落在共享那一组、与原来的个人视图分开，而一块按视图命名的面板在板子上的名字也就不变（[D25](../decisions.md#d25-阶段-3-收尾的四条细化2026-09-24) Q29）。「复制并替换」是 `ViewEngine.copyPanelView`：复制视图**保存时**的配置（不带面板的展示覆盖、不带板子的筛选），权限、标题、准入与「另存为」同一套；写失败（拒绝、断网）对话框留着、在字段下说原因，什么也不改；成了之后面板改为引用副本（`referToSaved`，展示覆盖、点击、接线都留着，warning 随之消失），读屏听到「已复制为共享视图「X」，这块面板改为显示它」，键盘回到面板的「⋯」。副本是立即写的，「取消」这块板不会把它删掉——与「另存为视图」一样（D25 Q29）。**「撤销」这一步只把面板改回原来的个人视图**，已写下的副本留在视图列表里：撤销管的是这块板的草稿，删掉一个已保存的视图是另一件事（而且是一次对别人可见的写），重做时也不必再建一份——与「另存为视图」之后的撤销同理。（见 test/dashboardPanelMenu.test.tsx「copies the personal view a shared board stands on, after asking, and points the panel at the copy」「says why a copy was refused and keeps the question open」「is offered only on a shared board, over a personal view, to whoever may make a shared one」；浏览器里「CopyPersonalViewAsShared」）
- **窄屏只改标题、移除、调顺序**（D22 J）：一列的读法是推导出来的，里面摆不出能写回的位置，而复制、换标签页、添加都是一次摆放——所以窄于 `md` 时编辑条上没有「添加」，面板菜单的「改」只有改标题与移除。**调顺序**是每块面板标题行最前面的那枚抓手（`DashboardArrange.tsx` 的 `PanelOrder`，与其他可排序列表同一个 `DragHandle`，[D49](../decisions.md#d49-可排序的列表一律拖拽排序2026-09-25)）：指针把面板拖到另一块的位置上，或在抓手上按 ↑／↓ 移一位，或点一下选「移到最前／往前移一位／往后移一位／移到最后」；栅格外包着一个 `DragDropProvider`（搭板子时才有），拖的是面板卡片、不是栅格项（栅格项的位置是栅格自己的 transform），放下时不做库的归位动画（`dropAnimation: null`）——栅格自己把面板放过去，库朝旧位置的动画落不了地，卡片会一直 `pointer-events: none`。runtime 把目标位置写回宽布局（`reorderPanel(panelId, to)`，内核 `src/dashboard/layout.ts` 的 `reorderPanelIn` 一步一位地走过去）——每一步挑一个让它**在阅读顺序里正好挪一位**、其余面板动得最少的布局：两块先试互换位置（同一行里一样大的两块互换，别的都不动），再试把其中一块像手摆一样放到每一个格子上（往上越过它，就是把它上面那块往下越过它）；按「读出来的顺序偏离多少对、另外动了几块、几块换了行、挪了多远」挑；每个候选都压紧过，所以结果是静止的。咬合的板子（没有一个候选能让它挪到那一位）退回成按目标顺序在第一列叠放——唯一一定读得对的布局，代价是这块板的并排（[D25](../decisions.md#d25-阶段-3-收尾的四条细化2026-09-24) Q27）。菜单里到头的项在、但置灰；键盘留在抓手上、随面板到新位置；板子的播报区说「「北区订单」现在是第 2 个面板，共 5 个」。每一次移动（不论挪几位）是撤销的一步。（见 test/dashboardLayout.test.ts「reordering the one-column reading」、test/dashboardHistory.test.ts「reordering the one-column reading, in the runtime」、test/dashboardBuilding.test.tsx「moves a panel along the column by its handle, says where it came to, and writes the grid back」；浏览器里 stories/view-engine/DashboardBuilding.test.stories.tsx「NarrowReorderByHandle」，含真指针拖动）

### 标签页（D22 E，批 B3）

- **标签栏在编辑条之下、面板之上，两个及以上才画**（`ui/dashboard/DashboardTabs.tsx`，经扩展的 `tabBar` 交给板子，嵌入视图里是栅格的 `header`）：一个标签页读作没有标签页。全局筛选对所有标签页生效，所以它在更上面。读的时候它是 Base UI 的 `Tabs`（`line` 变体，`tablist`），方向键在标签之间走、按下就切；栅格那一块随之是以当前标签命名的 `tabpanel`（`data-slot="dashboard-tab-panel"`）。**每个标签页是一张自己的栅格**：`DashboardGrid` 只画、只摆 `dashboard.tab` 那一页的面板，键盘摆放的邻居也只算这一页的；一页上什么都没有时说「这个标签页还没有面板」，不说整块板子没有。面板的名字仍按整块板子编号，状态条说到别的页上的面板时名字对得上。屏幕上是哪一页是 runtime 的（`DashboardController.tab`，只有它在跑），不是扩展的一项——栅格与新面板的落点都读它。（见 test/dashboardExtensions.test.tsx「the tab bar」）
- **只跑屏幕上的那一页**（runtime 收口，见 [runtime.md#dashboard](../runtime.md#dashboard)）：打开时只有这一页的面板查询；切过去才跑那一页，切回来直接画留着的行；整板刷新只刷屏幕上的这一页，别的页切回来时补一次。（见 test/dashboardTabs.test.ts「only the tab on screen runs」；浏览器里 stories/view-engine/DashboardBuilding.test.stories.tsx「TabsRunOnlyTheTabShown」数了查询次数）
- **记住每人上次的标签页，当前标签页交给宿主写进地址**（D22 E，用户「全按推荐」）：读者按下一个标签页，工作台经 `engine.rememberTab` 把它记进这个人的偏好（`ViewPreferences.lastTabs`，[management.md](../management.md#列表偏好与默认视图)），下次打开从那一页开始跑——故事里从视图列表换到另一块板再回来，落在上次那一页。地址是宿主的：`DashboardWorkbench` 的 `onTabChange(tabId | null)` 在屏幕上的标签页每次变化时说一声（打开那一刻也说），`initialTab` 是宿主从地址里读回来的那一页——它随 `instanceId` 读，指的是那块板子的一页；没受控时只给第一块板子。板子没有那一页就退回上次看的那一页。包本身从不碰地址。嵌入的板子同样画标签栏、能切，但不记。（见 test/dashboardExtensions.test.tsx「opens on the tab the host names」「switches tabs in an embed too, and remembers nothing there」）
- **搭的时候标签栏是一张要整理的列表**：`tablist` 里只能放标签，所以编辑中（与编辑条同一个编辑状态）它换成一个有名字的列表（「标签页」），每一行一个抓手（`DragHandle`，指针拖、在它上面按左右方向键，或点一下选「移到…」，落位说「「异常」现在是第 2 个标签页，共 3 个」）、一颗显示这一页的按钮（屏幕上那一页是按下去的样子，`aria-current`）和一个菜单（改名、删除标签页——左移、右移由抓手的菜单代替，[D49](../decisions.md#d49-可排序的列表一律拖拽排序2026-09-25)）；末尾一颗「添加标签页」。一块没有或只有一个标签页的板子，编辑中只有这一颗「添加标签页」。新加的标签页随即显示、名字就地可改（全选，直接打字替换）；双击或菜单里的「改名」也能改名（键盘直接在名字框里，菜单收起不把它拿走）；框是共用的 `RenameInput`（[README.md「就地改名只有一个框」](README.md)）：Enter 或离开保留、Esc 放回原名，空名 Enter 不动、离开放回原名，改完键盘回到那一页的按钮。**删一个带面板的标签页先问**（`AlertDialog`：它上面的 N 个面板会一起删除；按「保存」之前不会存下，按「撤销」可以找回），空的直接删——有了撤销也还问：被删的面板多半不在屏幕上，看不见的损失没人会去撤销（见上文「移除不问，可撤销」）。这些都是草稿里的编辑（`DashboardEditing` 的四个标签页命令），「保存」才写回。（见 test/dashboardExtensions.test.tsx「adds, renames, moves and deletes tabs while the board is built」「renames a tab by double-clicking it, and Escape keeps the old name」；浏览器里「TabsBuilt」）
- **移到标签页**：面板菜单的「移到标签页 ›」（上文「面板菜单」）放进那一页的第一个空位，离开的那一页若空了就说「这个标签页还没有面板」。（见 test/dashboardExtensions.test.tsx「moves a panel to another tab, where the tab it left says it is empty」）

### 在仪表盘里新建分析（D22 C，批 B3）

- **一个大对话框，里面就是分析视图**（`ui/dashboard/NewAnalysisDialog.tsx`）：从「＋ 添加 ▾」的「新建分析…」或空板子的「新建分析」打开。标题「新建分析 · 〈数据〉」，先选数据（只列声明了分析能力、定义准入没 error 的；只有一份时已选好），然后就是工作台的 `AnalysisParts`——同一个托盘（范围、维度、指标、结果）、同一个结果（表格｜图表、可视化面板开在结果左侧，它的「‹」在这里叫「收起可视化」，因为没有视图列表可回），改了就跑照读者自己对这份数据的偏好。它不开追问（`followUps={false}`：对话框里没有「旁边」可开）。对话框自己持有一个未保存的分析视图（`engine.create`，缺省配置：记录数，一打开就有一个数），关掉或换数据时放掉。（见 test/dashboardExtensions.test.tsx「a new analysis made in the dashboard」）
- **手机上标题框在两颗按钮之上**（U-14）：标题框与「取消」「放进仪表盘」同在对话框底栏，注册表的底栏在窄屏是自下而上叠的，按钮跑到了要填的框上面，Tab 的顺序又是反的。现在窄屏自上而下叠，先是标题。（浏览器里 stories/view-engine/Dashboard.test.stories.tsx「NewAnalysisTitleFirstOnAPhone」）
- **标题跟着读法走，直到作者自己起名**：缺省就是结果工具栏那一句读法（`analysisReading`，「按仓库 · 记录数」），作者一改就不再跟。「放进仪表盘」在草稿被准入拒绝或标题为空时不可按，字段下一句说为什么；板子满了就留着对话框说「放不下更多面板了」。按下就是 `addPanel({ kind: 'view', owned, title }, spot)`：`spot` 是编辑条算好的放置点——屏幕上那一页、读者看得到的第一行起的第一个空位；读屏听到「「…」已放进仪表盘」，键盘回到「添加」。取消不留痕迹。（见 test/dashboardExtensions.test.tsx「is the analysis view in a dialog, named by its reading, and lands on the tab on screen」「keeps the title its author typed, and cancels without a trace」；浏览器里「CreateOwnedAnalysis」）
- **「另存为视图…」**：板内分析的「⋯」里那一项，打开的就是「另存为」那一个对话框（`SaveAsDialog` 的 `promote`：标题从面板的名字开始，一句说它会成为「〈数据〉」的一个视图、面板改为显示它，受众先选板子自己的那一个——共享板上存成个人视图就是一块别人看不到的面板）。保存是 `ViewEngine.saveOwnedView`，面板随即改为引用它（展示覆盖保留），菜单里这一项随之消失；失败留在对话框里说。（见 test/dashboardExtensions.test.tsx「is saved as a view of its own, the panel pointing at it」；浏览器里「PromoteOwnedAnalysis」）

### 面板自己的展示（D22 D，批 B3）

- **「改这里的展示…」打开的就是可视化面板**（`ui/dashboard/PresentationDialog.tsx`，只给分析面板：记录面板没有可视化面板可画的东西）：左边是这块面板改后的样子（与栅格里的面板同一个子 runtime、同一个画法），右边是工作台的 `ChartPicker` 与 `ChartOptions`——图型网格、这种图的选项、表格合计行。每一下都当场写进这块面板的 `presentation`（`setPresentation`，草稿与屏幕同时）：分析编辑器的 `setLayout`／`updateChart`／`setTotals` 在这里改写为写覆盖，而不是写视图；一个与视图自己一样的样子不算覆盖（那一项不写，全都一样就是 `null`）。换图型只重画不重跑（D20，runtime 的收口见 [runtime.md#dashboard](../runtime.md#dashboard)），合计行是一次自己的查询、照跑。「完成」收起，「取消」放回打开时的样子，对话框里的「恢复为视图的样子」随时可按；关上时键盘回到面板的「⋯」。（见 test/dashboardExtensions.test.tsx「a panel’s own look」）
- **面板头上说「此处改为〈图型〉」**（`presentationMark`，`DashboardPanel` 标题后一枚 `secondary` 的 `Badge`）：「此处改为饼图」「此处改为表格」，只改了合计行时是「此处改了展示」；覆盖不合身被丢掉时不带（面板头上已有那条 warning）。有覆盖时「⋯」的「改」组多一项「恢复为视图的样子」＝`onResetPresentation(panelId)`＝`setPresentation(panelId, null)`，没有覆盖就没有这一项。（见 test/dashboardExtensions.test.tsx「offers 恢复为视图的样子 only over a look of its own」；浏览器里「OverrideToPieAndReset」：换成饼图后面板画的是饼、查询数不变，从菜单恢复后回到柱状图，对话框的「取消」放回原样）

### 扩展：搭板子里住在编辑条与面板菜单之外的那几件

`DashboardEditExtensions`（`ui/dashboard/extensions.ts`，经 `DashboardEditExtensionsContext` 提供，`/ui` 导出）是**一份**接口，每一项可选，**没提供就没有对应的入口**：

```ts
interface DashboardEditExtensions {
  onAddOwnedAnalysis?(spot: { fromRow: number; tab?: string }): void; // 「新建分析…」：添加菜单与空板子
  onEditPresentation?(panelId: string): void; // 分析面板的「改这里的展示…」
  onResetPresentation?(panelId: string): void; // 有覆盖的面板的「恢复为视图的样子」
  onSaveOwnedAsView?(panelId: string): void; // 板内分析的「另存为视图…」
  copyAsShared?: {
    offered(definitionId: string): boolean; // 这位读者能不能建这份数据的共享视图
    open(panelId: string): void; // 共享板上个人视图面板的「复制为共享视图并替换…」
  };
  tabBar?: ReactNode; // 编辑条之下、面板之上
}
```

- **`DashboardWorkbench` 把五项与标签栏全部提供**（`ui/dashboard/building.tsx` 的 `useDashboardExtensions`：命令与它们打开的四个对话框），所以默认工作台里这些入口都在；包在工作台外面的宿主若提供了其中某一项，**那一项用宿主的**，其余仍是工作台的。嵌入视图、宿主自拼的 `DashboardBoard` 没人提供就没有这些入口。
- 入口只在**一处**出现、只听**一个**编辑状态：编辑条、添加菜单、面板菜单都从 context 读它，按 `panelCommands`（`ui/dashboard/commands.ts`）决定哪块面板出哪一项；编辑状态是工作台里那一个（按下「编辑」到「保存」／「取消」，每次打开一个视图重新开始），标签栏的编辑形态读的也是它。
- **屏幕上是哪一页不是扩展的一项**：它是 runtime 的（`DashboardController.tab`），栅格与 `spot.tab` 都读那里——只有一个来源，只跑那一页也由它说了算。
- 对话框关上时键盘回到打开它的那颗控件（打开时那个菜单的触发钮——「添加」或面板的「⋯」——或空板子上那颗按钮），经一个稳定的 `finalFocus`：对话框的焦点管理在它换成新函数时会重新布防、顺手把键盘交回去。打开对话框的菜单项让菜单**不**在收起时把键盘拿回触发钮（`DialogMenuItem`，见上文「添加」）——菜单收起的动画晚于对话框打开，从前键盘会在对话框开着时被拿到板上的「添加」，打进标题框的字只进去一两个（浏览器里「CreateOwnedAnalysis」守着）。（见 test/dashboardBuilding.test.tsx「shows the extensions’ entries only where they are provided」）

## 筛选（D22 F、G，批 C）

模型与运行时见 [model.md#dashboard-配置](../model.md#dashboard-配置) 与 [runtime.md#dashboard](../runtime.md#dashboard)；这里是屏幕上的样子（`ui/dashboard/FilterBar.tsx`、`FilterSettings.tsx`、`FilterWiring.tsx`，由 `BoardFilters.tsx` 的 `useBoardFilters` 交给 `DashboardBoard`）。

- **筛选条在板子最上面**（F 屏）：在编辑条、标签栏、面板之上，对所有标签页生效；一个以「筛选」为名的 `region`。一个筛选一枚：名字、值控件、需要时一颗 ✕。**值控件就是条件编辑器的那几个**（`FilterValueEditor`，经内核的 `filterEditor` 选：日期是那套「日历／相对／命名时段」，文本或类别：自己列了一组的是选择；没列而接上的字段自己声明了一组（`enum` 的选项）就从那一组里选——显示标签、存代码，几个字段的同一个代码只出一次（内核 `wiredOptions`，照 Metabase 的类别筛选），读者选「待出库」、筛选存 `PENDING`，不必打协议代码；都没有才从接上的字段在数据里的值里挑、带记录数（`DashboardRuntime.valueCandidates`，与文本条件同一个 `SuggestedValue`），连这也没有才是输入框；ID 走宿主的候选源，数字、是否各是各的）；单值筛选存成一项的列表，控件里就是那一个值（`filterControlValue`／`filterStoredValue`）。没有「应用」：改了就跑（300 毫秒后面板自己重跑）。（类别见 test/dashboardFilterBar.test.tsx「picks a category from the labels its wired fields declare, and holds their codes」，浏览器里「CategoryPicksFromLabels」「TextOffersCountedValues」）
- **一枚的边就是它控件的边**（U-06，`variants.tsx` 的 `ControlFrame`）：名字、值控件、✕ 自己都不画边（D12：它们是条件编辑器的胶囊控件），所以这一枚的边就是控件的边，用 `--input`——两个主题下都到 3:1（WCAG 1.4.11）；原来是 `--border`，在这一枚的底色上量到 1.22:1。锁定的筛选的读数、设置弹层里的列表框同一个配方。（浏览器里 stories/view-engine/Dashboard.test.stories.tsx「FilterChipEdgesInLightTheme」「FilterChipEdgesInDarkTheme」）
- **必填带星号，永远有值**：星号画出来，读屏念「创建时间（必填）」（名字写在这一枚 `group` 的 `aria-label` 上，星号本身 `aria-hidden`）；在默认值上没有 ✕，改过之后那颗是「把「创建时间」恢复为默认值」（`RotateCcwIcon`），「清空」把它放回默认值而不是清空。非必填的 ✕ 是「清除「仓库」」。**「清空」**在筛选条末尾，一切都在起点（必填在默认值、粒度在默认粒度、其余为空）时禁用。（见 test/dashboardFilterBar.test.tsx「never leaves a required filter empty: its ✕ and 「清空」 go back to the default」；浏览器里 stories/view-engine/DashboardFilters.test.stories.tsx「RequiredNeverEmpty」）
- **必填的日期改成「指定日期」**（2026-09-25，「选择 指定日期 无效」）：「指定日期」在选出一天之前没有答案，非必填的一枚就此空着等；必填的一枚空一下就被放回默认值，类型当场跳回「时间段」、日历从没画出来。现在必填的日期从类型里换形状时**不写空**：此刻的值照跑，日历空着等一天；选出一天那一刻才写进去、面板按它重跑，走势卡锚到那一天「较前一日」（D39）；换回「时间段」是同一个选择框。值控件由 `FilterValueEditor` 的 `required` 知道这一点（`DateValue`：形状只在值本身变了时跟着值走）；一枚 `BETWEEN` 的日期此刻是「近 N 天」时，旁边换出的日历照样选两头（`dateTime` 种类给 `relativeDate` 也带上 `range`）。**日历不随板子重画**：登记处的日历每次渲染都把自己的部件做成新组件，渲染一次就是一个新日历——面板一应答板子就重画，正在按的那一天被换出文档，焦点落回 `body`，这一下什么也没选上；所以 `SurfaceCalendar` 是 `memo` 的，`AbsoluteDate` 交给它的已选日子与回调在值不变时不变（见 test/filterValueEditor.test.tsx「keeps the calendar it drew while its host renders again」）。（见 test/dashboardFilterBar.test.tsx「turns a required date into a day off the calendar, and back」；浏览器里 stories/view-engine/Home.test.stories.tsx「PicksASpecificDay」）
- **筛选条说的就是板子读的**（2026-09-26 审查 P1-1、P1-10）：必填的日期换到「指定日期」、还没选出一天时，此刻的值照跑，但它已不是筛选条上写的那个——值控件说它在等（`DateValue` 的 `onAwaiting` → `DashboardController.awaiting`），接上这枚筛选的面板把正文换成「请选择日期」（`Empty`，`panel-awaiting-date`），不再摆旧值的数；选出一天或换回「时间段」就回来。**只取一天的日期筛选**（`oneDay`，设置里「只选一天」）类型只有「指定日期」「时间段」，时间段只有今天、昨天、前天，日历只选一天、存成两头同一天（不再是「从这天起」）；运营日报的日期就是这种。**一天的区间写一次**：「2026年9月21日」，不写「2026年9月21日 – 2026年9月21日」。**非必填的日期空着时**，类型写「按各面板自己的范围」，它本身是一个选项（选它就清空），「清空」也回到它——从前写「指定日期 · 选择日期 – 选择日期」，面板却在读上月、今年。（见 test/boardDateFilter.test.tsx）
- **时间粒度是一组「按日｜按周｜按月」**（`ToggleGroup`，按 `units` 的顺序，名字「时间粒度」）：按下就整板重算，接得上的面板都换成那个粒度（`regrouped`）；换不了的面板头上带那条 note（「保留自己的时间粒度」）。编辑中旁边一颗「移除时间粒度」。（见 test/dashboardFilterBar.test.tsx「switches the time grouping of every panel that can take it」；浏览器里「TimeGroupingSwitches」数了查询次数）
- **在当前标签页上什么也没影响的筛选淡一档**（`filtersOnTab`，`ControlFrame` 的 `data-idle`）：边框变虚、底色退到背景，字保持原来的对比度——整枚降透明度会让文字过不了 axe 的对比度；旁边一颗 `InfoIcon` 的 `IconTooltip`，悬停与聚焦都说「这个标签页里没有受『仓库』影响的面板」。时间粒度同理（这一页没有面板按时间分组时）。（见 test/dashboardFilterBar.test.tsx「draws a filter that reaches nothing on the tab quieter, and says why」）
- **「不受『〈筛选〉』影响」**：一个**此刻有值**的筛选没接上某个数据面板时，那个面板的标题后一枚 `ToneBadge`（warning 语气、不带圆点，`data-slot="panel-not-reached"`），几个就并成一句：不受「仓库」、「时间」影响（这句单独站在屏幕上，所以用「」而不是『』）。没值的筛选什么也没筛，就不说——否则一块板子上每个面板都挂一串。徽标**放不下时折行**，不越过面板的边（`PanelMarks` 的 `BADGE_WRAPS`；注册表的徽标一行、`nowrap`、居中又藏起溢出，半宽指标卡上「Not filtered by “Time range”」两头都被切掉——补偿控制台走查 W11），「按下筛选」的徽标同一条。（见 test/dashboardFilterBar.test.tsx「runs a value on its own, only on the panels it reaches, and clears it」；浏览器里「UnwiredPanelSaysSo」；手机宽度下半宽卡上的徽标在卡内、不溢出，见 stories/view-engine/Home.test.stories.tsx「OnAPhone」）
- **按下之后键盘落在哪**（U-02）：筛选条上有几下按下去会把按的那颗控件拿走，原来键盘随之掉到 `body`，下一个 Tab 从页面开头走起。现在照面板的规矩（`useListFocus`、撤销的 `land`）落到下一个说得通的控件上（`ui/dashboard/landing.ts` 的 `useLanding`：按下时说要落在哪，拿走它的那次渲染之后再落；只在键盘真的掉了时才挪，被菜单、弹层、对话框拿走的不动）——✕ 落回它清掉的那一枚的值控件；「清空」被自己这一下禁用，落到第一枚的值控件；「移除时间粒度」落到「添加筛选」，从「添加筛选」加回时间粒度落到那组「按日｜周｜月」上；「完成接线」落回接线开始的那个齿轮；「移除筛选」落到顶上来的那一枚，最后一枚就落到「添加筛选」；关掉「链接里有的筛选没能用上」落到筛选条上。（见 test/dashboardFilterBar.test.tsx「goes back to the settings wiring started from, and on past a removed filter」）
- **地址是宿主的**：`DashboardWorkbench` 的 `initialFilters`／`onFiltersChange`（批 C1）；浏览器里「ValuesReachTheHost」。嵌入的板子同名（`initialFilters`／`onFiltersChange`，只含读者的筛选），每个筛选另有页面给的三态（可调 `adjustable`、锁定、隐藏），锁定与隐藏的值由 `pageValues` 给、从不走地址，见 [embed.md](embed.md#仪表盘的筛选逐个三态)。
- **地址里用不上的筛选说一次**（`BoardFilters.tsx` 的 `FiltersRefused`）：宿主交来的地址是读者的，可能已经过期——点名一个板子已经没有的筛选、给了它收不下的值——运行时收下能用的、其余不收（`DashboardRuntime.refusedFilters`，[runtime.md#dashboard](../runtime.md#dashboard)）。不收的在筛选条上方一条 `Alert` 说：标题「链接里有的筛选没能用上」，下面是目录里每一条的原因（「这个仪表盘没有筛选 gone。」……）；其余照常生效，筛选条上看得到。它**可以关掉**（「关闭」，键盘落到筛选条上），与嵌入视图被拒的作用域不同：那一条是页面的条件，每次都被拒、下面的行比页面要的宽，只要它还在就得一直说；这一条只关于板子打开的那一刻，筛选条已经说了此刻生效的是什么，读者可以再设。再打开一次、又有被拒的，再说一次。工作台与嵌入都有；嵌入里页面给的（锁定、隐藏）被拒是页面的事，照旧在上面按页面的说（[embed.md](embed.md#仪表盘的筛选逐个三态)），这一条只说读者自己那一份。（见 test/dashboardWorkbench.test.tsx「opens under what it takes of a stale address, the rest left out and said (D22 F)」「says nothing over the bar when the address was taken whole」、test/embeddedDashboard.test.tsx「opens on what it takes of an address gone partly stale: one stale name or bad value costs only itself」）
- **标题栏里原来那个条件折叠面板去掉了，「正在显示」条也不画**（[D27](../decisions.md#d27-仪表盘不画正在显示条2026-09-24)）：筛选条就是板子的「正在显示」。记录视图与分析视图留着那一条，是因为它们的筛选面板可收起、改了要「应用」才生效，要有一处说这次实际在什么条件下跑；仪表盘的筛选改了就跑，没有草稿与已应用两态，同一件事说两遍违背 D12。`DashboardWorkbench` 给 `WorkbenchShell` 的 `applied` 是 `false`，嵌入的板子本来就不画。（见 test/dashboardWorkbench.test.tsx「draws no applied band: the filter bar is what the panels show (D27)」；浏览器里 stories/view-engine/Dashboard.test.stories.tsx「GlobalFilter」）
- **固定范围在筛选条那一行，读者只读、作者整体删掉**（D23 Q16、D26 Q31、D27，`FilterBar.tsx` 的 `FixedScope`）：批 C 之前存下、筛选收不下的整板条件（`fixed`）在筛选条最前面一枚，写作「固定范围 仓库 不是 西南」，读的时候一颗锁（`IconTooltip`：「仪表盘本身让每个面板都只看这个范围，这里改不了」），没有 ✕——它是板子的，读者拿不掉。条目由 `useFilterEditor` 的 `fixed` 读出（工作台用 `useWorkbench` 那一份，嵌入自己取一份），经 `DashboardBoard` 的 `fixed` 交给筛选条；窄屏时它站在「筛选」按钮旁。**编辑中作者可以整体删掉它**（D23 Q16）：搭建时锁换成一颗 ✕（「移除固定范围」），按下即 `removeFixedScope`——`fixed` 成为空树，草稿与屏幕一起、面板随之重跑，「完成」时随板子保存；空树仍是那个成员，所以再打开不会被当成批 C 之前的板子再迁一次。它是搭板子历史里的一步（「撤销移除固定范围」），与其余编辑一样撤销、重做；这一枚随 ✕ 一起不在了，键盘落到「撤销」上——与移除面板落在同一处——读屏说「已移除固定范围」。只删整枚、不逐条删：它是一棵任意的树，逐条拿掉一支可能改变布尔含义（拆得开的叶子读取时已经迁成筛选的默认值）。读者没有搭建，永远拿不掉。（见 test/dashboardFilterBar.test.tsx「reads the board’s fixed scope at the head of the bar, with nothing to remove it by」「lets its author take the fixed scope out whole while building, undone like any edit」、test/dashboardEditing.test.ts「has its fixed scope taken out whole by its author, one step, and saved empty」；浏览器里「PreBatchCFixedScope」「PreBatchCFixedScopeRemoved」）
- **窄于 `md` 时筛选条收成一颗按钮与底部抽屉**（D26 Q38，`FilterSheet.tsx`）：一列的读法里（与栅格同一个断点读法，`header` 交下来的 `narrow`）筛选条只有一颗「筛选（已设 n 个）」（n 是读者自己那几个此刻有值的筛选；一个没有就只写「筛选」），按下打开注册表的 `Sheet`，从底边出来——与窄屏的可视化面板同一种做法（`SidebarColumn`），上面的面板还看得见、只压暗不模糊，在里面设的值照样改了就跑；抽屉里就是宽屏那一条的全部：每一枚筛选（编辑中带设置与抓手）、时间粒度、「清空」。读者改不了的——固定范围、页面锁定的筛选——照样只读地站在按钮旁（锁定的那几枚抽屉里也有，是整条筛选的一部分）。原来窄屏是一行横向滚动，一屏只看得到一枚半，那半枚还是个控件。（见 test/dashboardFilterBar.test.tsx「folds into one button and a sheet below md, the held ones read beside it (D26 Q38)」；浏览器里 stories/view-engine/DashboardFilters.test.stories.tsx「FiltersInASheetOnAPhone」）

## 记录面板：总数、翻页与宿主的命令（D39）

- **空着时说空在哪里**：记录面板查不到行时用工作台同一句话——视图自己的条件、板上的筛选或页面的收窄里有任何一条在起作用，就是「没有记录符合当前条件。」（`label.record.empty-hint`）；什么都没收窄才是「还没有任何记录。」。面板上不给出路按钮：条件是视图与板子的，在它们设的地方改（`emptyHintOf`，`EmbeddedView` 同一条）。（见 test/recordPanelHost.test.tsx「an empty record panel says what it is empty of」）
- **比面板宽的表朝还有列的一侧淡出**（补偿控制台走查 W13：1280 宽下集群面板七列比面板宽，macOS 默认藏起滚动条，最后一列「最早下次重试」像是不存在）：表格在面板正文里横向滚，正文按滚动位置在还有内容的那一侧淡出 32px（`dashboard/scrollMore.ts` 的 `useScrollMore`，`data-scroll-more` 是 `end`／`start`／`both`）——没滚时右侧淡出，滚到头换成左侧，全放得下时什么也不画。淡出是正文自己的 `mask-image`，盖得到粘住的表头与合计带，又不在它们上面多一层去挡按下；它在正文自己的竖向滚动条前停住，滚动条完整。正文是 Tab 停靠点，方向键就能横着滚。量在滚动时、正文尺寸变了、正文里的内容变了（结果到了、加了列）时，每帧至多一次。最后一列在滚到头时完整、右边留的仍是面板的边距（上一条）；表头与合计照旧粘在正文的上下两头。（见 test/scrollMore.test.tsx；浏览器里 stories/view-engine/CompensationOverview.test.stories.tsx「WideTableFades」在 1280 宽下量：未滚时 `end` 且有淡出，滚到头时 `start`、末列右缘在正文里，竖着滚表头仍在顶上）
- **表格面板按行长高，至多八行；还装不下的说出还有多少**（2026-09-26 Storybook 审查 [P1-3](../../../../storybook/docs/review-2026-09-26.md)：首页「付款超过 48 小时仍未发货」11 行只露 6 行、「发货仓」列被裁，品类「退款率最高的商品」前 10 只露 8 行，渠道与地域「各活动…」末行只露一半，售后「售后单明细」的「实退金额」被裁，「值班手册」183px 的内容装在 118px 的正文里——都看不出能滚）。
  - **长高**：读板子时，正文里是记录表或分析表格、或是文字面板与链接面板（内容自有高度的几种）时，面板报出「把正文整个画出来要多高」（`useScrollMore` 的 `whole`：卡片高度减正文内高、加正文里各块内容的高度——按内容量、不按 `scrollHeight`，后者从不小于正文，长高过的面板就永远量不出下一页短了）；栅格按整行把它长到装得下，至多 `GROWS_TO_ROWS`（8 行，710px：笔记本屏幕在板子标题下还看得全一块这么高的面板，表头、提示与翻页都在眼里，而不是一块跑出页面的面板里再套一层滚动），**从不比保存的高度矮**（与图表并排的短表不让那一行参差），作者给得比 8 行还高的照旧（`ui/dashboard/panelFit.ts` 的 `fittedLayout`）。它下面的面板一起往下挪、与它之间原有的空行不变，别的面板不动、不横移，存档里叠在同一格的两块仍叠着（内核 `grownLayout`，与 `stackedLayout` 一样是一种**读法**，从不交给 `place`）。图表、指标卡、空态与骨架铺满给它的地方，不报高度，也就不长。**搭的时候**每块面板按保存的大小画——拖与缩放改的是那个大小。窄屏的一列同样长。
  - **还有多少**：正文的末角挂一枚提示（`ui/dashboard/ScrollCue.tsx`，`Badge secondary`）：「下面还有 5 行」「右边还有 2 列」、两者都有时「下面还有 9 行，右边还有 3 列」，正文里没有表格时「下面还有内容」（`label.panel.more-rows`／`more-columns`／`more-both`／`more-below`，英文按单复数）。行数是没有整行在视野里的行——粘住的合计带遮住的也算——分析表格虚拟绘制时按 `aria-rowcount` 与视野里最后一行的 `aria-rowindex` 算；列数是表头里右缘越过正文右边的列（填充列不算）。竖向不淡出：那会把粘住的表头与合计带洗白，数出来比淡出多说一件事。横向仍是上一条的淡出，提示再补一个数。提示站在横向滚动条与粘住的合计带之上（`inset`），不压住它们；它是**滚动位置的画面，不是控件**：不进 Tab 顺序、`aria-hidden`、按下穿透到下面的行——正文本身是以面板名命名的 Tab 停靠点，读屏读表格自己的行。滚到底、滚到头，对应的那一半就不说了。没用 shadcn 的滚动区（scroll-area）：它把原生滚动条换成自画的一层并在正文外再套两层，而正文这个原生滚动口是粘住的表头与合计带、冻结列、虚拟行（TanStack Virtual 的 `getScrollElement`）和 `styles.css` 里「表格贴到面板两边」的 `dashboard-panel > card-content` 选择器共同依赖的，换掉它要把这些一起搬走，解决的却只是 macOS 藏滚动条这一半——数出来的提示两种系统上都在。
