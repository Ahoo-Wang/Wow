# 集成测试

此目录包含 Fetcher 库及其扩展的集成测试。这些测试验证各个组件是否能正确协同工作并与外部服务交互。

## 目录结构

- `src/` - 测试对象和工具
  - `cosec/` - COSEC 集成工具
  - `decorator/` - 装饰器模式集成测试对象
  - `fetcher/` - 核心 fetcher 集成测试对象
  - `generated/` - OpenAPI 生成器生成的代码
  - `wow/` - Wow CQRS 集成测试对象
- `test/` - 实际测试文件
  - `decorator/` - 装饰器模式集成测试实现
  - `fetcher/` - 核心 fetcher 集成测试实现
  - `openai/` - OpenAI 客户端集成测试实现
  - `wow/` - Wow CQRS 集成测试实现

## 运行测试

运行所有集成测试：

```bash
pnpm test
```

运行特定测试文件：

```bash
pnpm test test/<path-to-test-file>
```

例如：

```bash
pnpm test test/fetcher/typicodeFetcher.test.ts
```

## 测试对象

### Typicode Fetcher

测试核心 Fetcher 功能与 JSONPlaceholder API (https://jsonplaceholder.typicode.com) 的交互。验证：

- GET, POST, PUT, PATCH, 和 DELETE 操作
- 请求/响应处理
- 拦截器功能

### COSEC 集成

测试 COSEC 安全扩展，包括：

- 请求签名
- 响应验证
- 令牌管理
- 设备 ID 处理

### 装饰器模式

测试装饰器扩展，提供：

- API 端点定义
- 参数处理
- 结果提取
- 方法映射 (GET, POST, 等)

### OpenAI

测试 OpenAI 客户端集成，包括：

- 聊天补全（流式与非流式）
- 基于事件流扩展的服务器发送事件 (SSE) 处理

## 使用示例

`src/` 目录中的文件也作为各种 Fetcher 组件的使用示例：

### 核心 Fetcher 使用

```typescript
// integration-test/src/fetcher/typicodeFetcher.ts
import { NamedFetcher } from '@ahoo-wang/fetcher';
import {
  authorizationRequestInterceptor,
  cosecRequestInterceptor,
  authorizationResponseInterceptor,
  cosecResourceAttributionInterceptor,
} from '../cosec';

export const typicodeFetcher = new NamedFetcher('typicode', {
  baseURL: 'https://jsonplaceholder.typicode.com',
});

typicodeFetcher.interceptors.request.use(cosecRequestInterceptor);
typicodeFetcher.interceptors.request.use(authorizationRequestInterceptor);
typicodeFetcher.interceptors.response.use(authorizationResponseInterceptor);
typicodeFetcher.interceptors.response.use(cosecResourceAttributionInterceptor);
```

### COSEC 安全使用

```typescript
// integration-test/src/cosec/cosec.ts
import type {
  CompositeToken,
  CoSecOptions,
  TokenRefresher,
} from '@ahoo-wang/fetcher-cosec';
import {
  CoSecRequestInterceptor,
  AuthorizationRequestInterceptor,
  AuthorizationResponseInterceptor,
  DeviceIdStorage,
  JwtTokenManager,
  TokenStorage,
} from '@ahoo-wang/fetcher-cosec';

export class MockTokenRefresher implements TokenRefresher {
  refresh(token: CompositeToken): Promise<CompositeToken> {
    return Promise.reject(`Token :${token} refresh failed`);
  }
}

const cosecOptions: CoSecOptions = {
  appId: 'appId',
  deviceIdStorage: new DeviceIdStorage(),
  tokenManager: new JwtTokenManager(
    new TokenStorage(),
    new MockTokenRefresher(),
  ),
};

export const cosecRequestInterceptor = new CoSecRequestInterceptor(
  cosecOptions,
);
export const authorizationRequestInterceptor =
  new AuthorizationRequestInterceptor(cosecOptions);
export const authorizationResponseInterceptor =
  new AuthorizationResponseInterceptor(cosecOptions);
```

### OpenAI 使用

```typescript
// integration-test/test/openai/openai.test.ts
import { OpenAI } from '@ahoo-wang/fetcher-openai';

// 使用您的 API 配置初始化客户端
const openAI = new OpenAI({
  baseURL: 'https://api.openai.com/v1',
  apiKey: 'your-api-key-here',
});

// 流式聊天补全（服务器发送事件）
const stream = await openAI.chat.completions({
  model: 'gpt-3.5-turbo',
  messages: [{ role: 'user', content: 'Hello, how are you?' }],
  stream: true,
  max_tokens: 1,
});
for await (const event of stream) {
  console.log('Stream event:', event);
}

// 非流式聊天补全
const response = await openAI.chat.completions({
  model: 'gpt-3.5-turbo',
  messages: [{ role: 'user', content: 'Hello, how are you?' }],
  max_tokens: 1,
});
console.log('Chat response:', response.choices[0].message?.content);
```

## 环境变量

某些测试需要设置环境变量：

### LLM 客户端测试

要测试 OpenAI 客户端（聊天补全与事件流），请设置以下环境变量：

- `FETCHER_LLM_BASE_URL` - LLM API 的基础 URL
- `FETCHER_LLM_API_KEY` - 用于认证的 API 密钥
- `FETCHER_LLM_MODEL` - (可选) 要使用的默认模型

示例：

```bash
export FETCHER_LLM_BASE_URL="https://api.openai.com"
export FETCHER_LLM_API_KEY="your-api-key-here"
pnpm test test/openai/openai.test.ts
```

如果未设置这些环境变量，LLM 测试将自动跳过。

## 添加新测试

1. 在 `test/` 下的相应目录中创建新的测试文件
2. 导入要测试的组件
3. 使用 Vitest 框架编写测试用例
4. 确保测试是独立的，不依赖外部状态
5. 为外部服务测试添加所需的环境变量处理
