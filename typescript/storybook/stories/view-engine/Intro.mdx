# View Engine 导览

**研发声明「能怎样观察」，用户决定「这次怎样观察」，引擎负责编译、执行、渲染和保存。**

View Engine 是 Wow 的数据视图引擎。业务系统里大多数页面是「列表加筛选、排序、分页，偶尔一张图」，每个业务对象各写一套，观察方式一变就要改代码、发版。引擎把观察方式抽成可校验、可执行、可保存的配置：研发对每个业务对象接入一次，业务人员自己调整、保存、分享、嵌入。

这一页用几分钟讲清它能做什么，再带你走进一家虚构零售品牌的真实业务场景。左侧目录里的每个故事都能直接操作；保存、改名、删除都是真写入，只是存储在内存里，换一个故事就回到初始状态。

## 它怎样工作

<ValueChain />

定义随应用部署，是代码；配置是用户保存的观察方式，是数据，不是数据快照。所以同一份定义上可以有很多张视图：系统视图随定义发布，共享视图给一个团队，个人视图只给自己。

## 从哪里看起

1. [首页](./?path=/story/view-engine-首页--daily-report)：一个运营后台打开就是运营日报，宿主的外壳、导航与「催发货」都在，中间整块是引擎嵌入的仪表盘。
2. [订单工作台](./?path=/story/view-engine-业务场景-订单工作台--order-workbench-scene)：客服每天打开的几张系统视图，左侧视图列表里切换；改一个筛选，标题会提醒你还没保存。
3. [分析工作台](./?path=/story/view-engine-业务场景-分析工作台--order-analysis)：分析师存下的 {GUIDE_COUNTS.analysisQuestions} 个问题，每张打开就是答案。
4. [销售复盘](./?path=/story/view-engine-业务场景-销售复盘--overview)：四个标签页的月度复盘，点「编辑」就地搭板。
5. [订单详情页](./?path=/story/view-engine-业务场景-订单详情页--order-detail-page)：宿主的页面里嵌着一张视图，只看这一张单。

## 示例数据：栖木生活

「栖木生活」是一家虚构的中型家居生活品牌，做全渠道零售：三家店（官方旗舰店、直播专营店、企业团购店），五个渠道（自有 App、微信小程序、PC 商城、直播间、分销），四个仓（华东嘉兴、华北天津、华南东莞、西南成都）。

- **时间**：2024-09-01 到 2026-09-22，约 <Guide read={g => about(g.sizes.orders, '张')} />子订单、<Guide read={g => about(g.sizes.afterSales, '张')} />售后单、<Guide read={g => about(g.sizes.members, '个')} />会员、<Guide read={g => about(g.sizes.waybills, '个')} />包裹，外加订单的事件流。
- **现在**：钉在 2026-09-22 10:00（Asia/Shanghai），「今天」「昨日」「本月」「近 30 天」每次打开都一样，数字经得起核对。
- **怎么来的**：由种子生成、在浏览器里当场算，季节、大促、长尾、地域偏斜都在里面。数据源把引擎发出的 Wow 查询翻译成 MongoDB 查询作答，不预聚合——你看到的每个数，都是那个查询真的算出来的。

### 找一找：埋下的七处异常

数据里有意埋了七件「出了事」的事，每件都有一张分析或一块板能把它找出来。先自己找，再展开答案。答案里的数与名字不是抄在这一页上的：打开这一页时，把那张分析保存的查询当场跑一遍读出来，和点进去看到的是同一个数。

1. 一个商品的退款率在 2026 年 5 月之后突然升高，理由集中在「质量问题」。是哪一个？

   <Answer>

   是<Guide read={g => g.a1.title} />：退款率约 <Guide read={g => percent(g.a1.rate)} />，其余商品都不超过 <Guide read={g => percent(g.a1.othersAtMost)} />。看[分析工作台](./?path=/story/view-engine-业务场景-分析工作台--order-analysis)的「<Guide read={g => g.a1.view} />」，或[销售复盘的品类页](./?path=/story/view-engine-业务场景-销售复盘--category)的「<Guide read={g => g.a1.panel} />」。

   </Answer>

2. 2026 年 7 月下旬，某家承运商在两广的签收突然变慢。是谁、慢了多少？

   <Answer>

   是<Guide read={g => g.a2.carrier} />：台风那几天，<Guide read={g => monthDay(g.a2.week)} />起的那一周在广东的平均签收时长约 <Guide read={g => Math.round(g.a2.hours)} /> 小时，它平常一周约 <Guide read={g => Math.round(g.a2.usualHours)} /> 小时。看[履约与售后（省份 = 广东省）](./?path=/story/view-engine-业务场景-履约与售后--guangdong)的「<Guide read={g => g.a2.panel} />」。

   </Answer>

3. 2026 年 3 月 8 日，直播间的一场活动让之后几天的取消与退款大涨。原因是什么？

   <Answer>

   券可以叠加：<Guide read={g => monthDay(g.a3.day)} />那一天优惠占比约 <Guide read={g => percent(g.a3.discountRate)} />，其余日子都不超过 <Guide read={g => percent(g.a3.othersAtMost)} />。看[分析工作台](./?path=/story/view-engine-业务场景-分析工作台--order-analysis)的「<Guide read={g => g.a3.view} />」里最右边那一点。

   </Answer>

4. 2025 年双 11 零点刚过，有一种支付方式几乎全军覆没。是哪一种？

   <Answer>

   是<Guide read={g => g.a4.method} />：零点那一段选它的单，超时取消的占 <Guide read={g => percent(g.a4.timeoutRate)} />。看[分析工作台](./?path=/story/view-engine-业务场景-分析工作台--order-analysis)的「<Guide read={g => g.a4.view} />」。

   </Answer>

5. 有一小部分订单不知道是哪个城市的。它们在分布图里落在哪？

   <Answer>

   旧版小程序没有上报城市：<Guide read={g => g.a5.count} /> 张子单，约占 <Guide read={g => percent(g.a5.share)} />，城市等级为空，单独成一行「{zhCN['label.analysis.missing-group']}」，只落在「<Guide read={g => g.a5.channels.join('、')} />」那一列。看[销售复盘的渠道与地域页](./?path=/story/view-engine-业务场景-销售复盘--channels)的「<Guide read={g => g.a5.panel} />」。

   </Answer>

6. 2026 年 2 月，发货超时率冲到了一年里的最高点。为什么？

   <Answer>

   春节停运：<Guide read={g => monthDay(g.a6.week)} />起的那一周付款的单，发货超时率约 <Guide read={g => percent(g.a6.lateRate)} />，远过 <Guide read={g => percent(g.a6.redLine)} /> 的红线；节后积压消化完，<Guide read={g => monthDay(g.a6.backWeek)} />起的那一周回到红线以内。看[履约与售后](./?path=/story/view-engine-业务场景-履约与售后--fulfilment-tab)的「<Guide read={g => g.a6.panel} />」。

   </Answer>

7. 「现在」的前一天，一个仓的发货出了问题。是哪个仓、影响了多少单？

   <Answer>

   是<Guide read={g => g.a7.warehouses.join('、')} />仓，分拣线故障：<Guide read={g => g.a7.reportDay} />的「<Guide read={g => g.a7.onTimeCard} />」是 <Guide read={g => g.a7.onTime} />，低于 <Guide read={g => g.a7.target} /> 的目标；「<Guide read={g => g.a7.overdueView} />」的有 <Guide read={g => g.a7.overdue} /> 张，全在这个仓。看[首页](./?path=/story/view-engine-首页--daily-report)的<Guide read={g => g.a7.board} />，一路点到订单与它的事件流。

## 目录怎么读

- **接入导览**回答「我怎样把一个业务对象接进来」：定义、数据源、引擎与页面四个文件的真实代码，和它们跑起来的样子：[接入导览](./?path=/docs/view-engine-接入导览--docs)。
- **业务场景**回答「引擎能替我的业务做什么」：栖木生活的三块仪表盘、五个工作台、两张嵌入页与一面图型陈列。
- **能力**回答「某一项功能长什么样」：一项能力一页，场景尽量小。
- **组件状态**回答「空、加载、失败、冲突、窄屏时它是什么样」：[记录工作台](./?path=/docs/view-engine-组件状态-记录工作台--docs)、[分析工作台](./?path=/docs/view-engine-组件状态-分析工作台--docs)、[仪表盘](./?path=/docs/view-engine-组件状态-仪表盘--docs)、[EmbeddedView](./?path=/docs/view-engine-组件状态-embeddedview--docs)、[EmbeddedDashboard](./?path=/docs/view-engine-组件状态-embeddeddashboard--docs) 与 [筛选编辑器](./?path=/docs/view-engine-组件状态-筛选编辑器--docs)，用的是专为断言手挑的小夹具。
- **真实后端**回答「连上真服务是什么样」：[客户](./?path=/docs/view-engine-真实后端-客户-快照控制台--docs)、交易订单与商品定价三个服务的快照控制台与事件流分析台（补偿服务的控制台就是产品本身，在 `compensation/dashboard`），要先把服务转发到本机（见仓库里 Storybook 的 README）；文档页不挂载示例，打开目录不会发请求。

工具栏上的明暗开关、「Preset」与「Density」对场景都有效（主题一览自己钉住了每一条带的预设与明暗）。每个场景还有一个回归孪生故事，不在目录里，由 CI 在浏览器里逐个跑。
