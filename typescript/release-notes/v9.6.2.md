## Highlights

- **Generated models say which properties are required, and nullable numbers keep their `format`** (#4083, closes #4061). `wow-generator` adds `- required: …` to each model's doc comment and reads a nullable `anyOf: [{type: null}, X]` property's doc from `X`, so a nullable `int32`/`int64` is no longer indistinguishable from a decimal. Types are unchanged.
- **The `{Aggregate}AggregatedFields` enum lists the query fields an application declares** (#4081), not only the inferred ones, so clients generated from the document can query them.
- **Nested auto-configuration classes stay out of component scans** (#4079): on a host whose scan covers a Wow starter's package, they now register only through their auto-configuration, with its conditions and order.

> [!NOTE]
> A patch release: no breaking change. REST, storage and wire formats are those of 9.6.1. The OpenAPI document changes only in applications that declare query schema fields (#4081).

## Breaking

None.

## Behaviour changes

- **Declared query fields are documented** (#4081). In an application that declares query schema fields (classpath, working directory or `QuerySchemaRegistration` beans), the OpenAPI `{Aggregate}AggregatedFields` enum now lists them too; the view store's `ViewAggregatedFields` gains six `state.config…` members. Applications without declarations get the same document. If the declarations do not merge, the document lists the inferred fields and logs `Query schema of [...] does not merge; documenting its inferred fields.` at startup. **Act:** regenerate clients to pick up the new enum members, if you want them.
- **Nested auto-configurations follow their outer conditions on scanned hosts** (#4079). On a host whose `@SpringBootApplication` scan covers a Wow starter's package, the configurations nested in Wow's auto-configurations are registered only when the auto-configuration's conditions match, in auto-configuration order; for example, BI's route contract no longer appears when `wow.bi.script.enabled` is off. **Act:** nothing, unless you relied on those beans with the feature disabled.
- **Generated doc comments gain lines** (#4083). Regenerated clients add `- required: …` to model doc comments and `- format: …` to nullable numbers. **Act:** nothing; expect the added comment lines in a diff of generated output.

## Fixes

- **Component scans of a starter's package** (#4079): nested `@Configuration` classes of Wow's `@AutoConfiguration`s were registered before every auto-configuration and without its conditions.

## New

- **`RouterSpecs(currentContext, componentContext, routeContributors, querySchemaSources, querySensitivity)`** (#4081): renders the aggregated fields enum from the given query schema sources.
- **`QuerySchemaContext.declaredFields`** (#4081, `@InternalWowApi`).

## TypeScript packages

Every package in `PUBLISHED` ships together at `9.6.2`.

- **`@ahoo-wang/wow-generator`** (#4083): model doc comments list the required properties (`- required: a, b`, or `- required: (none)`); a property written as `anyOf`/`oneOf` of `{type: null}` and one non-reference schema is documented from that schema (its `format`, constraints, default and example), the property's own keywords first.
- The other packages: no changes.

## JVM (Maven)

- **Dependencies:** unchanged.
- **Docs and tests:** an inline `OpenAPIComponentContext` is documented as unable to render the built-in routes (#4080); `RouteIdentityBindingTest` pins the full-width space for blank identity path values (#4082).
