## Highlights

- **Datasets: query a warehouse table through Wow's admission and governance.** A dataset is a declared, table-like record set, such as an analyst's ClickHouse wide table. It is queried, scoped, masked and audited like an aggregate (#4116, #4120), served over `GET /dataset/{context}/{dataset}/schema` and `POST …/{count|list|paged|cursor|single|aggregation}` from a new ClickHouse backend (`wow-clickhouse`, #4122, #4127), and takes part in ABAC through declared tag columns (#4133). Datasets join, change and leave at run time (#4153); platform-level datasets and named ClickHouse sources serve a whole warehouse (#4156).
- **A dataset registry and an analytics server.** `wow-dataset-registry-*` drafts a dataset from a table, reviews each field's sensitivity, and publishes or retires it (#4155). `wow-analytics-server` is its own gateway over CoSec tokens, with a console that analyses any published dataset; it ships as a Docker image (#4182, #4183, #4185). `wow-cosec` reads the principal's ABAC tags from CoSec (#4177).
- **Aggregation windows computed by the server.** A derived metric can read `TOTAL`, `RUNNING`, `RANK` and `PREVIOUS` (period over period, year over year) over every group, not just the rows returned (#4169, #4170). MongoDB and ClickHouse compute the first three natively (#4173, #4179); the descriptor says which ones a storage offers (`analysis.windows`).
- **Group expanded elements by a field of their record.** An aggregation group takes `scope: ROOT`, so the events of a stream can be counted per day of the stream, on MongoDB and Elasticsearch (#4207, #4213). The descriptor says so (`analysis.rootGroups`).
- **The view engine** derives definitions from the dataset directory and keeps them in step with it (#4159, #4160, #4163), and stores a tenant's wording over a dataset in the view store (#4205, #4206). New: the kanban (#4113), the previous period and the same period last year (#4194, #4202), the top N within each value of a dimension (#4196), running lines computed by Wow (#4175), dimensions over a record's own fields while elements are expanded (#4217), stepping through records from the detail (#4152), and ⌘S / 「/」 anywhere on the workbench (#4146).

> [!IMPORTANT]
> **Existing REST routes, route ids, configuration, metric names and tags, header keys, storage formats and wire formats are those of 9.8.0**, and 9.8.x and 9.9.0 nodes can run side by side. Everything new is additive: the dataset routes, the `wow.query.datasets` and `wow.query.clickhouse.*` properties, and the descriptor's `analysis.windows` and `analysis.rootGroups`. The breaking changes below are signatures of SPI and internal classes; applications that use only the starter and the public entry APIs recompile against 9.9.0 without source changes.

## Breaking

**Policy.** Every breaking change in this release is a signature outside the compatibility scope of [`docs/compat-debt.md`](https://github.com/Ahoo-Wang/Wow/blob/main/docs/compat-debt.md) (`@WowSpi`, internal classes, or a constructor that gains a defaulted parameter), so there are no deprecation cycles or binary-only shims.

### TypeScript

#### `@ahoo-wang/wow-client`

- **Derived windows** (#4172). `DerivedExpressionType` and `DerivedExpression` gain the window node types. **Affects:** code that switches exhaustively over a derived expression's `type`. **Migrate:** handle or default the new types.

#### `@ahoo-wang/wow-view-engine`

- **`RecordLayout` gains `'kanban'`** (#4113). **Affects:** code that switches exhaustively over a record layout. **Migrate:** handle `'kanban'` or default it.
- **Derived lines** (#4194). `DERIVED_KINDS` and `DerivedKind` gain the two period comparisons, `DerivedGap` gains `'unsupported'`, `MarkWords` gains an optional `changeFrom`, and `AnalysisEditorController` gains `windows`. **Affects:** exhaustive switches over these unions, and hosts that implement `AnalysisEditorController` themselves. **Migrate:** handle the new members.
- **`ANALYSIS_AUTO_RUN_MEMBERS` gains `'top'`** (#4196). **Affects:** code that lists the members itself. **Migrate:** none beyond an exhaustive switch.
- **`AnalysisScope` gains `rootAggregations`** (#4217). **Affects:** code that builds an `AnalysisScope` by hand rather than with `analysisScope()`. **Migrate:** pass `new Map()`.
- **Message wording** (#4137, #4168). `label.write.unknown` and `runtime.query.forbidden` read differently; the keys are unchanged. **Affects:** hosts that override or assert these messages.

### Kotlin / JVM

#### `wow-query`

- **The dataset query model** (#4116, #4120). `QueryModelSchema(…, profile)`, `QuerySchemaCatalog(…, datasets)`, `QueryBackendStorages(…, datasetFactory, datasets)`, `SimpleQueryBackendProvider(…, dataset)` and `QueryModelCompiler.of(…, datasets)` gain a trailing defaulted parameter. `QueryModelProfile.identityField`, `payloadField`, `eventTimeField` and `systemField()` are nullable on the base class (the snapshot and event-stream profiles still return non-null). `QueryModelProfile.requiredScope` and `systemField()` are abstract on the sealed class, and `QueryModelProfile.of` returns `BuiltInQueryModelProfile`. The `QueryModelSchema.profile` extension is now a member. **Affects:** code that builds query backends, schema providers or the Catalog by hand, or reads a profile's fields through the base class. **Migrate:** recompile; handle `null` where you read a profile through `QueryModelProfile`; remove `import me.ahoo.wow.query.schema.profile`.
- **Aggregation windows and root groups** (#4169, #4207). `AnalysisDescriptor(…, windows, rootGroups)` and `AggregationSupport(…, windows, rootGroups)` gain trailing defaulted parameters; `AggregationGroup.Terms`, `.Histogram`, `.DateHistogram` and `.DatePart` gain a trailing `scope`, and so do the `terms`, `histogram`, `dateHistogram` and `datePart` functions of `AggregationQueryDsl`. **Affects:** Java callers that pass every argument, and binaries compiled against 9.8. **Migrate:** recompile; Java callers add the new argument (`null` for `scope`).
- **A ROOT group must lead the sort** (#4207). With `elements`, an `AggregationQuery` whose effective sort puts a `scope: ROOT` group after an element group is refused on construction (`groups with a ROOT scope must sort before the element groups.`). This is new syntax, so no existing query is affected.

#### `wow-spring-boot-starter`

- **Dataset serving** (#4127). `QueryAutoConfiguration.querySchemaCatalog(…)` takes the datasets and the dataset backend factory, and `QueryProperties`' constructor gains `datasets`. **Affects:** code that calls them directly. **Migrate:** recompile against the new signatures.

#### `wow-tck`

- `SnapshotQueryBackendSpec` gains `elementRootGroups` (default `true`) and two root-group cases, and its `saveAggregationStates` and `aggregationStates` are `protected` (#4207, #4213). **Affects:** a backend that runs the spec and cannot group elements by a root field. **Migrate:** override `elementRootGroups = false` and declare `AggregationSupport.rootGroups = SupportMode.NONE`.

### Server behaviour

None. Every existing route, route id and wire format is unchanged. The new dataset routes, the descriptor's `analysis.windows` and `analysis.rootGroups`, and the query's `scope` and window nodes are additive. In a mixed 9.8 / 9.9 cluster, a 9.8 node answers a query that uses `scope: ROOT` or a window node with a validation error, and its descriptor offers neither, so a client that reads the descriptor (wow-client, the view engine) sends them only to a 9.9 node.

### Pre-release changes

Signatures added after 9.8.0 and changed again before this release: `QueryDatasetScope` and `QuerySchemaCatalog`'s `datasets` (#4133, #4153), the ClickHouse dataset storage bindings (#4156), the protected `keepDefinitionsIn` of the engine's resources, which now takes a registrar (#4160), and `DatasetResources`' constructor, which gains `onWordingError` (#4206).

Labelled by the public-surface check for additive or documentation-only changes, not breaking: #4128, #4149, #4155, #4159, #4161, #4163, #4165, #4185.

## Behaviour changes

- **An element-scope rejection says how to reach the field** (#4124): `Field [x] requires its declared element scope: reach it through ELEMENT_MATCH in a filter, or expand it with the aggregation's elements.` **Act:** nothing, unless you match on the old text.
- **A command wait that runs out of time says what it waited for** (#4123): `Waiting for stage [PROJECTED] timed out after 10000ms.` in place of Reactor's internal text. **Act:** nothing, unless you match on the old text.
- **ABAC's missing-tag message** (#4133) reads `Query requires the principal's ABAC tags.` in place of `Snapshot query requires…`; the error code is unchanged.
- **Storage query backends register before the query fallbacks** (#4164). An application on MongoDB or Elasticsearch whose auto-configuration order happened to register the unavailable fallback first now gets its storage backend. **Act:** nothing.
