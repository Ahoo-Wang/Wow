## Highlights

- **`wow-openapi` is refactored from first principles** ([design](https://github.com/Ahoo-Wang/Wow/blob/main/documentation/designs/2026-10-09-wow-openapi-refactor-design.md)). Route contracts are pure data: route contributors only describe routes, and the renderer alone generates schemas and registers components. The route catalog is built once and generates no schema. The four aggregate route contributors are declarative tables. Main code shrinks from 6,408 to 5,339 lines, public classes from 114 to 53.
- **The OpenAPI document is rendered once and is safe to merge concurrently** (#4060). Before, every merge re-rendered into one shared context; concurrent merges (several Springdoc groups or locales) could throw `ConcurrentModificationException` or produce diverging documents.
- **Services that do not serve OpenAPI no longer generate JSON Schemas at startup** (#4057). Building the route catalog inferred every aggregate's query fields, a full schema generation per aggregate.
- **New module `wow-rest-contract`** (#4059) holds the REST wire vocabulary (header names, route paths, suffixes and variables, `BatchResult`, the BI script DTOs) and depends only on `wow-api`. `wow-apiclient` uses it instead of `wow-openapi`, so clients no longer pull swagger-core, victools and `wow-schema`.

> [!IMPORTANT]
> **REST routes, route ids, handler keys, the OpenAPI document and wire formats are those of 9.5.0**, so 9.5.x and 9.6.0 nodes can run side by side. Recompile against 9.6.0. Source changes are needed only for code that implements `RouteContributor`, builds route contracts, uses `wow-openapi` internals, or relied on dependencies `wow-apiclient` brought transitively ([migration guide](https://wow.ahoo.me/guide/migration#upgrading-from-9-5-to-9-6-0)).

## Breaking

**Policy.** As for 9.5.0, the maintainer chose a clean module over binary compatibility: no binary-only shims. App-facing header constants and `BatchResult` keep a deprecated alias until v10 (`docs/compat-debt.md`). Every v9 REST, storage and wire surface is unchanged.

### TypeScript

No API changes.

### Kotlin / JVM

#### `wow-rest-contract` (new) and `wow-apiclient`

- **The REST wire vocabulary moves to `wow-rest-contract`, package `me.ahoo.wow.rest`** (#4059): `CommandHeaders` (was `CommandComponent.Header`), `WowHeaders` (was `CommonComponent.Header`), `RoutePaths` (was `BuiltInHttpRoutePaths.Global`), `RouteSuffixes`, `RouteVariables` (was `BatchComponent.PathVariable`), `BatchResult`, and `bi.BiScript*` (was `me.ahoo.wow.openapi.contract.bi`). `wow-openapi` exposes the module as an `api` dependency. **Affects:** code that imports the moved declarations. **Migrate:** change the imports; the header constants and `BatchResult` still compile through deprecated aliases (see "Deprecations"). OpenAPI schema names stay `wow.openapi.*`.
- **`wow-apiclient` depends on `wow-rest-contract` and `wow-query` instead of `wow-openapi`** (#4059). It no longer brings `wow-openapi`, `wow-schema`, swagger-core / swagger-annotations and the victools jsonschema modules (compile classpath), nor `wow-models` (runtime). **Affects:** clients that used any of them through `wow-apiclient`, including a BFF serving its own Springdoc document that relied on `wow-openapi`'s `BoundedContextSchemaNameConverter`. **Migrate:** declare `io.swagger.core.v3:swagger-core-jakarta`, `me.ahoo.wow:wow-openapi` or `me.ahoo.wow:wow-models` yourself.

#### `wow-openapi`

- **`RouteContributor` describes routes only** (#4060). `contributeGlobal(currentContext)` and `contributeAggregate(currentContext, aggregateRouteMetadata)` lose the `componentContext` parameter; `id`, `order` and `category` are removed with `RouteContributors` and `RouteCategory` (the catalog orders routes itself). **Affects:** custom contributors. **Migrate:** drop the parameter and the properties; reference schemas with `HttpSchema.TypeRef(type, typeArguments)` and components with `HttpComponent.parameter / header / requestBody / response(key) { … }`.
- **Route contract model** (#4060, #4064). `componentRef: String?` on `HttpParameter`, `HttpHeader`, `HttpRequestBody` and `HttpResponse` becomes `component: HttpComponent<…>?`; `HttpRouteContract.pathSummary` / `pathDescription` are removed; `HttpSchema.TypeRef` takes `TypeRef` type arguments; `HttpSchema.ComponentRef`, `Long`, `Boolean`, `Formatted` and `Unspecified` are removed. A component builder's `HttpComponentContext` only generates schemas and references other components with `ref`. Two component instances of one kind and key must build equal components (compared after schema generation), otherwise rendering fails. **Affects:** code that builds or reads contracts.
- **`RouterSpecs`** (#4060, #4064): `mergeOpenAPIFromCatalog` is removed — call `mergeOpenAPI`; `componentContext` is private.
- **Component helpers removed** (#4060, #4062): the builder functions of `CommonComponent`, `QueryComponent`, `CommandComponent` and `EventComponent`; `QueryComponent`, `aggregate.event.EventComponent`, `CommonComponent.Response` and `BatchComponent`; `ApiResponseBuilder.listContent`. `OpenAPIComponentContext.componentSchema` has no default implementation. **Migrate:** reference components through `HttpComponent`; the migration guide lists the inlined key values.
- **Smaller public surface** (#4063). Internal now: `Https`, `PathBuilder`, `RouteIdSpec`, `Tags`, `OpenAPIExtensions`, `RouteCatalogBuilder`, `OpenApiRenderer`, `DefaultOpenAPIComponentContext`, the route metadata parsers, `BoundedContextSchemaNameConverter`'s companion, and the state, command-facade, command-wait, global-id and metadata contributors. `@InternalWowApi`: the command, snapshot, event and BI-script contributors. **Migrate:** `DefaultRouteContributors.all()` (public) for the built-in routes; write `Https` values as strings; `aggregateRouteMetadata()` / `commandRouteMetadata()` for route metadata.

### Server behaviour

None. Routes, route ids, handler keys, dispatch order, the OpenAPI document (JSON-equivalent) and wire formats are unchanged; `GET /wow/metadata` additionally lists the scope `me.ahoo.wow.rest` under the `wow.openapi` context.

### Pre-release changes

#4064 narrowed `HttpComponentContext`, made `RouterSpecs.componentContext` private and made `HttpComponent` equality include its kind — all APIs introduced earlier in this cycle and never released.

## Behaviour changes

- **OpenAPI rendering errors fail at startup** (#4060, #4064). With Springdoc present the document is rendered by `buildDocumentation()` at startup, so a broken contract (for example two different components under one key) fails application start instead of the first `/v3/api-docs` request. A first `mergeOpenAPI` on an event-loop thread without `buildDocumentation()` fails with a message asking for it. **Act:** library code that renders itself calls `buildDocumentation()` at startup.
- **`Schema` instances in the merged document are shared across merges; the key order of the `components` maps in the raw `/v3/api-docs` changed** (#4060). The JSON is equivalent. **Act:** an `OpenApiCustomizer` copies a Wow schema before changing it; compare documents as JSON.

## Fixes

- **No JSON Schema generation for the route catalog** (#4057): services without a served OpenAPI document no longer infer query fields at startup.
- **Concurrent `mergeOpenAPI`** (#4060): rendered once, merged as copies; no `ConcurrentModificationException`, no diverging documents, no growth per merge.
- **Inlining contexts** (#4060): with `OpenAPIComponentContext.default(inline = true)` components are inlined instead of referenced by a `$ref` to a component that was never registered.

## Deprecations

Removed in 10.0.0 (`docs/compat-debt.md`):

- `me.ahoo.wow.openapi.aggregate.command.CommandComponent.Header.*` → `me.ahoo.wow.rest.CommandHeaders`
- `me.ahoo.wow.openapi.CommonComponent.Header.ERROR_CODE` / `SPACE_ID` → `me.ahoo.wow.rest.WowHeaders`
- `me.ahoo.wow.openapi.BatchResult` (typealias) → `me.ahoo.wow.rest.BatchResult`
