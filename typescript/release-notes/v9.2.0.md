## Highlights

- **The Wow TypeScript packages move into Wow and ship with it.** `@ahoo-wang/wow-client`, `@ahoo-wang/wow-react` and `@ahoo-wang/wow-generator` replace `@ahoo-wang/fetcher-wow`, the Wow hooks of `fetcher-react` and `@ahoo-wang/fetcher-generator`, released from the same tag and with the same version as the server ([migration guide](https://wow.ahoo.me/guide/typescript/migration)).
- **View engine and view store.** `@ahoo-wang/wow-view-engine` lets users filter, analyse, chart and save views over Wow data; `@ahoo-wang/wow-view-store` keeps those views on a Wow server, through `wow-view-store-starter` in any Wow service or the standalone `wow-view-store-server` image ([view engine](https://wow.ahoo.me/guide/typescript/view-engine)).
- **Query capability descriptor.** `GET …/snapshot/schema` and `…/event/schema` describe what a client may filter, sort and aggregate on each field, and admission enforces exactly that ([query model schema](https://wow.ahoo.me/guide/query/query-model-schema)).
- **Richer queries.** Filters relative to the server clock (`BEFORE_NOW`, `AFTER_NOW`), groups by weekday, hour, day of month or month (`DATE_PART`), `FIRST` and `LAST` metrics, `DATE_DIFF` expressions and expression filters, and `SEARCH` inside `ELEMENT_MATCH` where the storage grants it ([aggregation query](https://wow.ahoo.me/guide/query/aggregation-query), [filter expression](https://wow.ahoo.me/guide/query/filter-expression)).

> [!IMPORTANT]
> **Operators of the view store: restrict the system-view path at the gateway before you deploy.** Stored system views are written through `…/view-store/tenant/(platform)/owner/(system)/…`, and the server has no setting for who may write there. Without a gateway rule that keeps `…/tenant/(platform)/owner/(system)/**` to administrators, anyone who can reach the view store can create, change and delete the system views of every tenant. See the view store README, [CoSec gateway rules](https://github.com/Ahoo-Wang/Wow/blob/main/view-store/README.md#cosec-gateway-rules) (#3854).

## Breaking

### TypeScript

The three client packages are new on npm. What breaks is the move from the fetcher packages; each step is in the [migration guide](https://wow.ahoo.me/guide/typescript/migration).

#### `@ahoo-wang/fetcher-wow` → `@ahoo-wang/wow-client` (#3324, #3326, #3393, #3398, #3399, #3405, #3425)

**Affects:** applications that use `@ahoo-wang/fetcher-wow`.

**Migrate:**

1. Replace the dependency: `pnpm remove @ahoo-wang/fetcher-wow && pnpm add @ahoo-wang/wow-client`, and keep the Wow packages on one minor with a `~` save prefix ([version ranges](https://wow.ahoo.me/guide/typescript/compatibility#version-ranges): `savePrefix: '~'` in the project's `pnpm-workspace.yaml` for pnpm, `save-prefix=~` in `.npmrc` for npm).
2. Rewrite imports from `@ahoo-wang/fetcher-wow` to `@ahoo-wang/wow-client`. The deprecated `Condition` API, `Operator` and the operator locales moved to `@ahoo-wang/wow-client/legacy`.
3. Apply the [API changes in the first release](https://wow.ahoo.me/guide/typescript/migration#api-changes-in-the-first-release): `ErrorCodes` and the header and metadata classes are frozen objects, errors read through `toWowError`, `DEFAULT_PROJECTION` and `EMPTY_PAGED_LIST` are gone (`projection()`, `pagedList()`), `any` defaults are `unknown`, streams yield rows instead of server-sent-event envelopes, and query methods take `abort?: AbortController | AbortSignal`.

#### Wow hooks of `@ahoo-wang/fetcher-react` → `@ahoo-wang/wow-react` (#3332, #3361, #3371)

**Affects:** applications that use `useSingleQuery`, `useListQuery`, `usePagedQuery`, `useCountQuery`, `useListStreamQuery` or their `useFetcher*` variants.

**Migrate:** `pnpm add @ahoo-wang/wow-react` (React 19.3 or later), import the hooks from it, and use its own option and result types; it no longer needs `fetcher-react`.

#### `@ahoo-wang/fetcher-generator` → `@ahoo-wang/wow-generator` (#3328, #3329, #3330, #3360, #3382, #3403, #3421)

**Affects:** projects that generate clients with `fetcher-generator`.

**Migrate:**

1. `pnpm add -D @ahoo-wang/wow-generator`. The CLI is `wow-generator`; `fetcher-generator` stays as an alias until v10, and so do the old configuration and manifest file names.
2. Regenerate every client once (`wow-generator generate …`) and commit the output: generated names no longer repeat `Command`, client files are camelCase, path variables follow path order, and query, header and body parameters are typed.

### Kotlin / JVM

Everything here is source or SPI: REST, storage and wire formats of existing aggregates are unchanged, except the approved exceptions under [Server behaviour](#server-behaviour). 9.1.x and 9.2.x nodes can run side by side during a rolling upgrade, with known differences while they do: a 9.1 node rejects a command carrying another space for a non-spaced aggregate that a 9.2 node wrote, cursor tokens of one version are rejected by the other, `/schema` answers in two shapes, a 9.1 node refuses with 400 the Elasticsearch fields 9.2 makes queryable, and the last node to start decides the Elasticsearch index templates. Each is described below; keep the window short.

- **Query backend SPI.** A `QueryBackend` receives an `AdmittedQuery` and implements four primitives (`stream`, `page`, `count`, `aggregate`) plus a cursor-position codec; the core derives every query shape, plans residual operators and owns cursor tokens. Storages register through `QueryBackendProvider`, which replaces `SnapshotQueryBackendFactoryBinding` and `EventStreamQueryBackendFactoryBinding`; adapters return `QueryStorageFacts` (`QueryStorageAdapter` replaces `QuerySchemaBackendAdapter`); the Elasticsearch and MongoDB filter compilers are single internal objects (#3455, #3487, #3502, #3508, #3516, #3595, #3765, #3766). **Affects:** custom storages and code that subclasses a built-in backend or passes a custom compiler. **Migrate:** implement the four primitives and register a `QueryBackendProvider` under your storage name; see [query backend](https://wow.ahoo.me/guide/query/query-backend).
- **Query types.** `QueryCapability` is an enum instead of a data class (#3451); `AggregationExpression` is sealed (#3429); `AggregationGroup.field` is nullable (#3539); `QueryRequestScope.resolve` returns a `QueryScope` (#3485); `QueryContext` has two new required parameters (#3483); `HttpQueryGuard` takes three constructor parameters instead of eight and no budget: bounded operations go through `guard.of(gateway)` (#3454, #3595); the data-class `copy(...)` of `BindingError`, `Terms` and `Histogram` changed its JVM signature (#3461, #3539; their 9.1 constructors are kept, #3827). **Affects:** code that constructs or extends these types. **Migrate:** recompile; replace `QueryCapability(...)` with the enum constant.
- **Custom `QueryGateway`s compiled against 9.1** get `QueryEntryPolicy.DEFAULT` from the interface default, not the configured `wow.query.*` budget, and their `describe` (new in 9.2, behind `GET …/schema`) fails with `QuerySchemaUnavailableException` (503 `QuerySchemaUnavailable`) because they have no schema to describe (#3595, #3827). **Migrate:** recompile, pass the configured policy and implement `describe`, or extend `AbstractQueryGateway`.
- **Internal API opt-in.** Types marked `@InternalWowApi` (`@RequiresOptIn`) appear in public signatures: `QueryModelProfile.systemField`, the TCK's `SnapshotQueryBackendSpec` and `FilterSemantics` (now in `wow-tck`, `me.ahoo.wow.tck.query`) (#3827). **Migrate:** third-party backends and TCK users add `@OptIn(InternalWowApi::class)` or the compiler flag.
- **Renamed Spring beans.** `noOpSnapshotQueryBackendFactory` / `noOpEventStreamQueryBackendFactory` → `unavailableSnapshotQueryBackendFactory` / `unavailableEventStreamQueryBackendFactory` (#3570, #3581); `jsonQuerySchemaSource` → `inferredQuerySchemaSource` (#3519); `mongo*QueryBackendFactoryBinding` / `elasticsearch*QueryBackendFactoryBinding` → `mongo*QueryBackendProvider` / `elasticsearch*QueryBackendProvider` (#3516); `querySchemaCatalog` moved to `QueryAutoConfiguration` (#3595). **Affects:** a host that overrides one of them by bean name: the override is silently ignored. **Migrate:** override the new name.
- **9.1 query-schema declaration files** (#3519, #3827). 9.2 reads declarations only at `META-INF/wow/query-schema/{ctx}.{agg}.{model}.json` or `config/wow/query-schema/…`, in the 9.2 format. A file at the 9.1 fallback location `wow-query-schema/{ctx}/{agg}/{model}.json` is not read: startup logs a **warning** and the model uses its inferred schema (`wow.query.schema.legacy-declarations=fail` fails it instead). A 9.1-format file at the primary path fails that model's schema. **Migrate:** convert the file to the 9.2 format (key table in [query model schema](https://wow.ahoo.me/guide/query/query-model-schema), "Moving a 9.1 declaration file"); during a rolling upgrade keep the 9.1 file at the fallback path and give each 9.2 node its 9.2 file in `config/wow/query-schema/`.
- **New startup checks.**
  - Two routes of the same method whose templates differ only in variable names (`…/{id}/{itemId}/remove` and `…/{id}/{sku}/remove`, or a custom route shaped like a built-in one) now fail at startup, naming both; one of them was already unreachable (#3798). A contained route is now tried before its container (`…/snapshot/count` before `…/{id}/count`).
  - `wow.query.require-authenticated-scope=true` requires `wow.webflux.state.point-read-admission=true` (#3626).
- **Query error texts.** Query errors name what is wrong in the framework's words (`limit must be between 1 and 10000.`); status codes and error codes are unchanged (#3460). **Affects:** clients that match on the message text. **Migrate:** match on the error code.
- **Removed or internal helpers.** `FilterNormalizer.normalize(...)` (admit through `QueryAdmission.Trusted`), `ICursorQuery.withUniqueSort`, `selectTopRows`, `HttpQueryGuard.of(QueryBudget)`, `FilterExpression.walkFilterNodes()`/`filterNodeCount()`, `FieldArity` (#3626); `DenseFill`, `BoundedTopRows`, `matchesHaving` and the other residual operators (#3601); `ResolvedField.definition`/`value`/`bindings`, `AdmittedQuery.schema`, `requireScalarMetricFilterFields` (#3587); `EventStore.appendResolvingOutcome` (#3827); `QueryModelSchemaMetadata`, `QueryValueSchemaMetadata` and `toMetadata()` (#3467).

Deprecated, still honoured until v10 ([compatibility debt](https://github.com/Ahoo-Wang/Wow/blob/main/docs/compat-debt.md)): the 9.1 masking annotations (`@Mask`, `@KeepMask`, `@Masking`) and the old `QueryTemporal`, read as `@Sensitive` and the new `@QueryTemporal` (#3519, #3827); the `wow.webflux.query.max-*` keys, read where their `wow.query.http.*` key is unset, with a warning (#3454, #3827); the 9.1 compensation console links, which redirect (#3827).

### Server behaviour

REST, storage and wire behaviour of existing aggregates is frozen within v9; each entry here is an exception the user approved, or a deployment step a 9.2 node needs, with the step to take before upgrading and what a mixed 9.1/9.2 cluster does.

#### Non-spaced aggregates ignore `Wow-Space-Id` (#3791)

An approved exception to the v9 freeze: 9.1 took the request's space for every aggregate, which was a contract bug. In 9.2 an aggregate that does not declare `@AggregateRoute(spaced = true)` never takes a space from a request or a command: its commands carry the default space `""`, its event stream keeps the state's space, and its queries (snapshot, event stream, state and tracing reads) get no space filter from `Wow-Space-Id` or, with wow-cosec, `CoSec-Space-Id`. Spaced aggregates are unchanged. fetcher-cosec sends a space header on every request, so a deployment that relied on the header to keep a non-spaced aggregate's data apart now sees the rows of every space.

- **In-process sources too.** A space stated for a non-spaced aggregate this service knows is dropped whatever its source: `CommandBuilder.spaceId(…)`, `toCommandMessage(spaceId = …)`, and a saga's inherited or explicit `.spaceId(…)`. A non-spaced aggregate changes space only through an explicit `SpaceTransferred` event.
- **Sagas.** A space no longer passes through a non-spaced aggregate into a spaced one: a command in space `S` to non-spaced `A`, whose event drives a saga that creates spaced `B`, now creates `B` in the default space. Set `B`'s space explicitly in the saga, for example from data the event carries. In the other direction this fixes a saga reacting to a spaced aggregate's event whose command to a non-spaced aggregate was rejected (`IllegalAccessSpaceAggregateException`), retried and sent to compensation.

**Before upgrading:** declare `spaced = true` on every aggregate whose data the space header was meant to keep apart, and set the space explicitly in sagas that create a spaced aggregate from a non-spaced one's event. Data already written with a space keeps it.

**Mixed 9.1/9.2 cluster:** a 9.1 node stamps the header's space into a command and filters a query by it; a 9.2 node writes `""` and does not filter. The same query can return different rows depending on the node that answers, and a 9.1 aggregate node rejects a command carrying a different non-blank space. Upgrade the gateways, the aggregate nodes and the query nodes together. After a rollback, records 9.2 wrote in space `""` are rejected (commands) or hidden (queries) for clients that send a space header. See [data access](https://wow.ahoo.me/guide/data-access#upgrading-from-9-1).

#### `/schema` routes answer with the capability descriptor (#3467, #3473, #3827; D77)

An approved exception to the v9 freeze. `GET …/snapshot/schema` and `GET …/event/schema` return a `QueryModelDescriptor` (fields, operators, sorts, aggregations, limits, `version`, ETag) instead of the 9.1 schema metadata. `POST …/snapshot/schema/refresh` and `POST …/event/schema/refresh` stay as deprecated aliases (removed in 10.0.0): they reload that model and answer as `GET …/schema`. Schemas also revalidate every `wow.query.schema.revalidate-interval` (default `5m`) and through the `wowQuerySchema` actuator endpoint.

**Before upgrading:** a client that parses the 9.1 body moves to the descriptor; scripts that call `…/schema/refresh` keep working.

**Mixed 9.1/9.2 cluster:** the same route answers in both shapes depending on the node. The 9.2 view engine falls back to the host's declared definition when a describe answers in the old shape.

#### Cursor tokens (#3502)

Cursor tokens carry a version and a fingerprint of the aggregate, read model and sort. A token issued by a 9.1 server, or for another model or sort, is rejected with the existing `Invalid cursor.` (400, `IllegalArgument`); the client restarts from the first page.

**Before upgrading:** nothing; clients restart a cursor once.

**Mixed 9.1/9.2 cluster:** a token issued by a 9.1 node is rejected by a 9.2 node and the other way round.

#### Elasticsearch: index definitions at startup, privileges, decimals, presence (#3823, #3824, #3825, #3832, #3835)

- **Index definitions are created at startup.** An index definition shipped under `META-INF/wow/elasticsearch/` (snapshot or, new, event stream `….es.json`) is created when the application starts. Wow ships definitions for the view store and the compensation `execution_failed` snapshot.
- **Privileges.** The Elasticsearch user needs `view_index_metadata` and `create_index` on those indices, and the cluster privilege `manage_index_templates` with `auto-init-template=true` (the default). Queries of an index that does not exist yet also need `manage_index_templates`, even with `auto-init-template=false`: without it they keep answering 503 `QuerySchemaUnavailable` until the first write, as in 9.1 (see [Behaviour changes](#behaviour-changes)).
- **Decimals on integral fields.** A value the model declares as a decimal is filtered, sorted and aggregated only on a floating field (`double`, `float`, `half_float`, `scaled_float`); on an integral field it offers presence filters only and the server logs a WARN naming the fix, because Elasticsearch truncated the decimals. Queries that filtered or sorted such a field are refused with 400 `QuerySchemaValidation`.
- **Presence filters.** `exists`, `isNull`, `notExists` and `isEmpty` also read `_ignored`, so a value Elasticsearch dropped through `ignore_above` or `ignore_malformed` now counts as present, and a capped `flattened` field offers no presence filter (400 `QuerySchemaValidation`).

**Before upgrading:** grant the privileges; reindex an index that maps a decimal value as an integer ([reindex](https://wow.ahoo.me/guide/extensions/elasticsearch#reindex-existing-index)).

**Mixed 9.1/9.2 cluster:** a 9.1 node still filters and sorts a decimal on an integral field, and answers presence without `_ignored`; a 9.2 node refuses the first and counts dropped values as present.

## Behaviour changes

Visible to users, not breaking: nothing to migrate unless an entry says so.

### Elasticsearch (#3766, #3823, #3824, #3825, #3832, #3835)

- **A missing index answers empty.** Wow creates an aggregate's index on its first write. Until then a query answered 503 `QuerySchemaUnavailable`; now list, page (total 0), cursor, count (0) and aggregate answer empty, as on MongoDB. The schema of the missing index is simulated from the index templates (`POST _index_template/_simulate_index/<index>`), which needs the cluster privilege `manage_index_templates` even with `auto-init-template=false`; without it the 503 stays until the first write (#3823).
- **Before the first write.** The simulated schema is kept for 2 seconds, never published; a query admitted on it that finds the index created meanwhile answers 503 `QuerySchemaUnavailable` (at most 2 seconds after an aggregate's first write) (#3825).
- **Drift warning.** An existing index is never changed. When it maps a path of its definition otherwise, startup logs one WARN naming the paths; for example a compensation `execution_failed` snapshot index created before Wow 9.0.7 shipped its definition. Reindex it to clear the warning ([reindex](https://wow.ahoo.me/guide/extensions/elasticsearch#reindex-existing-index)) (#3832).
- **Template rules for new indices only.** A dynamic string under `state` gets a `.keyword` sub-field capped at 8191 instead of 256, so free-text strings can be filtered, sorted and grouped through `.keyword`; a dynamic floating-point value maps as `double` instead of `float`. Existing indices keep their mapping (#3835). **Mixed cluster:** 9.1 and 9.2 nodes with `auto-init-template=true` both write `wow-snapshot-template` and `wow-event-stream-template` at startup under the same names, so the node that started last decides the template, and an index created meanwhile keeps that version's mapping for good. Set `auto-init-template=false` on the 9.1 nodes for the upgrade, or restart one 9.2 node once the last 9.1 node is gone, and check `GET _index_template/wow-snapshot-template` (its string rule has `ignore_above: 8191`).
- **`ignore_above` 8191 is queryable.** A keyword whose `ignore_above` is 8191 or more (the templates' `tags.*`, `*Id`, the event stream's strings) is now filterable, sortable and groupable. A value longer than the cap is not indexed: it matches no filter and sorts as missing; presence counts it (see [Server behaviour](#server-behaviour)) (#3824). **Mixed cluster:** a 9.1 node still refuses these fields (400 `QuerySchemaValidation`) where a 9.2 node answers.
- **Result window.** A page beyond `index.max_result_window` is a 400 `SIZE_OUT_OF_RANGE` at admission instead of an Elasticsearch 5xx (#3766). The descriptor's `limits.maxPageWindow` says the window the storage allows: the configured budget or the index's `max_result_window`, whichever is lower (#3847).
- **Distinct counts are exact up to 40000 per bucket** (about 3000 before), so a bucket with more distinct values reads a different, more accurate number. **Mixed cluster:** the same query can answer slightly differently depending on the node (#3847).
- **Aliases and data streams over several indices** answer queries over the fields their indices share, where they were refused before (#3847).
- **UTC date histograms on epoch-millis `long` fields** return the same buckets without a per-document script (#3847).

### Query errors and admission

- Server faults answer 500 `InternalServerError` instead of 400 (mask strategy failures, storage and driver failures, backend integrity errors); the driver text no longer reaches the body (#3597, #3621).
- A sort of more than 32 fields, or naming one field twice, is refused at admission on every storage (#3584).
- With `wow.query.http.allow-expensive-operators=false`, HTTP also refuses `DATE_PART` groups, dense fill and the `FIRST`/`LAST` metrics (#3587).
- MongoDB: a `Temporal.Date` field compares date operands as BSON dates where its validator declares a `date` (newly valid queries only) (#3765); a bad operand is a 400 instead of a 5xx (#3764).
- With `wow.webflux.state.point-read-admission=true`, state point reads run the caller scope, the policies and the authenticated-scope requirement (#3580, #3621).

### Operations (#3843, #3845)

- **Health in the images.** The example, compensation and view store images answer `/actuator/health` with the status only (`show-details: when-authorized` in their configuration templates), and their Docker `HEALTHCHECK` reads liveness instead of backend health. To see the details again, set `MANAGEMENT_ENDPOINT_HEALTH_SHOWDETAILS=always`, on an operator-only network (#3843).
- **`latest` image tag.** An image built from a patch tag of an older line no longer moves `latest`; only the highest stable `v*` tag does (#3843).
- **View store topics.** A host that embeds the view store on Wow's default topics logs one warning at startup (#3843).
- **Request failure logs.** A request answered with a 5xx is logged at `ERROR` with its stack trace (it was `WARN`); a client's 4xx through the global handler is logged on one line without a stack trace. Statuses, headers and bodies are unchanged (#3845).

### View store limits (#3823, #3825, #3829)

The view store, new in 9.2, refuses a title over 120 characters, a config over 240 KB, more than 1000 panels, preference ids over 256 characters, a `definitionId` or a panel reference over 256 characters, and a config whose `panels` is not an array of objects or whose `click` is not an object; the engine checks the title and config before sending.

## TypeScript packages

Install or upgrade with a `~9.2` range: a minor release may break (see [version ranges](https://wow.ahoo.me/guide/typescript/compatibility#version-ranges)). All five packages ship together at `9.2.0` and peer on each other with `~`, so upgrade them together. Peers: `@ahoo-wang/fetcher`, `fetcher-decorator` and `fetcher-eventstream` `^5.1.5`; React 19.3 or later for wow-react and the view engine's `/react` and `/ui`; Node `>=22.12.0`; TypeScript 6 or later.

### `@ahoo-wang/wow-client`

New compared with `@ahoo-wang/fetcher-wow` (what changed shape is under [Breaking](#breaking)):

- **Capability descriptor.** `QueryDescriptorClient` reads a query model's descriptor (`GET …/schema`, with ETag), so a client knows what it may filter, sort and aggregate on each field before it asks (#3482, #3489, #3515, #3535, #3552, #3738).
- **Query DSL.** `filter.beforeNow` / `filter.afterNow` (#3459); `DATE_PART` groups (#3524), `FIRST` and `LAST` metrics (#3532), `DATE_DIFF` expressions, expression filters and expression groups (#3539), `SEARCH` on element fields inside `ELEMENT_MATCH` (#3525); `aggregation.having` and `derived(d => …)` builders (#3395).
- **Errors you can act on.** A rejected query carries a stable code and the violating path (`QueryErrorCodes`, `QueryViolation`), read through `toWowError` (#3461, #3471, #3475, #3597).
- **Clients.** Every query client method is on its interface, with `LoadStateAggregateApi` and `LoadOwnerStateAggregateApi` (#3398); client methods are bound, so they can be passed around destructured, and each server's list limit is documented (#3418); `COMMAND_STREAM_ENDPOINT` and `QUERY_STREAM_ENDPOINT` endpoint presets (#3357); the command space is sent as `Wow-Space-Id` (#3320).
- **Package.** One output module per source file, so bundlers drop what you do not import (#3401); a doc comment on every public declaration (#3443).

### `@ahoo-wang/wow-react`

- A cleared controlled query (`query` set back to `undefined`) aborts the request in flight and goes idle, keeping the last result, instead of running the previous query again (#3420).
- List streams publish their rows at most once every 16 ms and keep one copy of them, so a long stream renders once per interval instead of once per network chunk (#3383).
- The hooks own their request state machine and their public types; nothing depends on `fetcher-react` any more (#3361, #3364, #3371, #3757).

### `@ahoo-wang/wow-generator`

- Generated code imports types with `import type` where it uses them only as types (#3291).
- The CLI exits with 2 on a usage error, and a bad manifest's error says how to fix it (#3417).

Regenerate once after upgrading (`wow-generator generate …`), as the [Breaking](#breaking) steps say.

### `@ahoo-wang/wow-view-engine`

- First release: record, analysis and dashboard views, their embeds, the `/react` controllers, the `/ui` components and the `wow-view-engine theme-check` command ([view engine](https://wow.ahoo.me/guide/typescript/view-engine)).
- Stored system views (D81): a host that grants `ViewPermissions.editSystem` (absent is false) lets that user save, rename and delete the system views its store keeps (`stored: true`), publish a personal or shared view as one (a copy, from the view manager), and pick the system audience in Save as. System views declared in code or configured on the server stay read-only (#3855).
- Saving works on a page served over plain HTTP: a write's request id no longer needs `crypto.randomUUID`, which browsers offer only in secure contexts (#3840).
- From the second-round review before the first release: a view that failed to open offers a retry (`OpenViewState.retry()`, `retryableOpen` in `/react`), a panel whose view could not be read is not called deleted, and the first describe has a deadline (#3842); declared actions report an unknown outcome and keep focus (#3834); saved views keep the store's order, limits and errors (#3829); time windows and number formatting (#3833); workbench and board focus hand-over, an added panel scrolled into view, a one-day date on the day in force (#3849); visual polish of chart words, gauge, filter pill and mixed select-all (#3848); the public surface and package shape, with a tokens-only CSS contract and `*Projection` names (#3831).
- Layout and accessibility: no dialog runs past the viewport, and the view manager's list scrolls under its heading (#3846); one scrollbar per region (#3852); a view manager row's actions name the view they act on (#3863); a date calendar opens with focus on its selected day and the arrow keys move between days, and dialogs keep an edge in forced colours (#3858); the second-round accessibility findings (#3826) and what the nightly WebKit run found (#3828). The accessibility statement was re-walked for this release, and a VoiceOver spot check of the record workbench and of the analysis tray's undo notice passed; the full screen-reader walkthrough comes after this release ([accessibility](https://wow.ahoo.me/guide/typescript/view-engine-accessibility)).
- Chinese copy names things instead of using 看／按／在 as one-character terms (#3841).

### `@ahoo-wang/wow-view-store`

- First release: `WowViewStore`, the view engine's `ViewStore` on the Wow view store (#3795).
- Stored system views: `WowViewStore` lists stored system views with `stored: true`, and creates (publishes as a copy), saves, renames and deletes them on `tenant/(platform)/owner/(system)` whatever the caller's tenant; configured and code system views stay read-only. `SYSTEM_OWNER_ID` and `SYSTEM_TENANT_ID` are exported (#3854).

## JVM (Maven)

- **View store modules** `wow-view-store-api`, `wow-view-store-domain` and `wow-view-store-starter` are published for the first time; a Wow service that adds the starter keeps saved views and preferences in two Wow aggregates. The standalone `wow-view-store-server` image is published with the same version (MongoDB only in 9.2.0) (#3795, #3819, #3832).
- `wow-bom` constrains only the published modules; it no longer lists the example modules and the benchmarks.
- **Elasticsearch index prefix.** `wow.elasticsearch.index-prefix` (unset by default) is put before every index, index template and template pattern Wow names (`staging.wow.sales.order.snapshot`, `staging.wow-snapshot-template` on `staging.wow.*.snapshot`), so several deployments share one cluster; unset, every name is unchanged. `ElasticsearchIndexNaming` carries it through the stores, the query backends, the index initializers and the templates ([index prefix](https://wow.ahoo.me/guide/extensions/elasticsearch#index-prefix)) (#3853).
- **Stored system views.** Besides `wow.view-store.system-views` (read once at startup), system views can be stored as views under the reserved tenant `(platform)` and owner `(system)`, global to every tenant and changed without a restart. `GET …/system-views` answers the configured views of the request's tenant and the stored ones of its application, each with `source` and, when stored, `version`; a stored view wins over a configured one with its id. Who may write them is the CoSec gateway's decision by that path: **without a rule that keeps `…/tenant/(platform)/owner/(system)/**` to administrators, anyone who reaches the view store can change every tenant's system views** (view store README, "System views"). The stored views are read from the view snapshots; a host without a snapshot query backend (in-memory) serves the configured views alone and warns at startup (#3854).
- **Elasticsearch queries.** Distinct counts at full precision up to 40000 per bucket, the page window the index allows, aliases and data streams over several indices, and date histograms on epoch-millis `long` fields without a script (#3847); `DATE_DIFF` reads an epoch as the date groups and MongoDB do (#3754). See [Behaviour changes](#behaviour-changes).
- **Query.** `BEFORE_NOW` / `AFTER_NOW` filters relative to the server clock (#3456), `DATE_PART` groups (#3524), `FIRST` / `LAST` metrics (#3532), `DATE_DIFF` expressions, expression filters and expression groups (#3539), `SEARCH` inside `ELEMENT_MATCH` where the storage grants it (#3525), `DECIMAL` and `MONEY` semantic types (#3552); `@Sensitive` on a value type protects it in every model (#3550, #3566); stable rejection codes on every decode and admission error (#3461, #3475); opt-in per-query audit through `QueryObserver` (#3498), ABAC tightenings (#3488), point-read admission for state routes (#3491, #3497), and query and schema meters (`wow.query`, `wow.query.rows`, `wow.query.schema.*`) (#3553).
- **OpenAPI.** The snapshot and event-stream query routes also have a tenant + owner variant (#3796).
- **Starter.** The default event and snapshot store can be a named binding (#3545).
- **Core.** An append that fails after it committed is resolved instead of decided again (#3739); a graceful batch shutdown no longer interrupts the window thread (#3470); `*Properties` constants follow Jackson's serialized names (#3479); getter query fields are inferred from Jackson serialization (#3296).
- **Compensation.** The console is rebuilt on the view engine, with its views kept in the embedded view store (#3472, #3512, #3520, #3541, #3544, #3706, #3709, #3710, #3711, #3814); a prepared execution times out only after `timeoutAt` (#3423); the WeCom client is registered only when its webhook is enabled (#3299).
- **Request failure logs** follow the status they were answered with (#3845); image health checks read liveness and health details need authorization (#3843). See [Behaviour changes](#behaviour-changes).
