## Highlights

- **The view store's OpenAPI routes are documented once at startup** (#4074): like Wow's own routes since 9.6.0, the view store no longer generates JSON Schemas on every Springdoc customize call (cache disabled, several groups or locales).
- **Closed view store routes leave the OpenAPI document on every host** (#4075), and a new `OpenApiDocumentFilter` hook lets an application change Wow's routes in the document whatever the Springdoc customizer order.
- **Custom route contributors can reference Wow's built-in components** through the new `WowComponents` (#4073).

> [!NOTE]
> A patch release: no breaking change. REST, storage and wire formats are those of 9.6.0. The OpenAPI document changes only on view store hosts whose component scan covers the view store starter (closed routes no longer listed) and when `wow.openapi.enabled=false` (view store routes no longer listed).

## Breaking

None.

## Behaviour changes

- **Closed view store routes are no longer documented** (#4075). On a host whose component scan covers `me.ahoo.wow.viewstore.starter`, the view store's customizer ran before Wow's, so its pruning missed the ~130 routes `ViewStoreRouteGuard` refuses; they stayed in `/v3/api-docs`. The shipped example, compensation and view store servers were not affected. REST is unchanged: those routes were refused either way. **Act:** regenerate a client generated from such a host's document; it loses the methods of the refused routes.
- **The view store follows `wow.openapi.enabled`** (#4074). With `wow.openapi.enabled=false` the view store no longer adds its own routes to a Springdoc document (and generates no schemas for them). **Act:** nothing, unless you relied on that.
- **Two different schemas under one component schema key fail the render** (#4072). Before, the second silently replaced the first. Built-in routes never do this. **Act:** give the custom component schemas distinct keys.

## Fixes

- **Duplicate component detection** (#4072): two components with one kind and key that register different schemas under one schema key were accepted, and the document showed the second schema. Now rejected; the error names the component section (`#/components/responses/…`).
- **View store OpenAPI** (#4074): schemas generated once at startup (also under `spring.main.lazy-initialization`); a first render on a Reactor non-blocking thread is refused, as `RouterSpecs.mergeOpenAPI` does.
- **Closed routes pruned whatever the customizer registration order** (#4075).

## New

- **`me.ahoo.wow.openapi.contract.WowComponents`** (#4073): the built-in components, as the same instances the built-in routes use, so referencing them never trips the duplicate-key check: `badRequestResponse`, `notFoundResponse`, `requestTimeoutResponse`, `tooManyRequestsResponse`, `unsupportedMediaTypeResponse`, `errorCodeHeader` / `errorCodeHeaderComponent`, `spaceIdHeaderParameter`, `idPathParameter`, `tenantIdPathParameter`, `ownerIdPathParameter`, `versionPathParameter`.
- **Component builders** (#4073): `ApiResponseBuilder.extension(name, value)` and `RequestBodyBuilder.required(Boolean)`.
- **`me.ahoo.wow.spring.boot.starter.openapi.OpenApiDocumentFilter`** (#4075): beans of this type run, in their order, right after Wow's customizer merges its routes into the document.

## TypeScript packages

Every package in `PUBLISHED` ships together at `9.6.1` with no changes.

## JVM (Maven)

- **Dependencies:** unchanged.
- **Tests and tooling:** the view store starter test checks the served document through the real customizer chain, including an application customizer that replaces `info`; the mixed-version gate runs against the released 9.6.0 image.
