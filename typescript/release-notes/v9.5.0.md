## Highlights

- **Kotlin computed properties no longer go missing from query models and OpenAPI.** When schemas were generated concurrently (query-schema inference does this for every aggregate), a getter-only property such as `val total get() = …` could randomly disappear from the inferred query model and from OpenAPI documents. Fixed in #4046 and #4054.
- **`wow-schema` is refactored to its contract.** Public classes go from 63 to 17. Thirteen definition providers collapse into two. The OpenAPI adapter moves to `wow-openapi`. Package dependencies are checked for cycles. Golden snapshots of every bundled type, both generator configurations, the OpenAPI builder and 68 query models prove that **every generated JSON Schema, OpenAPI document and query model is byte-for-byte the same as in 9.4.0** ([design](https://github.com/Ahoo-Wang/Wow/blob/main/documentation/designs/2026-10-09-wow-schema-refactor-design.md)).

> [!IMPORTANT]
> **Only code that uses the schema builders directly needs changes.** REST behaviour, configuration, storage and wire formats are those of 9.4.0, and 9.4.x and 9.5.0 nodes can run side by side. The required source changes are: `OpenAPISchemaBuilder` moves to `me.ahoo.wow.openapi.schema` in `wow-openapi`; four `SchemaGeneratorBuilder` members are removed; schema implementation classes are internal ([migration guide](https://wow.ahoo.me/guide/migration#upgrading-from-9-4-to-9-5-0)).

## Breaking

**Policy.** The maintainer decided (2026-10-09) to keep `wow-schema` clean rather than compatible: no binary-compatibility shims, and no source-compatibility deprecation cycle for these members. Generated schemas are a contract and did not change. Every v9 REST, storage and wire surface is unchanged.

### TypeScript

No API changes.

### Kotlin / JVM

#### `wow-schema` and `wow-openapi`

- **`OpenAPISchemaBuilder` and `InlineSchemaCapable` move to `wow-openapi`, package `me.ahoo.wow.openapi.schema`** (#4050, #4054). Before, they were in `wow-schema`, package `me.ahoo.wow.schema.openapi`. `OpenAPISchemaBuilder.toSchema` is no longer public. `SchemaMerger` and `JavaTypeResolver` are internal. **Affects:** code that uses the OpenAPI schema builder directly. **Migrate:** change the imports to `me.ahoo.wow.openapi.schema.OpenAPISchemaBuilder` / `InlineSchemaCapable`, and add `me.ahoo.wow:wow-openapi` if only `wow-schema` is on the classpath. Applications with the Starter's `openapi-support` capability already have it.
- **`SchemaGeneratorBuilder.openapi31`, `openapi31(Boolean)`, `typeContext` and `requiredTypeContent` are removed** (#4054). `openapi31` never had an effect: nullable shapes follow `Option.NULLABLE_ALWAYS_AS_ANYOF` and the Kotlin module. `build()` no longer leaves a type context on the builder. New: `buildConfig()`, and `copy()`, which gives an independent builder with the same settings (#4049). **Affects:** code that calls the removed members. **Migrate:** delete `openapi31(…)` calls. For a type context:

  ```kotlin
  val config = SchemaGeneratorBuilder().buildConfig()
  val typeContext = TypeContextFactory.createDefaultTypeContext(config)
  val generator = SchemaGenerator(config, typeContext)
  ```

- **Schema implementation classes are internal** (#4046, #4047, #4051, #4054). No longer public: every definition provider; the extension base classes `TypedCustomDefinitionProvider`, `MessageDefinitionProvider` and `AbstractStateAggregate`, removed with no replacement; `KotlinCustomDefinitionProvider` and the Kotlin nullable / read-only / required / write-only / ignore checks; the `@Summary` / `@Description` title and description resolvers; `IgnoreCommandRouteVariableCheck`; `WowSchemaLoader`; `JsonSchema`; `Types`; `WowJacksonModule`'s companion; and `WowSchemaNamingStrategy.flattenType`. `WowSchemaNamingStrategy.isStdType`, `resolveNamePrefix` and `toSchemaName` are `@InternalWowApi`. The definition providers covered `AggregateId`, `DomainEventStream`, the ranges, `CurrencyUnit`, `Money`, messages, state aggregates, `EnumText`, `Map`, `JsonNode`, `ServerSentEvent` and the query types. **Affects:** code that registered single providers or checks, or subclassed the base classes. **Migrate:** register `WowModule`, `KotlinModule` or `JodaMoneyModule` through `SchemaGeneratorBuilder` (they are on by default). For a type of your own, implement victools' `CustomDefinitionProviderV2` and add it in `customizer { it.forTypesInGeneral().withCustomDefinitionProvider(…) }`. `api/wow-schema.api` shrinks from 440 to 155 lines; the public surface is the builder, `WowOption`, the modules, the naming strategy, `JsonQueryModelSource` and the placeholder types `AggregatedDomainEventStream` and `ServerSentEvent*`.

## Behaviour changes

- **`OpenAPISchemaBuilder` no longer modifies the builder you pass in** (#4049). It used to replace that builder's `schemaNamingModule` with its own. It now works on a `copy()`. **Act:** nothing.
- **A schema generator, and an `OpenAPISchemaBuilder`, are documented as not thread-safe.** This was always the case: victools' Jackson module sorts properties with unsynchronized state. **Act:** build one per thread, as Wow's own query-schema inference already does.

## Fixes

- **Kotlin getter-only properties no longer go missing under concurrent schema generation** (#4046, #4054). The Kotlin getter provider was one global object whose "already expanded" set was shared by every generator and cleared by whichever generation finished first. Concurrent generations, as in query-schema inference, saw each other's types and dropped getter-only properties, randomly, from the inferred query model and from OpenAPI. Each generator configuration now has its own provider, which clears its set at the end of each generation, as 9.4 did for a single generator.

## TypeScript packages

Install or upgrade with a `~9.5` range: a minor release may break (see [version ranges](https://wow.ahoo.me/guide/typescript/compatibility#version-ranges)). Every package in `PUBLISHED` (`.github/scripts/publish-npm.mjs`) ships together at `9.5.0`; the packages peer on each other with `~`, so upgrade them together. The fetcher peer ranges are unchanged.

## JVM (Maven)

- **Dependencies:** unchanged. `wow-schema` still exposes `swagger-core-jakarta`.
- **`wow-schema` internals** (no release impact beyond the items above; main code shrinks from 3,579 to 2,804 lines):
  - one bundled-resource provider and one wrapper provider, with parsed templates cached and copied per use (#4047);
  - schema keywords always taken from the generator's configured version (#4047);
  - one reference/composition expander in the query-model walker (#4048);
  - package dependencies checked for cycles, root package included (#4045, #4054).
- **Tests and tooling:** golden snapshots for the schema generator, the OpenAPI builder and query models (#4045, #4050); a regression test for concurrent generation and one for multi-definition (OpenAPI) builds (#4046, #4054); a flaky `KeyedDispatchTest` made deterministic (#4053); the mixed-version gate runs against the released 9.4.0 image.
