## Highlights

- **`wow-core`, `wow-query` and `wow-spring` are reviewed from first principles.** In `wow-core`, `messaging` no longer imports the command, event or event-sourcing packages (#4096). `infra` no longer imports metrics (#4096). The metrics port no longer imports any domain package (#4095). In `wow-query`, the schema catalog no longer depends on the read models' backend factories (#4099). New architecture rules in `DependencyRules` keep these boundaries from regressing.
- **Recoverable failures in projections and sagas are always retried in-process** (#4094). `RetryableFilter` now orders itself before every function filter, subclasses included, whatever the registration order.
- **Faster hot paths.** Local-first sends no longer allocate a name object 3–4 times per message (#4094). Under 8 concurrent threads, admitting a dynamic query field such as ABAC `tags.<key>` takes 326 ns instead of 1154 ns (#4101).
- **A query observer can no longer silence the others** (#4098). An observer that throws an `Error`, such as `TODO()`, no longer skips query metrics.

> [!IMPORTANT]
> **REST routes, route ids, the OpenAPI document, configuration, metric names and tags, header keys and wire formats are those of 9.7.0**, so 9.7.x and 9.8.0 nodes can run side by side. Applications that use only the starter and the public entry APIs need no source change; recompile against 9.8.0. Code that imports one of the moved or removed internal classes follows the [migration guide](https://wow.ahoo.me/guide/migration#upgrading-from-9-7-to-9-8-0).

## Breaking

**Policy.** Every breaking change in this release is internal implementation, outside the compatibility scope of [`docs/compat-debt.md`](https://github.com/Ahoo-Wang/Wow/blob/main/docs/compat-debt.md). So there are no deprecation cycles or binary-only shims. Every v9 REST, storage and wire surface is unchanged.

### TypeScript

No API changes.

### Kotlin / JVM

#### `wow-core` (and the modules whose signatures name the moved types)

- **Domain specialisations leave `messaging`; batching leaves `infra`** (#4096). Package moves only; class names, constructors and behaviour are unchanged.
  - `TransportCommandBus` and `TransportServerCommandExchange` move to `me.ahoo.wow.command.transport`.
  - `TransportDomainEventBus` and `TransportEventStreamExchange` move to `me.ahoo.wow.event.transport`.
  - `TransportStateEventBus` and `TransportStateEventExchange` move to `me.ahoo.wow.eventsourcing.state.transport`.
  - `EventCompensator` and `EventCompensateSupporter` move to `me.ahoo.wow.event.compensation`.
  - `CommandOperatorMessagePropagator` and `WaitPlanMessagePropagator` move to `me.ahoo.wow.command.propagation`.
  - `me.ahoo.wow.infra.batch` becomes `me.ahoo.wow.batch`.

  The signatures that name these types change with them: the `Kafka*Bus` and `Redis*Bus` supertypes, the MongoDB and Elasticsearch store constructors that take `BatchOptions`, the starter's `toOptions()`, and the compensation and route beans.

  **Affects:** code that imports these classes, or lists one of the two propagators in a `META-INF/services` file. **Migrate:** change the imports and service-file entries, then recompile.

- **Metric decorators leave the metrics port** (#4095). `MetricDecoratorFactory` and the `metered(...)` extensions move from `me.ahoo.wow.metrics` to `me.ahoo.wow.metrics.decorator`; `WowMetrics`, `MetricDescriptor` and the rest of the port stay. **Affects:** integrations that decorate components with metrics themselves, without the starter. **Migrate:** import `me.ahoo.wow.metrics.decorator.MetricDecoratorFactory` and `me.ahoo.wow.metrics.decorator.metered`.

#### `wow-query`

- **`QuerySchemaCatalog` locates storages** (#4099). Its constructor changes from `(snapshots, eventStreams, compiler, aggregates, meterRegistry)` to `(storages, compiler, aggregates, meterRegistry)`, where `storages` is a `QueryStorageLocator`. **Affects:** code that builds the Catalog itself. **Migrate:** pass `QueryBackendStorages(snapshots, eventStreams)`.

#### `wow-spring`

- **One query gateway registration template** (#4093).
  - `QueryGatewayRegistrar` is `sealed`.
  - Removed: `registerQueryGateway(Map.Entry, BeanDefinitionRegistry)`, the no-arg constructor and the `appContext` accessors.

  **Affects:** integrations that subclass it to register their own gateway. **Migrate:** register your gateway bean under `snapshotQueryGatewayBeanName()` / `eventStreamQueryGatewayBeanName()`; the registrars leave an existing bean of that name untouched.

- **`PrepareKeyFactoryBean.setApplicationContext(ApplicationContext)` becomes `setBeanFactory(BeanFactory)`** (#4093). **Affects:** code that calls it directly; beans registered through `PrepareKeyAutoRegistrar` are unaffected. **Migrate:** call `setBeanFactory`.

## Behaviour changes

- **`SpringServiceProvider.getService(name)` returns `null` for an unknown name** instead of throwing, as the `ServiceProvider` contract documents (#4093). **Act:** a caller that relied on the exception checks for `null` or uses `getRequiredService`.
- **A negative backend count fails the query** with `500` (`Backend count must be greater than or equal to 0.`) instead of reaching the caller (#4100). **Act:** nothing, unless a custom backend answers negative counts.
- **ABAC missing-tag rejections are logged at DEBUG** (`403 IllegalAccessQueryScope`). Before, they were logged at ERROR with a stack trace (#4098). **Act:** alerts on ERROR logs no longer fire for them.
- **`RetryableFilter` always wraps the projection and stateless saga function filters** (#4094). Applications on the starter already had this order. **Act:** applications that assemble their own filter chains and register the function filter first now retry recoverable failures in-process; keep such handlers idempotent.

## Fixes

- `RetryableFilter` was ordered only before the exact `DomainEventFunctionFilter` class. In custom filter chains the projection and saga function filters could run outside the retry (#4094).
- `CompositeQueryObserver` caught `Exception` only. An observer `Error` skipped every later observer, including `QueryMetricsObserver` (#4098).
- `LocalFirstMessageBus` now closes both buses and both receivers even when one throws an `Error`. When both fail, it keeps the first failure (#4094).

## JVM (Maven)

- **Dependencies:** no changes.
- **Performance:** local-first delivery reuses the aggregate ID's materialized name (#4094); dynamic query fields are looked up without a lock (#4101); `count` goes through `BackendQueries` like the other query shapes (#4100).
- **Documentation:** the "Upgrading from 9.7 to 9.8.0" migration guide (#4096, #4097, #4099).
- **Tests and tooling:** new architecture rules `METRICS_PORT_HAS_NO_DOMAIN`, `MESSAGING_HAS_NO_DOMAIN`, `INFRA_HAS_NO_UPPER_LAYERS`, `QUERY_DSL_BUILDS_API_ONLY` and `QUERY_ENGINE_IS_MODEL_NEUTRAL` (#4095, #4096, #4098, #4099); the mixed-version gate runs against the released 9.7.0 image (#4102).
