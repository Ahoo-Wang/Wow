# Benchmark reports

Every report names the commit, command, environment and raw results that reproduce it. How the benchmark is run and read is in [the benchmark README](../../README.md).

The tree keeps current evidence only (decision D391). A report stays while a later comparison still uses it: the latest snapshot of each environment, the current Actions refresh and the latest Axon round of each machine. When a new snapshot merges, the one it replaces moves out in the same change, under the same rule: its files are deleted, and its row moves from Current to History with a permalink to the last commit that has it. A node's raw logs are not committed, unless they are the evidence for a conclusion. Everything that left is still reachable: the History links are fixed at commit `1357642891`, where each report sits with its directory and raw files.

## Current

Wow 10 is measured against itself: each change by alternating rounds against the code before it, and the head against a V10 baseline by each run of the benchmark workflow (`bench.yml`), whose report is the run's own. A snapshot records capacity; changes are decided by an ABAB against `main`.

## 9.x

The reports of the 9.x JMH benchmarks (`:wow-benchmarks`) are on the `v9` branch, in `wow-benchmarks/results/reports`, with the accepted 9.x baseline `framework-e2e.json` in `wow-benchmarks/results/baselines`. They measure the 9.x command pipeline and stores, not Wow 10, and the Gradle tasks that wrote them left with the 9.x code (decision D262): they cannot be regenerated on `main`. `main` no longer carries a copy (decision D391).
